# Cross-Chain Architecture Map — the management-chain index

The platform has rich *per-domain* architectures — an operational data model, a release-pipeline spine, a handoff framework, a knowledge architecture — each authoritative in isolation, none indexed against the others **by chain**. This document is that missing connective surface: for every management chain, it names in one place **(1)** the governing data model / entity that defines the chain's records, **(2)** the flow / escalation path along which work and state move, and **(3)** the holding gate / check that holds new work against the chain.

**What this is NOT.** It is **not** a rebuild of any per-domain architecture, and it is **not** a restatement of the docs it draws on. It is an **index**: every cell **links** its source and lets the linked home keep its single source of truth. The operational delivery chains (World B) had no flow map analogous to the release pipeline's five-function spine (World A); this map is the World-B analog and the cross-chain join over both.

## How to read this index

| Column | What it holds |
|---|---|
| **Chain** | The management-chain name (the row key). |
| **Governing data model / entity** | The canonical model/entity that defines the chain's records — a **link** to its shipped home ([`project-entity-model.md`](project-entity-model.md), a tracker schema, or a pipeline spec). Never the fields themselves. |
| **Flow / escalation path** | How work/state moves along the chain — a **link** to the authoritative flow (an entity relationship chain, a five-function-spine flow, a skill-mode sequence, or a lifecycle model). |
| **Holding gate / check** | The gate/check that holds new work against the chain — a **link** to the guardrail, gate spec, tracker tier, or Document-Tier rule. `[ASSUMPTION – CONFIRM]` marks a cell not yet defined. |

Entities are named as they appear in [`project-entity-model.md`](project-entity-model.md) §4 — the canonical **19-entity** model (§4 definitions · §5.1 the 21 directed chains, referenced below as `chain N` · §6 owning-agent matrix). The named entity is the durable key; the shipped model is the single authority for its number and fields.

## Update discipline

This index is the authoritative cross-chain surface. Any change that **adds a new management chain, renames a governing source, or moves a referenced home** MUST update this index in the same PR. Outbound link liveness is covered for free by `core/deploy/deploy.sh --check` Check 14 and `link-check.yml` (both scan `core/disciplines/`); Stage 13 Close verifies index currency for any chain-source touched in the release. A bespoke automated **content-currency** scan (assert every canonical chain appears here) is **deferred** until the chain set grows materially or a staleness incident is filed — the same trigger model as the deferred content-scan pattern in [`duplicate-source-discipline.md`](../standards/duplicate-source-discipline.md).
