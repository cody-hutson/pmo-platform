## `block-fs-boundary.sh` (BLOCK-FS-BOUNDARY-001..004)

| Field | Value |
|---|---|
| Hook | `.claude/hooks/block-fs-boundary.sh` |
| Matcher | Bash |
| Scope | Workspace-boundary scoping for Bash file commands beyond settings.deny coverage (cat/head/tail/sed); file-read (cat/head/tail/less/more/base64/xxd/od/hexdump/strings) + file-write (cp/mv/tee/dd) source+target; resolved-path prefix-match against `.claude/fs-boundary-allowlist.txt`; expansion-bearing operands dispositioned by an ordered guard cascade over their literal spans (refuse the ambiguous, the operands whose path only an evaluation produces — `$(`, a backtick, a parameter-transformation operator's shape — and the traversing, classify a decidable prefix, admit-and-record the undecidable) |
| Mode | Warn-mode initial (shared `.claude/hooks/.mode`); flip-to-enforce per the [`§ Shakedown → Enforce Transition Checklist`](../bypass-mode-readiness.md) |

Added in the modular-monolith-cleanup release. Composes with Anthropic's native `settings.deny` `Read(...)` / `Edit(...)` rules (which natively cover the Read tool, Edit/Write tools, and the recognized Bash file-command subset cat/head/tail/sed per `code.claude.com/docs/en/permissions`). This hook closes the residual Bash gap for cp / mv / tee / dd / base64 / xxd / od / hexdump / strings / less / more. Mode-gated via shared `.claude/hooks/.mode` (same file as `block-egress` + `block-mcp-writes`) — initial state `warn` per Shakedown → Enforce Transition Checklist.

### Rule registry

| Rule ID | Description |
|---|---|
| BLOCK-FS-BOUNDARY-001 | File-read verb (`cat` / `head` / `tail` / `less` / `more` / `base64` / `xxd` / `od` / `hexdump` / `strings`) with resolved target path outside the allowed roots in `.claude/fs-boundary-allowlist.txt` |
| BLOCK-FS-BOUNDARY-002 | File-write verb (`cp` / `mv` / `tee` / `dd`) with resolved source OR target path outside the allowed roots in `.claude/fs-boundary-allowlist.txt` |
| BLOCK-FS-BOUNDARY-003 | Operand refused by the guard cascade below: the `xargs` stdin sentinel (G0), a quoted structural construct carrying the canonicalizer's sentinel (G1), a `$(...)` subshell, a backtick, or the shape of a parameter-transformation operator (G2), or a literal `..` traversal component / absent cwd for a relative token / unavailable path normalizer (G3), or an expansion the span split cannot delimit — a `$` it does not recognize, an unterminated `${`, or a `${…}` span it would close inside a subscript |
| BLOCK-FS-BOUNDARY-004 | **Advisory, non-blocking.** An expansion-bearing operand with no decidable literal prefix to classify — the genuinely undecidable class. Admitted, and recorded on every invocation that reaches the verb check. **The disposition is mode-independent; the record is not.** It never blocks at any `.mode` value, `enforce` included — but at `.mode=off` the hook exits before the verb check, so no advisory record is written. Recording is scoped to `warn` and `enforce` |

**Settings.deny pairing:** the hook's verb coverage closes the residual Bash gap; for the Read tool, the Edit/Write tools, and the recognized Bash subset (cat / head / tail / sed), Anthropic's native `permissions.deny` rules in `.claude/settings.json` are the primary line of defense. The two surfaces are kept coherent — the deny patterns mirror the allowlist's negative space for the Read/Edit Anthropic surfaces (per-subdir explicit deny for `~/Documents/`, `~/Desktop/`, `~/Music/`, `~/Pictures/`, `~/Movies/`, `~/Public/`, the high-risk `~/Library/` subdirs, and other-user homes `//Users/<other-user>/**`). Per Stage 5 spec Section 1, the two surfaces are not perfectly DRY by design — `settings.deny` is deny-list-based while the hook is allowlist-based; the gitignore-spec syntax used by `settings.deny` does not support an "allow inside a deny region" pattern, so `~/Library/Application Support/Claude/local-agent-mode-sessions/` (the Cowork install path required by `deploy.sh --deploy`) is preserved via per-subdir explicit-deny on the Library sub-paths that need blocking, leaving the install path accessible.

> **Limit of that pairing — it does NOT cover the `-004` residual.** `settings.deny` entries are **path-pattern** rules (e.g. `Read(//Users/*/.ssh/**)`); they cannot expand `$X` any more than this hook can. The pairing paragraph above is true for **literal** paths only. An operand admitted under `-004` — `cat "$X"` where `$X` expands to an out-of-boundary path — is therefore **not** caught by a second layer, and it is wrong to describe it as defence-in-depth. What bounds the residual is the cascade itself (every *decidable* hostile shape stays refused) plus the `-004` record, which keeps the admitted class measurable so a later narrowing has data — **on an instance where the hook actually runs.** That second bound is mode-scoped and the first is not: at `.mode=off` the hook exits before the verb check, so the class is still admitted but nothing is recorded, and the measurability argument holds for `warn` and `enforce` only. An operator reading this table to decide an enforce flip should read the `-004` record count from a `warn`-mode instance; a zero count on an `off` instance is the dial, not the population.

### Path Resolution — block-fs-boundary.sh

For each target token extracted by `extract_target_tokens(verb)` (flag tokens skipped, same chained-command tokenizer as `block-rm-prefer-trash.sh`):

1. Strip surrounding single/double quotes.
2. **Guard cascade over the operand's literal spans** (classify the skeleton, not the token). Evaluated in this order — *refuse-before-decide*, so an ambiguous or executable construct can never reach the code that could admit it:

   | Guard | Condition | Disposition | Rule ID |
   |---|---|---|---|
   | G0 | token is exactly `$XARGS-STDIN` (the canonicalizer's stdin sentinel) | REFUSE | `-003` |
   | G1 | token carries the canonicalizer's quoted-span sentinel | REFUSE | `-003` |
   | G2 | token contains `$(` or a backtick, or carries a `${` and, anywhere, `@`, one character other than `]` or `}`, and `}` — the shape of a parameter-transformation operator | REFUSE | `-003` |
   | G3 | a literal span holds a `..` component; or the token is relative and `payload.cwd` is absent; or python3 is unresolvable / `realpath` fails | REFUSE | `-003` |
   | G5 | a decidable literal prefix (text before the first expansion, truncated at its last `/`) resolves **outside** all allowed roots | REFUSE | `-001` / `-002` |
   | G4 | that decidable literal prefix resolves **inside** an allowed root | ALLOW, silent | — |
   | G6 | no decidable prefix — the operand opens with an expansion | ALLOW, recorded at `warn`/`enforce` (no record at `.mode=off`) | `-004` |

   An **expansion span** is `$NAME`, the `$1`/`$@`/`$#`-class, or an *unquoted* `${…}`. Each is substituted with a sentinel that is a single path segment containing no `/` and no `.`, so an expansion can never introduce a separator or a traversal component into the skeleton that steps 3–6 then classify. A `$` that introduces none of those shapes is **not guessed at** — the split fails and the operand is refused. Nor is a `${…}` span the split would close inside a subscript. The split ends a span at its first `}`; when a subscript holds a braced expansion, that first `}` is the nested expansion's, while the shell is still inside the subscript and reads on across whitespace, `;`, `&`, `|` and line breaks. A span whose text holds both a `[` and a nested `${` is therefore refused like an unterminated one. Both marks are tested rather than the brackets counted, so the test stays one pass (`XFORM-COST-02`).

   > **Why a *quoted* `${…}` is refused rather than parsed.** `core/hooks/lib/command-position.awk` replaces command-structural characters inside a quoted span with a sentinel byte. On the canonicalized stream this hook actually reads, a quoted `${VAR}` and a quoted `$(cmd)` are therefore **byte-identical**. **Any policy that admits braced parameter expansions silently admits command substitution.** G1 refuses on the sentinel instead of parsing the brace, which handles the ambiguity locally and leaves the shared canonicalizer untouched. An *unquoted* `${…}` keeps its own glyphs, so G2 reads it directly: an unquoted `$(`, backtick or parameter-transformation operator's shape is caught there, and every other unquoted brace form passes G1 and G2 to the rest of the cascade. Do not "simplify" G1 into a brace test: it would re-admit quoted command substitution, and the suite's three-way G1 arm exists to fail exactly that edit.
   >
   > **Why G0 is carved out.** The canonicalizer routes an `xargs` denial **through** this unresolvable branch, emitting the literal token `$XARGS-STDIN`. A rule that allowed on a leading expansion would parse it as `$XARGS` plus a literal `-STDIN`, find an empty prefix, and admit it — turning that denial off with no other arm noticing. G0 is ordered ahead of the `$NAME` parser for that reason.
   >
   > **Coverage boundary of G2 — what it reads, and what it is declared not to cover.** G2 reads the operand's own text for three constructs and refuses each wherever it appears: `$(`, a backtick, and the shape of a parameter-transformation operator. Parameter-transformation operators are REFUSED at G2. `${parameter@operator}` is a bash parameter expansion that yields not the variable's value but text the shell derives from it, and which letter derives what is a property of the shell's version: its `P` member re-expands the value as a prompt string, which performs command substitution. Older bash releases and zsh reject the operator on a plain parameter, and older bash accepts it on an array element and ignores it, running nothing; the suite's `XFORM-SEM-01` arm runs the demonstration on the first bash at five fixed locations that accepts it, and reports NOT-EVALUATED where none does. The cascade classifies an expansion as one unknown segment of a value. The path of an operand carrying the operator is instead whatever an evaluation produces, as for `$(` or a backtick: no literal prefix decides it and no `-004` record describes it, so G2 refuses it under `-003` with them. That is a statement about what this guard can decide, not a control on execution. The same operator in a command this guard does not list, or in a word the token walk never hands over, is not examined, and execution capability is governed by the script-execution allowlist (`BLOCK-DESTRUCTIVE-022`). G2 refuses the operator's **shape**, not `P` alone and not a list of letters: an operand that carries a `${` and, anywhere, `@`, one character other than `]` or `}`, and a closing brace. The shape is wider than the operator, and the over-refusal is a decision. A default word, an alternate, a pattern or a replacement ending the same way, such as `${LOG:-a@b}`, `${U%@*}` or `${U/@/}` (the at-sign replaced by nothing), is refused. So is literal text of that shape anywhere in an operand that carries a `${`, and so is the backslash-escaped spelling, as `\$(cmd)` already is. `${arr[@]}`, `${@:2}`, `${!prefix@}` and a default word that does not end that way are not refused. The suite's `XFORM-OVER` arms pin the first group and its `XFORM-NEAR` arms the second. The test is two passes over the operand, each linear in its length, and the suite's `XFORM-COST-01` arm holds that shape. The refusal holds unquoted, behind any literal prefix inside or outside an allowed root, nested in another expansion's word, and in the quoted spelling when the canonicalizer's quote mask is unavailable: unbalanced quotes hand the command back unchanged, step 1 strips the quotes, and the shape is read from the operand's text. While the mask is available, the quoted spelling is refused by G1 instead, because the mask replaces the braces G2 would read, so G1 stays load-bearing for it. G2's test needs the `${` and the shape in one word as the token walk hands it over, and inside a subscript the walk's words are not the shell's: the shell reads on across whitespace, `;`, `&`, `|` and line breaks there, where the walk ends a word or a segment and reads one physical line at a time. An operator use whose subscript holds a braced expansion, broken inside that subscript, therefore reaches the cascade with its `${` and its shape in different words, or with the shape in no word at all. It is refused instead by the span split (the expansion-span paragraph above), under the same `-003`: the word carrying the `${` holds a span the split would close inside the subscript. The suite's `XFORM-FRAG` arms pin each such break — whitespace, a tab, `;`, `&`, `|`, a newline and a line continuation, with no prefix and behind a prefix inside or outside an allowed root — each beside a copy of the hook whose split does not refuse it. The span split refuses more than that class, and the width is a decision: any span whose text holds a `[` and a nested `${` is refused, so a subscript holding a braced expansion is refused when nothing breaks it, plainly (`${arr[${i}]}`) and with a word (`${arr[${i}]:-x}`), and so is a word holding a bracket and a nested braced expansion (`${A[0]:-${D}}`, `${X:-${Y[0]}}`, `${X//[${C}]/_}`). Behind a literal prefix outside every allowed root, such an operand, and an operator use broken that way, is refused under `-003` rather than under the prefix rule's `-001`/`-002`. A subscript holding an unbraced expansion (`${arr[$i]}`) and a nested default with no bracket (`${CFG:-${HOME}}`) are not refused. The suite's `XFORM-OVER` arms pin the first group, and its `XFORM-NEAR` arms the second. All of this concerns an operand the token walk hands to the cascade; a word it never hands over is not examined at all, whatever it carries. Which words it hands over is set by mechanism, not by a list of positions. The hook looks for a listed verb only at a command start it recognizes — the start of a line, or after `;`, `&` or `|` — in the command as the shared canonicalizer rewrites it: the canonicalizer marks each command start it resolves, including one that follows a prefix word from its bounded set, and hands the command back unchanged when its quotes do not balance. The token walk then reads that command one physical line at a time, ends a segment at every `;`, `&` or `|`, takes the words after the verb only in a segment whose first word is that verb, and skips every word that begins with `-`. A word those rules leave out is never examined. Three such positions follow from the rules directly: a flag-position word such as `-${VAR@P}`, an assignment ahead of the verb such as `VAR=${VAR@P}`, and every word of a command this guard does not list. Five more are measured. Two are operand positions of a listed verb: an operand placed after a redirection operator that carries an ampersand, where the ampersand ends the verb's segment; and an operand on a continuation line, which the walk reads as a line of its own. Two are positions where the listed verb is not recognized at all: a verb word written in quotes; and behind a listed prefix word while an unbalanced quote elsewhere in the command switches the canonicalizer off. A former third — a verb behind a wrapper's own option or behind one of the words `nice`/`stdbuf`/`timeout`, or an absolute-path wrapper — is now resolved by the shared canonicalizer, which walks each wrapper's option grammar and matches a prefix word on its basename; the residual there narrows to a launcher outside the canonicalizer's bounded prefix set, which that card routes without an owner (References, below). The suite pins the two operand positions at today's verdict, each paired with a copy of the hook whose walk hands the word over; the two verb positions are named here and not pinned.
   >
   > **G2 does not see a value the shell re-evaluates.** This is a declared exclusion, not an oversight. An arithmetic context (`${v:offset}`, `${array[index]}`) or an indirection (`${!ref}`) runs a command substitution carried in *another variable's value* — the suite's `XFORM-RESID-04` arm observes all three on `/bin/bash` — while the operand shows nothing, and no lexical guard can refuse those without refusing ordinary substring, index and indirection forms. G2 refuses the operator because its shape is in the operand. These forms carry nothing there, so the operator's refusal does not close them, and the limit is stated instead of half-closed — the same limit that admits `cat "$X"`. The value they re-evaluate can arrive from outside the command text — from the environment, or from a file the shell sources — where no reader of the command can see it, a parser included, so the limit is declared without an owner. This guard scopes where the file verbs it lists may read and write; it is not a control on what a command may execute.
   >
   > **Two brace forms are refused by where the operand breaks, not by G2.** zsh's flag form (`${(flag)NAME}`) and the brace-form command substitution (`${ command; }`, and its `|` form) each execute on a shell that implements them: zsh runs the first, and ksh the second (measured). The canonicalizer starts a command at the first form's unquoted parenthesis, and after the second form's space or pipe. The token walk therefore hands over only the opening `${`, an unterminated brace the span split refuses under `-003`. The suite's `XFORM-SPLIT` arms pin both verdicts, each beside a copy whose span split admits an unterminated brace, so a change to the walk or the split that would admit either is a deliberate arm change.
   >
   > Each refusal this boundary names is mode-coupled like every `-001` to `-003` verdict: it blocks at `.mode=enforce`, warns and admits at `.mode=warn`, and is absent at `.mode=off` and while master activation is off.

   G5 refuses under `-001`/`-002`, not `-003`, and its message names the resolved **prefix** and says so — an operator is never told a path fully resolved when only its prefix did.
3. Tilde expansion: `~` → `$HOME`; `~/<path>` → `$HOME/<path>`.
4. Absolute (`/<path>`) → use as-is; otherwise → join with `payload.cwd`.
5. Normalize via Python `os.path.realpath` (system-default `/usr/bin/python3`). Collapses `..`/`./`, does not require path existence, and follows symlinks. Same `os.path.realpath` posture as `block-rm-prefer-trash.sh` (and `block-destructive.sh`).
6. Walk `.claude/fs-boundary-allowlist.txt` line-by-line; tilde-expand each entry; trim trailing slash; prefix-match the resolved path against each allowed root. First match → allow. No match → block (or warn-log when `.mode = warn`).

**Allowlist format:** one absolute path per line (NOT a bash glob — exact prefix-match after realpath); `#` introduces comments; blank lines ignored; trailing slashes normalized on both entry and target. Tilde-prefixed entries expand to `$HOME`. Subpaths of an allowed root are implicitly allowed.

**Symlink-following posture (intentional):** same as `block-rm-prefer-trash.sh` — `os.path.realpath` follows symlinks. A symlink inside an allowed root pointing to a target outside any allowed root resolves to the outside target and is blocked. This matches the strict-policy requirement: "block any file access whose resolved path is outside the allowed roots."

**Cost of a refusal on a large operand.** A PreToolUse hook that outlasts the runtime's command-hook timeout does not block, so what a refusal costs on a large command is part of what it guarantees. The refusal message, and the `-004` record, render the operand with each canonicalizer sentinel shown as `<quoted-expansion>`; on bash 3.2 that global pattern substitution costs more than linear time in the operand once the operand carries a sentinel, so a large quoted operand could hold the hook past the timeout and turn its refusal into an allow. An operand of at least a fixed bound is now rendered first by one `sed` pass in the C locale, whose output equals the substitution's byte for byte (`AC-FSB-X-EQ`); a shorter operand keeps the substitution, whose cost the bound keeps below the pass's own, and a pass that fails leaves the operand to it, so the message is the same on every path. The suite holds a refused read of a large quoted operand carrying structure throughout inside a fixed budget at 10, 20 and 40 KB, in UTF-8 and in C (`AC-FSB-X1` to `-X6`). Beside those arms, a copy whose pass never runs is stopped at the budget (`AC-FSB-X-CTL`), and a copy whose pass tool is missing refuses with the same message (`AC-FSB-X-FB`). **That is the renderer's cost, not the hook's:** each operand the walk hands over costs a `python3` process for its normalization and a read of the allowlist, so the hook's time grows with the number of operands; and an operand carrying many unquoted expansions is split by a loop that re-reads the text it has left at each one, which grows faster than the operand.

**Absolute-path-aware verb anchor:** same anchor pattern as the other three regex-based PreToolUse hooks — file-read and file-write verbs invoked via canonical absolute-path prefix (`/bin/cat`, `/usr/bin/cp`, etc.) are detected uniformly with the verb-at-command-start form. See [`§ Absolute-Path-Aware Verb Anchor`](../bypass-mode-readiness.md).

See [`§ Known Limitations`](../bypass-mode-readiness.md) for this hook's shell-redirection, nested-shell + quoted-path, and `~/Library/<unenumerated-subdirs>` settings.deny-coverage-gap residuals.
