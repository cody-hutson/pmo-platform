# Label Attribute-Disposition Registry
#
# Per-row dispositions for the DIVERGED class of deploy.sh --check Check 51
# (core/deploy/tools/check-label-parity.py --dispositions). A DIVERGED row is a label
# that is DECLARED in a pack's [[labels]] facet AND LIVE on GitHub, whose colour
# and/or description disagrees with the declaration.
#
# Format: <disposition> <label-name>  # <rationale>
#
# Disposition FIRST, and the order is forced rather than stylistic: a label name may
# contain spaces (`cluster: architecture`), so a name-first record is unparseable,
# whereas the disposition is a closed space-free enum and the label name is then the
# free-form remainder.
#
# disposition values (closed enum):
#   reconcile-live         the DECLARATION is right; live is wrong. Remediated by the
#                          operator running the `gh label edit` line that
#                          `check-label-parity.py --emit-fix` renders.
#   reconcile-declaration  LIVE is right; the declaration is wrong. Remediated by
#                          editing the row in core/packs/<pack>/pack.toml — never in
#                          core/specs/label-taxonomy.md, which per ADR-070 holds the
#                          GRAMMAR — group definitions, rules and namespace patterns —
#                          and cannot express a colour or a description at all.
#   accept-override        the divergence is a DELIBERATE operator choice and is not
#                          drift. The row is suppressed and reports in no arm.
#                          Optional axis qualifier: `accept-override:color` /
#                          `accept-override:description`; the bare form covers both.
#                          Axis scoping matters — accepting a colour must not
#                          silently accept an unreviewed description, so a row
#                          registered on one axis still reports on the other.
#
# A `reconcile-*` row is OWNED but still divergent, so it KEEPS reporting until the
# operator-run cascade closes it. Only `accept-override` suppresses. A row registered
# here that is no longer divergent (or no longer live) reports as DIVERGED-STALE and
# should be removed — an unaudited suppression that has silently stopped matching is
# the defect class this arm exists to close.
#
# Blank lines and #-prefixed comments ignored. A malformed record is a HARD parse
# error (exit 2), never a silent skip: a dropped record is a suppression the operator
# believes is in force.
#
# Governance: additions follow the "No ungoverned changes" protocol
# (CLAUDE.md Guardrails) — GitHub Issue + plan + PR required.
#
# See: core/specs/label-taxonomy.md § Instance Model
#
# ---------------------------------------------------------------------------------
# WHY THE 27 `reconcile-live` ROWS BELOW ARE ONE RULING AND NOT 27 JUDGEMENT CALLS
#
# The 24 rows whose LIVE description is empty share one cause. Their declarations
# were authored into the packs; NO CODE PATH IN THIS REPOSITORY HAS EVER WRITTEN A
# LABEL DESCRIPTION TO GITHUB. `--emit-fix` renders the `gh label edit` commands and
# runs none of them, and there is no other writer. The empty live description is
# therefore ABSENCE-OF-WRITE — the original state of a label created by the
# apply-an-unrecognised-label path, which auto-creates it with a default colour and a
# null description — and never a deliberate override that was made and then lost.
# There is no operator choice to preserve, so `reconcile-live` is the only disposition
# consistent with the evidence.
#
# The 11 of those 24 that ALSO diverge on colour corroborate it: the DECLARED palette
# is semantically coherent (`status: approved` green / `deferred` yellow / `proposed`
# grey) and the live one is not (teal / red / peach) — the signature of GitHub's
# default assignment, not of a considered choice.
#
# The remaining 3 (`bug`, `documentation`, `duplicate`) carry GitHub's verbatim
# out-of-the-box description text. Same repository-default family the § Excluded
# Labels table names; same ruling.
# ---------------------------------------------------------------------------------
