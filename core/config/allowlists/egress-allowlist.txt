# Egress Allowlist — core/hooks/block-egress.sh BLOCK-EGRESS-004 (curl POST) and BLOCK-EGRESS-007 (gh api POST)
#
# Hosts / gh-api paths to which outbound uploads (POST/PUT/PATCH/DELETE) are permitted.
# Uses bash glob patterns (shell case matching), NOT regex.
#
# TWO MATCH DOMAINS SHARE THIS FILE. A DECLARED ROW IS CONSULTED ONLY IN ITS OWN.
#   host         — the host portion of a curl upload URL (BLOCK-EGRESS-004),
#                  e.g. api.github.com. Only curl is checked against this file:
#                  wget uploads are denied unconditionally (BLOCK-EGRESS-005), and
#                  no row here can permit one.
#   gh-api-path  — the resolved path of a gh-api write (BLOCK-EGRESS-007),
#                  e.g. repos/[OPERATOR_GITHUB]/pmo-platform/issues*
#   A row declared host is never matched against a gh-api path, and a row declared
#   gh-api-path is never matched against a host.
#
# Format:
#   - One pattern per line
#   - Token-substituted at install time: [OPERATOR_GITHUB]
#   - A line whose FIRST character is # is a comment, and blank lines are ignored.
#     A # after leading whitespace is NOT a comment: that line is read as a pattern
#     that can never match, so never indent a comment.
#   - Scope directive: a line reading exactly `# egress-scope: host` or
#     `# egress-scope: gh-api-path` declares the domain of the ONE row on the line
#     immediately below it. Anything else on that next line (a blank, a comment,
#     another directive) discards it, so a scope never carries onto a later row.
#     Any other value after `# egress-scope:` makes the row below it match NOTHING:
#     a mistyped scope fails closed, never open.
#   - Every row in this managed section carries its directive. A row with NO
#     directive above it (possible only in the OPERATOR ADDITIONS region) is
#     consulted in BOTH domains, which is how every row was matched before
#     directives existed. Put a directive above it to confine it to one domain.
#   - Whatever its directive, a pattern whose FIRST path segment carries a glob
#     character (*, ? or [) is never matched against a gh-api path. A host wildcard
#     such as *.github.com reaches a path only by absorbing the whole front of it,
#     and a query string lets any write end in host-shaped text
#     (issues?x=a.github.com), so a leading glob must never grant a gh-api write.
#   - That rule works in ONE direction: it keeps a host wildcard off gh-api paths,
#     and it does nothing at the host check. So a row with no directive and no `/`
#     — a glob such as gist* or a literal such as gists — is still matched as a
#     curl host, and a slashless literal is still matched as a gh-api path as well.
#     Give every operator row a directive.
#
# What a gh-api path pattern is matched AGAINST (BLOCK-EGRESS-007):
#   - The RESOLVED, UNQUOTED path. The matcher consumes quote marks while
#     tokenizing, so `gh api "<path>"`, `gh api '<path>'` and `gh api <path>` all
#     produce the same token and therefore the same verdict. Do NOT add a quoted
#     spelling of a pattern — it can never match.
#   - The path is located by walking flags, so it is found wherever it sits in the
#     command line: `gh api -X POST <path>` and `gh api <path> -X POST` are
#     equivalent. A value-taking flag's VALUE is never mistaken for the path.
#   - EVERY gh-api invocation in a command is matched, not just the first, and a
#     write is matched wherever it sits in the command — inside a loop body, a
#     subshell, a command substitution, or behind a `VAR=x` prefix.
#
# PREFIX-ANCHORING — keep this true when adding a gh-api path pattern.
#   A path pattern must spell out literally every segment up to and including the
#   account whose repositories it grants — `repos/<owner>/...`, `orgs/<org>/...`,
#   `users/<user>/...` — and may wildcard only below that. The managed catch-all
#   `repos/[OPERATOR_GITHUB]/*` pins the owner, and so grants every repository of
#   that one account. -007 relies on the pinned account: content in a path that the
#   hook cannot evaluate (a `$VAR`, a `{placeholder}`) is wildcard-normalized and
#   adjudicated only BELOW the path's first three segments, which is sound only
#   because every path pattern pins the account literally. A pattern that wildcards
#   into the account would let an unevaluable path match an account nobody
#   adjudicated. The hook enforces the part of this rule that separates a path
#   pattern from a host wildcard (the leading-glob rule above); pinning the account
#   is the author's obligation, and the egress hook's test suite checks it for every
#   row in this managed section.
#
#   A path whose AUTHORITY itself is unresolvable — `repos/{owner}/{repo}/...`,
#   `repos/:owner/...`, `repos/$OWNER/...` — is DENIED with its own cause, and NO
#   allowlist entry can change that. gh resolves those placeholders at execution
#   time from the environment, a default-repo setting, or the current remote, none
#   of which the hook can see. The fix is to spell the owner and repository out in
#   the command, not to add a row here.
#
# Add custom entries to the OPERATOR ADDITIONS section at runtime, or run one of:
#   ./.claude/hooks/allowlist-add.sh .claude/egress-allowlist.txt '<host-pattern>' --scope host
#   ./.claude/hooks/allowlist-add.sh .claude/egress-allowlist.txt '<path-pattern>' --scope gh-api-path
# Without --scope the helper still adds the row, with no directive, and prints how it
# will be matched. Re-running with --scope declares an existing bare row in place.
#
# ---
