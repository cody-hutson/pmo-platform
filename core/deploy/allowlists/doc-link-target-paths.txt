# doc-link-target-paths.txt — SINGLE SOURCE OF TRUTH for the doc-link checker's
# scan scope (the --target-paths globs). Consumed by BOTH surfaces that run the
# check-doc-links.py primitive over the governance/reference/rules/skill corpus:
#
#   * core/deploy/deploy.sh  Check 14   (deploy-time)  via --target-paths-file
#   * .github/workflows/link-check.yml  (PR-time)      via --target-paths-file
#
# Both pass THIS file with --target-paths-file, so their scan scope can never
# drift — the two used to carry a byte-identical inline --target-paths string,
# and keeping two copies in lockstep is exactly the drift hazard this file
# removes (one list, two identical references).
#
# Format: one glob/dir/file per line (relative to the workspace root). Blank
# lines and '#' full-line comments are ignored. A directory entry is scanned
# recursively for *.md (check-doc-links.py expand_globs: a dir -> rglob("*.md"));
# a glob such as `*.md` matches workspace-root top-level *.md only.
#
# --require-targets contract (both callers pass it): EVERY entry below must
# resolve to >= 1 file, or the checker exits 3 (path-resolution failure, ALWAYS
# hard-fail, independent of warn-mode) — a relocated/typo'd scan surface can
# never read green. When adding an entry, confirm it yields >= 1 .md today.
