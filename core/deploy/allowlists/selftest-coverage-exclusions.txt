# Self-test coverage exclusions — the PRECISION mechanism for the discovery gate
# (release/tools/check-selftest-coverage.py).
#
# Format:  <repo-relative path>  # <reason>
# An entry WITHOUT a reason is a parse error, asserted by the engine's own
# --self-test. Suppression must cost a written justification, in the diff,
# attributable to an author.
#
# WHY THIS FILE EXISTS RATHER THAN A TIGHTER REGEX. The advertise predicate is
# recall-biased on purpose: a false negative is an unenforced self-test — the exact
# defect the gate closes — and it is SILENT, while a false positive is one line here
# and it is LOUD. Precision belongs in this file. Do not "fix" a false positive by
# narrowing the regex; that re-opens the silent class.
#
# WHAT AN ENTRY HERE IS NOT. Excluding a tool is never a valid disposition for a
# FAILING self-test that genuinely dispatches. The engine emits a standing
# ::warning:: for any in-scope exclusion whose comment-stripped text still contains
# --self-test, precisely so a real self-test cannot be quietly retired from the gate.
# Narrowing a '# scope:' directive in the manifest is not a disposition either — it
# is a hard failure (Arm B(i)).

# --- Predicate false positives (F3): matched by the recall-biased predicate, but the
# --- file has no --self-test dispatch. The quoted match is REQUIRED so the claim is
# --- checkable without re-deriving it.

# --- Non-hermetic self-tests (F4): the tool genuinely dispatches on --self-test, but
# --- the suite cannot reach a verdict on a CI runner. These are REAL self-tests taken
# --- out of the gate, NOT retired false positives, and the engine raises a standing
# --- ::warning:: naming them on every run for exactly that reason. Each is a
# --- hermeticity defect in the tool, owned by that tool's card — the disposition is
# --- "fix the tool", never "narrow the scope", and it stays visible until it is fixed.
# --- (No F4 entries currently. The section header and its doctrine above are
# --- RETAINED deliberately: they document the class, not any one instance, and the
# --- next F4 candidate needs the written boundary. parse_exclusions ignores
# --- "#"-leading lines, so an empty section is well-formed and costs nothing.

# --- widened to accept the script's own checkout root rather than exempting the
# --- fixture from the destructive-scope guard. See release/ADRs/ADR-142.)
