# Fixture manifest for check-issue-ref-validity.sh --self-test
#
# Format, pipe-separated:
#   class | source file under cases/ | destination path in the fixture repo | expect in delta mode | expect in path mode
#
# `flag` = the file MUST appear in the report. `zero` = it MUST NOT.
#
# WHY TWO EXPECTATION COLUMNS. Delta mode scans only the lines ADDED between the
# two fixture commits; path mode scans every line of the file. Z-6 is the class
# where those genuinely differ, and collapsing them into one column would force
# that class to be dropped rather than asserted.
#
# A source that also exists under base/ is written at the BASE commit and MODIFIED
# at HEAD, so its pre-existing content sits outside the added-line delta. Every
# other source is ADDED at HEAD.
#
# The destination path is load-bearing for Z-2: the ONE surviving path-exemption
# arm is only reachable from a file that actually LIVES at the exempt path, which
# is why Z-2a is written to `release/releases/`.
#
# There used to be two more rows here — Z-2b and Z-2c, pinned to the gate's own
# rules page and the PR template, the second path-exemption arm. That arm was
# deleted: those files are exempt because they CARRY the whole-file override
# marker, discovered on every run, not because a hand-maintained list names them.
# The rows could not simply follow the arm into this corpus. This manifest is the
# input to the differential equivalence oracle, which asserts BYTE-IDENTICAL
# report text against the pre-extraction body — and that body still carries the
# deleted arm, so any fixture at those paths makes the two implementations
# disagree and fails a required status check ON A CORRECT CHANGE. The class now
# lives corpus-free in run_self_test()'s `self-doc` block, where it asserts BOTH
# directions (marker present -> zero, marker absent -> FLAG) plus the
# rationale-carrying marker form, rather than the single zero-direction these two
# rows asserted. Their two synthetic numbers are reused there, so no
# verdict-map.txt row is orphaned.
#
