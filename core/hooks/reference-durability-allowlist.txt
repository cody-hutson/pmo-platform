# reference-durability-allowlist.txt
#
# Path allowlist for block-fragile-refs.sh + the reference-durability deploy-check
# check + the reference-durability CI workflow. One glob per line. A leading '#'
# introduces a comment. A trailing slash matches a directory (prefix match). All
# other lines are file/glob patterns matched against the incoming file path.
#
# Allowlist entries document WHY a path is exempt — the structural reason the path
# legitimately carries flagged constructs (links, version apparatus) — not a wish
# to silence warnings. Adding a path is governance-approved for non-trivial scope.
#
# Per core/standards/reference-durability-standard.md § The override-marker and
# allowlist mechanism. For a single file that needs a single class, prefer the
# per-file override marker over a path allowlist entry.

# Historical-by-design corpus: archived release artifacts are immutable history and
# legitimately carry references frozen at their authoring time. Never re-author them.
release/releases/archive/

# Entity-model derivation surface — pervasive intra-doc anchor links on touched lines.
# entity-field-schemas.md (G2 field schemas) is a navigational reference doc whose
# AC-checklist, §3 per-entity sections, and §4 X-rule table cross-link to each other and
# to project-entity-model.md via intra-doc anchors ([§3.0](#30-...), [§3.6](#36-...), etc.).
# The reference-durability issue-ref detector cannot distinguish an anchor link's `#N`
# fragment (e.g. `#3`, `#30`, `#36`) from a bare GitHub issue reference, and is not
# governed by the per-file allow-link marker. The ADR-018 Work Item amendment (roster
# 17->18 cascade + the new §3.18 field schema) re-touched lines carrying these
# pre-existing anchor links, surfacing them in the added-lines delta. They are NOT
# net-new fragile refs — they are the doc's own navigation. Exempting the file mirrors
# the sibling project-entity-model.md entry above (same derivation surface, same reason).
core/schemas/entity-field-schemas.md
