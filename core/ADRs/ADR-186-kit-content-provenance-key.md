# ADR-186 — Kit content declares its provenance through a required `source` key at two altitudes, projected as a new sibling annotation class

## Status

**Accepted.** Operator-ratified at the `kit-content-and-defaults` Stage 5 Collective Review scope-lock on 2026-09-04. One sub-decision — the annotation's name — was deliberately deferred to Stage 6 so it could be rendered against the real diff rather than against a design sketch; it is recorded in **D4** below and is part of this Accepted record.

## Context

A methodology pack declares kinds, fields and criteria. The grammar said what each declaration must *contain* and never said where its content *came from*. So a reviewer reading a shipped pack could not distinguish a criterion derived from a named body of practice — the Scrum Guide, the Kanban Method, an INVEST-class heuristic — from one reverse-engineered out of a single deployment's issue tracker. The type-packs README already stated the sourcing expectation in prose; nothing made it checkable, and prose an author never has to satisfy is a preference, not a boundary.

The forces are three.

1. **The corpus-versus-local-convention boundary is the whole value of a methodology pack.** A pack that quietly encodes one team's habits under a methodology's name is worse than a pack with no content, because it ships the habit with the methodology's authority attached.
2. **A downstream conformance lint needs something to audit against.** A completeness check that can only assert *a criterion exists* is weaker than one that can assert *a criterion states its origin*, and the second requires a declared key rather than a convention.
3. **Whatever ships must not break the deploy-time pack-conformance check.** That check runs a discrimination control before its live-corpus run, and that branch increments the issue counter **outside** the warn-mode gate. Most shipped criteria tables omit the `checks` key entirely, both discrimination fixtures included, so any rule keyed on *absent-or-empty* turns the check red on both control arms regardless of mode. This constraint shaped the requiredness condition, not just the runner decision.

## Decision

### D1 — `source` is the fifth base field of a criteria check entry

A `criteria.{readiness,done,gate}.checks[]` entry carries `id`, `statement`, `level`, `automatable` and **`source`** — a flat TOML string naming the body of practice the check derives from. Never an inline table, never a nested block: an inline table opens with `{` after the `=`, so the value-reading probes the release's own acceptance criteria depend on would return zero on both their subject and control arms, which is a broken probe rather than a clean result.

`source` is placed on the check entry rather than folded into `statement` or `description` because provenance is a **separate axis** from what a check asserts. The four existing fields describe the assertion; none carries where it came from without overloading. The shipped `scrum` manifest already demonstrates the overload it replaces — a field's provenance carried as a parenthetical inside its `description` — which is a shadow home for a fact that now has a real one.

### D2 — The FieldDecl amendment is a declared pack-layer SUPERSET, not a redefinition

`fields.kind_specific[]` FieldDecls previously reused the entity layer's row shape *verbatim*. They now reuse it **plus `source`**, and the grammar says so in those words. The alternative — adding a `source` column to the entity-layer field schema — is rejected: `source` records which body of practice a **pack author** drew a declaration from, which is a fact about the pack, not about the entity field. Pushing it into the frozen entity layer would make a pack-layer concern the entity layer's problem for every consumer of that schema. Retaining the word *verbatim* while adding a member was the other alternative, and it ships a false sentence.

### D3 — Two altitudes, with a present-and-empty block carrier, and NO inheritance in either direction

An **entry** always carries its own `source`. A **block** — a `[kinds.criteria.*]` or `[kinds.fields]` table — carries one **only when its array is present and empty**, where it states the practice basis for the *emptiness*. That is the machine-readable form of an explicit, reasoned empty set: an empty set that has been reasoned about is a first-class outcome of this grammar, not an unfinished one.

The condition is **present and empty**, deliberately, and **never absent-or-empty**. The distinction is the whole of Context force 3: an absent-or-empty condition has a true antecedent on every table that omits `checks`, which is most of the corpus and both discrimination fixtures.

**No inheritance, in either direction.** A block `source` never satisfies an entry's requirement, nor an entry's the block's. The two answer different questions — *why this declaration exists* versus *why none does* — and inheritance would let one block `source` silently discharge an unbounded number of entry obligations, converting a per-declaration audit into a per-block one.

### D4 — The annotation is `x-pmo-content-source`: a NEW sibling class, a ROOT-level array, LEVEL-INVARIANT

**(a) It mints a new sibling annotation class; it extends no existing key's contract.** An earlier framing claimed this extended the controls facet's provenance key. **That claim is withdrawn.** The precedent it rested on has 0 declared subjects, 0 materialized instances, and — the arm that settles it — **no member of the population that could carry a materialized instance exists at all**, because the corpus holds zero derived per-kind schemas. A zero measured over a population that cannot exhibit the construct is not evidence of an established pattern. The honest and stronger framing is the one ADR-077 D3 already established for its own annotation: a **new sibling class** in the `x-pmo-*` family, under the same *no new physicalization and no new enforcer* constraint, which this decision satisfies.

**Reuse is re-rejected on a ground that does not depend on a consumer existing.** Reusing the controls facet's key would require **one key carrying two disjoint value domains** — a parseable internal pointer and a free external practice string — with **no discriminator**, over **two disjoint subject sets**, at **two placements**. That is the same-name-different-meaning defect this dialect already carries a standing disambiguation note about, taken on by construction rather than arrived at by accident. The earlier rejection reasoned about breaking a consumer that splits on a separator; no such consumer exists, so that argument would have collapsed the moment one shipped.

**(b) Root-level and level-invariant, forced by the derivation.** Both placements are precedented, so precedent does not decide it. Three constraints do. **(1) The `required` seam.** The derivation's L1 arm names three schema-expressible constraint forms: `enum`, `pattern`, `required`. **`enum` and `pattern` ARE property-level keywords** — the claim that L1 cannot carry provenance at all is false and is not made here. `required` is the seam: a root array of property names with no per-entry object, so a `required`-projected check has no per-constraint site to annotate. **(2) Multiplicity:** one property may be constrained by several L1 checks carrying different sources. **(3) Non-disturbance:** keeping provenance out of the property body leaves the seven-class crosswalk and the three by-level projection arms byte-identical. Splitting provenance across property-level for two forms and root-level for the third would split **one axis across two readers**.

The entry shape is `{ ref, declared_in, practice }`. The member is `practice` and **not** `source`, because the shipped reference schema's referential-annotation entries already carry a member literally named `source` holding something else; reusing it would mint a second same-name-different-meaning pair inside one dialect. The member is `ref` and not `id` because it names the declaration's own identifier rather than one the derivation mints.

**(c) The name: `x-pmo-content-source` is RETAINED, and the retention is re-grounded because its original ground does not survive measurement.** The design offered `x-pmo-practice-source` as a rename and deferred the call to Engineering. Both candidates were measured at zero corpus citations and zero citations in either downstream content design, so the rename was genuinely cheap in either direction rather than defaulted. Rendered against the real diff:

- The stated rejection criterion for an earlier candidate was **probe containment**, and it reproduces as a control (`x-pmo-provenance` ⊂ `x-pmo-provenance-token`). It **does not fire** on either candidate here, in any of four directions. The criterion is therefore neutral between them and selects nothing.
- The design's affirmative ground — *every sibling names the annotated thing* — is **false on measurement**, and this record says so rather than repeating it. Across the family's 29 distinct tokens, most stems name the value's content or the annotation class. The `-source` suffix subfamily has exactly one prior member, so it is a precedent, not a pattern.
- What actually decides it is the **member-name collision**. The entry object's practice-bearing member is `practice`. Under `x-pmo-practice-source` a reader writes `x-pmo-practice-source[].practice` — stem and member repeating one word, with the member carrying the load. Under `x-pmo-content-source` the same read is `x-pmo-content-source[].practice`: *the content's source, whose practice is X*. Renaming the member instead would re-open the collision the paragraph above closed.
- Two secondary grounds: the key binds to the acceptance vocabulary the change is graded on (*kit content*), and the corpus's own device for a **strictly worse** collision — an identical field name, two disjoint meanings — is a disambiguation note, not a rename, so the weaker collision takes the proportionate remedy.

**The residual is real and is recorded rather than dismissed.** The two keys both end `-source`, both answer a question about origin, and can co-occur on one materialized schema. The mitigation ships in the grammar as a disambiguation table separating them on four axes — question answered, subject set, placement, value domain. **And the rename stays cheap for longer than the deferral assumed:** neither downstream content change cites the annotation name — measured at authoring time as zero in each, against live arms over the same two documents that each return a non-zero family-token count — so their landing does not close the window. The event that closes it is the first materializer implementation, and none exists.

### D5 — The value is a CONVENTION, not a grammar invariant

The grammar requires the key and constrains its *type* (a non-empty flat string). It does **not** constrain the value's format. The convention — name the work, its edition or year, and the locator where the work has one — lives in the type-packs README and is stated as a convention.

Mandating a locator separator was weighed and rejected on a counter-example: INVEST is a six-letter acronym with no sections, so a required separator would **forbid an authentic citation** of a body of practice the platform's own shipped defaults already name. A grammar rule that makes a true statement unwritable is worse than a convention that makes a lazy one merely conspicuous.

### D6 — The versioning discharge rests on NON-ENFORCEMENT, on a measured population of SIXTEEN

The meta-schema stays **v1**; no shim. The record is §6.2d, authored on the established three-axis form: axis 1 (optional add) N/A because `source` is required, axis 2 (relaxation) N/A because nothing widens, axis 3 a **restriction**.

**This is the first of the four extensions whose restriction meets a non-empty population, and the analysis says so instead of borrowing its predecessor's sentence.** The three prior extensions could each write *every shipped pack is byte-identical after this change*. **That sentence is false here and is not transferred.** The affected population, as of the authoring commit, is **16** — at that time 12 present-and-empty criteria tables, 3 present-and-empty field tables and 1 FieldDecl — every site in the two shipped archetype manifests, with both limbs reconciled against the structure they count. The composition is a point-in-time reading by construction: a versioning analysis measures the corpus at the moment the rule enters it, and the deriving walk is stated in the grammar's own §6.2d table so the figure is reproducible rather than merely asserted. An earlier reading of **zero** measured only the entry limb and reported it as the whole; two correct counts over different denominators look exactly like one wrong count, which is why the reconciliation is part of the claim rather than a footnote to it.

What carries the verdict instead is that **no runner exists that could reject any of the 16** — the validator does not descend into a criteria block's interior at all. Backward compatibility here is a fact about the absence of an enforcer, and the record states that plainly rather than implying a stronger guarantee.

**The permanent residual is stated as a class, not as a count.** A subset of the affected blocks ship as reasoned empty sets carrying a permanent block-level `source`, one of them held empty deliberately so a separate tracked piece of work retains its scope — so the block-altitude population does not trend to zero. Following the third extension's own recorded lesson (*a literal total went stale on the day it was authored while an enumeration could not*), the residual is described rather than totalled. And the honest consequence is named: **when the content-completeness lint ships, every declaration that has not adopted `source` becomes a finding.** That is the intended behaviour, and it is why the shipped manifests are remediated in the release that introduces the rule.

### D7 — The unenforced requiredness is admitted as class 3-O with a POSITIVELY-stated declared observable, and no rule id is minted

The rule is authored on the **obligation limb** — a stated trigger and an act, with no verdict for the negation — which is class **3-O** per ADR-162. The record deliberately omits the *is a pack-validation error* phrasing the neighbouring `condition` rule uses: that phrasing readmits the rule as the verdict-shaped class, whose two dispositions are *wire* or *downgrade*, and **both are unavailable** — wiring trips the discrimination trap, and downgrading deletes the requiredness the change exists to establish. *Register as a named gap* is reachable only through 3-O.

Class 3-O then obliges, none optional: a `**Runner:**` label in the passage (here, `NONE`, naming the gap), a row in the gate-coverage register with an empty enforcing-gate cell and no runner pointer, and — per ADR-162 and the gate-efficacy standard — **the observable the compliant path emits and the bypassing path does not**.

**The observable is stated POSITIVELY, and the polarity is a decision rather than a formatting choice.** The register's other no-runner row states an *absence*, and that form is **forced** there: its compliant and bypassing calls are byte-identical, so no positive token exists. Here one does — the `source` key — and it is trivially extractable, so this row models the register's runner-scheduled form, which reasons about polarity explicitly. The observable is the key's presence at every declaration site, emitted as a **per-limb** extraction: both the criteria-entry count and the FieldDecl count must be non-zero, because a single aggregate is satisfied by the criteria limb alone while the field limb is small enough to read empty by accident.

**No `PACK-*` rule id is minted.** Every id in that family carries a self-test arm that reddens when it has no mutation arm; an id with no runner is a gate that cannot fail. The intended runner is the content-completeness lint, and it is handed over with two constraints and one guard: **entry-scoped, never array-scoped**; **new fixture directories, never an edit to the two discrimination fixtures**; and a **self-test arm asserting both discrimination fixtures declare zero check entries**, because the trap-safety property is a *measurement* that nothing currently pins — neither fixture carries a comment saying its `checks`-free state is load-bearing, and the likeliest author of the edit that breaks it is the lint itself.

### D8 — The mechanism states its own limits, DESCRIPTIVELY, and deliberately carries no MUST

The grammar states, beside the rule, what `source` guarantees — that a claim's origin is **declared and auditable** — and what it does not — that the claim is **true**. A well-formed citation naming a real body of practice, containing no repo-internal token and derived from nothing local, satisfies every graded arm this change ships while asserting something the cited work does not support. The mechanism is not defective; it was never asked to check truth. What would be defective is a release whose value proposition reads as though auditability implied correctness.

**The form is descriptive and the reason is mechanical, not stylistic.** A phrasing such as *a reviewer MUST read the `source` value against the named work* has a stated trigger and an act with no verdict for the negation — which is **class 3-O again**, owing a second `**Runner:**` label and a second register row in the same release. Stating the identical fact descriptively mints no unregistered obligation. This follows the gate-efficacy standard's own house style for a mechanism naming its limits, whose enumerated items carry no MUST for exactly this reason.

The adjacent scope boundary is folded into the same statement rather than given its own clause, because it is the same sentence-shape: `source` is scoped to check entries and FieldDecls, and pack-level control declarations carry **no** content-provenance key. That is a stated boundary, not an oversight — no shipped pack declares a control today, so the gap is latent, but a WIP or pull-limit control is a named core practice of a published method and therefore exactly the object this key exists to make auditable. Extending `source` to controls crosses the controls facet's own provenance key and is owned by whichever change first declares a control.

### D9 — The rule is stated `role`-TOTAL

The rule binds on every pack whatever its `role` — `base`, `archetype` and `kit` alike — and the value domain admits **archetype-bound** bodies of practice and **archetype-neutral** ones. A kit pack, whose kinds must be archetype-neutral, therefore has an honest value available for a reasoned empty set rather than being forced to cite an archetype or to leave the key off.

The two rules do not interact mechanically: the archetype-neutrality constraint reads the kind's projection field and never the `source` string, so this is a semantic completion, not a validation conflict. Scoping `source` to archetype packs only was the alternative and is rejected — it re-hollows kit content, which is the failure the downstream completeness lint exists to catch. Stating the rule for all three roles mirrors the grammar's own earlier correction, where a one-directional statement left the unnamed role's case unwritten and permissive.

## Consequences

**Positive.** Every field and criterion a pack declares names the body of practice it claims to derive from, so the corpus-versus-local-convention boundary becomes readable off the manifest instead of trusted. A reasoned empty set gains a machine-readable form, so *we decided nothing belongs here* and *nobody got to it* stop being the same artifact. The downstream completeness lint gains a declared key to audit rather than a prose expectation. No rule id is minted, so the deploy-time conformance check's reachable verdict set is unchanged and no new gate can fail vacuously. The projection is level-invariant, so a consumer reads every declaration's provenance through one code path.

**Negative, and stated rather than smoothed.** The requiredness ships **unenforced** — declared, registered, and unrun — and its closure depends on a lint in a later milestone. `source` guarantees a claim is declared and auditable, not that it is true, and no gate this release ships detects a well-formed false attribution; that residual is closed only by a person reading the value against the named work. The annotation shares a `-source` suffix with a sibling key answering a different question, mitigated by an in-artifact disambiguation table rather than removed. And the trap-safety property the entry-scoped design depends on is a **measurement that nothing pins** — the guard that would convert it into an invariant is handed to the lint rather than shipped here.

**Neutral.** The register's resolution-pointer verdict is unmoved: a named-gap row correctly carries no pointer, so the row buys register-anchoring and discoverability — review-time properties — and no computed count moves. The three by-level projection arms and the seven-class crosswalk are byte-identical.

## Reversibility

**CHEAP · confidence HIGH.** Every edit is additive into three existing files plus this record: no deletion, no path relocation, no anchor move, no consumer contract narrowed, no validator rule, no fixture change, and no meta-schema version move. A standard branch revert restores the prior state exactly. The one cost that grows with time is the annotation *name*, and it is bounded and named in **D4(c)**: it stays cheap until a materializer implementation exists, and none does.
