# ADR-217 — The script-execution wrapper walk reads each wrapper's option grammar from rows

## Status

**Proposed** — authored at Stage 6 Engineering, after the operator's Collective Review scope-lock rendered the scope this record documents. The Stage 13 ratification beat owns the transition to Accepted; this record is not written Accepted at authoring.

**Numbering provenance.** Claimed as **217** against an anchor of **216** on `origin/main`, read from the repository's own ADR-numbering detector, which also reported 217 and 218 held on sibling branches (detection only, never binding). The number binds at the Stage-12 claim; should the mainline claim it first, the renumbering tool moves this record at merge time and appends one provenance note here per hop. In-release prose cites this record by its slug token, which carries no number shape and resolves at the claim.

## Context

BLOCK-DESTRUCTIVE-022 resolves command position by walking a prefix run of variable assignments, compound-command keywords and transparent command wrappers before it reads the verb. A transparent wrapper execs the rest of its argv, but only after its own options, and an option that takes a separate argument puts a second token between the wrapper and the command word. The walk knew the wrapper words and not their grammar: it stopped on the first option, read that option as the command word, matched no verb, and adjudicated nothing. `nice -n 10 bash <script>` is the same execution as `nice bash <script>`, and it was not the same verdict. A wrapper's own flags were a declared residual; `nice` and `stdbuf` were not in the set at all, with no recorded reason, though both meet the walk's own membership criterion — a wrapper that execs the rest of its argv unchanged.

The vocabulary was also held in more than one place. The egress rule's prefix-command walk, the shared command-position canonicalizer and a continuous-integration lint each hold a list of wrapper words, and the three walks among them read their lists with different grammars: this walk and the egress walk match the basename, the canonicalizer matches the exact token, only the canonicalizer steps over a leading redirection and an escaped verb, and only the egress walk steps over dash-led tokens. The lists had drifted — two words present in the egress list and absent here, three keywords present there and absent here — and nothing failed when they did.

The arity of an option is a fact about a program, not about shell grammar. This hook already holds per-program facts of that kind as data: four per-interpreter tables beside one another, so that admitting an interpreter means adding a row to each rather than editing control flow.

## Decision

1. **The whole wrapper set is walked with its grammar.** `nice`, `stdbuf` and `timeout` join `sudo`, `env`, `command`, `builtin`, `exec`, `nohup`, `time` and `xargs`. Each wrapper has one row in getopt notation, beside the per-interpreter tables: the short options that take an argument (attached or as the next token), those that take one only when attached, the long options that may take theirs as the next token, the options under which the wrapper executes nothing and only describes or edits its operand, and what stands between the option run and the command word (one positional operand for `timeout`, a run of `name=value` operands for `env`, nothing otherwise). A walker steps over one wrapper's option run and operands and leaves the index on the command word. It steps; it never adjudicates. A describe-only option (`command -v`, `sudo -l`) makes the segment no execution, which is the verdict those spellings already had. A long option is read the way the program's own parser reads it. Every wrapper here that reads long options does so through getopt_long, which takes an exact name, or any prefix naming exactly one of its long options, for that option; so each such row also carries the program's whole long-option table, taken from its parser's option table rather than its manual, and a long token is resolved against that table before the row is asked about it. A prefix naming two or more options, or a name that is none, is kept as written and stepped over as a flag, and the program rejects it and runs nothing. `exec`, `builtin` and `command` are shell builtins that read no long option.

2. **The failure direction is stated, not argued away.** A row closes what it lists. An option no row lists is stepped over as a flag, so if it takes a separate value, that value is read as the command word and nothing is adjudicated — the verdict every wrapper option had before the rows existed. That is the fail-open-on-omission direction the operand walk's notes reject for an arity table, accepted here on a measurement: the nothing-to-omit alternative, a scan for the verb, refuses ordinary commands whose arguments merely name an interpreter, in an arm that refuses on landing.

3. **An attached split string is read for a command word before the walk decides where the command is** (the first build condition). `env`'s split-string option takes env's own argv as its argument, prepended to what follows, so an attached spelling — `env -S<string>`, `env --split-string=<string>`, or any prefix of the long name the parser takes for it, such as `env --split=<string>` — is read for a command word of its own. When the value carries one (`env -Sbash <script>`, `env --s=bash <script>`), the walk stops on that token and adjudicates it exactly as it did before the rows existed: the command is inside the string, out of this walk's reach. When it carries none — an empty value, only options, or an assignment (`env --s= bash <script>`, `env --s=-i bash <script>`, `env -SFOO=1 bash <script>`) — env's command is the token that follows, so the walk steps past the split token and adjudicates that command, and an arg-taking option in the value consumes its separate argument as it does in a cluster. GNU env runs that command; the first form built stopped on every attached split token and left it unadjudicated. A value holding a `/` is read as a command word, so an option carrying a path keeps its pre-rows verdict. The separate spelling, short or long (`env -S bash <script>`, `env --split bash <script>`), is stepped over as a flag, so the token after it is read as the command word.

4. **Three classes the rows move toward allow are declared precision improvements.** An option argument shaped like a script path (`env --chdir=<path>.sh ls`, `sudo -D<path>.sh ls`) was read as a direct execution of the whole option token; and an `env` operand whose name is not a shell name (`env a-b=<path>.sh ls`) was read the same way. The program executes neither path: the first is an option's argument and the second is an environment assignment. What was checked, stated exactly: six of the eight corpus rows that record the two classes were run on the reference host's own programs, each in a sandbox holding only marker scripts, and none executed the path — `env --chdir=<path>` through the host's own `-C` spelling, because the host's `env` reads no long option; `sudo -D<path>` and `xargs -a<path>` were not run and rest on the published manuals. The third class moves toward allow for the same reason: a dash-led token whose option name the row does not list — an unknown name, or a prefix of two or more options — carrying an attached script path (`env --zz=<path>.sh ls`, `sudo --c=<path>.sh ls`, `env -Z<path>.sh ls`, and on a builtin row `exec --zz=<path>.sh ls`). It too was read as a direct execution of the whole option token; the walk now steps over it as a flag, so the command is the token that follows, and the program rejects the option and runs nothing, so the path is not executed. Its corpus rows were not run either; the class rests on the parsers' documented rejection of an unknown or ambiguous option. Every other verdict the rows change moves toward refusal.

5. **The `xargs` deny is reached behind `xargs`'s own options, and it is narrowed, not closed** (the second and third build conditions). The deny fires when `xargs` was walked and no token follows the interpreter, because the operand list then arrives on standard input, which a PreToolUse hook cannot read. Behind an option it now fires as it did without one, for an interpreter of every family, and it has no rollout phase: a non-shell interpreter fed by `xargs` is refused with no record-only stage, as it already was without an option. Its predicate is "no token after the interpreter", and an interpreter's own flag is a token, so `xargs -n 1 bash -x` stays allowed while the script it runs arrives on standard input. That is declared and pinned, not closed here.

6. **`if`, `while` and `until` join the keyword arm.** An interpreter invocation in the condition of those three is adjudicated as it already was after `then` or `do`. The one class this widens is declared and pinned: a quoted argument of a command that is not a recognised carrier, holding prose such as `note; if bash <script> then`, is split at its separator and the piece after it is read as a condition. That over-block is recoverable and was already true of `then` and `do`.

7. **Each guard keeps its own vocabulary, and the suite asserts the copies.** No shared library is introduced. A parity arm reads the wrapper and keyword words of every copy — this walk, the egress walk, the canonicalizer and the continuous-integration lint's list — and fails on a difference its declared table does not carry and on a declaration whose difference no longer exists, so a declaration cannot outlive the divergence it excuses. The canonicalizer's own gaps are not edited here; they are routed to their own card.

8. **Not decided by this record.** A space-bearing quoted assignment value ahead of the verb is declared in the rule's readiness text in both directions and pinned; its fix is routed to its own card, and the text the design handed for it is not built.

## Alternatives Considered

- **Membership only.** Add the words and model no option. Rejected: `nice -n 10 bash <script>` and `stdbuf -o0 bash <script>` stay allowed, which is the card's own failing case.
- **A dash-run skip** — behind a wrapper, step over every dash-led token, as the egress walk does. Rejected: a separate argument (`nice -n 10`) is read as the command word, and commands that run nothing new are refused (`sudo -l bash <script>`, `env -u bash grep -c bash <path>`).
- **An inline arm for the two named words.** Right-sized if only `nice` and `stdbuf` had been in scope. Not taken: the scope-lock rendered the whole wrapper set, and an inline arm would leave `sudo -u <user> bash <script>` and the `xargs` option bypass open beside a new option model.
- **A verb-locator scan, unbounded or bounded to one token**, as the egress rule uses for its own gated verb. Rejected on measurement: this rule's domain token is an interpreter name, an ordinary argument (`time grep -rn bash <path>`), and its shell arm refuses on landing, so the scan refused 162 or 35 of 510 legitimate payloads; it also has no verb to locate for a direct execution. The sibling guard's doctrine transfers and its mechanism does not, because there the domain token is a rare pair and the arm records.
- **Rows with a one-token look-ahead after an unlisted option.** The opposing view, and its strongest argument is the rule's own readiness text, which prefers a construction with nothing to omit. Rejected: precision then needs every option of every wrapper, flags included, enumerated so that "unlisted" can be recognised; it refuses commands that run nothing new behind an unlisted option; and it needs a further copy of the interpreter literals in a change whose subject is divergent copies.
- **Every token the direct-execution arm's operand domain claims stays the command word** — the review's broader form of the first build condition. Not taken: it gives up a measured precision gain on option arguments that execute nothing and adds records for paths attached to a new word's options. The narrow form keeps only the tokens that carry a command line, and it closes every executing row of that class once a long option is read by every spelling its parser accepts and an attached split value is read for a command word of its own; the first form built matched long options as written, and an attached prefix of the split string escaped it (the next entry), and it then stopped on every attached split token, so a value carrying no command word left the command after it unadjudicated (the third decision item).
- **Matching a long option as written.** The first form built, rejected on Stage 7's measurement. getopt_long takes any unique prefix for the option, so an attached prefix of `env`'s split string (`env --split=<path>`) was an option no row lists: the walk stepped over it, and the execution it carried moved from recorded to allowed. The value of an abbreviated listed option (`nice --adj 10`) was read as the command word, leaving the command behind it un-adjudicated.
- **A shared word-list library read by both guards.** Rejected at the scope-lock: under the two guards' designs the only fact they share is one word list, and an always-enforce hook would gain a startup dependency to share it.
- **Extending the shared canonicalizer, or a quote-aware parser.** Out of this release: this rule is deliberately not routed through the canonicalizer, which serves the anchored rules of four hooks, and a parser replaces the primitive every arm traverses.
- **A stdin deny behind the operand walk for `xargs <shell>`** — the review's second counter-design. Not adopted at the scope-lock; the residual it would close is declared under the fifth decision item.

## Consequences

**Positive.** An unlisted script behind a listed wrapper's listed options is adjudicated as it is without the wrapper. Two declared residuals retire: a wrapper's own flags, and `timeout`, whose recorded reason for exclusion was the duration operand a row now consumes. Option arity is data beside the other per-program tables, so a new option is one letter and a new wrapper one row, and no control flow changes. The copies of the vocabulary can no longer drift silently. An attached split string that carries no command word no longer hides the command that follows it. The rule's readiness text states what the walk does and what it leaves.

**Negative.** New refusals land from the first publish with no record-only stage: a shell interpreter or `source` reached behind a wrapper's options, and any interpreter fed by `xargs` behind its options. A direct execution and a non-shell interpreter behind a wrapper's options are recorded at their arms' rollout phases, so the would-fire drain gains rows from wrapper-prefixed positions, and nothing in a row says which position wrote it; a count taken across the publish boundary is not one population. Entries for Linux builds of the wrappers are confirmed against published manuals but are exercised by no pipeline host, whose binaries are BSD. An option a row's table does not list that takes a separate value leaves its command un-adjudicated (an abbreviation of a listed option is that option and is closed with it); an attached command line written with a prefix of the split-string option (`env --s=bash <script>`) takes the full spelling's verdict, the declared one-string residual, where the first form built stepped over the prefix and recorded the script behind it; a split value that holds a `/` is read as a command word, so an option carrying a path inside the value keeps the verdict it had before the rows; a malformed `timeout <command>` with no duration is read one token late; `sudo`'s long describe-only spellings are read as flags, so what follows them is adjudicated. Launchers outside the set stay outside it.

## Reversibility

MODERATE. A revert of the change's commits restores the walk, and an instance runs the restored walk only after the hook publisher republishes the bundle. Every position the rows closed re-opens on that revert.
