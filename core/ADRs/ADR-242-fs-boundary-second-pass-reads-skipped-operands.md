# ADR-242 — The filesystem-boundary guard reads, in a second add-only pass, the operands its token walk does not hand over

## Status

**Proposed** — authored at Stage 6 Engineering from the Stage 5 design (revision 1). Ratification is recorded in this frontmatter's `status:` field and is never inferred from milestone closure.

## Context

The guard refuses a listed file verb's literal operand outside the allowed roots. It finds the verb with an anchor regex and hands the operands to its cascade with a token walk, both over the shared canonicalizer's output. At six positions the walk never handed the operand over: after a redirection operator that carries an ampersand; on a continuation line; after a redirection operator that carries a pipe; after a process substitution; with the verb word written in quotes; and behind a prefix word while an unbalanced quote switches the canonicalizer off. The canonicalizer causes three of these through insertions its three other consumers rely on — for them each extra insertion is an extra match, and so an extra refusal — and a fourth through its fail direction, which keeps the status quo for every consumer. Its quote scanner also has a third state the fail direction does not cover: marks the shell does not read as quoting can bring the scanner's count back to even, so the mask is on and inverted over real command text.

## Decision

1. **A second pass, after every first-pass verdict.** The rule-evaluation loops judge the command exactly as before. Only then does a second pass read the words the walk did not hand over and judge each through the same per-operand disposition, with the same rule IDs and messages. Under `enforce` a first-pass refusal exits before the second pass runs; under `warn` its records are written first. The second pass can therefore only add a refusal or a record: no verdict the guard gave moves to allowed, and no refusal changes rule.
2. **What it reads.** Each base text — the command, and, when it carries a line continuation, the command with every continuation joined, never after a line on which an unquoted `#` opens a comment — is read three ways: with each top-level redirection operator's ampersand and pipe taken out, so the canonicalizer cuts it only where the shell does; with, in addition, every mark the canonicalizer's quote scanner reads apart from the shell mapped to a neutral byte and restored after canonicalizing, whenever such a mark is present, whether or not the canonical output changed; and with every quote mark neutral, only when the canonicalizer hands its input back unchanged, the input carries a quote mark, and the scanner-repair reading did not restore the mask either. The marks the scanner reads apart from the shell are an enumeration, not a closed class: an escaped quote inside ANSI-C quoting; the quote marks and parentheses of a here-document body line the scanner would leave in another quote state; a parenthesis inside quotes, a comment or an escape within a command substitution, which the scanner counts and the shell does not; every quote mark inside a command substitution nested in double quotes; and a quote mark in a comment the shell opens after a parenthesis or a redirection character. Each reading of the unjoined command is also read with its continuations joined. On a here-document body line the redirection join and the continuation join act on every operator and every line end, so a body the lexer misreads can never switch a reading off; only the scanner repair tells body lines apart. In each reading a segment's first word is compared with the listed verbs after shell quote removal, ANSI-C quoting decoded, and one leading `=` dropped.
3. **What is an operand.** The first pass's token rules, plus: a redirection word is not an operand and a bare operator takes its word with it; the words of a process-substitution body are the inner command's, its parentheses counted with a `case` pattern's closing parenthesis left out; and after the body's close the reading crosses a single separator the canonicalizer inserted — never one the command carries — while the canonicalizer may still be reading the rest as a new command.
4. **What it does not repeat.** Every word the first pass handed over, and every word an earlier reading handed over, is not judged again.
5. **The canonicalizer is unchanged.** Its insertion-only contract and its fail direction stand, and none of its consumers' verdicts moves; the second pass only runs it on transformed copies of the command.
6. **Completion is proven, not inferred.** The whole pass, its judging included, runs in one command substitution with errexit re-armed inside it; every external call it makes is checked; every helper reports success through a flag set as its last statement and checked by its caller; and the pass prints its completion line as its very last act. A non-zero status or a missing completion line is a reading that did not complete: refused under `enforce`; under `warn`, stood down loudly with a warn-log record whose rule field is `INPUT-NOT-EVALUATED`, which the enforce flip reads. The walk program exits non-zero unless its first line is the header that counts the already-judged pairs and every counted pair arrives. The second pass runs only when the canonicalizer has passed its canary; on the warn-degraded path it does not run and writes that record instead. Every program is fed from a here-string.
7. **Cost.** Each reading is a linear pass plus a canonicalizer run. The canonicalizer's own scan grows quadratically with the command, which is the status quo cost class of every consumer; the second pass adds at most two runs per base on a common command and at most six in all, each on a copy no longer than the command whenever the command carries none of the bytes the neutral map uses, and no longer than twice the command otherwise. A command carrying none of the triggering shapes — no quote mark, no such redirection operator, no continuation, no mark the scanner reads apart from the shell — adds no canonicalizer run.

## Alternatives Considered

- **Rewrite the walk in place** (the strongest alternative). One walk instead of two, but every operand verdict passes through changed code, so the absence of a refuse-to-allow movement can only be measured, never constructed; every walk mutation in the suite moves, and the anchor regex changes. Rejected on confidence.
- **Teach the canonicalizer's default output** not to start a command at a redirection's ampersand or pipe or after a process substitution, to drop quotes on the verb, to read here-document bodies, and to model ANSI-C quoting. Rejected: removing an insertion, or switching the quote mask on where it is off today, moves refusals its other consumers give today to allowed.
- **A new opt-in view of the canonicalizer** (its `CMDPOS_VIEW` seam, which already emits views no consumer reads). A view this guard alone asks for leaves every other consumer's default output byte for byte, and the scanner already knows one fact this design cannot recover from its output — whether its scan balanced. It is the lift-up path for these readings: the redirection join, the continuation readings, the scanner repair and the quote-removed verb comparison now exist in this guard, in the deletion guard's walk and in the script-execution rule's word scan. Not taken here because the shared-walk card family owns that seam and merges after this release; that family owns the lift-up, and this pass's readings retire into the view when it lands.
- **Refuse the whole shape** at those positions. Rejected: the operand can be read at every one of them, and an in-root operand must stay admitted.
- **A parser per call.** Rejected: ADR-187 makes command-start detection one shared canonicalizer, and an interpreter start on every Bash call is a standing cost.
- **A hybrid** that moves verb-quote removal into the canonicalizer. Rejected on blast radius: a guard-local quote removal closes the position without a shared-primitive change.

## Consequences

- **Positive.** An out-of-root literal operand of a listed verb at each of the six positions is refused under the plain form's rule at `enforce` and recorded at `warn`; an in-root one stays admitted. Adjacent faces close as well: a verb at a plain command start hidden by an inverted quote mask; a quoted prefix run while a quoted parenthesis inside a command substitution switches the mask off; a grouped verb with the mask off; a continuation that splits a prefix word or the verb word; and a verb inside a process-substitution body at those positions.
- **Declared moves, allow to refuse.** The six positions' out-of-root operands, those adjacent faces, and the suite's two pins of an expansion-bearing operand at the redirection and continuation positions.
- **Declared over-blocks.** A here-document body line is read with its redirection operators and its line continuations joined, whatever its delimiter's quoting, so a body line can read like a command line — an extension of the body-line over-block the canonicalizer already declares; quoted text carrying structure on a body line the scanner repair neutralizes is read as command text in that reading; quoted text carrying structure ahead of a listed verb, in a command whose quote mask neither the canonicalizer nor the repair can restore; a `<<` the shell reads as a shift (an arithmetic command, or the `$[ ]` form) is read as a here-document operator, so the lines after it are read as body lines — every reading stays on there, and only the body over-block widens; and a process-substitution body whose parentheses do not balance in the reading, read on past its true close.
- **Declared limits.** A prefix word written partly in quotes, which the canonicalizer's prefix lookup does not read; a verb behind more than ten prefix-run words, past the canonicalizer's own cap. A verb word only an evaluation produces — an expansion, a glob or a brace form — is not recognized, as an operand of that shape is not decided; a verb word in another letter case is owned elsewhere (References). A `case` inside a process-substitution body whose subject holds a quoted blank, or whose pattern list otherwise does not follow `case WORD in`. A mark the scanner reads apart from the shell that this enumeration does not name. A redirection's target stays out of this guard's subject, and the first pass's existing reading of a separate-word target is unchanged.
- **Cost.** The second pass multiplies the number of canonicalizer runs on a command, never the length of the text a run scans beyond twice the command; the quadratic scan is the canonicalizer's own.

## Reversibility

**MODERATE · Confidence HIGH.** Revert the commit and refresh the deployed hook. Each reading has a one-line off switch; the second pass as a whole has one.
