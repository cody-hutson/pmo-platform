### intake-elicitation-skill (2026-06-06, version-less) — Conversational intake front door (`intake-desk` — meets an idea at any altitude, types it, elicits the right fields, applies the 5-test live, and logs a typed item — never a scratch file)

Single-issue release delivering a new operations-module skill, `intake-desk`, the conversational front door for intake; `novel` release class, CHEAP reversibility, single-branch (D-C SINGLE), **version-less** (operator decision — no `vX.Y`, no git tag, no GitHub Release; `.version` stays `v3.19`), following the `public-flip-install-blockers` precedent. Before this release intake was cold form-filling against static templates with no funnel — a gap that had already produced an improvised scratch file committed in the wrong place. `intake-desk` turns a half-formed idea into a well-formed, correctly-typed, correctly-placed work item logged to the work tracker. It meets the idea at its altitude by assumption-then-confirmation (the run-the-business vs change-the-business cut, then a specific level — initiative / story / task / bug — proposed as a labeled assumption the user confirms or corrects; an unresolvable altitude is carried as a triage-owned `[ASSUMPTION – CONFIRM]` rather than stalling), proposes the work-item type and its place in the intake hierarchy, and holds the type provisional so it re-routes on reclassification (a "bug" that is really a missing capability becomes an `improvement`). It elicits the type- and level-appropriate field set — a bug's reproduction and environment, a story's acceptance criteria and value, an initiative's outcomes and domain — with the required fields derived at use time from each `.github/ISSUE_TEMPLATE/<type>.yml` (the living source) rather than duplicated, selected via a BABOK-grounded domain-adaptive technique library, and applies the 5-test rule live as the clarity gate (the stop condition is the 5-test passing for the type at the altitude, not a question count). It captures one work item per request — a container's child work is a body decomposition callout for later slicing, never auto-created — and emits to the configured work tracker (GitHub Issues MVP via `gh issue create`) only after a binary AskUserQuestion confirm, carrying required structured fields (a bug's Severity, an improvement's Category) via labels or a labeled first body line and falling back to the observation tier when a field cannot be represented; unresolved unknowns are emitted as stage-owned `[ASSUMPTION – CONFIRM]` handoff items. The skill has no write path to a tracked file — the originating defect it exists to close. Two modes: Elicit (guided interview) and Triage-readiness check (run the 5-test against a draft). The MVP binds to the current three work-item types (`improvement` / `bug` / `observation`; no `adr` — authoring an ADR is an architecture act, not intake) via a parameterization seam the work-item type system later repoints with no SKILL.md rewrite; the elicitation-technique content is sourced to IIBA BABOK Guide v3 (the platform's first encoding of the requirements-elicitation domain, upgrading the Stage 4 SHIP-WITH-FLAG label to Mode A).
