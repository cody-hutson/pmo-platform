
# Deploy and release tooling health: checks that were silently passing now actually run

2026-06-20 · v2.09

Eleven small fixes to the platform's own deploy and release scripts. Several built-in checks were silently skipping the thing they were supposed to verify, and a few maintenance scripts pointed at folder paths that no longer exist after the repository was reorganized. This release re-points them at the real paths and makes the checks run for real. Everything is a surgical correction to existing tooling — no new behavior you invoke directly, and nothing you need to do.

## What changed for everyone using the platform

- **A deploy check that quietly skipped its own job now runs.** The check that keeps a governance rules file and its deployed copy in sync was pointed at a folder that no longer exists, so it silently skipped instead of comparing. It now compares the real pair. *Why it matters:* a rules file drifting out of sync with its deployed copy is now caught at deploy time instead of going unnoticed.

- **Copy failures during deploy now say what actually went wrong.** When the deploy step copied supporting files into a read-only location and failed, it reported a generic message with no cause. It now reports the actionable root cause. *Why it matters:* a failed deploy points you at the fix instead of leaving you to guess.

- **Repository maintenance scripts work again after the folder reorganization.** Several scripts that compute release metrics, summarize release learnings, detect change blast-radius, and clean up leftover release branches were still looking for folders under the old, pre-reorganization layout and quietly did nothing. They now resolve the current paths. *Why it matters:* the cleanup and reporting that runs around each release does its job instead of silently no-op-ing.

- **A leftover-branch cleanup now catches the branches it was missing.** The end-of-release cleanup didn't recognize version-prefixed release branches or agent worktrees, so they accumulated. It now matches them. *Why it matters:* stale release branches and worktrees get cleaned up instead of piling up.

## Known limits

- This release fixes existing tooling; it adds no new commands or features you invoke directly. One new deploy check (a path-resolution validation) ships logged-but-not-blocking, so it surfaces findings as warnings until it is later turned on to block.
- A one-time cleanup of the stale framework-catalog entries the new path-resolution check guards against is tracked separately; this release ships the recurrence-prevention check, not that cleanup.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

CHEAP / HIGH confidence. Every change is a surgical correction to existing scripts or an additive check; nothing migrates data. The release was built one commit per issue, so any single fix reverts on its own via `git revert <commit>`, and the whole release reverts via `git revert -m 1` of the integration merge. Newly added checks ship logged-but-not-blocking, so even an unreverted defective check warns rather than blocks a deploy. Standard 7-day rollback window.
