# Methodology packs: pick a delivery method, or bring your own

2026-07-03 · v3.60

A delivery methodology — Scrum, Kanban, or a house style of your own — is now a **self-contained, swappable "pack"** rather than something hardwired into the platform. You can select a shipped best-practice pack, or bring and override your own config, without hand-editing any skill. This release lays the foundation (the pack format, the two starter packs, and a methodology-neutral label grammar); the agents that *read* packs to change their behavior come in a follow-up.

**Heads-up:** this is a foundation release — it establishes the substrate, so day-to-day agent behavior is unchanged for now. The visible payoff arrives when the consuming skills are wired to the packs (tracked as a follow-up).

## What changed for everyone using the platform

- **No user-visible behavior change yet** — this release builds the methodology-pack substrate (the format + the baseline packs + the label grammar). Agents don't consume it yet, so your day-to-day flow is the same. *Why it matters:* it's the groundwork that makes "switch methodology without re-configuring the platform" possible in an upcoming release.

## Known limits

- **Packs aren't wired into the skills yet.** Selecting a pack doesn't change agent behavior until the consumer refit lands (follow-up #2021). The packs exist and validate; they're just not read yet.
- **Kanban WIP-limit gate ships as a documented stub.** The grammar for it is in place, but the concrete limit is operator-local config, deferred by design.
- Two starter packs ship (`scrum`, `kanban`) plus a shared `_common` base; more archetypes are added later as thin deltas.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE / HIGH confidence.** The grammar change is additive (existing type-packs parse unchanged) and the packs are new files, so rolling back is a `git revert` of the release merge plus dropping `core/packs/` — no data migration and nothing downstream consumes the new surface yet.

### Operator and engineering detail

The methodology-pack model is the convergence point of three things the platform already valued separately: shipped **best-practice defaults**, **plug-and-play selection**, and **bring-your-own / override** config. Rather than bend the packs to fit a rigid grammar, this release *widens the grammar* to serve that convergence.

- **The contract (ADR-069 / ADR-070).** A methodology pack is the plug-and-play composing unit at `core/packs/<archetype>/`, bundling a methodology's operational surface (kinds + work-status + fields + labels + gates) as best-practice defaults, selected per `delivery_approach` and overridable per project. The composition *grammar* is recorded as a sibling ADR extending ADR-018 at the meta-schema altitude.
- **The grammar widen (`work-item-type-schema.md`).** Additive pack-composition layer: a `role ∈ {archetype, base}` discriminator with `extends` delta-inheritance (a shared `_common` base carries the archetype-invariant ~80%; archetype packs declare only deltas), a `[[labels]]` contribution facet, a work-status projection, and `kinds` relaxed-to-optional for base packs. The meta-schema stays at v1 (additive + one requiredness relaxation; no shim).
- **The label grammar (`label-taxonomy.md`).** Restructured grammar-only — the universal groups + rules stay; the concrete per-repo label rows move into the packs' `[[labels]]`; `type:*` is documented as a namespace pattern; the parity gate reads the doc + pack union so no label is orphaned.

A pack manifest is a small TOML file — an operator can read or customize one directly:

```toml
# core/packs/scrum/pack.toml (illustrative)
[meta]
pack_id    = "scrum"
applies_to = "Scrum"     # the delivery_approach archetype this pack serves
role       = "archetype" # vs. role = "base" for the shared _common pack
extends    = "_common"   # inherit the shared ~80%; declare only deltas below

[[kinds]]                # Scrum's work-item kinds
kind_id = "story"
# base fields / criteria / lifecycle inherited from _common; deltas here

[[labels]]               # per-pack label contributions (projected over the grammar)
name          = "type:story"
projects_kind = "story"  # bound to a declared kind — labels can't drift from kinds
```
