# A check that could not measure now says so, instead of reporting a pass

2026-10-17 · v4.75

Seven controls that used to report their own blindness as a result now report it as its own state: a check that did not measure, measured less than it declares, or lost its own instrument says "not evaluated", never "passed". Two of them change an exit code or a stop condition that scripts and release runs can see.

> **Skip the rest** unless you read the platform's deploy-time check output or its pull-request checks, script against the close-completeness check's exit code, run releases through the pipeline, or have the fragile-reference hook deployed.

## Who this affects

- Anyone who reads the deploy-time check output or the pull-request checks
- Anyone whose script or workflow reads the close-completeness check's exit code
- Anyone who runs a release through the pipeline: the release hub's quota check before a launch, and the Stage 13 close-out
- Anyone with the fragile-reference hook deployed in their workspace

## What you need to do

1. **Run the update from your main checkout, not from a worktree** (`./update.sh`). The fragile-reference hook and its pattern file must now be deployed together: the hook refuses a pattern file that lacks its new scope rule, standing down in warn and failing closed in enforce. Run from a linked worktree, the update re-points the shared post-merge hook into that worktree ([#8468](https://github.com/cody-hutson/pmo-platform/issues/8468)).
2. **Only if a script or workflow of yours reads the close-completeness check's exit code:** read 0 as clean only, 2 as a finding that is logged but not blocking, and 3 as a verdict that was not evaluated or was withheld. Before this release, a finding also exited 0.
3. **Only if you run the release hub's quota check by hand:** run the host-API evaluator once per routing turn, read its record only when it exits 0, and render its verdict line as written.

## What changed for everyone using the platform

- **The close-completeness check exits 0 only when it finds nothing.** A finding now exits 2; a run that could not reach GitHub, or whose release-body comparison could not run, reports not evaluated and exits 3, instead of reporting 75 releases with no published Release. *Why it matters:* a green run of that check now means the releases were checked and are complete, and its 15 real findings show on every pull request it covers until they are cleared.

- **Checks say how much they looked at.** A check now declares the set of files it covers and reports how many it examined; a scan that found nothing to examine, or examined less than it declares, is reported that way instead of passing. The local-context check now scans the rules folder its standard names, and three release folders that never existed are gone from the module guide, a check, a hook and a CI gate. *Why it matters:* a clean result can no longer come from a scan that read fewer files than you think it did.

- **Every place that could read "not measured" as "passed" is listed and tested.** A census records each reader of the release-body comparison's exit status, each workflow step that reduces a captured exit status to zero or not zero, and each test suite with the runner that executes it, and the conformance suite re-derives all three on every run. The release-body comparison check no longer prints a clean verdict over rows it did not compare. *Why it matters:* a new spot where a control's own failure would read as a pass fails the conformance suite when it is added, not after it has hidden a defect.

- **The fragile-reference hook judges a large write instead of calling it malformed.** A Write or Edit above the command-line size limit now gets the verdict a small one gets; an input the hook cannot read is reported as not evaluated, which blocks in enforce mode and warns otherwise. *Why it matters:* large valid writes are no longer refused for the wrong reason, and an unreadable input is no longer misreported as bad JSON.

- **The release hub's quota check reads its own probe.** Before a launch, the host-API part of the check makes a few small charged requests and reads the quota counters from those responses; a reading that shows none of its own draw defers instead of proceeding. *Why it matters:* the hub no longer launches work on a quota reading it cannot tell apart from an exhausted pool. It reaches your hub once the updated release hub is deployed.

- **A close-out no longer calls a merged pull request unmerged.** The Stage 13 close-out reads every pull request over REST through one classifier, names a read that does not answer by its cause, and stops an apply run before its first write unless the release pull request is answered as merged. *Why it matters:* a GraphQL quota drained by other releases no longer stops a close, and a mistyped pull request number stops it before anything is stamped.

## Known limits

- The close-completeness check is logged but not blocking. Its 15 findings, 13 published-body drifts and 2 Velocity fields, stand until a re-emit sweep clears them, and the check cannot be switched to blocking before that.
- The quota check's GraphQL reading is graded as an assumption, not a source. The write-only half of the host's secondary limit, request rate and mutation weight, is still unmetered ([#7847](https://github.com/cody-hutson/pmo-platform/issues/7847)), and a hub's own wait on check settlement still has no polling rule ([#7427](https://github.com/cody-hutson/pmo-platform/issues/7427)).
- The local-context check's operator and coworker name pass is skipped without a word when its needle file holds no needles ([#8467](https://github.com/cody-hutson/pmo-platform/issues/8467)), and its exemption list resolves to nothing ([#7892](https://github.com/cody-hutson/pmo-platform/issues/7892)).
- The census reports a new test suite with no runner rather than failing on it; the merge decision stays with the owner of executor coverage.
- The release-body comparison's own failed read can still surface as drift ([#4714](https://github.com/cody-hutson/pmo-platform/issues/4714)), the exit-code family's advisory handshake is still open ([#7889](https://github.com/cody-hutson/pmo-platform/issues/7889)), and the other hooks still carry the input-reading idiom this release replaced in one ([#7835](https://github.com/cody-hutson/pmo-platform/issues/7835)).
- The close-out's remaining GraphQL-bound writes and issue reads are unchanged ([#7876](https://github.com/cody-hutson/pmo-platform/issues/7876)).
- The version this workspace reports changes to v4.75 on the first update after this release closes.

Report issues at https://github.com/cody-hutson/pmo-platform/issues, and report a suspected vulnerability privately as the [Security Policy](https://github.com/cody-hutson/pmo-platform/blob/main/SECURITY.md) describes.

## Reversibility

MODERATE / HIGH. Reverting the single release merge restores the earlier checks, hooks and tools; the deployed hook bundle and the release hub package are then refreshed from the reverted tree, and the hook and its pattern file revert together. The revert stops once, on the release plan the version claim renamed, and keeps the stamped plan. Findings raised meanwhile stay as records, and the version tag is kept as the record that the version was claimed.

### Operator and engineering detail

**The exit contract of the close-completeness family.** One function maps the verdict to the exit: `CLEAN` 0, `INCOMPLETE` 2 (advisory), `NOT-EVALUATED` 3 under every sentinel, a withheld `SKIP` 3, and, under an `enforce` sentinel, `INCOMPLETE` and `SKIP` 1; an unexpected token fails closed on 1. Check 48 reports `NOT-EVALUATED` when the host lookup fails or the body-drift engine is missing, not executable or exits outside its 0–3 contract, and a withheld `SKIP` when a row cutoff matches no row or an allowlist names every verified row. The flip to enforce is a three-step clause recorded in the sentinel file and the gate-coverage register row; an allowlist at the engine's default path reaches the local check only.

**Population records.** The gate-efficacy standard's Requirement (b) adds a `population:` declaration to every gate whose verdict is a claim over a file-root population, and Requirement (c) adds the population-shortfall mode: each run prints what it examined, and a scan short of its declaration reads `degraded` or `not-run`, never clean. Checks 25 and 31 are the worked reference, and the reference-durability gate declares its population too. The two lines, in the standard's own form:

```text
#   population: roots=<root list> filter=<member predicate> exempts=<unit>
DENOM: <check-id> — status=<fetched|degraded|not-run> declared=<n> resolved=<k> examined=<m> exempted=<e>
```

**The census, ADR-217.** Three keyed records — the drift engine's exit consumers, the workflow steps that reduce a captured status to zero versus non-zero, and the suites with their executors — are re-derived and graded by the conformance suite on every run. Check 47 counts the rows its drift engine did not evaluate as `NOT-EVALUATED` and fails closed on an engine exit its contract does not define. The install-regression precision probe derives its member list from the runner it copies, so it can fail again.

**The fragile-reference hook.** Every payload read moves by here-string, so the argument-size limit no longer decides the verdict; an unreadable input is `INPUT-NOT-EVALUATED`, mode-coupled per ADR-078; a compile canary for the detector constants stands the hook down once, before any detector, when a constant cannot compile. The durable-corpus scope predicate `is_durable` now lives in the shared pattern file, read by the hook and the CI gate, and each refuses a pattern file without it.

**The host-API axis, ADR-218.** `release/tools/host-api-axis-verdict.sh` sends a repository-free REST probe and a GraphQL probe charged by selecting `__typename`, reads each pool in-band from the probe's own response, and anchors it on the probe's own draw. A reading with no draw of its own is `UNANCHORED` and DEFERs; a refused probe is `CONTRADICTED` and DEFERs; the backoff for a refusal that publishes no reset is capped at 3600 s, its count carried on the DEFER action item. ADR-218 supersedes ADR-156 in part, and both ADR-217 and ADR-218 were ratified at this release's close. The refusal classifier, `release/tools/lib/host-refusal-class.sh`, is shared with the close-out.

**The close-out's pull-request reads.** All six GraphQL-bound pull-request reads in `automated-closeout.sh` go through one REST reader and the shared classifier; merged is read from the pull request's merged flag, never from a merge-commit identifier; the chore-PR lookup is owner-qualified, compares the owner without regard to letter case, and refuses a candidate set it cannot establish as complete.

**How it shipped.** Seven cards landed on one branch as one merge at `c943e44e`, claimed as `v4.75` with a signed annotated tag on the first attempt. The deployed hook tier and the script-execution allowlist were refreshed and verified by content after the merge; the release hub's version restamp and package rebuild ride the Stage-13 chore pull request, and its deploy follows that merge. The branch synced with the main branch three times while siblings merged, and its two decision records were renumbered twice on the way.
