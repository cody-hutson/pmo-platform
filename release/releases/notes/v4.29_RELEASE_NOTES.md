# Checks now tell you when they could not measure

2026-08-15 · v4.29

Several checks reported the same clean result whether they had run, run partially, or been unable to run at all. Each one now reports its own measurement state, so a green result means the check looked rather than that it gave up.

## What changed for everyone using the platform

- **A check that could not measure now says so.** Checks previously emitted one clean-looking result for both "I looked and found nothing" and "I could not look." They now carry a distinct state for a degraded or unrun measurement, and that state never stops your release on its own. *Why it matters:* a green check result is now evidence the check ran, instead of a result you have to go behind and confirm.

- **A targeted run of the count-and-structure check no longer reports a false alarm.** Running it against a single path used to report the entire baseline — 71 entries at this release's starting point — as out of date. It now resolves what it was actually asked to scan before reading any counter. *Why it matters:* you can point the check at one path and act on the answer, instead of discarding it because you know the alarm is spurious.

- **An advisory signal can no longer turn into a blocking one by accident.** One check's advisory branch shared its identity with an enforceable one, so turning enforcement up elsewhere would have quietly started failing releases on advice. The advisory branch now carries its own identity. *Why it matters:* raising enforcement on one check no longer risks stopping your release on a signal that was only ever meant to inform.

- **Release telemetry stops reporting an unmeasurable total as a clean zero.** When the underlying labels were missing, one indicator reported "nothing to measure," which read identically to "measured, and it is fine." It now separates a genuine read failure from a gap in the data, while a real zero still reports as a real zero. *Why it matters:* you can tell a healthy release report from one that had nothing to read.

- **The version-collision gate now exercises the branch it exists for.** The gate never supplied a candidate version to compare, so the branch that detects a collision was unreachable and every run passed. It now injects one. *Why it matters:* the gate can now actually catch a version already taken, rather than passing because it never tried.

- **One spelling of the "could not measure" state, enforced.** A new check scans the whole corpus and fails on any second spelling of that state. *Why it matters:* searching for degraded results returns all of them, rather than the subset that happened to use the spelling you guessed.

## Known limits

The whole-corpus vocabulary check runs when a change is proposed, not when one is merged. A violation that arrives through a merge is caught on the next proposed change rather than at the merge itself, so there is a short window where the corpus can hold a second spelling without a red signal.

One check reports four pre-existing findings that predate this release and are unrelated to it. They were left alone deliberately rather than swept in, because correcting them here would have mixed unreviewed changes into a release that did not examine them.

Report issues at the repository issue tracker.

## Reversibility

MODERATE / HIGH. The individual check changes revert cleanly. Reverting the shared vocabulary after other checks have adopted it leaves those adopted terms without a defined home — the cost is orphaned terminology, not a behavior regression.

### Operator and engineering detail

**The contract.** The release freezes a two-register degraded-state vocabulary as a rider on the probe-validity discipline, recorded as [ADR-134](https://github.com/cody-hutson/pmo-platform/blob/main/core/ADRs/ADR-134-degraded-state-emit-contract.md). Register A carries a check's own measurement status; Register B carries the terminal token a consumer reads. The contract holds that a check's emitted state set carries a distinct member for every reachable state of its predicate, that degraded and clean never share a member, and that the degraded member never gates. Across six designs and six builds, no emitter invented a token outside the frozen set — two builds coined one while drafting and removed it before commit.

The shape below is the emit change: one clean-looking result becomes two distinguishable ones.

```text
# before — one result for two different conditions
STALE=71                     # could not resolve scope, and reported anyway
STALE=0                      # measured, genuinely clean

# after — Register A (scan status) + Register B (terminal token)
status=fetched   files_read=40  pairs_examined=118  STALE=0
status=degraded  files_read=0   pairs_examined=0    NOT-EVALUATED
```

Register A values: `fetched`, `truncated`, `degraded`, `fixture`, `not-run`. Register B values: `NOT-EVALUATED`, `DEGRADED`. Every member of both registers carries the meaning *this is not a clean result*.

**Transport is conditional on the kind of condition.** Two cards resolved the transport question oppositely and both are correct. The close-class telemetry tool emits in-band in its output line, because its consumer treats any non-zero exit as a hard failure — an exit-code emit there would convert a measurement outage into a gate, which the rider forbids in terms. The count-and-structure check exits 3 on an input-deficient population, because that is an input failure rather than a measurement outage. A measurement outage must never gate; an input failure should.

**The convention shipped with no way to detect violations of it, and the first merge proved it.** The rider landed with four comment citations, zero predicates and zero workflows. A sixth instance of the defect then arrived through this release's own merge and passed CI 47 of 47 green — the violating lines were unchanged relative to the pull-request base, so the changed-file scan every sibling gate uses would have gone green on the exact triggering event. That is why the enforcing gate scans the whole corpus rather than the changed set. The gate was demonstrated failing on the real unfixed corpus first, naming all five sites, and only then passing after the fix, with the sanctioned-occurrence control rising by exactly the five converted sites. Ordering the sensitivity arm first caught two defects in the gate itself, including structural blindness to the underscore form it exists to catch — neither visible to a change that builds the gate and the fix together and observes green.

**Measured outcome.** Merging took the mainline population of the wrong spelling from 12 to 0 — the release removed the existing instances, not only future ones. The post-merge whole-corpus scan reads 0 unsanctioned renderings against a non-zero control of sanctioned occurrences, so the zero is a measured zero rather than an empty extraction.

**Acceptance criteria were themselves under test.** Three cards carried criteria that would have certified the defect they were written to eliminate — one unrunnable as written, one whose discriminator produced four false positives at the release base, and one satisfiable by a still-broken tool. Across roughly two dozen criteria the shipped code was consistently stronger than the criterion that graded it. A criterion's control works only when its control arm produces the same observable as its subject, so it can actually fail; the predictor of that property was not the authoring stage but whether the author had operated the mechanism being graded.
