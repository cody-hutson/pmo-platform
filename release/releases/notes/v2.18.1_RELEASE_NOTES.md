# Operator-instance path decoupling (v2.18.1)

2026-06-22 · v2.18.1

The operator-instance and PII-needle paths were resolved by several inconsistent hardcoded paths across the deploy tooling and the PII pre-commit guard — so relocating the instance silently degraded the guard (it failed *open*). This release converges them onto one resolver and closes that gap.

## What changed
- **One resolver.** All instance/needle path reads in the deploy tooling and the PII hook go through `core/deploy/lib-instance-path.sh` (`${CLAUDE_WORKSPACE_ROOT:-$HOME/Claude}` per ADR-032; `PMO_INSTANCE_PATH`/`PMO_LOCALIZED_NEEDLES` still honored as overrides). No new variable invented.
- **Template + create-once scaffold.** The repo ships `core/config/localized-context-needles.txt.example`; install/update create your local needle file from it only if absent — your names live local + gitignored, never committed (the `.env` / `.env.example` pattern).
- **Persistence.** `update.sh` never regenerates your needle file (pre-update backup + a byte-identical round-trip test guarantee it survives updates).
- **Fail-closed guard.** When an operator instance exists but the needle file is missing or still the untouched example, the PII pre-commit guard now fails **closed** (distinct messages) instead of silently skipping; a genuinely fresh clone only warns. Ships warn-mode-initial, flips to enforce after a shakedown window.
