# Label checks now report disagreements instead of quietly passing

2026-09-02 · v4.48

The platform keeps a written registry of the labels it uses to classify work, and a check that compares that registry against the labels actually in use. That check had been returning a clean verdict while holding no evidence for it, and this release makes it report what it actually finds.

> **Skip the rest** unless you label or triage work items, you write files that quote exemption markers, or you read the throughput figures recorded at each release.

## Who this affects

- Anyone who labels, files, or triages work items
- Anyone who writes a file that shows an exemption or override marker as an example
- Anyone who relies on the label check's verdict, or on the throughput figures recorded at each release

## What changed for everyone using the platform

- **The label check now reports disagreements instead of absorbing them.** A label whose colour or description differs from its registry entry is reported as its own advisory finding, with a place to record what was decided about it. *Why it matters:* the check used to return a clean result while holding no evidence for it — one kind of result was discarded on the way out and read as success, so "nothing found" could equally have meant "nothing was examined."

- **The check keeps working when the connection it used to rely on is exhausted.** It now reads the live label set over a different transport. *Why it matters:* the old one runs out of capacity most often at release close-out, which is precisely when this check runs, and it used to report an unresolvable error while the same information was fully available another way.

- **Work-item type labels are checked against what your methodology packs actually declare.** A label is no longer accepted merely because its name carries the expected prefix. *Why it matters:* type labels in live use had nothing declaring them and drew no complaint from the check meant to notice, and a setup that declares its own kinds is now checked against its own declarations rather than against a fixed list.

- **An exemption marker shown as an example no longer grants the exemption.** A marker written inside a code block, or inside backticks in a sentence, now reads as an illustration rather than a claim. *Why it matters:* a file whose only purpose was to document the marker had been exempting itself from the very rule it described.

- **Following the printed instructions now works.** The override marker the reference gate's own error message tells you to write is now the form it accepts. *Why it matters:* the message and the matcher previously disagreed, so doing exactly what the failure told you to do still failed.

- **Exemptions are found by looking rather than by consulting a list kept by hand.** A self-documenting file now exempts itself by declaring the marker. *Why it matters:* an exemption can no longer outlive the reason recorded beside it, which is what happens when the list and the reasons are maintained separately.

- **Throughput figures now recognise declared work-item kinds.** A work item's class resolves in three stated steps, reading the kinds your setup actually declares instead of a hand-written list. *Why it matters:* a story that used to be filed as maintenance because nothing recognised its kind now counts as the feature work it is, and three categories the old list named — which existed in no label set anywhere — are gone.

## Known limits

- **The label check reports; it is not a gate, and that is a settled position rather than an unfinished one.** Its advisory posture is recorded as ratified on architectural grounds: making it blocking is declined, not postponed, because what it examines lives outside the repository and no change to a repository file can satisfy it. Specific finding counts are deliberately not quoted here — the live label set changes outside version control, and those figures moved more than once during this release; read them from the check rather than from this note.
- **The label cleanup this release prepares has not been run.** The work that would reconcile the live labels to the registry is deliberately still pending an operator decision, and it reaches 83 issues. It is the one step here that cannot be undone — a deleted label can be recreated with its name, colour and description, but never with the issues that were attached to it — so nothing has been created, changed, or deleted on the live label set. This release ships the ability to see the disagreements, not the act of resolving them.
- **Five acceptance criteria stay ungraded until that cleanup runs.** They assert conditions that only become true afterwards, and they were recorded as not-yet-applicable rather than marked as met or failed.
- **Two conditions were bounded rather than resolved.** A large population of work items carrying both a category and a kind label is described but not relabelled, and two categories still fall through to the default class. Both are named so the gap is deliberate rather than discovered later.
- **Three defects found here were filed rather than fixed.** One check reports a pair of facts from shared code where only one is true for the caller asking; one record exists to name the marker gap this release closed; and one records a plan file whose own internal link broke when the file was renamed at release time, repaired after the merge.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP**, confidence **HIGH**, for everything this release actually ships. Every change is a repository file, reversed by a single revert of the release merge, which retains both parents for exactly that purpose; no live label was created, edited, or deleted, so there is no state outside version control to unwind. The label retirements the findings authorize are **IRREVERSIBLE** and were deliberately not performed — they carry their own sign-off gate. The caveat on reverting is that it restores the two gaps closed here: an exemption marker quoted inside a code block would again grant the exemption it illustrates, and the label check would again discard one class of its own findings.

### Operator and engineering detail

Full audit detail is in the RELEASE_LOG Deployment Log for this version and in the release plan. Four things are worth reading rather than inferring.

**The clean verdict was structurally unearned, not merely optimistic.** The parity primitive classified each row into a set of result classes, and one class had no branch on the way out — it was computed, then dropped, and the absence of findings among the surviving classes rendered as success. The fix gives divergence its own advisory class and its own per-row disposition registry, so a divergence is now either reconciled in one direction or explicitly accepted with a rationale recorded beside it. Dispositions carry a closed enum and an optional axis qualifier, so accepting a colour override does not silently accept an unreviewed description. The verdict-class separation is recorded as ADR-174.

**The transport change is about when the check runs, not about preference.** Capacity exhaustion on the previous transport clusters at release close-out, which is the window this check occupies, while the same data was reachable over the other transport throughout. The check now reads the live set that way, and the pre-delete capture prescribed for the label cleanup was moved to the same transport for the same reason — a capture that returns nothing on an exit-zero path, immediately before an irreversible delete, is worse than one that fails loudly. That capture is the only rollback substrate the cleanup will ever have, which is why it is specified as a sign-off precondition rather than an execution step.

**The marker hole was closed on both surfaces that enforce it, with the standard restated as the authority.** The pre-write hook and the CI gate each independently treated a marker inside a fence or inside inline backticks as a live claim, so a file documenting the marker exempted itself from the rule it documented. Both were fixed in the same change and the standard was restated as the single authority the two implement, rather than leaving two implementations to agree by coincidence. The fixture set was extended and two self-documenting fixtures retired in favour of discovery from the marker.

**The velocity map was measured against the live label set and three of its arms were phantom.** The allocation map named `type:feature`, `feature`, and `cluster: tech-debt`; none exists in any live label set or pack declaration, so those arms read as coverage while being unreachable. Retiring them changes no work item's class — each still resolves the same way through the stated default. What does change the picture is the new middle tier, which resolves declared work-item kinds from the pack set at run time through the same resolver the parity gate uses, so a deployment that declares its own kinds is measured against its own declarations with no edit to the standard or the tool. The producing tool now asserts every surviving token against the pack set in its self-test, with a firing control on a known-retired token. The precedence question — a kind label and a category label being one classification at two altitudes rather than two competing signals — is recorded as ADR-173.

The per-row disposition registry is the one new shape an operator authors by hand. Disposition comes first because a label name may contain spaces, which makes a name-first record unparseable:

```
# <disposition> <label-name>  # <rationale>
reconcile-live         status: rejected   # declaration is right; live attributes drifted
reconcile-declaration  type:story         # live is right; the pack row is stale
accept-override:color  cluster: security  # deliberate operator choice, colour axis only
```
