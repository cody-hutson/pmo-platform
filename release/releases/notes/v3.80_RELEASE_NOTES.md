# Release close-outs are now reliable for theme-named releases

2026-07-22 · v3.80

This release hardens the internal machinery that ships platform updates. It does not change how you use the platform — it makes the *release process itself* fail loudly instead of silently when something is off, so future updates are less likely to stall or ship with a missing piece.

## What changed for everyone using the platform

No user-visible behavior changes — this is an internal reliability release. See the operator detail below for what got more reliable.

The one thing worth knowing at a glance: releases named by theme (like this one) previously risked a silent failure during their final close-out step. That class of failure is now closed, and — fittingly — this release proved the fix by closing itself out cleanly.

## Known limits

- **#2678 lifecycle bookkeeping** — one issue in this release was auto-closed early by an unrelated merge; its attribution is reconciled in the release log, not a functional gap.
- **New close-out edge case (follow-up filed)** — the close-out tool's auto-exclude rule matches on issue *title*, so an issue whose title contains "Stage-13" can be wrongly skipped during close. Worked around by hand this release; a fix is tracked for a future release.
- **CI flake [#3661](https://github.com/cody-hutson/pmo-platform/issues/3661)** — an unrelated test intermittently false-reds and passes on re-run; filed, out of scope here.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

### Operator and engineering detail

Full audit trail: the RELEASE_LOG row at [release/releases/RELEASE_LOG.md](https://github.com/cody-hutson/pmo-platform/blob/main/release/releases/RELEASE_LOG.md). Four fixes on the Stage-13 close-out surface, shipped as one PR (#3618), class `routine`:

- **#2539 — slug resolver hardened (a2→a4).** `automated-closeout.sh`'s `extract_milestone_slug` now resolves pure-alpha / hyphen-less theme-named milestones to the slug (field 2) instead of falling through to the version (field 1) — the defect that made a theme-named release's own close-out fail at the phase-6 transition. AC-3 unified the dry-run/apply row-match predicate (`log_row_match`) so a dry-run can no longer pass while the apply aborts; a new fail-loud preflight (D-3) uses a true `findall` count so an over-match fails loud rather than silently mis-resolving. **This release is itself theme-named, so its close-out ran the fix against itself and transitioned cleanly (`log_row_match n=1`) — the reflexive self-heal.**
- **#2435 — tool self-tests wired into CI.** `claim-version.sh --self-test` and (folded in) `check-release-body-drift.sh --self-test` now gate on every PR via `release-tooling-smoke.yml`; previously they ran only by hand.
- **#2540 — CI mirror of `deploy.sh` Check 5(d) registry-currency.** New `check-registry-currency.sh` + a filter-free workflow assert that every rostered skill has its `registry.md` row. Roster authority is the `deploy.sh` per-module arrays (canary excluded, per ADR-008) — **not** a filesystem walk (which drifts +3 against the real roster); an array-shape guard rejects the one-line garbage array form; enforce posture; registered in the gate-coverage register.
- **#2678 — drift check reads `origin/main`.** `check-release-body-drift.sh` now compares the published Release body against the committed note on `origin/main` rather than the local working tree, via a `REPO_ROOT` seam (the production-reachable `DRIFT_CANONICAL_REF` knob was dropped). Its exit-2 consumers were corrected to diagnose a git-capability absence instead of a false "gh offline".

**Process notes.** Provisional version moved v3.78→v3.79→v3.80 across the run as two concurrent releases (#264, #3543) claimed the intervening slots — each caught at a Commit-0 / claim-time re-verify (one a HALT at Stage-6 that re-rendered D-Version), and the atomic ref-CAS won v3.80 on first attempt. The `--admin` override was used at merge (base-branch policy prohibits a plain merge even when CLEAN). Stage-5 designs went through adversarial review (Phase A6.5) which surfaced real defects — a believed-but-absent D-3 gate, a warn-mode rationale that was factually false, and an exit-code overloading — all corrected as binding conditions before Engineering. Stage-7 DevTest all-PASS, Stage-8 QA ACCEPT (34 edge cases, 0 failed), Stage-9 GO operator-authorized 2026-07-21.
