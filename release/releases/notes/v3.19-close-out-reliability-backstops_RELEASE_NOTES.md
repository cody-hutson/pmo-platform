# Stage 13 close-out reliability backstops — completeness gate, outcome-bound mandatory close, tooling smoke gate, slug/Keychain hardening, working orphan `--apply`

2026-06-03 · v3.19

This release hardens Stage 13 Close along five axes so a release can no longer close incomplete, the close-out automation can no longer rot unexercised across a repo migration, and the orphan-branch cleanup actually removes what its report says it will. It is internal pipeline hardening — no operator-facing behavior change — and it is the first release to close on its own repaired close-out automation, exercised on its own merge-ahead path.

## Who this affects

- **Anyone running a Stage 13 Close.** The close-out is now outcome-bound: a release MUST land its complete enumerated output set (release-corpus LOG row + INDEX row + DIGEST entry + NOTES file, plus the post-cutover tag and Release) on main, verified, before the milestone closes. The automated close-out is the mandated mechanism; a documented chore-PR fallback covers the cases where its preflight legitimately blocks.
- **Anyone merging a release ahead of the Stage 12 gate.** A direct-to-main merge is now an explicitly supported close path that does NOT waive the downstream close outputs — the full close-out still runs.
- **Anyone changing release tooling under `release/tools/`.** A CI smoke gate now exercises the close-out script on every such PR; a broken release tool fails that PR instead of surfacing at the next release.

## What changed for everyone using the platform

- **Release-corpus completeness gate — `deploy.sh --check` Check 32 (#576).** The check iterates every release row in `release/releases/RELEASE_LOG.md` (at/after the corpus-era cutover) and asserts the matching `RELEASE_INDEX.md` row, `RELEASE_DIGEST.md` entry, and `notes/<slug>_RELEASE_NOTES.md` file all exist (filename resolution tolerant of both the version-stem and milestone-slug naming conventions). *Why it matters:* the documented-but-skippable "Appended at Stage 13" convention becomes a mechanical guard — the canonical incident closed a release with only the LOG row, the INDEX/DIGEST/NOTES silently missing until manual review. Warn-mode-initial per the bypass-mode-readiness shakedown ladder.

- **Outcome-bound mandatory close-out + documented merge-ahead path (#581, reworked at #598).** `stage-13-close.md` Phase A8 and `hub-spoke-bridge.md` Procedure 7 now mandate that a release close with its complete output set verified on main — the binding is on the **output set** (the Procedure 7 Step 4 Verification table is the canonical set), not on a single mechanism. The automated close-out is the mandated mechanism; hand-assembling the corpus row-by-row is prohibited (it silently drops outputs); the documented Phase B chore-PR mechanism is the named fallback for when the automated preflight legitimately cannot pass. A "merge-ahead close-out" subsection makes an operator direct-merge an explicit, supported close path that does not waive the close outputs. *Why it matters:* every recent incomplete close originated from a release merged directly and then improvised — binding the outcome and naming the fallback keeps the close both complete and always satisfiable.

- **CI smoke gate for the close-out tooling — `release-tooling-smoke.yml` (#583).** On any PR touching `release/tools/**` (or the RELEASE_LOG schema), CI runs `automated-closeout.sh --self-test` (in-process unit checks — version / row-state / milestone-slug / parser-clean parsing, JSON render, and a hard assertion that all four corpus paths resolve) and `--check-paths` (an offline corpus-path resolution probe), plus a precision probe proving the path gate actually FAILS on a deliberately-broken corpus path in a throwaway tree. Both gates are offline (no git remote / gh / network). *Why it matters:* the exact rot that hid stale paths and a stale column index for several releases — surfacing only when the script was finally run — now fails the PR that introduces it.

- **Schema-aware slug + locked-Keychain graceful degradation in `automated-closeout.sh` (#584).** `extract_milestone_slug` is now schema-aware: it returns the field-2 milestone slug on the current 8-column LOG row (not the field-1 version), with self-test coverage of both the 8-column and legacy 5-column shapes. A credential fallback (`GIT_TERMINAL_PROMPT=0` plus a `gh auth git-credential` helper layered onto git remote calls) makes a locked or headless macOS Keychain degrade gracefully — the script fails fast with a clear message instead of hanging on a credential prompt with no tty.

- **Working orphan-branch `--apply` with chore-branch scope, stale-ref prune, and post-apply verify in `cleanup-orphan-state.sh` (#556).** `--apply` now actually executes git-porcelain removal (the `REMOVE` action printed but ran as a no-op before, so merged branches survived). `--release-close <slug>` detection now includes the sibling `chore/<slug>-*` Stage 12/13 corpus branches, not just `release/<slug>`. A `git remote prune` step clears stale remote-tracking refs left after server-side merge deletions so the report's remote view matches reality. A post-apply verify re-checks each removed target and reclassifies any survivor (e.g. a branch still held by a worktree) to `SKIPPED — survived apply` rather than silently claiming success.

## Operator action

None. This release is internal pipeline hardening — close-out reliability tooling and protocol text. There is no configuration to set and no operator-facing behavior change. The new gates ship warn-mode-initial; flip-to-enforce is a separate, later operator action after shakedown.

## Known limits

- **Check 32 is warn-mode-initial.** The release-corpus completeness check ships in warn-mode per the bypass-mode-readiness shakedown ladder — a missing INDEX/DIGEST/NOTES is reported but does not yet fail the run; flip-to-enforce follows a warn-log review with zero false positives. Its stricter signed-tag / published-Release sub-checks are cutover-gated and dormant by default (a row that predates the artifact resolves to N/A, never FAIL).
- **The smoke gate is offline-only.** `release-tooling-smoke.yml` exercises the close-out script's `--self-test` and `--check-paths` with no git remote, gh, or network call — by design, so the job is deterministic and credential-free on a fresh runner. It validates parsing, path resolution, and parser-clean discipline; it does not exercise the network-dependent phases (chore-PR creation, milestone close, Release publish), which remain covered by the live close-out and the Procedure 7 Step 4 verification.

## Process note

This release validates the repaired close-out automation on its own merge-ahead close. The five backstops shipped as four direct-to-main PRs rather than one Stage 12 release PR, so there is no single `DEPLOYED` RELEASE_LOG row and the `automated-closeout.sh` single-`--pr` preflight does not fit; per the outcome-bound mandate (Phase A8), the binding is on the output set and the close was produced via the documented Phase B chore-PR fallback. As the capstone of the milestone, `automated-closeout.sh --self-test` and `--check-paths` were run live on main and both PASS — confirming the repair is live — and `deploy.sh --check` Check 32 plus the Procedure 7 Step 4 completion-verification table are the satisfying gates for this close. The signed `v3.19` tag and the GitHub Release are backfilled at the operator authorization gate.
