# Foundation for a queryable warehouse of your project documents

2026-07-03 · v3.61

This release installs the tooling to turn your project documents into a searchable index — classifying each document by kind and lifecycle, mapping how documents relate to one another, and answering questions like "what depends on this file?" or "which documents are orphaned?" The tools ship ready and safety-gated; **populating the index from your live documents is a separate step, deferred to a follow-up**, so this release is foundational rather than immediately visible.

## What changed for everyone using the platform

- **A document-classification-and-index capability is now in place — but not yet switched on.** *Why it matters:* the ability to ask blast-radius, orphan-detection, and portfolio-rollup questions across your project documents is one gated step away, rather than not built at all.
- **RAID log entries can now carry a structured source-reference** instead of a free-text tag. *Why it matters:* where a risk or action came from becomes something the platform can trace, not just something you read.
- Otherwise, **no immediate change to day-to-day behavior** — the capability activates when its tooling is deployed and run against the live corpus (see Known limits). See operator detail below for the full scope.

## Known limits

- **The document backfill is deferred.** The index tooling is built and verified, but it has not been run against your live documents yet — so the searchable warehouse is not populated. That run is tracked as a follow-up and gated behind an explicit confirmation and a ≥95% accuracy spot-audit before anything is written.
- **Expected coverage when it runs is partial** — roughly a quarter to two-fifths of active documents will classify confidently, because most of the corpus sits in folders that don't follow the standard naming scheme. Closed-project archives are intentionally left out.
- The relationship-metadata emission on newly-created documents becomes active only after the affected skills are re-deployed.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE / HIGH.** The release shipped as a single pull request and is fully git-revertable; **no live document was modified** (the corpus backfill was deferred), and the index itself is disposable — rebuildable from source. Rollback is: revert the release PR and drop the index; there is no data-loss surface because nothing was written to your documents.

### Operator and engineering detail

Four work items closed the Project-Data-Architecture storage tail (RELEASE_LOG `#107-pda-tail-closeout`, **Outcome: PARTIAL**): a node-classification tool that stamps each document's domain/type/lifecycle frontmatter, a relationship-edge layer (write-time emission across file-router / ppm-agent / tracker-manager plus a RAID `source_ref` field), the SQLite index builder that materializes the warehouse from that frontmatter, and a throwaway feasibility probe that confirmed a scheduled-task session **can** spawn a sub-agent (VERDICT PASS — unblocks the per-project orchestration epic's fan-out architecture; the governance amendment that formalizes it is tracked separately, not in this release).

The release ran the full 13-stage pipeline: two independent adversarial design reviews surfaced a premise problem (the builder ships inert without populated frontmatter) that drove a mid-pipeline re-scope to include the backfill, and a second premise finding (the live corpus is too non-canonical for comprehensive coverage) that set the honest coverage promise (active-project scope only). QA hardened the two corpus-writers behind an explicit `--i-am-at-stage-12` confirmation token so neither can mutate documents by accident, and wired the tools' self-tests into CI. At Stage 12 the operator chose **merge-only**, deferring the expensive live-document backfill to follow-up **#3123** — decoupling the reversible code deploy from the irreversible data mutation. The domain classification migrated to human-readable values (`source`/`managed`/`generated`) mid-release and the builder was reconciled against the live schema rather than the design's original assumption. Provisional version `v3.55` re-versioned forward to `v3.61` across a heavy concurrent-release window (v3.54/v3.55 are permanent, benign numbering gaps).
