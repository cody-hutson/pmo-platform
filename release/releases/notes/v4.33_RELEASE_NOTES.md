# A settled home for your files, and an undo for hook updates

2026-08-20 · v4.33

This release gives the platform one agreed answer to "where do my files live?" — so tools stop
disagreeing about it — and adds a safety net so a bad security-hook update can be undone even
after it has finished successfully.

## Action required

**Run one command in your terminal to finish this update:**

```bash
cd ~/Claude/pmo-platform && bash docs/scripts/setup-workspace.sh
```

The automatic update installed the new shared files your security hooks need, but it left the
hooks themselves at their previous version. It reported them as "edited by you" and declined to
overwrite them — a protection that fired incorrectly here, because they had not been edited.
They are simply older copies. The command above brings them up to date.

Nothing is broken until you run it. Your current hooks work; they are just a few weeks behind.

## What changed for everyone using the platform

- **Your personal platform files now have one agreed location**, instead of each tool working it
  out separately and occasionally disagreeing.
  *Why it matters:* a tool that guessed differently could write to one place and read from
  another, which looks like your settings silently not saving.

- **A session opened outside your main workspace folder now finds the platform's instructions.**
  *Why it matters:* previously, working from a different folder could start an assistant that had
  never loaded your rules — so it behaved like a stranger to your setup.

- **A security-hook update can now be undone after it has already succeeded.**
  *Why it matters:* until now the safety net was thrown away the moment an update finished, so a
  problem noticed ten minutes later had nothing to restore from. Snapshots now outlive the update
  and the last five are kept.

- **An update interrupted by a crash or power loss is now recoverable.**
  *Why it matters:* the previous safety net only survived a clean failure. A hard kill left
  nothing behind.

- **The update now refuses to install a half-finished set of security hooks.**
  *Why it matters:* hooks missing a file they depend on refuse everything rather than fail
  quietly, which would leave the assistant unable to run any command — including the ones needed
  to fix it.

## Known limits

- **The hook reconcile above is manual.** The installer cannot tell a stale copy from an edited
  one, so it preserves both. The distinction has to be made by a person for now.
- **Platform rule files still do not reach a running session.** They are written to the repository
  but nothing copies them into place. Tracked as **#633** — pre-existing, not introduced here.
- **An optional setting left deliberately blank is still treated as unset** and will prompt for a
  value, which stops an unattended run. Tracked as **#5649**.
- **Three items found during this release were filed rather than fixed:** #5644, #5635, #5634.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE**, confidence **HIGH**.

The repository half reverts cleanly: reverting the release commit restores every tracked file,
and the plan's rollback strategy applies unchanged. The installed half is separate — reverting
the repository does not undo an update already applied to your machine, which is what the new
snapshot-and-restore path exists for. That path was exercised before shipping: a deliberately
damaged hook set was recovered from its snapshot, restoring 27 of 27 files.

### Operator and engineering detail

Raw audit detail sits in the `v4.33` Deployment Log row; this is the narrative around it.

**The deploy landed partially, and every automatic signal said otherwise.** The update reported
exit 0, printed `Hook-library closure: PASS`, and finished with "Update complete" — all three
accurate, none of them evidence the release had reached the runtime. The closure assertion
derives its required-library set *from the hooks already deployed*, so the previous bundle's four
libraries satisfied it; it would have passed identically had this release never existed. The
shortfall surfaced only by hash-comparing deployed files against source: **12 of 22** hooks
differ, including all four this release modified.

**The "operator-edited" classification was wrong in every instance.** Each preserved hook matches
a historical source commit exactly — three at `6dadf334` (2026-07-25), one at `81e35588`
(2026-08-10). They are stale platform copies, not local work, so the reconcile discards nothing.
The classification rests on a recorded baseline that has drifted.

**What did land, and was verified rather than assumed:** the shared library four security hooks
load at startup is now deployed for the first time (the hook library went from five files to
six); the durable snapshot introduced by this release fired on a real deploy rather than a
fixture, capturing its first generation; and the regenerated script-execution allowlist retained
its new entries through a tamper-detected rebuild — confirming the fix was made at source rather
than only on this host.

**Two verification practices are worth carrying forward.** Guard tests added this release were
*mutation-verified* — deliberately broken, watched to go red, reverted and hash-checked — after
two of four existing arms were found incapable of failing at all. And a test arm asserting
recovery to the wrong state was caught by its own file counts: it expected a restore to return
the post-update file set, which would only be true if the snapshot were taken after the write it
protects, i.e. the exact defect being guarded against.

**Cycle-time reads N/A for a reason worth fixing:** the Stage-9 GO was emitted under a decision
subtype rather than the gate outcome the measurement tool queries, so the anchor it needs was
never written in the shape it looks for.
