# Comms and artifact drafting now focus on PMO-unique work and hand commodity drafting to Anthropic

2026-06-14 · v1.17

The two skills that draft your communications and project artifacts are refocused on the work that is genuinely PMO-specific, and the commodity drafting that an Anthropic skill does well is handed off to it at design time — so the PMO skills carry no live dependency on an outside skill while you use them. The comms skill now owns executive briefs and stakeholder emails directly, the artifact skill has a tighter, clearer catalog, and a routing tree decides which path a request takes.

## Who this affects

- Anyone who drafts a stakeholder communication — the comms skill now covers six PMO-unique communication types and directly produces executive briefs and stakeholder emails, with its audience-calibration and escalation rules intact
- Anyone who asks for a project artifact — the artifact skill now offers a tighter PMO-unique catalog and routes anything outside it to a commodity drafting path, so you get the right tool for each request

## What changed for everyone using the platform

- **The comms skill now owns executive briefs and stakeholder emails directly.** It produces both in the right voice without reaching for an outside skill while you use it, because that voice was built into the skill ahead of time. *Why it matters:* an exec brief or a stakeholder email comes out in one step with no setup, and the result does not depend on any outside skill being available when you ask.
- **The comms skill is focused on six PMO-unique communication types.** It keeps the rules that make its output principal-grade — audience calibration, escalation discipline, and the no-status-theater guardrails — and drops scope it never needed to own. *Why it matters:* the skill does the PMO-specific communications well rather than spreading across commodity drafting another tool handles better.
- **The artifact catalog is tighter and clearer.** The artifact skill now lists the project artifacts that are genuinely PMO-specific and hands commodity drafting to a separate path. *Why it matters:* you see a focused menu of the artifacts the PMO skill is built to produce, instead of a long list mixing PMO-specific work with generic documents.
- **A routing decision now picks the right drafting path for each request.** A decision tree routes an artifact request to the PMO catalog when the work is PMO-specific and to the commodity drafting path otherwise. *Why it matters:* each request lands with the tool best suited to it, without you having to know which skill owns what.

## Known limits

- This release refactors the two authoring skills and their routing; it does not change any project artifacts or communications you have already produced.
- The commodity-drafting handoff happens at the skill's design time, not while you are using it — the offloaded voice is captured into the skill ahead of time, so there is nothing for you to configure or connect.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

CHEAP / HIGH confidence. A single revert of the release pull request restores the prior skill scope, the prior artifact catalog, the routing tree, and the prior ADR numbering; the change is a skill-scope refactor with no data migration to unwind. The standard 30-day outcome window applies.

### Operator and engineering detail

**Release shape.** `novel` release class, CHEAP reversibility, five issues delivered through one integration pull request at merge SHA `79d8827d0fb57f671ad49c0a80acf9e376bc5a55`, signed-annotated `v1.17` tag at the merge SHA (zero signing bypasses). The deliverables are scope narrowings + an own-with-harvest ownership move on `comms-writer`, a catalog narrowing + a Wrapper Mode + a `CLAUDE.md` Part-D routing decision tree on `artifact-generator`, and an ADR-collision resolution. Both skills' `.skill` packages were rebuilt at Stage 12 so package-to-source parity holds on main, and the explicit-name `./core/deploy/deploy.sh --deploy comms-writer artifact-generator` deployed both skills + both packages to the runtime targets. This release was authored in-pipeline as v1.15; the concurrent platform-self-measurement-and-quality-method release claimed v1.15 first and delivery-capacity-and-lifecycle-gating landed v1.16, so the canonical version is v1.17.

**comms-writer scope + ownership (#174, #173).** `comms-writer` is narrowed to the 6 genuinely PMO-unique communication types, with the PMO-critical rules — audience calibration, escalation discipline, and the status-theater guardrails — explicitly preserved through the narrowing rather than dropped (the narrowing removes scope the skill never needed to own, not the rules that make its output principal-grade). Under the own-with-harvest pattern, `comms-writer` takes ownership of executive-brief and stakeholder-email generation: the Anthropic voice is harvested into the skill at design time, so generation produces the voice with no runtime Anthropic dependency.

**artifact-generator catalog + offload (#176, #175).** The `artifact-generator` catalog is narrowed to its PMO-unique artifact set — 27 artifacts after the narrowing plus the own-with-harvest additions — removing the commodity artifacts an Anthropic scaffolding skill produces better. A new Wrapper Mode offloads commodity artifact scaffolding to an Anthropic skill, and a Part-D routing decision tree in `CLAUDE.md` routes an artifact request to the PMO catalog versus the Anthropic offload path so the PMO-unique-versus-commodity boundary is explicit at request time.

**ADR-collision resolution (#791).** A duplicate `ADR-022` basename collision in `core/ADRs/` is resolved by renumbering the skill-sourcing-coupling-posture ADR to `ADR-023-skill-sourcing-coupling-posture.md` (the platform-config-vs-operator-toml-split ADR retains `ADR-022`), with the cross-references reconciled and the skill-sourcing registry trigger-(d) wired. Resolving the collision in-release rather than shipping it with a fast-follow is the cleaner path because an ADR number is a durable reference other documents cite.

**Process notes.** Re-versioned v1.15 → v1.17 in-pipeline under two concurrent releases that claimed the lower numbers; the reusable lesson (filed earlier as #769) is that the Stage 12 pre-merge check must re-verify the version number is still unclaimed, not just file/gate divergence.
