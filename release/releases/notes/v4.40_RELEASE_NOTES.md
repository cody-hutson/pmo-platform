# Seven pipeline rules that disagreed with themselves now agree

2026-08-28 · v4.40

Seven places where the release pipeline's own rules contradicted each other, contradicted the tools that implement them, or declared a vocabulary nothing enforced are now reconciled to a single statement each. A readiness gate that rejected evidence which was present, a grading rule that told reviewers two opposite things, and a classification threshold that counted a file every release is required to write all now behave as written.

## What changed for everyone using the platform

- **A readiness gate stopped rejecting evidence that was not missing.** The gate that holds a work item until its evidence is supplied recognised only one of the two evidence conventions in live use, so a body written in the other one failed on evidence it actually carried. It now admits both: a bracketed evidence label, or two or more of the six review-discipline field labels appearing together inside the Evidence section. *Why it matters:* a work item written in the platform's own second documented convention no longer stalls on a gate that could not see it.
- **The acceptance-grading rule no longer says two opposite things.** The QA stage told reviewers both that every PARTIAL verdict owes an Override Record and that only an acceptance-blocking PARTIAL does; three graders hit the contradiction in a single release. The obligation is now stated once — it attaches to an acceptance-blocking PARTIAL — and every other mention points at that statement instead of restating it. *Why it matters:* two reviewers grading the same PARTIAL now owe the same record.
- **Release classification stopped counting a file every release is required to write.** The threshold that promotes a release into the heavier review depth counted the release ledger among its rule-defining surfaces whenever a plan declared it — so a three-surface threshold could behave as a two-surface one. The ledger is out of the counted set, leaving six genuinely rule-defining surfaces. *Why it matters:* a release is promoted to deeper review for what it actually touches, not for doing the bookkeeping every release does.
- **A release plan no longer loses its practice-provenance label on the way into the branch.** The label recording which body of practice a design draws on was written at planning and dropped when the plan was transcribed into the branch's first commit. A check now asserts the label is present in the committed plan outright, rather than only asserting it did not change. *Why it matters:* the record of where a design's practice came from survives to the point where someone actually reads the plan.
- **Two verification record types that declared no vocabulary now reject an unknown label.** Two release-verification event subtypes were writable precisely because nothing checked what went into them. Both now carry a declared label set, and a write carrying a label outside it is refused. *Why it matters:* a malformed verification record is caught as it is written rather than discovered by whoever next tries to read it.
- **The event log can now be checked for currency and attribution, not only presence.** A new read-only check reports records that are stale, incomplete, or unattributable, measured from a recorded cutover instant so that records written before it report as legacy rather than as violations. *Why it matters:* a record that exists is no longer mistaken for a record that is current.
- **The published release page has one owner, and the close-out now says which path produced it.** The public release page was specified as produced by the merge stage but was in practice produced by the close stage — where the check that verified it was checking its own output. Production is owned by the merge stage; the close stage keeps a backstop that changes nothing when the page is already there, and records which path produced it. *Why it matters:* the close-out report can tell a release page the merge stage published from one the backstop had to create.

## Known limits

- **The plan-conformance check still cannot see one class of declared file.** The checker that asserts a release delivered what its plan declared matches declared paths against a fixed list of top-level directories, and one directory is missing from that list. A dropped row is not reported as unreadable, so the check reports clean while the row is invisible. Exactly one row of this release's own plan was affected and was graded by reading the diff instead. The gap is open and tracked separately.
- **Nothing re-checks a release's size ceiling after its class changes.** The size ceiling is asserted once, at the boundary before the class is set — and the class is a multiplier on the quantity being measured. This release ran 24% over its own ceiling from the moment its class changed, through five subsequent gates, and was accepted with recorded rationale rather than split. The missing re-check is filed as a separate work item and was deliberately not added to this release.
- **The widened evidence gate admits a bounded second shape, not any evidence.** The second convention is recognised only when at least two of six specific field labels are co-present inside the Evidence section. A more permissive reading was designed and rejected on measurement: it admitted 2 of 239 bodies, so it would have widened almost nothing while weakening the gate.
- **The log-integrity check reports; it stops nothing.** It is read-only by design and gates no stage. Its verdicts became meaningful only once the cutover instant was bound at merge time — before that binding it returned a clean result on every input, including a malformed one.

Report issues at the repository issue tracker.

## Reversibility

MODERATE / HIGH. `git revert -m 1` on the release merge commit reverses all seven cards at once: every path is a text or tracked-config edit, the new tool and its fixtures are additive, and there is no schema migration, no data movement and no file move. One asymmetry is real and is stated rather than hidden — this release changed the tool that performs its own close-out, so a revert of the merge would not un-run the close that had already happened; the changed step is unchanged in its return codes and leaves the published page present either way, so the residual is a mislabelled close-out record, not a missing release page.

### Operator and engineering detail

**Every one of the seven cards falsified something in its own premise, and the corrections ran both ways.** One card's premise proved *stronger* than filed — the emit-ownership defect affects 11 of 12 recent releases, not the two the card claimed. Others had a headline number that did not survive contact with live state: a "30% of a triage batch" figure re-derived to 49% under a loose probe and 4.4% under a specificity-preserving one, with the defect itself confirmed live in both readings. Two cards were not stale but **wrong on arrival**: one card's proposed remedy was prohibited by schema text authored three days before the card was filed, and another's premise had been narrowed by a commit landing one day before its filing. A stale card was right once; these never were, because the corpus moved between observation and write-up — which places the remedy at intake rather than at triage or planning.

**The release's own headline figure reproduced the exact defect it reported.** The planning artifact attributed 20 malformed rows to the event log. Re-derived at Solutioning: **0 of 2,686**. The original probe counted bare pipe characters rather than unescaped-pipe field splits — which is precisely the distinction the card existed to draw. Both numbers reproduce on demand: the naive bare-pipe test returns exactly 20 and the correct field-split test returns 0, so the finding is a measured correction rather than a disagreement.

**The load-bearing cross-issue criterion was one-normative-statement-plus-citations.** For each rule this release canonicalised, the merged corpus must carry exactly one normative statement with every other mention citing it — graded by enumerating every occurrence of the obligation clause, classifying each as normative or citing, stating the denominator, and running both a sensitivity and a specificity arm. A fix that re-restates the rule is the same defect in new clothes, and only a cross-issue check sees it. Two restatements invisible to a token-keyed sweep surfaced this way at QA and were converted to citations; a third occurrence, an archival quotation inside a decision record's own Context section, was classified and deliberately left untouched, since editing it would falsify that decision's history.

**No gate was left unable to fail.** Every predicate this release widened, registered, or reconciled carries a recorded negative-arm result on the merged pull request: the widened evidence gate still fails an evidence-free body, the newly registered vocabularies still reject an off-vocabulary label, and the reconciled Override-Record trigger still identifies a case that requires a record. A recorded pass without its paired failure was graded NOT MET.

**The subtype vocabulary is registered in a table deliberately separate from the tool's own `--source` enum**, because adding a third value to that enum would have been rejected by the read tool. One registry row, showing the shape a subtype now declares:

```
| Registry key   | Input filter                                                      | Labels recognized in payload           |
|----------------|-------------------------------------------------------------------|----------------------------------------|
| qc4-06-result  | --event-type release-synthesis --event-subtype qc4-06-result      | verdict / outcome_excerpt / evidence_anchor |
```

Registering an exact type-and-subtype pair binds that subtype alone: every other subtype of the same type still resolves to the empty set and stays free-form, and that non-regression is asserted directly in the tool's self-test rather than left to inference. The registry's label charset was also widened to match the write-side extractor exactly — it had shipped as a strict subset, which held only by the coincidence that every declared token is lowercase. A narrower charset does not fail loudly; it silently drops the label and the conforming payload is then rejected as unrecognized.

**Six decision records were authored on one branch and none was numbered ahead of time.** The numbering oracle is a read, not a reservation, so back-to-back authoring without re-running it collides. Numbers were allocated one at a time at authoring, in implementation-sequence order, and the whole block was renumbered once when a sibling release merged its own record into the mainline first. The asymmetry decides the rule: a duplicate number is mechanically renumberable, whereas a gap blocks the repository. All six were ratified at this close gate and now read `Accepted` with provenance in their own `status:` field, which is where that must be verified.

**One close-out measurement is reported as unmeasurable rather than filled in.** The plan-review gate event for this release was emitted after the deploy it is supposed to precede, so the two anchors are inverted and the computed interval is negative. The tool flags that as a log-integrity condition, and the ledger records it as unmeasurable with the inversion named — not as a duration, and not as the earlier claim that no gate event existed.
