# Stage 4 planning discipline — mandatory currency + crisping gates, release-plan versioning, analysis-class methodology-design variant

2026-06-02 · v1.04

This release codifies three Stage-4 / pipeline-discipline protocols within the v1.* Pipeline Discipline track. Stage 4 now runs mandatory currency and crisping gates at entry; the release plan has a defined versioning protocol (git history is the version trail); and analysis-class releases — those whose deliverable is a research artifact — get a Stage 5 persona variant tuned for research-methodology design rather than stretching the architecture-assessment persona.

## Who this affects

- Anyone running Stage 4 Planning (two entry gates — currency + crisping — now fire as mandatory named phases)
- Anyone authoring or revising a release plan (the plan is a committed file; revisions are git commits; no in-file version number)
- Anyone running an analysis-class release (a research artifact — audit, gap analysis, methodology design) now gets a Stage 5 persona variant with methodology-design gate criteria and a handoff schema

## What changed for everyone using the platform

- **Stage 4 entry runs mandatory currency + crisping gates.** Phase A0.5 reconciles each issue's acceptance-criteria context against current platform state; Phase A0.6 re-runs the substantive intake checks against each bundled issue's current body and routes weak or stale bodies to a crisping pre-gate before plan-design. *Why it matters:* stale paths/versions and weak issue bodies are caught structurally at planning entry instead of depending on whether a prompt happened to include the check.

- **The release plan has a defined versioning protocol.** The plan is a single committed file; its revisions are git commits (git history is the version trail — no in-file revision number), with an explicit rule for when a mid-flight change requires re-planning versus a minor adjustment. *Why it matters:* plan changes are auditable through git history rather than silently overwritten.

- **Analysis-class releases get a methodology-design persona variant.** When a release's deliverable is a research artifact, Stage 5 activates a Research-Methodology Design variant (sampling frame, evidence-grading rubric, coding scheme, analysis plan) with its own gate criteria and a Stage 5→6 handoff schema — not a new pipeline stage. *Why it matters:* research methodology gets first-class design treatment without stretching the architecture-assessment persona or changing the 13-stage pipeline.

## Known limits

- The methodology-design variant is a Stage 5 persona variant, not a separate stage (Option B per ADR-011). If a future analysis-class cadence needs a distinct methodology-peer-review gate that the Stage 5 transition gate cannot express, a later ADR can supersede this one and add the stage.
- The currency and crisping gates are judgment-graded at entry; their effectiveness is observed over subsequent releases.
- A reference-hygiene gap surfaced during this release (issue-refs and links leaking into non-ledger files) is tracked for a follow-up (#558).

Report issues via the standard intake at the GitHub Issues page.

## Reversibility

MODERATE / HIGH. The three changes land via a single release PR (#540); `git revert <merge-sha>` reverts the slice. The methodology-design variant is a contained governance edit (no stage-count change); #42 and #337 are additive protocol edits. Documentation and protocol-definition changes only; no schema migrations, no breaking interfaces.

### Operator and engineering detail

**Release shape.** Operator-confirmed `routine` class at Stage 4 with Deep design review applied locally to the methodology-design ADR. **#42 — Stage 4 currency + crisping gates.** Added Phase A0.5 (G-PL1 AC/substrate currency gate) and Phase A0.6 (G-PL2 pre-plan crisping gate) to `stage-04-planning.md`, plus a Stage-4-entry currency+crisping mandate and two failure modes to the `release-planner` skill. **#337 — release-plan versioning protocol.** Added a Release-Plan Versioning Protocol section to `release-process.md`: plan-as-committed-file, git-history-as-version-trail (no in-file version number), and a minor-vs-major re-planning decision rule binding to the existing inter-stage feedback tiers. **#517 — analysis-class methodology-design treatment (ADR-011).** Fissioned from the original methodology-design item (#192) into the design core (#517) plus an Option-A-contingent renumber sweep (#518). ADR-011 selected Option B (a Stage 5 persona variant) over Option A (a new 14th stage): the Release Class enum is closed with no analysis-class member, Stage 5 activation is all-or-nothing, and the per-stage-shard standard routes a new gate criterion to MODIFY-existing. Authored the Research-Methodology Design variant in `release-personas.md` plus methodology-design gate criteria (§ 7) and a Stage 5→6 handoff schema (§ 12) in `stage-05-solutioning.md`. #518 voided (no stage-count change); the pipeline stays 13 stages.

**Durability cleanup.** At PR review the operator flagged issue-refs, milestone URLs, an operator-instance release-log path, and version-anchored cutover clauses that had leaked into ADR-011, the release plan, and the four governance edits; these were stripped and the rules reframed version-agnostic.
