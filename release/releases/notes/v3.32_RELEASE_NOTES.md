# The release hub now follows the autonomy rules it operates under

2026-06-30 · v3.32

This release makes the release hub honor the platform's own autonomy model at runtime. Two changes land together: the hub stops re-presenting already-authorized actions as if they need a fresh approval, and the full-phase-scope discipline is written into the stage specifications so a directed phase runs every in-scope item through to the phase boundary.

## What changed for everyone using the platform

- **The release hub no longer re-asks you to approve work you have already authorized.** When you approve a release plan or a bounded auto action, the hub now treats that approval as standing and proceeds, instead of pausing again at each step to ask for the same permission. *Why it matters:* you stop seeing redundant approval prompts for decisions you already made, so a release run reads as continuous progress rather than a stream of repeated yes/no gates — while the genuine human checkpoints (plan review, and anything hard to undo) still stop for you.

- **A directed phase now runs to completion for every item in scope, by rule.** The "full-phase-scope" discipline — run all the gates for every in-scope item out to the phase boundary, and finish steps that were waiting on a temporary blocker once it clears — is now written into the stage specifications the hub reads, not just held as a convention. *Why it matters:* when you ask for a phase to run, it completes the whole phase instead of stopping partway to ask which item to handle next, so you get finished work rather than a to-do list.

- **The hub records when it pauses for an approval it did not actually need.** A new measurement counts any time the hub stops for a gate that the autonomy rules already cleared. *Why it matters:* this gives an objective signal that the no-redundant-prompting behavior is holding over time, so the improvement can be confirmed rather than assumed.

## Known limits

- This release governs the release **hub's** behavior. It does not change how individual project work, status updates, or transcripts are processed.
- One follow-on item from the design review (a machine-checked backstop for the new eligibility precondition) is tracked separately under issue #172 and is not part of this release.
- The operator-local note that recorded the full-phase-scope correction is retired as the codification-complete signal; that cleanup is a workspace-local step the hub performs after close, not a change shipped in this release.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.
