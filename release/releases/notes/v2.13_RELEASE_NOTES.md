# Finding-disposition and deferral discipline, applied uniformly across the pipeline

2026-06-20 · v2.13

This release closes four gaps in how the pipeline handles *findings* and *deferrals* — so the same rules apply at every gate instead of relying on ad-hoc judgment. Acceptance criteria that describe a behavior now survive intake with their meaning intact, a QA rejection caused by an unclear requirement is sent upstream rather than patched downstream, and work that gets pushed to a later stage can no longer quietly disappear.

## What changed for everyone using the platform

- **Acceptance criteria can now state a behavior or domain outcome** (paired with a declared verification method) at the intake, bundle, and planning gates — they're no longer silently rewritten into a file-content/system-state check. *Why it matters:* an AC like "a reviewer can approve in one click" passes the gates with its real meaning preserved, instead of being degraded into something narrower.
- **A QA rejection now splits by cause.** An *implementation* reject (the build doesn't meet a sound AC) still returns to engineering; a *requirements-clarity* reject (the AC itself is stale, ambiguous, or premise-invalid) now routes to the premise-rejection protocol — return-to-triage, override-with-deviation-log, or defer. *Why it matters:* a bad requirement gets fixed at the source rather than worked around late.
- **Work deferred between pipeline stages now has rules.** There are explicit criteria for what makes a deferral valid (versus a scope-gap rationalized away), an owner and target stage for each, per-gate accounting so each stage tallies the items deferred into it, and a staleness flag that fires when an item lingers within two stages of its target. *Why it matters:* a mid-pipeline "we'll handle it later" can't silently vanish.
- **Deferred issues get a recurring re-evaluation cadence** — reviewed at each release-planning ceremony and at least monthly, with clear criteria for re-opening them back into the active queue. *Why it matters:* the deferred backlog is resurfaced on a schedule instead of quietly accumulating.

## Known limits

- This release admits behavioral/domain acceptance criteria at the *gates*; the executor that runs them as Stage 7/8 checks is tracked separately (#103).
- Out-of-scope items found during the release are tracked, not fixed here: a Gate-3 criterion ID-collision (#1632), a cosmetic formatting fix (#1634), and a hardening item for the engineering spoke workflow (#1642).

Report issues at https://github.com/cody-hutson/pmo-platform/issues.
