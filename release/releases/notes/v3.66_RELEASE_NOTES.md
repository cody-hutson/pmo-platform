# Engineering documents now start from a canonical template, not a blank page

2026-07-09 · v3.66

The platform has long catalogued which engineering documents it expects — architecture decision records, runbooks, design docs, and more — and named the industry standard each one follows. But the starting files themselves did not exist: the catalog pointed at seven document families and marked each "template — none." This release authors those seven templates, so an engineer opening a new ADR or postmortem now starts from a structured, standard-anchored file instead of an empty page, and the catalog that lists them is complete.

## What changed for everyone using the platform

- **Seven engineering-document types now have a ready-to-use starting template.** Architecture Decision Record, Runbook, Design doc (with FDD/TDD/HLD/LLD variants), RFC, Product Requirements Document, Postmortem, and Test plan each get a canonical template file. *Why it matters:* you no longer reinvent the structure each time — every one of these documents starts consistent, complete, and shaped by its recognized industry standard (Nygard for ADRs, Google SRE for runbooks and postmortems, IETF for RFCs, PMBOK for test plans, and so on).
- **The document catalog has no remaining gaps.** The template registry that maps each document family to its standard previously showed seven "none" entries; every one is now filled and pointed at its real template file, and a missing Test-plan entry was added so the catalog is internally complete. *Why it matters:* when the platform or a teammate asks "what's our standard template for X," the answer is now always a real file, not a to-do.
- **Every template carries its own provenance and lifecycle state.** Each file records where it came from, which standard it follows, and that it is an early **draft** — not yet a promoted, in-production template. *Why it matters:* you can trust what a template claims about itself, and you can see at a glance that these are new and still settling rather than long-proven.

## Known limits

- The seven templates ship as **drafts**. They are ready to use and structurally complete, but they have not yet been promoted through the platform's proof-of-utility review, and no automated skill consumes them at runtime yet — so a template's mirror does not auto-propagate anywhere; the canonical file under `operations/templates/` is the single source.
- Each template names the Anthropic plugin that implements its standard as a cross-reference, but those plugin suites are not currently installed in this workspace, so the alignment is recorded as anticipated rather than live-verified. It is re-checked if and when a template is promoted.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH.** The release added seven template files plus registry-row edits to the document catalog, and has zero downstream instances (nothing has been authored from these templates yet). Roll back by reverting the release pull request — each file and each catalog row reverts independently in hours with no data migration and no consumer impact.

### Operator and engineering detail

Three issues closed the software-domain-templates slice of the KA-Reference epic (RELEASE_LOG `software-domain-templates`, **Outcome: SUCCESS**): tracking umbrella #71 plus two wave slices (#2149, #2150), delivered as one branch / one PR / one merge (release PR #3308, merge SHA `671e0bf`, signed tag `v3.66`). Release Class **novel** — seven new reference-doc-class files and two D-class decisions. The work consumes the already-shipped 5-Layer Template Architecture (`template-taxonomy.md` / `template-storage.md` / `template-protocol.md`) and builds no new registry, protocol, storage, or schema.

**Wave 1 — ADR / Runbook / Design doc (#2149)** — three templates anchored to their catalog canons: ADR to Nygard 2011 (Context / Decision / Status / Consequences), Runbook to the Google SRE Workbook §Runbook Design, and Design doc to the Google design-doc convention with an FDD/TDD/HLD/LLD variant discriminator. The ADR template is scoped as the software-domain, engineer-facing template and deliberately kept distinct from the platform-internal `core/ADRs` schema (coordinated with the KA-ADR epic #1175).

**Wave 2 — RFC / PRD / Postmortem / Test plan (#2150)** — four templates anchored to IETF RFC 7322 + the Rust RFC template, the `product-management:write-spec` convention, the Google SRE §Postmortem Culture, and PMBOK 7 §Quality + `engineering:testing-strategy`. This wave also executed the D-TaxonomyRowShape decision: it added a ninth row to the catalog's authoritative canon table for the Test-plan family and swept the table's own count, its reconciliation note, and the surrounding gap-count prose atomically, so the catalog reads "9 rows" with zero residual gap markers.

**Lifecycle and registration decisions** — every template ships at `review_status: DRAFT` with a 15-field provenance header (the Collective Review corrected an earlier 14-field expectation to a 15-field set-equality check). Two operator decisions shaped scope: **D-MirrorRegistration** ruled canonical-only, so no template-sync-map mirror entries were registered this release (registration follows the first runtime consumer); **D-TaxonomyRowShape** added the Test-plan catalog row rather than leaving the family catalogued only in the per-family section. An independent adversarial design review returned Major-but-no-Blocker findings on both waves, ingested as advisory input at Collective Review; Dev Testing passed both waves after three small fix-forward corrections (a branch rebase, a provenance-field transcription, and template blank-line consistency), and QA accepted all three issues at full score. The six skill packages that mirror the template catalog rebuild at close-out.

Follow-ups filed for out-of-scope items surfaced during the run: a promotion-evidence-path gap in the template protocol (#3290 catalogs the registry-hygiene cluster, #3289 the plugin-inventory / promotion-path defect), a blast-radius tooling over-match (#3291), and a quota-gate scope gap (#3299).
