# Diagram pilot + a home for diagrams, a reusable surface-enumeration checklist, and a frontmatter-complete release-plan corpus

2026-06-05 · v1.05

Three pipeline-discipline improvements landed in the v1.* Pipeline Discipline arc. Process diagrams now have a canonical home (`core/diagrams/`) and a first working example; anyone enumerating the documents a change touches gets a reusable six-form checklist with a design-review gate; and every release plan now carries the same searchable frontmatter the release notes already had.

## Who this affects

- Anyone authoring design artifacts or diagrams for a platform process (there is now a canonical diagram location and a worked example to follow)
- Anyone running a documentation-reorganization or surface-enumeration step at design review (a reusable checklist now backs it, with a gate)
- Anyone searching or auditing the release-plan corpus by frontmatter (all release plans are now searchable by the same fields as the notes)

## What changed for everyone using the platform

- **Process diagrams now have a canonical home and a worked example.** Centralized diagrams live in one place, and the first one — a current-state map of the platform's top-level structure — is published and linked from the architecture and operating-model references. *Why it matters:* you have a place to put a process diagram and a real example to model it on, instead of deciding location ad hoc per document.

- **A reusable checklist backs surface enumeration at design review.** When a change touches documentation across the corpus, there is now a single six-form reference checklist plus a design-review check that confirms the enumeration was done. *Why it matters:* the documents a change actually touches are less likely to be undercounted, so cross-reference gaps surface at design time instead of after merge.

- **Every release plan is now searchable by the same frontmatter as the release notes.** All release plans carry the standard six-field frontmatter (version, date, type, issues, PR, links). *Why it matters:* you can search and audit the plan corpus the same way you already search the notes, and the release-corpus validator now passes cleanly across both.

## Known limits

- The diagram work is a pilot plus a scope definition, not a full backfill — only the architecture diagram ships in this release; diagrams for the other process flow types are sequenced as a follow-up (#398).
- The surface-enumeration checklist was re-derived against the current corpus; its effectiveness is observed over subsequent design reviews.
- The release-note validator and its companion schema work have a separate follow-up tracked at #83; a corpus-wide path-drift sweep (#399) and a diagram-tooling defect fix (#400) are tracked separately.

Report issues via the standard intake at the GitHub Issues page.

## Reversibility

Documentation and protocol-definition changes only; no schema migrations, no breaking interfaces. Standard rollback window.

### Operator and engineering detail

**Release shape.** Operator-rendered `novel` class at the Stage 5 Collective Review scope-lock (2026-06-05; revised from the milestone's initial `routine`) on two triggers — a new `core/diagrams/` structural pattern plus a first-of-kind design-artifact backfill (trigger a), and a D-class location-canonicalization ADR (trigger b). The three issues are near-independent; the dominant Stage 4 finding was substrate staleness — two of three were originally scoped against a pre-re-versioning substrate that no longer exists, requiring operator-gated reconciliation before Engineering.

**#64 — design-artifact discipline pilot (Option A).** Scope-locked to a pilot plus a per-flow-type scope definition, with the bulk corpus backfill fissioned to #398. The pilot is the `architecture` flow type, producing `core/diagrams/architecture-platform-structure.md` (a centralized current-state ASCII tree of the modular-monolith top-level layout), referenced from ≥3 parent docs and reciprocated with bidirectional links from the architecture-overview and operating-model disciplines per the standard's cross-reference protocol. The centralized-diagram location was canonicalized to `core/diagrams/` via the committed `core/ADRs/ADR-015-centralized-diagram-location.md` (numbered 015 because ADR-013/014 already exist on-branch and the core-ADR convention is monotonic-across-platform), and 8 corrected paths were applied to `design-artifact-standard.md`. The `size:L` label was set against the unbounded "all flow types × all processes" reading; the containable slice (pilot + location ADR + in-scope path corrections + the scope-definition table) is the correct boundary and the bulk is a distinct increment (#398).

**#91 — Stage 5 surface-enumeration undercount (Option B).** Added a reusable six-form ref-form checklist at `release/references/protocols/doc-corpus-reorg-ref-forms.md` plus a gated check (Phase A3.2 in `stage-05-solutioning.md`; design-review-checklist check 1.5). The issue's original "surface enumeration" evidence anchor no longer exists post-re-versioning, so the ref-form set was re-derived against the current modular-monolith corpus rather than anchored to the dead evidence numbers.

**#116 — frontmatter-schema backfill umbrella.** The original "76 historical files" premise was void in the re-versioned repo; the live corpus is 5 release plans plus 7 release notes (all 7 notes already carried the 6-field frontmatter; all 5 plans lacked it). Phase 1 (the `lint_release_corpus.py` validator with the 6-field schema) had already shipped, so the real remaining work was adding the 6-field frontmatter to the 5 plan files (plus the Commit-0 plan). The reconciled scope also called for flipping `deploy.sh` Check 15 from warn to enforce; verified against the live `deploy.sh`, Check 15 (release-corpus) was RETIRED in v2 (release-corpus moved to operator-instance; the number is a deliberate citation-continuity gap), so there is no warn-mode release-corpus check to flip — recorded as void-target in the plan Deviation Log rather than forced. To make the schema-mandated `issues:` frontmatter mergeable past the reference-durability CI gate, the 5 plans plus this plan were added to the reference-durability allowlist in a dedicated commit (ratification flagged).
