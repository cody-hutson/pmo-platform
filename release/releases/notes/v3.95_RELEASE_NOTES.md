# Set the platform's runtime posture in config — and keep it across updates

2026-07-26 · v3.95

This release makes the platform's runtime posture — which surface backlog decisions read from, whether the security hooks are active, and which model and effort level spokes run at — something you set in canonical configuration instead of in hard-coded spots scattered across the code. It also fills in the platform-config keys that v2.00's features already pointed at, so they now resolve to documented defaults instead of reading as unset.

## Who this affects

- **Operators who deploy or configure the platform** — you now have one documented config home for spoke model/effort, security-hook activation, and the backlog-decision surface.
- **Anyone whose work reads the QA failure-mode detectors or the rollout log** — the config keys those features referenced now exist with defaults, so they resolve instead of reporting "unset."
- **Everyone else** — no action. Everyday project work is unchanged, and the new security hooks ship OFF by default.

## What changed for everyone using the platform

- **Spoke model and effort now live in one canonical config surface (#340).** A new `[spoke_runtime]` section is the single place to set the default model and the chip model for hub-spawned work; effort stays governed by the standing "max effort" directive rather than a second copy. *Why it matters:* changing the model spokes run at is one obvious edit instead of a hunt across several files that can drift out of sync.
- **Security hooks are now an opt-in you turn on once, and it survives updates (#310).** A fresh clone ships with the workflow guards OFF; you enable them at install or in your durable per-user config, and `update.sh` never resets that choice. *Why it matters:* you decide whether the guardrails are active, and your decision isn't silently undone the next time you update.
- **Turning the guards off never disables the safety-critical ones (#310).** The master switch governs only workflow-convenience hooks; the hooks that block credential reads, egress, PII, and path leaks always stay on. *Why it matters:* on a public repo, a convenience toggle can't accidentally open the door to a leaked commit.
- **The session now checks its own model and effort at launch (#339).** A new startup check compares the running session's model and effort against your configured posture and flags a mismatch. *Why it matters:* you find out at the start of a session if it launched at the wrong model, not after the work is done.
- **The backlog-decision surface is no longer wired to a single board (#102).** The triage step that reads priority and decision dates now resolves them by a configurable role, with GitHub Projects as the unchanged default. *Why it matters:* teams that track work somewhere else can point the platform at their own surface instead of being locked to one board.
- **The config keys earlier features referenced now exist with defaults (#1212).** The QA failure-mode detectors and the rollout log that prior releases pointed at now have real config sections with documented defaults. *Why it matters:* those features resolve to a value instead of reporting "unset," so they behave predictably out of the box.

## Known limits

- **The new security hooks are OFF until you opt in.** A fresh clone imposes no workflow guards until you enable them at install or in your per-user config — this is deliberate, not a defect.
- **The session model/effort check is advisory.** It flags a mismatch at launch but does not block the session or change the model — it tells you, and you decide.
- **The two new config-surface checks start logged but not blocking.** The master-enable reconciliation check and the session verifier report findings without failing a build or halting a session while they settle in.
- **Effort has no config field by design.** Effort follows the standing "max effort" directive; to change it you change that directive, not a value in `[spoke_runtime]` — this keeps a single source of truth.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues.

**MODERATE** · confidence **HIGH**. The release is a single pull request (#4037); a `git revert -m 1` of the merge removes all five slices and restores the prior config, hook, and triage behavior. ### Operator and engineering detail

Full detail: RELEASE_LOG row `#deployment-log-v395` (v3.95), plan `release/releases/plans/v3.95_RELEASE_PLAN.md`.

Novel-class release, D-C SINGLE topology, P0 fully-serial — five issues shipped as delivery slices on one branch, one PR (#4037), 39 files (+1,655/−32), built in dependency + contention order #1212 → #102 → #340 → #310 → #339. Three writers (#1212 / #340 / #310) converge on the platform-config template as disjoint sections, resolved by build-order rather than merge conflict.

**#1212 — the v2.00 config-key back-fill.** Adds `[failure_mode_detectors]` (the D6 breadth-burnout ceiling and the D8 trust-erosion floor that the pmo-qa-auditor detector battery reads at evaluation time) and `[progressive_rollout]` (the location + format of the release-executor rollout-log) to the platform-config template, on the existing sibling-section pattern. Flagged at Engineering Commit 0 as template-only; the schema + catalog mirror was completed in-release via #340's config-surface work (Stage-7 action item AI-001) and re-verified at Stage 8, so all four new sections carry documented defaults across template, schema, and catalog.

**#102 — config-resolved backlog-decision surface (G2-06 / G2-12).** Rewords the two symmetric gate criteria (the D-G2-12 fold) and the Stage-2 triage step so priority and decision-date resolve from the configured ticketing surface's role rather than from a single hard-wired GitHub Projects board. GitHub Projects stays the default; the coupling to one board is removed.

**#340 — canonical spoke model/effort surface (`[spoke_runtime]`, ADR-095).** Establishes one discoverable home for the default spoke model and the chip-path model, with effort deliberately expressed as a pointer to the standing directive (no stored, drift-prone copy). `deploy.sh` Check 27 now reads the default from config instead of a hard-coded literal. **ADR-095** records the decision and supersedes-in-part the prior "two surfaces by design" stance, while preserving the two Anthropic-owned runtime carriers (agent-definition frontmatter and settings.json) as derived, verified representations.

**#310 — opt-in security-hook activation + the SECURITY-EXCLUDED floor (Check 60).** Adds a durable master-enable, implemented as one shared library that collapses the per-hook edits, plus an install-time opt-in that persists in the per-user config surface across updates. The **D-R9 SECURITY-EXCLUDED** scope is the load-bearing constraint: the master switch governs only workflow-class hooks, and the security/floor-class hooks (credential-reads, egress, gh-path-leak, PII, destructive, scope-segregation, shell-injection, and the Tier-0 autonomy floor) always enforce and are never silently disabled — the failure mode of a silently-off egress or PII hook on a public repo is irreversible. A new `deploy.sh` **Check 60** reconciles the master-enable hook-class map against the D-R9 security registry (logged but not blocking initially).

**#339 — SessionStart model/effort verifier.** Adds a startup hook that reads the launched session's model and effort and compares them against `[spoke_runtime]`, flagging a mismatch (workflow-class, non-blocking). It reads #340's canonical surface — not a hard-coded expectation — and honors #310's master switch; the hook-registry glob was generalized so posture-hook fragments assemble into the deployed mirror.

The four new config sections and their shipped defaults:

```toml
[failure_mode_detectors]        # v2.00 QA detector thresholds (D6 / D8)
concurrency_ceiling  = 5        # D6 breadth-burnout ceiling (count)
walk_back_rate_floor = 0.15     # D8 trust-erosion floor (0.0–1.0)

[progressive_rollout]           # rollout-log persistence surface
rollout_log_dir      = "core/hooks"
rollout_log_format   = "jsonl"

[spoke_runtime]                 # canonical spoke model/effort (#340)
default_spoke_model  = "opus"   # subagent-path default; effort is a pointer, no field
chip_model           = "opus"   # spawn_task chip path (independently tunable)

[security_hooks]                # opt-in workflow-hook activation (#310)
master_enabled       = false    # default OFF; security/floor hooks always enforce
```
