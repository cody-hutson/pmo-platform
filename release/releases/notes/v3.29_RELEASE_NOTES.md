# The release pipeline now has named parallelism postures for Stage-6 engineering

2026-06-30 · v3.29

## What changed for everyone

- **The release pipeline's Stage 6 (Engineering) now has named parallelism postures.** Explicit, documented rules for how a release's engineering work runs concurrently versus serially, instead of each run re-deriving it — a founding decision record (ADR-052) fixes the posture taxonomy, wired into the Stage-4 planning and Stage-6 engineering references, the hub-spoke orchestration bridge, the `failure-mode-standard`, and the release-planner skill. *Why it matters:* concurrent engineering work on a release is now governed by a stated posture — which work can run in parallel, and what serializes on shared files — rather than ad-hoc per-run judgment, making parallel release execution more predictable and safe.

Internal release-pipeline governance — no user-facing workflow changes.

This release was re-versioned forward from a provisional **v3.28** to **v3.29** at the Stage-12 atomic claim: the label-taxonomy-canonicalization milestone published v3.28 first, so the anchor recomputed the next-free version.
