# Ready-to-use Change Impact Matrix and Training Plan templates

2026-07-25 · v3.89

If you plan a go-live or a system upgrade, you no longer rebuild a change-impact matrix or a training plan from scratch — both now ship as registered, discoverable templates you can copy and fill in. This release also lines up the RAID-log template's columns with the RAID data schema so the two no longer disagree.

<!-- Not universal: only affects change/comms planning + RAID-log authoring, so the skip-gate + "Who this affects" apply. -->

**Most people using the platform don't need to do anything.** This adds two optional templates and fixes one existing template's header. If you don't author change plans, training plans, or RAID logs, nothing changes for you.

## Who this affects

- **Anyone planning a go-live or upgrade** — a standard Change Impact Matrix and Training Plan are now available under the shared templates library, discoverable through the change-management workflow.
- **Anyone authoring a RAID log from the template** — the template's column headers now match the RAID schema exactly, so a log created from it validates and exports cleanly.

## What changed for everyone using the platform

- **A new Change Impact Matrix template is available** — a nine-column structure (topic, current vs. future state, level of impact, customer impact, impacted stakeholders, change-management plan, notes). *Why it matters:* change-impact analysis for upgrades and go-lives starts from a consistent, complete structure instead of a blank page.
- **A new Training Plan template is available** — a six-column structure (team, lead, approach, content/deliverables, topics, notes). *Why it matters:* training needs for a rollout are captured the same way every time and are easy to hand off.
- **The RAID-log template header now matches the RAID schema** — 15 columns in the schema's order. *Why it matters:* a RAID log built from the template no longer diverges from the schema, so validation and downstream exports line up.

## Known limits

- Both new templates ship at `review_status: DRAFT` — they are usable now; a reviewer read-pass promotes them to `REVIEWED` in a later pass.
- Two out-of-scope observations were surfaced and logged for follow-up, not fixed here: a CI freshness-gate blind spot for template-into-package syncs, and a template-protocol sidecar convention that the live RAID template pre-dates.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE · HIGH confidence.** The whole release is additive (two new files) plus one header reconcile, delivered as a single merge. Rolling it back is a `git revert` of that merge followed by a corrective release — quick and low-risk, but not an instant undo once the templates are in use.
