# Four stale documentation references get drained from the corpus

2026-07-01 · v3.40

This release fixes four small documentation-drift sites in the platform's internal reference material — places where the written guidance had fallen out of step with how the platform actually works. A protocol now names the log file it really writes, a retired intake instruction now points at the current path, folder-casing is made consistent, and a project-path placeholder is unified to one canonical form across the schema and skill documents. Nothing changes in how anyone uses the platform; every change is a wording or consistency correction, and all existing guards and historical records are preserved.

## What changed for everyone using the platform

- Nothing changes in how you use the platform. There are no new commands, no workflow changes, and nothing breaking — this is an internal documentation-consistency cleanup. <!-- impact:foundational -->
- The internal docs are now consistent with reality in four spots: the doc-link maintenance protocol names the shared warn-log it actually writes to, a retired "log improvements to a file" instruction now routes to the current GitHub-Issues intake, folder references use one consistent lowercase casing, and the placeholder used to describe where a project's files live is written the same way everywhere. *Why it matters:* consistent, accurate references mean anyone reading the docs — or any agent following them — is pointed at the real file, the real path, and the real intake, instead of a stale one.

## Known limits

- These are documentation edits to the internal reference corpus. They take effect for work going forward and do not rewrite historical records — for example, a changelog line that mentions the old folder casing is deliberately left intact as an accurate record of what happened.
- The change deliberately does not touch behavior, schemas, or runtime checks. The one migrated skill (`project-initiator`) had its compiled package rebuilt so the shipped artifact matches its updated text, but its behavior is unchanged.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH confidence.** All four changes are additive wording and consistency edits to reference documents — no data, no schema, no runtime behavior. Rolling back is reverting the release PR with no migration.

### Operator and engineering detail

See the `#30-doc-link-drift-drainage` RELEASE_LOG row for the raw audit trail. All four cards are documentation-drainage chores on one branch / one merge (file-disjoint, shared parent epic only, no dependency edges). `routine` release class.

- **Doc-link protocol log-surface reconciliation (#108).** `core/standards/doc-link-maintenance-protocol.md` §8 named a log surface that had drifted from the shared warn-log the protocol actually writes (as enforced by `deploy.sh` Check 14). The §8 reference is reconciled to the real shared warn-log so the protocol documents the surface it uses.
- **Projects/ → projects/ casing (#131).** The genuine capital-P `Projects/` prose references in `core/governance/OPERATIONS.md` and `operations/OPERATIONS.md` are lowercased to the canonical `projects/` form. This card was re-scoped on 2026-06-30 to the real OPERATIONS prose references (the broad placeholder-token variants were routed to #2700). A changelog line that names the historical `Projects/` casing is preserved intact as an accurate historical record — casing canonicalization applies to live references, not to the record of past events.
- **Drain the last live IMPROVEMENTS.md / IMP-### site (#2684).** `core/schemas/routing-rules.md`'s Self-Update Protocol still carried the retired "log to IMPROVEMENTS.md / IMP-###" intake instruction. It is drained and routed to the current GitHub-Issues intake path, removing the last live pointer to the dead mechanism. (Split from #4; the separate Pattern-C detection work was removed from this milestone on 2026-06-30 as net-new build rather than a drainage chore, and remains under epic #1172.)
- **Unify the project-path placeholder token (#2700).** The placeholder describing where a project's files live is unified to the canonical `projects/[Project]/` form across `core/schemas/frontmatter-schema.md`, `core/schemas/navigation-layer-schema.md`, `core/schemas/routing-rules.md`, `core/schemas/sqlite-index-schema.md`, `core/specs/health-check-specification.md`, and `operations/skills/project-initiator/SKILL.md`. This card owns all placeholder-token variants per the BROAD boundary resolution surfaced by the #131 re-scope. Because `project-initiator` is a migrated skill, its compiled `.skill` package (and content sidecar) were rebuilt in the same release PR so the deployed artifact stays atomic with the SKILL.md edit.
- **One PR, one merge.** All four cards shipped on one branch / one merge per the milestone-as-one-PR model. The prior direct-build PR #2703 was closed unmerged on 2026-07-01 (it bypassed the governance gates; no changes reached main), and this release delivered the same scope through the gated pipeline.
- **No behavior, schema, or runtime-check change.** The release touches only reference-corpus documentation, one migrated skill's text, and that skill's rebuilt package; carve-outs #2701 (AUDIT_FRAMEWORK refresh-or-retire) and #2702 ([PROJECT_KEY] localization review) are tracked separately.
