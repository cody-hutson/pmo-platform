# Hook fixes now reach your instance, and partial updates stop reporting success

2026-09-20 · v4.67.1

Security and behavior fixes to the platform's hooks now actually land on your instance when you refresh them. Before this release the refresh could decline every hook on a normally-maintained instance and still exit successfully, so a merged fix could sit undeployed indefinitely while the command said it had worked.

## What you need to do

1. Update to this version, then run the hook refresh once. On an instance that has been updated over time, one or more hook fixes were almost certainly declined by the old behavior and are still not deployed — this release makes the refresh able to land them, but it does not reach back and apply them on its own.
2. Read the exit status of that run. A run that declines a hook now ends with a distinct non-zero status and names what it declined. If you see it, use the new reconcile command on the named hook.

## What changed for everyone using the platform

- **Hook updates actually apply.** The refresh used to overwrite a hook only while its contents still matched a checksum recorded at first setup. Ordinary platform updates advance the hooks without advancing that record, so on any maintained instance the refresh eventually classified every platform-updated hook as your own local edit and left it untouched. It now recognizes a platform version by its history and refreshes it; only a genuine local edit is preserved. *Why it matters:* a merged security fix reaches the running instance, instead of sitting undeployed while the command reports success and the superseded version keeps enforcing.

- **An update that leaves a control out of date no longer exits successfully.** When the refresh declines at least one hook, it now finishes with its own non-zero status and names what it declined, rather than printing an inline warning and exiting zero. The full update path inherits this. *Why it matters:* you can tell "everything updated" apart from "everything updated except the one thing you were updating for" without comparing files by hand.

- **A supported way to force a declined hook back to source.** A new reconcile command overwrites a hook the refresh has preserved, for the case where you have looked at the difference and decided the platform's version should win. The message that reports a preserved hook names this command. *Why it matters:* a preserved hook is no longer stuck until the next full reinstall, and the way out is printed at the moment you need it.

- **Declining remains the safe answer in every uncertain case.** Where the tool cannot establish a hook's history — no version history available, a shallow copy, a source tree that is not a checkout, or a history longer than its search limit — it keeps your file. *Why it matters:* this release can only widen what it is willing to refresh, never narrow what it protects, so it cannot newly overwrite something the previous version would have kept.

## Known limits

- The history check has a search limit. A hook whose matching platform version sits further back than that limit is preserved rather than refreshed, and the run reports it as declined. Re-running the refresh does not change that outcome — the reconcile command is the route.
- Nothing is applied retroactively. Hooks that the previous behavior declined stay as they are until you run the refresh again on this version.
- The setup script still runs on macOS only and exits with a configuration status elsewhere. That boundary is unchanged by this release.

Report issues at the platform's GitHub issue tracker.

## Reversibility

CHEAP / HIGH. The release reverts as a single merge revert, which restores the previous refresh behavior. There is no file-format or stored-state change, so nothing needs migrating back. If a refresh has already overwritten a hook you wanted to keep, it writes a snapshot of the previous bundle before changing anything and the existing restore command recovers from that snapshot. The version tag stays in place as the record that the version was claimed.

### Operator and engineering detail

**The discriminator is adopted, not invented.** A three-valued history classifier with exactly the needed semantics already shipped in the deploy checker, and its own header names this misclassification. The verdicts, the walk cap, and the rule that an unfinished search is not a finding are taken verbatim, so the two copies cannot disagree; the duplication is registered with a named successor extraction rather than hidden. The decision record is ADR-203.

**The persister is field-scoped, and that is the decision that changed the design.** The planned fix was to write the checksum map back to the state file after a refresh. Reading the preserve branch closely shows it does not only warn — it re-anchors the baseline to the deployed bytes. Persist the whole map and the next refresh reads that re-anchor as permission to overwrite, so a genuine operator edit is not protected, its destruction is merely deferred by one run. The release carries the proof as a standing regression arm: it was authored against a deliberately whole-map persister, observed destroying an edit on run 2, and only then did the correct implementation land.

**Caller-visible exit contract.** The refresh gains one terminal status it did not previously have, distinct from the codes that mean the refresh failed to run: this one means the refresh completed and left a named control superseded. It is raised after the success mark, so it never rolls the refreshed bundle back. The full update path inherits it, so a wrapper that treats any non-zero as a failed update will now see a status meaning "the update applied, and one named control did not". The no-change contract is unchanged in intent and strictly more accurate in practice — a mixed run that refreshed some hooks and declined one previously lost its deployed flag and could report no changes over real work. The statuses a caller parses:

```text
0    success
1    generic failure (validation, operator-cancel)
64   invalid arguments
66   source repo missing
69   missing prerequisite
73   mkdir or copy failed
74   write failure
75   refresh completed, but declined >=1 hook — a deployed control is not the merged version
78   unsupported platform
130  interrupted
```

**The suite that proves the fix now obeys the rule the fix teaches.** The regression suite's five history arms skip where the checkout carries no history to plant from, and its exit status previously consulted failures alone. With the continuous-integration job's full-history checkout removed, the required check therefore read green with four acceptance criteria unmeasured — observed, not hypothesized. The suite now exits non-zero on any skipped arm unless a runner permits the skip deliberately, and the banner keeps naming the unmeasured criteria. This was added after the plan-review gate as the operator's condition on approval. The suite grew from 51 arms to 77.
