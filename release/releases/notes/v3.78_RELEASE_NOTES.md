# Your portfolio view can no longer show Green over a failing or stale project

The portfolio view is no longer handwritten — it is assembled from what each project actually publishes, so what you read at the top traces back to something a project reported. Health scoring now checks how fresh that data is and rolls risk up across components, so the portfolio cannot show Green while a project underneath it is failing or its numbers have gone stale.

## What changed for everyone using the platform

- **The portfolio view is now built from what each project publishes.** Every project publishes a small, standard summary of its own status, and the portfolio page is composed from those summaries instead of being maintained by hand. *Why it matters:* what you read at the portfolio level now traces back to something a project actually reported, so a change made at the project level stops quietly getting lost on the way up.
- **Green can no longer hide a failing part of a project.** Portfolio health is scored in three layers and then multiplied down by an integrity factor, so a project with a failing part underneath it cannot average its way up to Green. *Why it matters:* the dashboard stops reassuring you at exactly the moment you most need it to warn you.
- **Data that has gone stale is called out instead of trusted.** Scoring checks how recently each project published, and a summary that has aged past its window is held back rather than counted as current. *Why it matters:* a Green that is merely out of date now reads as stale rather than as healthy.
- **Risks are combined across components, not just listed per project.** A risk profile gathers each project's risks up to the portfolio without assuming any one way of running delivery. *Why it matters:* a risk showing up in several projects at once now surfaces as one portfolio-level pattern instead of hiding as several unrelated entries.
- **Portfolio, program, and project now mean something specific.** The three levels have a defined structure and naming convention, including the program level that previously had no home between portfolio and project. *Why it matters:* you can say where a piece of work sits without inventing a convention for each project.

## Known limits

- The end-to-end path is proven against the two sample projects that ship with the composer. The measure this release set for itself — one real, active project publishing a summary that flows through to a composed view with its freshness honored — is met the first time a live project publishes one, not by this release landing.
- The portfolio file's existing handwritten content is replaced by the composed structure. This is a presentation change with no data migration behind it, so previously handwritten notes in that file are not carried across automatically.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE / HIGH confidence.** Every code change is additive — one new contract, one new composer, one new template, and additive sections in two skills — so a single revert of the release restores the previous behavior cleanly. The one effect a revert does not undo by itself is the portfolio file's regenerated structure, which is rewritten rather than migrated; restoring prior handwritten content there is a manual step. Standard rollback window.
