# System-Specialist template — one method, a specialist per system

2026-07-02 · v3.58

The platform can now produce a **principal-level specialist for any specific system** — a WMS, an ERP, a CRM, and so on — by instantiating one parameterized template instead of authoring each specialist from scratch. The reusable core is a *learn-a-system* method: ingest the system's supplied docs, build an internal model, then answer and act as that system's principal owner — grounded only in what those docs support.

**Who this affects:** operators onboarding a *specific* named system who want a specialist that answers from that system's own documentation. Nothing changes for anyone who isn't standing up a system specialist.

## What changed for everyone using the platform

- **A new System-Specialist template is available.** *Why it matters:* to get a specialist for a particular system you instantiate the template once — set the system name, point it at that system's doc corpus, register a distinct trigger — rather than hand-writing a new skill.
- **Instances answer only from the ingested corpus.** *Why it matters:* the specialist refuses or flags questions its documentation doesn't cover instead of inventing plausible-but-wrong system behavior.
- **A WMS pilot ships as a worked example.** *Why it matters:* it demonstrates the end-to-end path (docs → model → grounded answers) you'd follow for your own system.
- **The template itself never deploys as a live skill.** *Why it matters:* only the per-system instances you create become active — the template stays a blueprint.

## Known limits

- The WMS pilot's corpus is a small illustrative sample, not a production WMS's full documentation; production instances should extend the out-of-corpus eval set (tracked residual RR-2).
- This is the first template of its kind (a Phase-D frontier capability); the Business-Ad-Hoc specialist umbrella it generalizes toward stays tracked and out of scope here.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE / HIGH.** The release is additive — a new template, a pilot instance, and a one-line deploy allowlist entry — so reverting removes them cleanly. The one exception: this release also ratified ADR-019 (Specialists compose shared skills, not absorb them), which 13 existing specialist skills already depend on, so that ratification is intentionally not reverted.
