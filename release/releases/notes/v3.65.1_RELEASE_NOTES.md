# The pipeline no longer trusts comments from people outside your repo

2026-07-04 · v3.65.1

The release pipeline reads issue and PR comment threads as it works — that is where each stage posts its output and where the next stage picks it up. On a public repository, anyone can add a comment to those threads. This release makes the pipeline treat any comment from an account that is not the repository owner or a collaborator as untrusted: it is shown to you as third-party content but is never read as pipeline instructions, requirements, or evidence. It is a direct hardening against prompt-injection through the comment channel.

## What changed for everyone using the platform

- **Comments from outside the trusted set are never acted on by the pipeline.** Any comment whose author is not the repository owner, an organization member, or a collaborator is now surfaced to you as untrusted third-party content and excluded from every stage's reasoning — the check is on the account's relationship to the repo, never on how helpful the comment looks. *Why it matters:* a well-written suggestion from a stranger is exactly what a prompt-injection attempt looks like; the pipeline now refuses to treat any such comment as an instruction, so a passing comment can't steer a release.
- **Trusted feedback still flows exactly as before.** Comments from the owner and collaborators continue to be read and classified normally. *Why it matters:* the gate blocks strangers without getting in the way of the people who actually run the project — it is a filter, not a wall.
- **Finished release threads are locked when a release closes.** Completed stage sub-task threads (and the release's own work item) are locked at close, so no comment can be added to them after the fact. *Why it matters:* it shrinks the window in which an outside comment could land inside an active release thread at all.

## Known limits

- This release gates the *comment* channel. It deliberately does not yet gate untrusted content in issue *bodies* read by intake and triage — a higher-consequence surface tracked as a follow-up ([#3303](https://github.com/cody-hutson/pmo-platform/issues/3303)). Until that ships, an issue opened by an outside account is still triaged by a human, not auto-executed on its author's say-so.
- Two unrelated tooling defects found during this release are filed for separate fixes: an impact-analysis script that over-counts across worktree copies ([#3300](https://github.com/cody-hutson/pmo-platform/issues/3300)) and an event-log schema mismatch ([#3301](https://github.com/cody-hutson/pmo-platform/issues/3301)).

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE / HIGH.** The change is additive governance and reference text plus one new decision record, shipped as a single merged pull request, so the edits themselves are clean to unwind. It rates MODERATE rather than CHEAP because the release is tagged and published: rolling back means reverting the pull request, deleting the `v3.65.1` tag, and withdrawing the GitHub Release, after which the pipeline returns to treating all comments alike.

### Operator and engineering detail

One work item (#3261) closed the comment-trust-boundary hotfix (RELEASE_LOG `#109-comment-trust-boundary`, **Outcome: SUCCESS**). Release Class **hotfix** by operator override at the Stage-3 gate: the change touches five `pipeline/stage-*.md` files, which mechanically trips the cross-cutting trigger, but the override was held at the Stage-9 gate because the deeper review those files would normally demand had already been performed — an independent Phase-A6.5 adversarial design review plus blast-radius and N-way-consistency analysis.

**Author-association gate (canonical home: the Inter-Stage Feedback Protocol).** The trust rule lives once in `release-process.md` as an author gate that runs before the existing tier-by-change-nature classification; the comment-consuming stage shards (Solutioning, Dev Testing, QA, Plan Review) and the hub-spoke operational seam cite it rather than restating it. The trusted set is `OWNER` / `MEMBER` / `COLLABORATOR`; `CONTRIBUTOR` (a merged-PR author with no standing write access) is deliberately outside it, and `MEMBER` is included as a forward statement for a future org migration with an explicit note to re-examine the set at that point.

**Lock-at-close (Stage 13, Phase C5).** A new, non-blocking close-out step locks finished sub-task threads and the delivery card; the manual step was chosen over a CI workflow because a workflow file would be its own governed change and would worsen rollback.

**Corrected a false claim.** Four carriers asserted that in single-operator use "no review comments arrive" — false on a public repo. The wording now preserves what is true (no *assigned* reviewer) while dropping the false absolute.

The independent adversarial review returned SURVIVES-WITH-FINDINGS and all nine adopted findings were implemented, including a fix that scopes two acceptance-criteria checks so they do not false-fail against the release's own audit records. Dev Testing passed 11/11 and QA acceptance passed 11/11 with no overrides. For full implementation detail see the [RELEASE_LOG.md entry](https://github.com/cody-hutson/pmo-platform/blob/main/release/releases/RELEASE_LOG.md#deployment-log-v3651).
