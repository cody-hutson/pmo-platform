# The rules mirror is delivered, and what it lands is bounded

2026-09-05 · v4.54

The platform's rules directory now actually arrives in your workspace when you deploy, and the sessions that never loaded it are finally told to read it. What arrives is under a quarter of what it would have been, it has a published entry test and a size budget that is re-measured on every build, and its cross-tree links resolve from where the files land instead of pointing back into the repository.

## What changed for everyone using the platform

- **The rules directory is written for you.** Deploying now produces the workspace rules directory — nine files — instead of leaving it absent while a check reported nothing wrong. *Why it matters:* the rules your sessions are supposed to read are present in the workspace where sessions look for them, rather than existing only in the repository.

- **An empty rules directory no longer reads as a healthy one.** The sync check used to report the same clean result whether the directory was perfectly in step or had never been written at all. Those two states are now reported differently. *Why it matters:* "nothing to report" now means your copies match, not that there was nothing there to compare.

- **Operations-rooted sessions are told the rules exist.** The context anchor those sessions load now names the rules index directly, delivered through the same update that refreshes the workspace charter. *Why it matters:* the half of sessions that never loaded any rule file now have a path to it, which no wording change inside a rule file could ever have reached.

- **Links inside the delivered rules resolve from where they land.** Every cross-tree link in the delivered set was rewritten to the one form that resolves identically from the repository and from the deployed copy. *Why it matters:* following a link out of a delivered rule file lands on the document it names instead of dead-ending.

- **The delivered set has a published entry test and a size budget.** There are now written criteria for what belongs in the rules corpus and a measured ceiling of 204,800 bytes for the whole directory; the admitted set measures 149,168 bytes, leaving 27.2% headroom, and a check re-measures it at build time. *Why it matters:* the set that loads into every session can no longer grow without anyone noticing, and the budget is enforced by measurement rather than by memory.

- **The two lists naming the mirrored files can no longer drift apart.** Each place that declares the mirrored file set now registers itself where it stands, and a check compares every registered declaration against the others before a change can merge. *Why it matters:* a one-sided edit to the file list is caught by a check instead of by whoever happens to notice, which is how the last such edit was caught.

## Known limits

- The two new checks report findings but do not yet stop a release; they are logged and reviewed, and the decision to make them blocking is deliberately separate from shipping them.
- The rules directory and the instruction to read it travel on two different commands. Running only the deploy ships the files without the instruction, and nothing detects that combination automatically — see the operator detail below.
- The size budget covers the admitted rules set only. Other content a session loads at start is outside it and is not measured by this check.
- The entry test is applied when a file is proposed for the set. It does not re-adjudicate the nine files already admitted; those were measured once, against a named commit, and the record says which one.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH confidence.** Every source change is additive, and reverting the release merge restores the previous corpus in one operation. The one surface that does not revert with the files is the workspace directory already written to disk; it is restored by running the deploy again from the reverted source.

### Operator and engineering detail

**The registration contract is the shipped shape, and it is what makes a third holder cheap.** Each holder of the source-side mirror-pair path set wraps its own declaration in an in-band marker naming the holder, its separator, and the field position the source path occupies. The parity primitive discovers holders by scanning for the marker rather than by an identifier list, so adding a holder costs one marker pair and zero change to the check. The two live holders genuinely differ — one splits on a colon, the other on a literal tab — which is precisely why an identifier-keyed extractor was falsified by measurement and rejected. One entry of the shipped marker, from the deploy script's holder:

```bash
# mirror-pair-set: BEGIN holder=deploy-script sep=colon field=1
local -a _mps_rows=(
  "core/rules/git-workflow.md:$DEPLOY_ROOT/.claude/rules/git-workflow.md:engineering"
  "core/rules/analysis-mandate.md:$DEPLOY_ROOT/.claude/rules/analysis-mandate.md:conduct"
)
# mirror-pair-set: END
```

**Two carriers on two paths, and the second one is the missable step.** The deploy script states in its own usage banner that it does not refresh composition surfaces, and both surfaces that carry the instruction to read the mirror are registered composition-surface rows. The content therefore ships on `./deploy.sh --deploy` and the instruction ships on `./update.sh --surfaces-only`; a release that runs only the first delivers the content half with the reach half missing, and the resulting workspace looks correct to every check, because the sync check verifies the files and nothing verifies the instruction. There is no automated backstop for that combination today. This release ran both commands and read the delivered instruction back at its destination rather than trusting the exit code — the operations context anchor now names the rules index at the deploy root.

**How the corpus got from 650,591 bytes to 149,168.** Two populations were carried before: an eleven-member mirror pair set and a twelve-member directory-shaped fragment set that a loop copied wholesale. The confirmed scope retains nine members and required three acts, not two — removing both list entries while the directory loop still ran left 277,655 bytes, which is 136% of the ceiling. Retiring that loop is the third act and is what takes the payload from 3.18× the ceiling to 72.8% of it. The founding measurement is pinned to commit `060ec486` with a stated stability window rather than to a date, because the whole release landed on one day and a dated anchor could not distinguish two commits that measure differently — which is how the figure first went stale while still reading as correct. The pinned figures are a snapshot; the live authority is the budget check, which re-measures at build time.

**The link rewrite chose the one depth-invariant form.** Forty-nine relative-form links across the nine retained rule files were replaced with the leading-slash workspace-rooted form, which is the only form that resolves identically from the repository and from the deployed location. The canonical rule stating that requirement was authored in the link-maintenance protocol and mirrored into the rule corpus, so the delivered set carries the rule it obeys; a stale clause in the engineering-stage spec that contradicted it was repaired in the same change rather than annotated.

**Also shipped, and worth naming.** A plan-row binding gate now checks that each acceptance criterion in a release plan binds to a real row; it ships advisory, because no continuous-integration job currently grades a plan with it, and that is stated rather than implied. The undeclared-entry enumeration in the mirror-sync check reports what it finds without failing. Twelve remediation items raised during development testing landed across three waves before the release entered acceptance review.

**What did not land, and why it is recorded.** One acceptance criterion asserts a dependency edge that is not present on the issue it names; one criterion's expected value fails the plan executor's own numeric grammar and remains the single failing row; two version-adjacent tokens ship unresolved because the stamping tool has no way to tell a record from a citation; and the cycle-time instrument reports a deploy failure for this release that did not happen — its anchor set is a fixed pair of deploy targets that a rules-only release cannot be a member of, so the release is structurally unmeasurable by it rather than failed. Each is carried in the close-out record with its evidence.
