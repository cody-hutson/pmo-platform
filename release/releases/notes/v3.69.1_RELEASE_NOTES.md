# Security patch: hooks stop allowing actions through when a dependency is missing

2026-07-11 · v3.69.1

Two coordinated-disclosure advisories are fixed. The more serious one had disabled the tool-permission perimeter entirely on a documented install path, without any visible sign that it had.

## Who this affects

- **Everyone with the security hooks installed**, and in particular anyone who installed `jq` via Homebrew — the affected path is a documented install configuration, not an exotic one.
- **Anyone who has generated or opened an eval-review page** built from eval output.

## What you need to do

1. **Pull the latest clone and re-run the installer (`setup-workspace.sh`).** This release changes the hooks themselves *and* adds a helper file they depend on, and both have to land in your deployed hook directory together.
2. **Confirm the hooks are live** by triggering any blocked action you normally see refused. If it is still refused, the perimeter is working.

## What changed for everyone using the platform

### Security

- **The tool-permission hooks now refuse instead of allowing when they cannot run.** Every one of the twelve hooks depends on `jq` to read the request it is judging. When `jq` could not be found under the pinned search path, a hook exited as if it had approved the action — so the whole perimeter went quiet while still appearing installed. Each hook now resolves `jq` by absolute path through one shared helper, and refuses the action outright when it genuinely cannot evaluate it. *Why it matters:* a missing dependency used to silently turn your protection off; now it stops the action instead, so you find out rather than being unprotected without knowing.
- **A second silent bypass in the file-boundary hook is closed.** That hook also let `..` path traversal through when `python3` was unavailable — the same shape of failure, in the one hook whose whole job is keeping writes inside the workspace. *Why it matters:* the check that guards where files can be written no longer depends on an optional interpreter being present to do its job.
- **The eval-review page no longer executes content that came from eval output.** Text captured in an eval run reached the page's rendering points without being escaped, so crafted output could run as script when someone opened the page. Escaping now happens at each rendering point, with a second layer applied as the data is passed in and spreadsheet links sanitized on the way out. *Why it matters:* opening an eval-review page built from someone else's output is no longer a way for that output to run code in your browser.

### Fixed

- **The hardened hooks actually reach an installed workspace.** The shared helper the new hook behavior depends on was not being copied into the deployed hook directory, so the fix would have installed hooks that could not find the very thing that makes them safe. The installer now deploys the helper alongside the hooks. *Why it matters:* without this, the security fix above would have shipped and changed nothing on your machine.

## Known limits

- **The everyday update command did not refresh hooks at this release.** Picking these changes up required a full installer re-run; a later release (v3.69.1's successor line, v3.73.1) made the routine update command refresh the deployed hook bundle on its own.
- **A hook that cannot evaluate a request now blocks it.** That is the intended trade: in enforce mode a genuinely unresolvable dependency stops the action rather than waving it through. Warn and off modes still degrade rather than block.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH confidence.** Every change is a code fix plus tests plus one new helper file — no state is migrated and no data format changes. Reverting the merges restores the prior behavior, at the cost of reopening both advisories.

### Operator and engineering detail

**GHSA-9cjm-v22x-4x33 (High, CVSS 7.3) — hook fail-open on unresolvable dependency.** The PreToolUse hook class read its payload through `jq` resolved from the pinned PATH. When resolution failed the hooks exited 0, which the harness reads as approval, so the perimeter failed **open** regardless of the configured mode — including enforce. The fix introduces `core/hooks/lib/dep-resolve.sh` as a shared absolute-path resolver and applies a **mode-coupled** posture across the whole class: enforce fails closed with exit 2, warn and off degrade. Twelve hooks were changed — `block-autonomy-ceiling`, `block-credential-reads`, `block-destructive`, `block-egress`, `block-fragile-refs`, `block-fs-boundary`, `block-gh-path-leak`, `block-mcp-writes`, `block-rm-prefer-trash`, `block-shell-injection`, `block-skill-direct-edit`, and `audit-mcp-usage` — each with a new per-hook regression suite under `core/hooks/tests/`, plus a CI regression guard in the security workflow. The second fail-open closed in the same pass was `block-fs-boundary`'s `..` traversal path when `python3` was absent. `ADR-078` records the dependency-resolution posture as a durable decision rather than a per-hook fix.

**GHSA-rw36-5pf9-w2vc (Medium, CVSS 5.0) — stored XSS in the eval-viewer.** Attacker-influenced eval output reached `innerHTML` render sinks in `viewer.html` unescaped. The fix escapes **per sink** rather than at a single choke point, adds defense-in-depth escaping on the transport path in `generate_review.py`, and sanitizes xlsx hyperlinks. The `pmo-skill-refiner` package was rebuilt in the same merge, so the tagged package does not carry the vulnerable viewer.

**Delivery-path gap, and why it is the load-bearing third piece.** `lib/dep-resolve.sh` was not in the installer's hook co-deploy list, so a deployed workspace would have received hardened hooks that could not resolve their shared helper. The fix adds the co-deploy to the installer and to the CI layout setup. This class of gap — a security fix that ships but does not deploy — is what the sibling `v3.73.1` release later addressed structurally, by making the routine update path refresh the deployed hook bundle instead of leaving it to a full installer re-run.
