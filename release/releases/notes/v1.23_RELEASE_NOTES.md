# Change management gains a pluggable methodology toolkit; intake and sub-tasks get reference standards

2026-06-14 · v1.23

The change-management skill stops being ADKAR-only and becomes a toolkit of five change methodologies — ADKAR, Kotter's 8-Step, Lewin's 3-Stage, the Bridges Transition Model, and McKinsey 7-S — with a selection step that picks the right one (or the right combination) for a given change. Two more reference standards ship alongside it: an intake-governance standard for the intake desk and a cross-pipeline sub-task methodology reference.

## What changed for everyone using the platform

- **Change management now offers five methodologies, not one.** ADKAR was the only codified change framework; Kotter, Lewin, Bridges, and McKinsey 7-S each have a usable reference now too. *Why it matters:* the right model depends on the change — a top-down transformation, an individual-adoption push, a foundational unfreeze, a human transition, or an alignment check — and the skill can reach for the one that fits. ([#1011](https://github.com/cody-hutson/pmo-platform/issues/1011), [#1012](https://github.com/cody-hutson/pmo-platform/issues/1012), [#1013](https://github.com/cody-hutson/pmo-platform/issues/1013), [#1014](https://github.com/cody-hutson/pmo-platform/issues/1014))
- **The skill picks the methodology for you.** A new selection step chooses the applicable methodology (or combination) from the change's context — type, delivery approach, scope, and dominant risk — or honors your explicit choice. *Why it matters:* you get a fitting methodology without having to know all five. ([#1015](https://github.com/cody-hutson/pmo-platform/issues/1015))
- **One authoritative definition of the ADKAR scale.** The ADKAR 1-5 scale and barrier-point rule were defined twice, slightly differently; they are now consolidated into one source of truth the other change docs reference. *Why it matters:* no more conflicting versions of the same scoring guidance. ([#267](https://github.com/cody-hutson/pmo-platform/issues/267))
- **Intake demand has a governance standard.** A new intake-governance reference gives the intake desk business-case tiering, a WSJF prioritization formula, intake SLAs, a six-type demand taxonomy, and anti-pattern detection. *Why it matters:* incoming work is tiered, scored, and SLA'd consistently instead of triaged ad hoc. ([#268](https://github.com/cody-hutson/pmo-platform/issues/268))
- **Sub-tasks have a methodology reference.** A cross-pipeline sub-task methodology standard documents how sub-tasks are created, written, tracked, and measured across Engineering, Dev Testing, QA, and Close. *Why it matters:* a single canonical reference for how the pipeline uses sub-tasks. ([#224](https://github.com/cody-hutson/pmo-platform/issues/224))

## Known limits

- The methodology toolkit ships as reference docs plus a selection step; it does not change how any existing change-management mode produces its artifacts — it adds the methodology layer those modes can draw on.
- The sub-task methodology reference is a best-practices document; the underlying decomposition protocol it summarizes continues to live in the Stage 6 engineering spec.
- The four new methodology references and the selector ship as content; broadening or tuning the selection logic is a fast-follow as the toolkit is exercised.

### Operator and engineering detail

**The change-management methodology suite (#267, #1011–#1015)** — `change-management` evolves from ADKAR-centric to a pluggable methodology toolkit. `adkar-framework.md` is authored as the single source of truth for the ADKAR 1-5 scale + barrier-point rule, consolidating the two divergent definitions that previously lived in `references/impact-assessment.md` (§ADKAR Barrier Point Integration) and `references/readiness-checklist.md` (§ADKAR Readiness Scoring) — both now carry a one-line pointer to the SSOT and keep only their application-specific content (the impact-dimension interaction matrix; the readiness decision logic), so exactly one authoritative scale definition remains corpus-wide. ADKAR is the structural exemplar the four new methodology references mirror: `kotter-8-step.md` (org-process), `lewin-3-stage.md` (foundational meta-frame + force-field analysis), `bridges-transition.md` (psychological-transition layer), `mckinsey-7s.md` (static alignment-diagnostic via the 21-pair consistency assessment). The keystone `methodology-selection.md` selector encodes the selection judgment — five axes (unit-of-change primary + delivery-approach + org-scope + time-horizon + dominant-risk tie-breaker), a unit-of-change→methodology table and a delivery-approach→combination table that promotes the `impact-assessment.md` seed (its "Primary Framework" column reconciled to point at the selector, so one authoritative selection view remains), and a combination-logic engine — wired into `SKILL.md` via a new Step 2.5 (gated to Modes A/C/D; explicit user choice wins, else the selector runs). Each methodology is registered in `core/specs/framework-catalog.md` (canonical_doc populated; tier `evolving`/12mo for ADKAR/Kotter/Bridges, `stable`/36mo for the fixed Lewin/7-S classics; the selector deliberately gets no catalog row as a mechanism, not a framework; out-of-suite seed entries named-not-mapped). The whole cluster routed through one batched `change-management` version bump (v1.10 → v1.23) and is bundled in the `change-management.skill` package (rebuilt at Stage 12 for Check-7 freshness).

**Intake governance (#268)** — `operations/skills/intake-desk/references/intake-governance.md` gives intake-desk a portfolio-prioritization governance layer: deterministic business-case tiering (`[budget]` = Tier 2 by definition), a WSJF formula (`WSJF = CoD ÷ Job Size`), tier→SLA mapping (Tier 2 = 3 business days), a six-type MECE demand-source taxonomy, anti-pattern detection that reuses (does not fork) the existing `>95%` rubber-stamp threshold from `delivery-engine/references/gate-checklists.md`, and a mandatory worked acceptance trace. `intake-desk` SKILL.md gains the reference-files row and bumps to v1.23; `framework-catalog.md`'s Cost-of-Delay row gains a `canonical_doc` pointer to the new doc.

**Sub-task methodology (#224)** — `release/references/standards/sub-task-methodology.md` is the cross-pipeline best-practices reference (pipeline integration, creation rules, information requirements, writing/tracking discipline, `gh` sub-issue tooling, metrics) summarizing — not duplicating — the Stage 6 §A2 decomposition protocol, with a one-line cross-ref added to `release/governance/release-process.md`'s Stage 6 section.
