# Nine tools and checks that reported a wrong answer now report the right one

2026-09-18 · v4.65

Nine of the platform's tools and checks each returned a confident wrong answer in one specific situation — a single number repeated under five different health labels, a check that failed because of its own environment rather than your content, a documented rule that nothing actually enforced. Each now returns the answer it measured, or says plainly that it could not measure.

> **Skip the rest** unless you read a portfolio health roll-up, rely on a repository check to stop a bad change, or run the platform's deploy tools yourself.

## Who this affects

- Anyone who reads a portfolio or project health roll-up
- Anyone who relies on a repository check to stop a bad change from merging
- Anyone who runs the platform's deploy or corpus tools directly

## What changed for everyone using the platform

- **Portfolio health now shows five separate readings instead of one borrowed five times.** The per-project Health Indicators table listed five dimensions but printed the composed project rating in every row. Each dimension now resolves on its own and shows either its own value or `UNSOURCED` with the reason, and the composed project rating is stated once underneath, labelled as a roll-up across the dimensions rather than a value for any one of them. *Why it matters:* five labels showing one number reads as five findings that agree, when only one thing was ever measured.

- **A repository check that blamed your content for its own missing setting now refuses instead.** When one environment setting was absent, the check that validates issue references reported the content as bad rather than reporting that it could not check. It now stops and names the missing setting, and its message states the exact-match rule it actually applies. *Why it matters:* a check that reports a content problem it never looked for sends you to fix something that was never broken.

- **Three tools that walk the documentation corpus now share one rule for which folders to skip.** Each carried its own hand-written rule and they disagreed at the edges, so the same file could be inside one tool's view and outside another's. *Why it matters:* two reports about the same corpus could disagree about which files exist in it, and nothing said which one to believe.

- **A file sitting at the top of the corpus is no longer recorded as its own parent.** The tool that plans relationship edges gave every top-level file a parent, and for those files the parent it chose was the file itself. *Why it matters:* a file that contains itself is a loop, and anything following those relationships either spins or quietly drops the file.

- **A published wording rule that nothing enforced is now enforced.** One term on the release-notes banned-wording list was documented as banned but missing from the checker that claims to enforce that list. The checker now covers it, and its own self-check fails if the published list and the enforced set ever drift apart again. *Why it matters:* a rule nobody enforces is worse than no rule — authors follow it while the check quietly passes text that breaks it.

- **A tool that only worked when called by its full path now works either way.** The skill-editor session starter failed its own self-check when started through a short relative path, because it looked for itself after it had already changed directory. *Why it matters:* the same tool reported itself healthy or broken depending purely on how you typed its name.

## Known limits

- Every dimension in the Health Indicators table currently reads `UNSOURCED`, because no backing field is declared for any of them yet. The change is that the table now says so and says why, instead of showing a borrowed number in all five rows.
- The governed list of health dimensions and the code that renders them live in two places, and nothing yet checks that the two agree. While every backing value is empty a divergence stays cosmetic; the follow-up is deliberately sequenced ahead of the first real backing value, not after it.
- Three related observations were filed and deliberately not acted on: the project-rollup template family writes trailing `#` comments on lines the shared parser reads literally (87 values across 14 files), one skill names a health dimension differently from the governing contract, and one contract entry declares a type without the field a downstream query keys on.
- Revert-detection was measured for one of the nine fixes only. For that one, a revert that also removes the self-check added alongside it restores the original defect silently. Nothing equivalent was measured for five of the others, and this note says so rather than implying coverage that was not established.
- One identifier pattern is declared locally with a pointer comment instead of citing the shared grammar, because the shared grammar's own home has not shipped yet.
- The banned-wording checker's self-check does not see a list row written in the alternate table form, so such a row would be neither enforced nor reported as unenforced. This predates the release and is carried deliberately.

Report issues at the [pmo-platform issue tracker](https://github.com/cody-hutson/pmo-platform/issues).

## Reversibility

CHEAP / HIGH for six of the nine fixes — they share no files and each reverts cleanly on its own. MODERATE / HIGH for the remaining three, which are entangled across three shared files, so the smallest safe unit of reversal is the whole release merge rather than any single fix. No schema change, no data migration, no stored state to unwind.

### Operator and engineering detail

**Three of the nine were test harnesses reporting the wrong cause, not tools producing the wrong output.** One install-if-missing suite asserted preservation for one of its four mode files and nothing for the other three, so "your customizations survive an update" was untested for most of the population it claimed to cover; the loop now runs over the whole population. A form-family runner reported an empty predicate extraction as a sentinel-marker fault, sending a reader to the wrong cause entirely. A carve-out guard reported a defined function as missing when a pipeline into a short-circuiting reader lost the race — the same broken-pipe class the repository's own idiom gate scans for, which did not catch this one because that gate reads added lines and this was a pre-existing site. That is the gate behaving as designed, so no gate change was in scope.

**The shared frontmatter parser was frozen rather than fixed, and a decision record says why.** Measured over 737 tracked files carrying frontmatter and 6,664 top-level keys, 639 values contain a `#` and 543 carry it with no preceding whitespace, so the obvious comment-stripping fix corrupts 543 values, and a stricter rule still truncates several more. The parser therefore gains a docstring, a frozen-semantics block and self-test cases with no behaviour change; the constraint is applied at the one consumer that declares a shape, which validates the join key and raises rather than rendering a portfolio silently missing a project. Two clauses of that frozen block were themselves found false during adversarial design review — an internal-space guard that is unreachable, and a quote-stripping rule that re-strips after slicing — and were corrected before shipping, with matching self-test cases so the corrected wording is held by test rather than by prose.

The Health Indicators table's new shape, one row per dimension with its own source:

```
### <project-id> — Health Indicators

| Dimension | Status | Source |
|---|---|---|
| Schedule | UNSOURCED | Schedule Performance Index (SPI) — no §2 contract field carries it |
| Scope | UNSOURCED | Scope — no §2 contract field carries it |
| Quality | UNSOURCED | Risk + Integration Risk (composed) — no §2 contract field carries it |
| Stakeholders | UNSOURCED | Stakeholder Engagement (optional) — no §2 contract field carries it |
| Integration | UNSOURCED | Integration Risk — no §2 contract field carries it |

_Composed project RAG: <value> — it is a roll-up ACROSS these dimensions, not a value FOR any one of them._
```

**What this release found out about its own claims.** The recurring defect across verification was a statement of the form *cannot*, *never* or *always* carried without any check that would fail if it were false. It surfaced roughly ten times: a parser described as having eight importers that has six; a dependency edge that does not exist; a design constraint binding two components that implement different transforms; an acceptance row expecting an outcome its own ratified contract cannot produce; a fixed pass-count criterion whose suite legitimately grew; an inherited scope figure that was false at the commit it was measured at; and a release-wide claim that reverts announce themselves, which held for none of the cards it was measured against. Two remediation passes then "fixed" a false claim by rewording it, and acceptance review found both rewordings still false. The adopted rule is to make the claim executable, or bound it to exactly what a check samples, and to show a change on each side of that boundary — applied most visibly to one gate whose negative control differed from the real marker in every dimension at once and therefore discriminated none of them, where near-miss controls differing in exactly one dimension each turned three previously-green loosenings red.

**Carried deliberately, named rather than implied closed.** The dimension-list-to-code parity check, the identifier grammar's shared home, the template family's comment convention, the skill-versus-contract dimension name, and the alternate-table-form blind spot in the banned-wording self-check are each recorded as accepted residuals with a routed follow-up, not as oversights.
