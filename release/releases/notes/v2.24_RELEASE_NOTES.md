# Corpus conventions and standards hygiene

2026-06-26 · v2.24

Ten housekeeping changes to the platform's own reference and governance documents: two standards files move to the folder their naming says they belong in, four new reference docs fill known gaps, three places where a hand-typed count or format had drifted from reality are corrected, and an audit confirms the corpus does not bake in any one project-management methodology.

> **Skip the rest** unless you read or rely on the platform's own reference and governance documents (standards, conventions, audit recommendations). No skill behavior changes.

## What changed for everyone

- **The corpus is confirmed methodology-neutral.** An audit of the reference corpus checked whether any document silently assumes one way of running projects (Scrum, Kanban, Waterfall) and recorded the result in a findings register; the verdict is that the platform stays a "bare toolkit" you configure to your own methodology. *Why it matters:* you can trust that the platform's guidance does not quietly push one methodology onto your project.
- **Audit recommendations now carry a status at a glance.** Recommendation documents gain a per-item status badge so you can see what is open, done, or deferred without reading the surrounding prose. *Why it matters:* the state of a recommendation is visible at a glance instead of inferred.
- **Two reference gaps are filled.** A "process" best-practices reference (the missing third domain) and a catalog of Claude Code runtime-state surfaces (where backups, session storage, and environment-variable precedence live) are now part of the corpus. *Why it matters:* guidance that was previously missing or tribal knowledge is now documented where you can find it.

## Known limits

- These changes are confined to the platform's reference and governance documents; no skill output or command behavior changes.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `cluster: documentation` label.

## Reversibility

CHEAP / HIGH confidence. `git revert -m 1` of the integration PR reverses the whole release; every change is additive or a path/text correction, so reversion is clean. Standard 30-day outcome window per the release class.

### Operator and engineering detail

**Standards relocation (#77)** — `failure-mode-standard.md` and `process-flow-diagram-standards.md` move from `core/specs/` to `core/standards/` via history-preserving `git mv` (both are normative standards by naming and content, matching the `design-artifact-standard.md` precedent already at `standards/`). A workspace-wide inbound-reference sweep across 88 live files repoints every `specs/…` path-string to `standards/…`, preserving relative depth; three bare same-dir links the grep cannot see and one mover-internal link were hand-fixed, the second caught by the co-equal `check-doc-links.py` gate. Pure structural relocation — the two movers are the same files at new paths. This release's `.skill` package rebuild (41 packages) is a downstream consequence: ~40 `SKILL.md` files carried the swept path-strings, so their content-hash baselines went stale and were rebuilt at close.

**Methodology-assumption audit (#1094)** — a substrate-neutrality spike audited the corpus for embedded methodology assumptions and landed a findings register plus a "bare toolkit" verdict; the intermediate audit working-summary was discarded per the intermediate-artifact discipline (the register is the durable surface).

**Minimal-addition authoring discipline (#751)** — a codified discipline for keeping governance and reference additions minimal (add the least content that achieves the goal; prefer a cross-reference over a duplicate), cross-linked to the duplicate-source discipline.

**Reference-gap fills (#764, #163)** — `domain-best-practices/process.md` adds the missing third best-practices domain; a new reference catalogs Claude Code runtime-state surfaces (`~/.claude/backups/` snapshots, session storage, env-var precedence).

**Audit-recommendation status badges (#171)** — a per-recommendation status-badge convention for `recommendations.md`-class audit files, plus a Stage-13 maintenance hook so the badges are kept current at release close.

**Count and format drift fixes (#580, #663, #81)** — `skill-deployment.md` roster counts are de-hardcoded to derive from the live `deploy.sh` arrays (the static "12 vs 13" figure had drifted from the live count); the km-governance count narrative in `framework-catalog.md` is de-hardcoded to point at the catalog as source of truth; `triage-design-rereview.md §7` gains the missing `size:XS` row and a Trivial tier so its size enumeration is complete.

**Diagram inventory (#113)** — `process-flow-diagram-standards.md` gains an Adoption section recording the diagram inventory and exemption register (four diagrams, none embedded in any `SKILL.md`); de-sliced from a suspected hidden epic to a single documentation card after live verification.

**Version note** — the milestone and branch were named for `v2.23`; the release re-versioned to `v2.24` at the Stage 12 gate because a concurrent release (`functional-people-graph`) claimed `v2.23` first. The merge SHA is the audit anchor; `claim-version.sh` computed the next-free slot against the live published set.
