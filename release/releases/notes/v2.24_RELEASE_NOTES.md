# Corpus conventions and standards hygiene — two relocations, four new reference docs, and several drift fixes

2026-06-26 · v2.24

This is a housekeeping release for the platform's internal documentation. Two standards documents move into the standards folder where they belong, four new reference documents fill known gaps, a handful of stale counts and file paths are corrected, and an audit confirms the platform's documentation is a methodology-neutral toolkit. Nothing changes in how skills behave for you day to day.

## What changed for everyone

- **A clearer, more consistent reference library.** Two standards documents were moved into the standards folder (and every link to them updated), and four new reference documents were added — a "minimal-addition" authoring discipline, a third domain-best-practices area (process), an audit-recommendation status-badge convention, and a catalog of Claude Code runtime state surfaces. *Why it matters:* the documentation that governs how the platform is built and maintained is more complete and lives where you would expect to find it.
- **Several stale counts and paths corrected.** A few internal documents had drifted out of sync with the live system — a skill-deployment roster count, a set of catalog document paths, and a missing size value in a sizing list. *Why it matters:* the reference docs now match reality, so anyone reading them is not misled by an out-of-date number or a broken path.
- **The toolkit is confirmed methodology-neutral.** An audit checked whether the platform's core documentation bakes in any one project-management methodology's assumptions; it confirmed the substrate stays neutral. *Why it matters:* the platform remains a bare toolkit that adapts to your chosen way of working rather than presuming one.

## Known limits

- This release is documentation and governance only — there are no behavior changes to any skill, no schema changes, and nothing to deploy beyond refreshed skill packages.
- The methodology-neutrality audit (the substrate check) produced a findings register; authoring the methodology best-practice packs it clears the way for is a separate, later piece of work.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `cluster: documentation` label.

## Reversibility

CHEAP / HIGH confidence. `git revert -m 1` of the integration PR reverses the whole release byte-for-byte; the changes are additive documentation plus mechanical link updates, with no migrations, deploy state, or data involved. Standard 30-day outcome window per the release class.

### Operator and engineering detail

**Standards relocation hub (#77)** — `core/specs/failure-mode-standard.md` and `core/standards/process-flow-diagram-standards.md` were relocated into `core/standards/`, with a live-verified 90-file inbound reference sweep rewritten to the new paths and re-grepped to zero dangling `specs/` references. This was the release's blast-radius hub and ran first, because its sweep rewrites a reference inside `triage-design-rereview.md` (the file #81 edits) and relocates the diagram standard (the file #113 audits). The mechanical inbound-ref rewrites touched ~30 `SKILL.md` files, which (together with the release-cut version bump) is why the `.skill` packages were rebuilt at close.

**Four net-new corpus docs** — `core/disciplines/minimal-addition-discipline.md` (#751) codifies a minimal-addition authoring discipline for the governance and reference corpus, cross-linked from `duplicate-source-discipline.md`; `core/standards/domain-best-practices/process.md` (#764) adds the missing third domain-best-practices area; `core/standards/audit-recommendation-status-badges.md` (#171) defines a per-recommendation status-badge convention for audit recommendations files; and `core/references/reference/claude-code-runtime-state.md` (#163) catalogs Claude Code runtime state surfaces (backup snapshots, session storage, env-var precedence), registered in the Governance File Map.

**Drift fixes (#580, #663, #81)** — `core/rules/skill-deployment.md` (#580) reconciles the roster counts that had drifted from the live `deploy.sh` arrays (12 vs 13; the bootstrap example omitted `intake-desk`); `core/specs/framework-catalog.md` and `km-governance-framework.md` (#663) correct stale `canonical_doc` paths on the internal rows plus the km-governance count narrative; and `core/standards/triage-design-rereview.md` (#81) adds the missing `size:XS` entry to its §7 size enumeration.

**Substrate-neutrality audit (#1094)** — a `type:spike` audit of the corpus for embedded methodology assumptions, confirming the "bare toolkit" substrate (no methodology vocabulary hardcoded as universal beyond the `delivery_approach` resolver). The output is a findings register staged under `pmo-platform/analysis/`, not a corpus mutation; it is the precursor that clears K1 methodology best-practice pack authoring (#1090).

**Version note** — the release was planned and built as v2.23 (branch `release/v2.23-corpus-conventions-and-standards-hygiene`); at Stage 12 the v2.23 slot was claimed by the concurrent `v2.23-functional-people-graph` release (PR #2020), so the atomic claim took the next-free minor, **v2.24**, per the defer-to-merge allocation rule. Version identity only — no scope or design change.
