# Self-measurement for release close-out; a session sensor that ships switched off

2026-07-22 · v3.83

This release is almost entirely internal plumbing: it gives the platform better ways to measure how well its own releases close out, and it adds a new session-learning sensor that is installed but deliberately left switched off. Nothing about how you invoke a skill or read a status output changes here.

## What changed for everyone using the platform

No user-visible behavior changes — see operator detail below.

## Known limits

- **The session-learning sensor ships switched off.** The new `session-retro` skill is installed, but its automatic end-of-session capture cannot fire under any shipped setting. Turning it on is a separate, deliberate decision that has not been made, so for now the sensor records nothing on its own (tracked in #3705).
- **The event-log schema change covers one axis, not both.** This release extended the event log to describe decision sub-types; the second axis (the event payload) was deliberately left for a later release (tracked in #3704).
- **The new measurements start collecting from here forward.** The telemetry instruments added in this release begin recording at this release; they do not reach back and reconstruct history for releases that already shipped.
- Several follow-ups were filed for later releases rather than fixed here: a self-test enforcement gate (#3702), an intake scope gate (#3703), a fallback list check (#3712), and the way new decision records are numbered (#3713).

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

MODERATE / HIGH. The release landed as a single merge commit, so reverting that commit removes the telemetry standards, the new skill, and the schema change together; each of the fourteen slices is also an independent commit that can be reverted on its own. The one part that is not a plain revert is the published `v3.83` version tag, which is a public marker and is removed separately if a rollback is ever needed.

### Operator and engineering detail

**Close-out and phase telemetry (#2647, #2645, #2646)** — This release hardens the read-models that measure pipeline close-out quality. The close-class telemetry standard moves to v1.02: Indicator 6 (evidence preservation) now holds terminal Stage-12/13 sub-tasks out of its denominator, so the number measures whether phase evidence was preserved rather than measuring the clock at the moment it was read — on this milestone that corrected a reading of 0.75 to a true 1.00 with two terminal sub-tasks excluded. The front-cluster and middle-cluster phase-telemetry standards were reconciled to the tools that compute them, including a fix so that same-second events with fractional-second timestamps sort chronologically instead of lexicographically (a defect that could silently drop a real escape and publish a fabricated clean signal). Each of those fixes shipped with a discriminating test — the defect was re-introduced in a throwaway copy to confirm the test actually fails — which answers this release's recurring lesson that a test sharing the code's premise cannot falsify it. Issue #2646 records the per-indicator determination.

**Event-log schema (#3301, ADR-086)** — The pipeline event-log schema was extended along the decision-subtype axis, and ADR-086 (event-log schema, decision-subtype extension) was amended before ratification to state its real guarantee: whenever the schema file is readable — every in-repo and CI run — the validator's accepted set is the schema itself, so the two cannot drift; the static fallback list is recorded honestly as a best-effort degradation path with one known divergence, not as a strict mirror. The payload axis is deferred to #3704.

**Session-retro sensor and the Stop-hook class (#2423, ADR-087)** — The new `session-retro` skill reflects on a finished work session and emits session-grained learnings as signal-only rows in the pipeline event log; it is a sensor, never an actuator, and it never writes the operator memory store. It ships with its automatic firing mechanism — a `Stop`-hook that would re-enter the session at its boundary — present but inert, and it is provably unable to fire under any shipped setting. ADR-087 records that mechanism as a hook class with a ship-inert activation boundary: shipping the artifact and switching it on are separate decisions, and only the first was authorized here. Activation remains gated on #3705.

**The 30-day post-deploy review (#166)** — This was a Stage-12 measurement action rather than a build. The indicator review was re-run at close and its result recorded on the issue; the issue closes only if the measured value falls inside its acceptance band, and stays open otherwise.

**Version re-anchor (v3.80 to v3.83)** — While this release ran through planning and execution, three concurrent releases consumed the intervening version slots: close-out-reliability-hardening took v3.80, the version-identity-and-parser-SSOT release took v3.81, and governance-doc-reconciliation took v3.82. The provisional `v3.80` label was therefore re-anchored upward to `v3.83`, and no `v3.80` tag was ever cut by this release. A pre-merge relabel corrected the version on the branch — the `.version` marker, the plan file, the decision-record release line, and the new skill's version stamp and rebuilt package — before the merge, so the merge commit carries `v3.83`. The residual is immutable history recorded as accepted: the branch name and the fourteen on-branch commit subjects keep their as-authored `v3.80` labels, because rewriting them would require a force-push. The abandonment is recorded as one row in the re-version ledger.

**Verification and accepted residuals** — Stage 7 development testing all-PASS; Stage 8 acceptance shipped with four partially-met criteria, each with a tracked residual; Stage 9 GO was operator-authorized, with an Operator Override Record granted for the close-class acceptance criterion. The release shipped these residuals knowingly: the inert session-retro hook (#3705), the deferred event payload axis (#3704), a self-test enforcement gate (#3702), an intake scope gate (#3703), a fallback-list check (#3712), and the decision-record numbering approach (#3713).
