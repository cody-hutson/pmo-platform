# Security controls now judge what a command does, not how it is written

2026-08-16 · v4.31

Five security controls could be talked past by changing how a command was written rather than what it did — a quoted path, an environment-variable prefix, a command inside a loop. Each control now reaches the same decision however the command is spelled, and a control that cannot understand its input refuses rather than allows.

## What you need to do

1. Redeploy the hook bundle from your own terminal. Until you do, the controls described here are live in the repository but not in the copies your sessions actually run.
2. Verify the redeploy by comparing the deployed files' content hashes against the source, not by the command's exit status. A stale baseline can report success while deploying nothing.
3. Expect commands that used to pass to start being refused. Three of the five tightenings have no observation window and take effect the moment they are deployed.

## What changed for everyone using the platform

- **A command is judged by what it does, not by how it is typed.** The same script execution written bare, in single quotes, in double quotes, or behind a leading setting assignment now reaches one verdict instead of four. *Why it matters:* putting quotes around a blocked command, or a setting in front of it, no longer changes whether it is allowed.

- **Every command on a line is checked, not just the first.** The checks no longer stop at the first command they recognise. *Why it matters:* chaining a blocked command behind an allowed one no longer carries it past the check.

- **A control that cannot read its input now refuses instead of allowing.** When a shared helper file a control depends on is damaged in a way that still looks valid, the control used to stop inside its own safety test and let everything through; it now denies and names the cause. *Why it matters:* the worst case changed from a hole nobody can see into a stop everybody can — including you, which is why the step above matters.

- **A real home-folder path is reported even when the account name looks like a test name.** An exemption keyed on ten common account names used to clear genuine paths as though they were test data; it is gone, and only an explicit per-line marker exempts a line now. *Why it matters:* a path that would identify your machine can no longer escape the leak check by the accident of what your account is called.

- **The loop case for outbound calls is watched rather than blocked, for now.** When a batch of outbound write calls runs inside a loop, the check records the decision it would have made instead of acting on it, and stays that way until it is deliberately switched on. *Why it matters:* you can see what the stricter rule would have stopped before it starts stopping anything.

- **The release found and repaired a fault in its own fix, twice.** A change meant to stop one control from objecting to harmless text turned out to let real commands through. It was caught, repaired, caught again, and accepted only after a second, independent check built its own test set from scratch rather than re-running the first one. *Why it matters:* the controls you are being asked to trust were not signed off by the same work that wrote them.

## Known limits

- The guarantee that a control refuses when its input is unreadable covers three controls only — the ones that always enforce. Every other guarded control keeps exactly the exposure it had before this release. That boundary was chosen deliberately and recorded, not overlooked.
- One command matcher filters its operands in a way that lets a token ending in punctuation slip past the allowed list. This is older than this release and is unchanged by it; it is now tracked as its own item rather than left as an unnamed edge.
- The outbound-call change ships watched rather than enforced. Advancing it is an operator decision that has not been taken.
- One gap in the allowed-list for outbound calls was deliberately left out of this release. Correctly fixing the spelling problem made that gap easier to reach than it was before, so it is tracked separately and openly rather than quietly.
- The controls in this release govern the repository as merged. They do not govern your sessions until the hook bundle is redeployed.

Report issues at the repository issue tracker.

## Reversibility

MODERATE / HIGH. Reverting the single merge commit restores every control at once; nothing was migrated and no stored format changed. The asymmetry is the part worth knowing: the new dependency check runs before the escape hatch that would normally let an agent work around a misbehaving control, so if that check ever misfires it cannot be repaired from inside a session. Recovery in that case is a hook-bundle reinstall from your own terminal, which the controls do not gate. That single path was weighed against the alternative and kept on purpose.

### Operator and engineering detail

**One invariant, five defects.** The release is organised around a single claim: a control's verdict must not depend on how its input is spelled, and a control that cannot evaluate its input must deny. The four waves were the username-keyed path-leak exemption (deleted rather than tuned, because a username can never distinguish a fixture from a real path — the two are the same string), the dependency floor beneath every hook, the destructive-command matcher's quote-stripping and assignment-prefix arms built as one work unit, and the outbound-call matcher's loop-form and first-invocation-only gaps. `ADR-136` records the dependency-integrity primitive; `ADR-130` is its antecedent on guard mode-coupling.

**The dependency floor, and the boundary it deliberately stops at.** A syntactically-valid corrupt dependency library used to terminate a hook *inside the guard's own condition*, so the guard could not report its own failure and the hook exited allowing everything. The repair is scoped to the three always-enforce hooks. The remaining mode-capable cohort carries the same idiom with a syntax precheck that a valid-syntax early exit also defeats — recorded as an open class so a green result here is not misread as closing it. The guard is evaluated before the bypass check, which is what makes the failure mode operator-recoverable rather than agent-recoverable; moving the bypass check above the guard was considered and rejected in the governing ADR.

**Spelling invariance, concretely.** Each of the following previously diverged; all four now reach one verdict, with a must-flag case paired against a must-not-flag control for every spelling:

```
bash tools/deploy.sh                  # bare
bash "tools/deploy.sh"                # double-quoted
bash 'tools/deploy.sh'                # single-quoted
FOO=1 bash tools/deploy.sh            # leading assignment
echo ok; bash tools/deploy.sh         # second invocation, now adjudicated
```

**The fix that failed twice, and how it was finally accepted.** Stage 8 rejected the destructive-matcher repair on its false-positive criterion: 15 shapes converted a `main` BLOCK into a shipped ALLOW, each proven by direct execution. The first repair closed 12 of them and left the class open — the root cause sat one layer past the fix, because inside double quotes the shell evaluates command substitution regardless of the carrier verb, and ANSI-C quoting desynchronised the scanner's state machine, which modelled only inside-single and inside-double. The hub recommended dropping the suppression; the operator chose a third attempt, briefed to derive its test set from the predicate's **input space** rather than from the design's account of its own failure modes. That attempt found the class was 41 real executions rather than 15 and closed all of them: 0 of 41 allowed, 0 regressions across 117 graded assertions, suite 186→207 and harness 785→806, both exactly +21. Because the fixer had by then graded its own work, an operator-directed independent re-grade built a 97-case matrix **before** reading the fixer's enumeration and returned all three false-positive criteria met with an accept: the suppression fires on 19 of 97 cases (a live mechanism, not a silent drop), none of those 19 would really execute, and there were 0 reverse conversions.

**The Stage-9 conditional go, and why the obvious remedy was rejected on measurement.** Plan Review passed with a condition naming two coupled defects in the outbound-call hook: an unparseable classification was being handed the widening flag unconditionally, softening cases that deny today, while the published rule said a case that already denies is never softened; and quote-neutralisation ran before comment stripping, so at full enforcement an ordinary command carrying a trailing comment with an apostrophe was classified unparseable and denied. The obvious remedy for the first activates the second, so they had to close together. The spoke built the reviewer's candidate remedy as a standalone variant and measured it: it converted 23 commands the replaced matcher allowed into day-one denials, including the milestone-close call this very release needed at Stage 12. The shipped fix instead makes comment text quote-**inert** rather than stripping it — 0 softened old denials, 0 new day-one denials, with the hook's test file growing 110→140 cases. Both findings were wider than the review had measured: 15 softenings against 3, and 25 false-positive-class members against 2.

**Two methodology findings the release paid for.** First, template reuse defeats construct breadth: all nine of the third fix's command-substitution controls instantiated one template carrying two features incidental to the threat, and a 2×2 factorial showed only the both-features cell blocked — so the control set was far narrower than its count suggested. Second, reference-currency validates that cited paths *exist* but never that cited populations are *consumed*, which is why an entire contention model survived re-review with every path resolving and the dependency it asserted being false. Both are filed rather than absorbed into this release's prose.
