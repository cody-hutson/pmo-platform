# Two new skill-measurement auditors, plus a suite-wide skill-hygiene pass

2026-07-01 · v3.41

This release adds two new measurement skills — one that reports how much of the context window the loaded platform components consume, and one that measures how reliably skills trigger when they should. Alongside them, the whole skill catalog gets a structural-hygiene pass so every skill follows the same section and heading conventions. Nothing changes in the day-to-day workflow; the measurement skills are opt-in, and the hygiene work is a consistency cleanup.

## What changed for everyone using the platform

- **Context-budget auditor.** A new skill measures how many tokens the loaded platform components (skills, rules, schemas) consume across the context window. *Why it matters:* you can now see which components are the heaviest and make an informed call before the platform runs low on working room.
- **Skill-compliance auditor.** A new skill measures how accurately skills trigger — how often the right skill fires for a given request, and how often the wrong one does. *Why it matters:* trigger accuracy becomes a number you can track and improve, instead of a hunch about whether skills "usually" fire correctly.
- **Consistent skill structure across the catalog.** Every skill now uses the same conventions for its safety-rules section and its mode headings. *Why it matters:* skills read and behave more predictably, and the platform can check the whole catalog for conformance in one pass instead of skill-by-skill. <!-- impact:foundational -->

## Known limits

- The two new auditors are measurement tools you invoke deliberately — they report numbers, they do not change any skill's behavior on their own.
- The skill-compliance auditor's routing-conflict detection ships as a specification this release; the code that implements the deeper cross-skill analysis is a tracked follow-up, so this release measures trigger accuracy but does not yet run the full semantic conflict scan.
- The hygiene pass is a structural-consistency cleanup to the skill definitions — it changes how the files are organized, not what any skill does for you.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

**CHEAP / HIGH confidence.** Everything in this release — the two new skills, the ADR, and the catalog-wide structural edits — reverts by reverting the release PR; no data, schema state, or migration is involved.

### Operator and engineering detail

**Skill-suite structural hygiene (Wave A).** The catalog-hygiene sweep ratified and applied a mode-heading separator standard, restored Guardrails conformance across the catalog, and consolidated vestigial sections. The canonical mode-heading form is now `<H2-or-H3> Mode <ID> — <Name>` with a single em-dash flanked by spaces (` — `, U+2014) as the separator between the mode identifier and the mode name — for example, a heading previously written `### Mode A: Backlog scan` conforms as `### Mode A — Backlog scan`. #1135 decided and documented this in `canonical-skill-structure.md §4` (survey-grounded: the em-dash majority idiom was ratified over the colon-form minority); #1136 applied it across the colon-form multi-mode SKILL.md set. #1133 brought the SKILL.md catalog to full `## Guardrails (Platform)` conformance (12 inserts of the missing section + 26 renames of bare `## Guardrails`, preserving pmo-qa-auditor's `## Guardrails (Extended)` variant) and fixed a folded `failure-mode-standard.md` drift. #1132 consolidated vestigial Mode-Detection sections in project-initiator and eval-writer. Two contract reconciliations rode along: #571 cross-referenced delivery-engine's DoR/DoD gate vocabulary to G1/G3 + DT-2, and #676 reconciled the stale canary entry in `per-skill-output-contracts.md §Skill 12`.

**Measurement instrumentation (Wave B).** #16 added the `context-budget-auditor` skill (`core/skills/context-budget-auditor/` — SKILL.md + `measure-context-budget.sh`), which quantifies token consumption across loaded platform components. #17 added the `skill-compliance-auditor` skill (`core/skills/skill-compliance-auditor/` — SKILL.md + `scenario-and-calibration-schema.md` + `measure-skill-compliance.sh`), which quantifies trigger-rate accuracy across the skill catalog, together with ADR-061 defining the trigger-rate metric class and the boundary between the compliance auditor and eval-writer. Both skills registered in `registry.md` / `deploy.sh` / `OPERATIONS.md`.

**#704 shipped spec-only.** #704 (routing-conflict detection beyond Jaccard — cross-skill invocation-path analysis) shipped as a specification only this release: the mechanism, the sibling-harness decision, and the O(n²) cost design are specified, but zero code was mutated. The deferred implementation is tracked as follow-up #2699.
