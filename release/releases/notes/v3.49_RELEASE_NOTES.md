# Governed file movement: routing now spans all four directions

2026-07-02 · v3.49

The file router used to govern only files arriving from outside; it now governs every direction a file can move — inbound, staging, promotion, and cross-project — so the same routing rules apply wherever a file goes. Intake gets two matching refinements: it checks for an existing owner before proposing a new container, and it can log low-touch items for you without prompting when you've enabled it.

## Who this affects

Anyone who files work items or lets the platform route files. The auto-logging behaviour only activates if you've raised your `automation_level` above its default — everyone else sees the same intake flow as before, plus the new duplicate-container check.

## What changed for everyone using the platform

- **File routing now covers all four movement directions.** The router handles inbound files, staging, promotion, and cross-project moves under one rule set, instead of only classifying inbound arrivals. *Why it matters:* when you ask the platform to move or promote a file, it knows where the file belongs and which approval applies, rather than leaving promotion and cross-project moves unmanaged.
- **Intake checks for an existing owner before creating a container.** When you file something large enough to become a container (an initiative or epic), intake first scans the tracker for an existing owner and stops to confirm rather than silently creating a duplicate. *Why it matters:* you stop accumulating two half-owned epics for the same body of work.
- **Low-touch items can log themselves without prompting.** A new non-interactive intake mode detects and files routine items on its own, bounded by your `automation_level` setting, and never touches governance, financial, security, or RAID-closure items. *Why it matters:* routine capture happens without a round-trip, while the decisions that should stay human stay human.

## Known limits

- This release extends two existing skills (file router, intake) — it adds no new skill and changes no stored data.
- The auto-logging mode has no enforcement hook behind it yet; it is governed by your `automation_level` ceiling and self-downgrades to an observation if it cannot cleanly file an item. It stays off unless you raise that ceiling.
- The router owns one genuinely new approval gate — cross-project moves out; the other directions reuse the existing promotion approval rather than adding a parallel one.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

### Operator and engineering detail

`routine`-class release on milestone `08-INTAKE-governed-file-movement` (#211) — three EXTEND-mode changes to existing operations-module skills on one branch / one PR (#2861, `--merge` at `ee649ad`), build order #240 → #565 → #289 under D-C SINGLE topology and P0 fully-serial posture (the #565→#289 order serialized the two edits contending on `intake-desk/SKILL.md`).

- **File-router governs all four movement directions (#240).** Extended `file-router` from inbound-only to the full inbound / generated-staging / promotion / cross-project set. It resolves the promotion target and cites artifact-generator's existing PROMOTE/REVISE/REJECT gate rather than restating it; it owns a genuinely new approval gate only for cross-project-out. Two gate-types: a confidence-threshold gate for the inbound family (inbound + cross-project, both Layer-2 scored) and a flat-approval gate for the Domain-C family (generated-staging + promotion, target pre-stamped).
- **Container-altitude existing-owner scan (#565).** Added an `intake-desk` Phase-2 hard-gate that, for container-altitude items only, scans the tracker for an existing owner before proposing a new container, and reconciled failure mode #7 in place (stays at 9 FMs, no redundant tenth).
- **Mode C — Ambient Auto-Log (#289).** Added a non-interactive intake mode (detect→create) governed by the `automation_level` ceiling, with an honest no-hook-backstop safety framing and the per-item→standing weakening stated rather than softened; the Tier-0 set (governance / financial / security / RAID-close) is never auto-created regardless of level. The `core/CLAUDE.md.template` auto-logging rule was rewired to invoke Mode C (9→12 FMs). The `intake-desk` and `file-router` `.skill` packages were rebuilt at close-out.
