# Two security fixes are now locked in by automated regression checks

2026-07-12 · v3.74

The security fixes from the last few releases are now backed by automated checks that fail the build if either weakness reappears. The platform's engineering charter also now treats Security as a first-class value, so a missing security safeguard shows up as a visible gap instead of going unnoticed.

## What changed for everyone using the platform

- **Two past security fixes can no longer quietly come back.** The two build-security issues fixed in recent releases — a safety hook that could switch itself off, and a cross-site-scripting hole in the local eval-review tool — now each have automated checks that fail the build if the weakness reappears. *Why it matters:* a fix that isn't tested tends to erode over time; these two are now held in place by the pipeline, not by anyone's memory.
- **The safety hooks are now proven to fail closed when they can't run their check.** A new automated test walks every safety hook that depends on an outside tool and confirms that, in enforce mode, a hook whose tool is missing blocks the action instead of quietly allowing it — and one hook that still allowed the action in that case was fixed to block. *Why it matters:* a safety check that turns itself off when a tool is missing is worse than no check, because you think you're protected.
- **The eval-review tool's cross-site-scripting hole is now guarded two ways.** The tool that renders eval outputs gained both a code-scanning rule and a browser-level regression test that flag the exact injection pattern the earlier fix closed, plus extra hardening on the few remaining spots where untrusted text reached the page. *Why it matters:* if a future edit reintroduces the unsafe pattern, the pipeline catches it before it ships, instead of a security researcher catching it afterward.
- **Security is now one of the platform's first-class engineering values.** The build-philosophy charter that names what the platform optimizes for — alongside things like maintainability and stability — now lists Security too, with a coverage map showing which parts of the toolkit actually enforce it. *Why it matters:* a surface with no security safeguard now shows up as a named gap to close, rather than being invisible to the charter's own gap-finder.

## Known limits

- **The gates lock the known patterns, not every possible variant.** These checks catch the specific weaknesses the two advisories used — a hook that fails open on a missing tool, and the eval-viewer's injection sinks. A genuinely new variant of the same class is not automatically covered; the gates raise the floor, they do not replace review.
- **One new deploy-time check starts logged but not blocking.** The deploy-path completeness check for these classes reports findings first and is flipped to blocking after a short shakedown with no false positives, following the platform's standard rollout for new checks.
- **The one deployed behavior change rides along with a normal update.** Only the safety-hook fix actually changes a file on your machine; it reaches your workspace the next time you run your usual update, with no special step required.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH confidence.** Almost everything in this release is additive — new tests, a code-scanning rule, a new CI workflow, and governance-document updates — except one scope-locked hook fix that makes an always-on safety hook fail closed (block) in enforce mode when it cannot evaluate. A single revert of the release restores the prior behavior (which is the less-safe one, so reverting is a rollback of the fix). The one governance change — adding Security as a charter value — is MODERATE rather than CHEAP only because other documents now reference it; the revert itself is a clean document edit. Standard rollback window.

### Operator and engineering detail

**Prevention layer for two advisory classes.** This release is the durable regression-prevention layer that the v3.73 security patch explicitly deferred ("handled separately"). It ships as three slices on one PR (#3428). **#3407** adds a glob-derived fail-closed meta-test that enumerates every `block-*.sh` hook and asserts each jq-dependent hook fails closed (`exit 2`) at all three dependency-resolver paths, and fixes `block-autonomy-ceiling`'s enforce-mode fail-open by reordering its dependency gate to be mode-aware (enforce → block; warn/off → degrade) — closing the residual ADR-078 flagged. **#3409** adds a three-rule custom `template-context-XSS` semgrep ruleset (R1 transport-taint, R2 raw-HTML DOM sink, R3 script-context placeholder) that keys on the *missing* context-aware encoder — so the fixed generator passes without annotation — plus a reviewed nosemgrep baseline, the S1 output-encoding standard, and hardening of three residual eval-viewer sinks. **#3408** adds transport-level and jsdom rendered-DOM XSS regression tests, a net-new `eval-viewer-tests.yml` CI workflow, and ADR-082 (jsdom as the first node_modules dependency, canonicalized).

**Security as the sixth first-class value (S2 / ADR-081).** `build-philosophy.md` previously enumerated five first-class values with no Security row — and because its gap-finder only fires for cells that exist, a missing security enforcer could never surface as an empty cell. This release elevates Security to the sixth value with a full coverage-matrix row, landed with honest GAP markings (Hooks populated by the real enforcers; Agents and Hub/Spokes GAP; the Skills output-encoding cell populated by S1's semgrep enforcer). The value ships paired with its first proven enforcer — the fail-closed meta-test — rather than as a naming-only row, which is the exact "shelf standard with no gate" failure the retro indicts. ADR-081 records the charter amendment; the workspace-root `CLAUDE.md` "five values" bullet lives outside this repo and is flagged for out-of-band update, not silently dropped.

**Dropped slice and mid-pipeline re-version.** The original fourth slice, #3410 (deploy-path sourced-lib completeness + the `positional-issueref.awk` co-deploy fix), was dropped — it was subsumed by the concurrent v3.73 GHSA-g9g6 fix and its v3.73.1 delivery-path follow-up, which co-deployed that helper and single-sourced the install list. During the build, that concurrent v3.73 hotfix also claimed the provisional `v3.73` version, so this release was merged onto the new mainline (both security sides preserved as additions-only on the shared `viewer.html` and `security.yml`) and re-versioned from v3.73 to v3.74; an atomic re-check confirmed v3.74 was next-free with no collision. The integration used a merge commit (not squash), deliberately, to preserve that reconcile history, and required an admin override past branch protection with CI green (32/32).
