# Decision records follow one standard, and the index can no longer go stale

2026-08-05 · v4.11

The three documents that govern how the platform's architecture decision records are written disagreed with each other, so "write it to the standard" named three different targets. This release settles them on one, brings all 118 existing records to it, and replaces the hand-typed list of those records with one generated from the records themselves.

> **Skip the rest** unless you read or write the platform's architecture decision records.

## Who this affects

- Anyone who writes a decision record, or adds one to the release module
- Anyone who reads the decision records to find out why the platform works the way it does
- Anyone whose work has stalled because another change already claimed the record number they wanted

## What you need to do

1. **Adding a record to the release module now means running a command rather than typing a row.** Add the record file as before, then run the index generator so the listing picks it up. A hand-typed row is now rejected by a check instead of quietly drifting — that is intended, and the listing says so in its own text.

Nothing else changes. No existing record needs editing, no setting changes, and nothing you have already written needs migrating.

## What changed for everyone using the platform

- **One requirement set instead of three that disagreed.** The three documents that define how a decision record is written now state a single requirement set, with the schema as the one place it is defined and the others citing it. *Why it matters:* "write it to the standard" now names one target, so a record can be finished rather than argued about.
- **Every record on the platform now conforms.** All 118 records were brought to that requirement set: 118 durability findings were drained to zero, 21 records gained a missing "Alternatives Considered" section written from evidence already in the record, and 25 identity-field references were relocated. *Why it matters:* you can open any decision record and find the same sections in the same order, so reading one teaches you how to read the rest.
- **The release listing of decision records is generated, not typed.** It used to be four hand-kept enumerations of one set of files, ending at four different numbers, with 8 of its 16 rows showing a status the record they linked to contradicted. It is now projected from the records, with every column derived. *Why it matters:* the listing can no longer disagree with the records it lists, and a stale row now fails a check rather than sitting there for months.
- **Two changes can add a decision record at the same time.** Record numbers are now assigned when a change merges rather than when it is written, and a tool reconciles a collision without losing anything — renaming the record, rewriting its references, updating the listing, and writing down the move. *Why it matters:* your work no longer waits on somebody else's number, which is not theoretical — this happened three times while this very release was in flight.
- **New records start out conformant.** The scaffolding tool now derives the required section list from the standard instead of carrying its own frozen copy, and checks its own output before handing it back. *Why it matters:* a new record can no longer start life missing a section that the standard has since added.
- **A measurement that had been reporting only its accurate half now reports both.** The check that finds numbers baked into record prose was quietly missing any count preceded by a word ending in "g" or "v". *Why it matters:* the check had been described as covering more than it did, and anyone relying on its clean result was relying on a narrower answer than they thought.

## Known limits

- **34 records still miss at least one section of the required set, deliberately.** Filling them would mean inventing decision content the record does not hold, which the authoring rules forbid outright. The gap is disclosed rather than papered over, and is tracked as [#4758](https://github.com/cody-hutson/pmo-platform/issues/4758).
- **A record merged from another branch can still arrive non-conformant, and nothing will say so.** The listing can no longer drift; the records themselves still can. This is not hypothetical: 19 other merges and 10 new records landed while this release was in flight.
- **The check that would enforce the new structural rule is logged but not blocking in this release, on purpose.** Turning it on while the corpus sweep could still be undone would leave a blocking check standing over records that a rollback had just returned to non-conforming. That switch belongs in a small follow-up once this release has settled.
- **The rule requiring a written reason on the issue-reference escape hatch ships with none of its occurrences meeting it** — 0 of 60 in decision records, 0 of 185 across the repository — and the example the rule cites fails the rule it illustrates. Tracked as [#4763](https://github.com/cody-hutson/pmo-platform/issues/4763).
- **One assistant is reported as having no recognisable mode list** because the check that looks for one matches the word "Modes:" anywhere in a file. Accepted for this release and tracked as [#4734](https://github.com/cody-hutson/pmo-platform/issues/4734).
- Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `adr` label.

## Reversibility

MODERATE / HIGH confidence. One branch, one integration commit with two parents, so reverting it restores every file's bytes in a single step. The constraint is what a revert *leaves behind*: it restores a corpus that no longer conforms to a standard that would still be published, so the follow-up switch that makes the structural rule blocking must stay off until this release has settled. Standard 7-day window.

### Operator and engineering detail

**The through-line is one defect wearing seven costumes.** Every card in this release is an instance or a prevention of the same failure: a rule stated in more than one place, where the copies drifted apart and nothing reconciled them. The requirement level for the alternatives section was stated on five surfaces at four mutually incompatible levels. The immutability rule said the body of an accepted record is frozen while the shipped durability lint's entire remediation path assumed otherwise. The release listing and the record set disagreed four different ways at once. The fix in each case is the same shape — one authority, everything else cites it — and the release ships the checks that hold it there.

**The section set is the shape contract that changed.** The schema's §3 is now the single defining surface for the body sections, and the alternatives section moved from "optional, recommended" to required-with-conditional-content — present always, with a declared single-forced-approach reading where no options were weighed:

```
## Status                   required   restates the frontmatter status
## Context                  required
## Decision                 required
## Alternatives Considered  required   content conditional: where a single forced
                                       approach existed, the section declares that
                                       explicitly; an ABSENT section is the defect
## Consequences             required
## Reversibility            required   CHEAP | MODERATE | EXPENSIVE | IRREVERSIBLE
## Related ADRs             required
```

The conditionality attaches to the section's content, never to its presence, which is what makes the omission test structural and mechanically checkable while leaving the judgment about what the section says with the author. "Only one option existed" stops being an unstated opt-out and becomes a reviewable claim on the record.

**The listing's format changed in the same way and for the same reason.** The release module's index now carries a declaration naming its source file set, its generator, and the columns it derives — all five of them — followed by a delimited region that the generator owns end to end. Nothing in that region is authored; a hand-typed row fails re-derivation. The mechanism is not new: the repository already carried a governed derived-surface contract with two working instances before this decision, and this registers as a third rather than inventing a fourth pattern.

**Deriving the cells, not merely the rows, is the decision that mattered.** The originating observation reported the gap as two missing rows, because two were the only ones a prose line happened to name as pending. Re-derived against the file set it was fourteen. Adding the missing rows would have left three other hand-kept enumerations in place and re-created the defect on the next merge — and it would not have touched the stale-status half at all, which is a per-cell drift rather than a coverage gap. The flip of this release's own four records to accepted was the first live exercise: two index cells drifted the moment the records changed, the generator reported both by name, and re-derivation returned to zero.

**Record numbers now bind at merge, and the mechanism was exercised three times in production during this release.** The old rule allocated a number when a record was written, which meant every long-lived branch was exposed to every sibling that merged ahead of it, and pre-reserving a higher number was no remedy because the checker fails a gap as readily as a duplicate. The new rule binds against the mainline only — an unmerged claim on another branch is a detection signal, never a binding one — and a tool performs the reconciliation in six steps, including the numbering-provenance note that the hand-performed recovery reliably skipped. This release's own records moved twice under it, and a third collision resolved during Stage 12.

**The residual is named rather than implied.** The corpus is not fully conformant to the section set after this release, and the record that governs the claim says so: 34 records still carry a gap in the required set, and one superseded record can never conform because the immutability policy forbids the two edits it would need. Sections whose backfill would be authoring a decision rather than recording one stay out of scope with their blocking authority named. The completeness claim is therefore scoped to a stated baseline rather than asserted as a universal, and its residual is one sentence rather than a hedge: the index cannot drift, the corpus can.

**Five defects in this release were one defect, and it is worth stating plainly because it will recur.** A predicate that matched *form* instead of *fact*: a skip-pattern that matched single-line comments but not multi-line ones; a reference prefix matched without a word boundary, so any count preceded by a word ending in "g" or "v" was silently suppressed; a mode check matching a keyword anywhere on a line; a test suite asserting that text was present rather than that code had executed; and a provenance pattern matching any "number to number" shape rather than the specific move, so a second renumber hop wrote nothing and the verification step asked the same shape question and passed over the gap. Each was written by a competent author, each passed its own tests, and each was one token from correct. The testing-side twin is the same shape from the other direction: roughly sixteen probes failed for mechanical reasons during this release and every one of them read as good news — a line-anchored differ over timestamped logs printing a clean delta across a run that contained a real regression, a file extraction that produced a zero-byte "control", and a single-variable control run against a subject that was exempt for several reasons at once. A zero whose control also returns zero is not a finding.

**Ratification was rendered at close, not at review, and that is itself a finding.** All four records this release authored carried frontmatter promising they would flip to accepted at the release's plan-review gate. No pipeline stage performs that flip. The operator rendered the ratification explicitly at the close gate instead; the promise was corrected on all three surfaces it appeared on inside each file, so the records do not join the sixteen already on the mainline whose two statements of their own status disagree. The gap is filed rather than quietly patched.
