# The branch-cleanup tool now actually cleans up squash-merged branches

2026-07-01 · v3.42

The tool that clears out stale release and chore branches (`cleanup-orphan-state.sh`) was quietly finding nothing to remove on this repository, because the repository squash-merges its pull requests and the tool could not reach the GitHub CLI it needed to recognise a squash-merged branch. This release fixes that root cause and the cluster of reliability bugs behind it: after a release, the cleanup now reaps the release branch and its `chore/*` helper branches on its own, reports each branch exactly once, and deletes an already-merged branch without needing a force flag — with no hand-rolled `git branch -D` workarounds.

## What changed for everyone using the platform

- If you run the periodic branch-cleanup or the end-of-release cleanup, it now works as intended on this repository: squash-merged release and chore branches are actually detected and removed, where before the run came back empty. *Why it matters:* stale branches no longer pile up silently, and you no longer have to delete them by hand. <!-- impact:targeted -->
- The cleanup report no longer shows the same local branch twice, and it can remove a merged branch even when your working copy is a little behind the latest `main` — without asking for a force flag. *Why it matters:* the report you review before approving deletions is accurate, and the safe (non-force) path now covers the normal case.
- This is a change to an operator-run maintenance script. If you never run branch cleanup yourself, nothing in your day-to-day use of the platform changes. *Why it matters:* the scope is deliberately narrow — no workflow, command, or behaviour changes for anyone who is not running the cleanup tool. <!-- impact:targeted -->

## Known limits

- The fix targets this repository's setup, where pull requests are squash-merged and the script runs under a locked-down `PATH`. It resolves the GitHub CLI by absolute path (the same way it already resolved `lsof`); if the CLI is genuinely not installed, the squash-merge detection still cannot run and the affected branches are reported as skipped rather than removed.
- Force deletions (`-D` / `--force`) remain opt-in and are never performed automatically — the default cleanup path only removes branches that are safely merged.
- One card in the cluster (#669) was trimmed to a residual `--help`/self-test fix; its original primary defect was already resolved by earlier work (#1678).

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE / HIGH confidence.** The change is limited to one operator-run script (`release/tools/cleanup-orphan-state.sh`, plus a one-line reference in `core/rules/git-workflow.md`). Rolling back is reverting the release PR; the only lasting effect of running the improved tool is branch deletions, which are themselves recreatable from their merge commits if ever needed.

### Operator and engineering detail

See the `#85-cleanup-orphan-tooling-reliability` RELEASE_LOG row for the raw audit trail. All seven cards touch the single file `release/tools/cleanup-orphan-state.sh` (plus `core/rules/git-workflow.md § Step 10` for #684) and shipped on one branch / one squash-merged PR (#2789). `routine` release class — cleanup-debt drainage against one existing tool.

- **`gh` unreachable under the pinned `PATH` (#2790) — the keystone.** The script pins `PATH=/usr/bin:/bin` and had no absolute-path resolver for `gh` (unlike `lsof`, which already had `resolve_lsof_bin`). On the canonical host that made every `gh`-dependent path inert — including #2216's squash-merge (MERGED-branch) rescue and #655's PR-state prefetch — so the whole squash-merge-reaping capability silently did nothing. Fixed by adding `resolve_gh_bin()` mirroring `resolve_lsof_bin`. This card was surfaced at Stage-8 QA as the Success-Indicator blocker and folded into the release at the Stage-9 gate so the milestone actually delivers reaping.
- **`--release-close` skips squash-merged branches (#2216).** The ancestry SKIP in `classify_local` fired before the PR-state rescue, and `--release-close` ran with `require_pr` set such that a squash-merged branch (no ancestry to `main`) was classified as not-removable. The ordering is corrected and `--release-close` runs with `require_pr=0`, so a branch whose PR is MERGED is reaped even though squash left no direct ancestry.
- **`--release-close` scope missed `chore/vX.Y-stage-*` branches (#684).** The scope matched the four slug-anchored release-branch patterns but not the per-stage chore branches a release creates. The patterns are extended additively to cover `chore/vX.Y-stage-*`. This card resolved the cross-milestone duplicate with #2048 item 3 (the cleanup-tool fix lives here) and carries the release's only Stage-10 Docs touch, a one-line update to `core/rules/git-workflow.md § Step 10`.
- **`--apply` could not delete a merged branch from a behind-HEAD checkout (#683).** `apply_removals` used `git branch -d`, which is HEAD-relative, while the eligibility check was origin/main-relative; a checkout slightly behind `main` failed the `-d` merged-check even though the branch was genuinely merged. The apply path is aligned to the origin/main-relative determination so the normal (non-force) deletion covers this production case.
- **Batch-prefetch PR state (#655).** The script made roughly two `gh` calls per branch to read PR state. It now prefetches PR state in a single batched pass (O(1) `gh` calls per run), which both speeds the run and is the consumer of #2790's now-reachable `gh`.
- **Duplicate local-branch rows under `--all` (#670).** `--all` listed some local branches twice because the spawn-task and historical candidate sets overlapped with no presence-check. A presence-check on the candidate set de-duplicates the rows so each branch appears exactly once in the report.
- **`--help` residual (#669).** Trimmed to residual after the primary `--help` truncation defect was resolved incidentally by #1678; the remaining end-anchored usage-window fix and a self-test assertion land here.
- **One PR, one merge.** All seven cards shipped on one branch / one squash-merge per the milestone-as-one-PR model. #1552 (a refuted P1 data-loss claim) was cut at the Stage-4 plan gate; #654, #1481, and #1552 were verified already-resolved and closed out of scope.
