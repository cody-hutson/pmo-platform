# The script guard lets harmless text through and refuses what it cannot finish

2026-11-22 · v5.14

The guard that refuses to run a script your workspace has not listed now lets through two kinds of here-document that run nothing, and its record of direct script runs stops counting text that only looks like one. A command the guard cannot finish reading, because it is too long or too slow to read, is now refused instead of being let through.

> **Skip the rest** unless your sessions run shell commands on a workspace that takes this guard, or they pass very long text inline in a command.

## Who this affects

- Anyone whose sessions run shell commands on a workspace that has taken this release's guard bundle.
- Anyone who passes a long body of text inline in a single command, such as a pull-request body or a commit message.
- Operators who read the script guard's records for its review on 2026-12-15 (Tue).

## What you need to do

1. Refresh your workspace's guard bundle: run `./update.sh` from the platform repository root. The changes below reach a workspace only through that refresh.
2. When a command would carry more than 65,536 characters of text inline, pass the text by file instead: a pull-request or issue body through `--body-file`, a commit message through `-F`, and a file's contents through the Write tool. The guard now refuses the inline form, and its refusal says so.

## What changed for everyone using the platform

- **Here-documents that run nothing are no longer refused.** A here-document whose text cannot expand into a command is now allowed when it is fed to `cat` and nothing in the command reads `cat`'s output, and when its receiver, `cat` or one of the commands the guard already trusts with text, sits behind a grouping bracket or a shell keyword. A body whose receiver could run it is still refused. *Why it matters:* writing a file or a message that mentions a script stops being blocked.
- **The option check's refusal names its cause.** When the guard reads a shell's options as though a command string follows, because an option word, a combined option cluster or an option's argument is not written plainly, and then refuses, the refusal now says which of the three it was, and for two of them how to rewrite the command. *Why it matters:* you can see which part of the command to change instead of guessing.
- **A command the guard cannot finish reading is refused, not let through.** The guard now stops reading one command after 120 seconds, and refuses a command longer than 65,536 characters before reading it; both refusals say to pass long text by file. *Why it matters:* a command the guard cannot finish no longer outlasts the session's time limit for the hook, which lets a command through unchecked, and an unusually long command gets an answer within two minutes.
- **The guard's record of script runs stops counting text as runs.** In the record the guard keeps while it only logs direct script runs, a word that begins with a backtick inside text is read as what the backtick opens, and a listed script run inside a value's command substitution is recorded as that listed script, in the spellings this release admits. *Why it matters:* the decision due at the guard's 2026-12-15 (Tue) review, on whether to start refusing those runs, reads a record that no longer counts text that runs nothing.

## Known limits

- Both record classes are narrowed, not cleared. Some spellings of each still write a record, and each is declared in the guard's readiness reference. The records such text still writes inside a substitution or a group belong to their own class, whose owner is filed with this release's follow-ups.
- The live-traffic readings that measure this release are owed. The two record classes and the option check's refusals are read inside the release's 30-day window, which opened when this platform's own workspace refreshed its guard bundle on 2026-11-22, ahead of the 2026-12-15 (Tue) review. Their counts are not in this note, and the three work items that carry them stay open until they are taken.
- The two-minute limit covers this guard rule's own reading of a command. The hook's other rules, and its start-up, are outside it. A hook that runs past the runtime's own time limit still does not block the call; a settings-level remedy is tracked in [#8660](https://github.com/cody-hutson/pmo-platform/issues/8660).
- The test that keeps every loop in the rule under the time limit reads loops by their spelling, and it has known limits. No loop in the guard falls in them today; they are tracked with this release's follow-ups.
- A workspace picks up this release when an update refreshes its guard bundle. The version a workspace reports changes to v5.14 on the first update after this release closes.

Report issues at https://github.com/cody-hutson/pmo-platform/issues, and report a suspected vulnerability privately as the [Security Policy](https://github.com/cody-hutson/pmo-platform/blob/main/SECURITY.md) describes.

## Reversibility

MODERATE / MEDIUM. Reverting the single release merge restores the script guard as it was, and a workspace runs the restored guard only after an update refreshes its guard bundle again, or after the hook refresh's restore option returns it to the earlier generation. The version tag is kept as the record that the version was claimed. A revert brings back the harmless-command refusals and the unbounded reading this release removes.

### Operator and engineering detail

**The exec arm's two hold-backs (#8490, #8548).** The exec arm declines a command word that begins with a backtick to the enclosure position its backtick opens, with the nested-opener stop its adversarial review asked for, so the text-shaped class is narrowed and re-attributed: the rows such text still writes at enclosure positions belong to the enclosure-position class, whose owner is filed with this release's follow-ups. An allowlisted script run inside an assignment's command substitution is read as that script when the word that closes the substitution is one literal path the allowlist admits; the enclosure view adjudicates the substitution's command as before, so an unlisted or unresolvable script keeps both of today's records. A later segment of a command whose bail latched stays a declared residual (D-8548-A), and corpus rows AS20 and AS21 pin a blank- or wrapper-led over-block, in the safe direction, held as a follow-up. Plan deviation DEV-14 records that CIAC-2's re-grade clause does not hold for row LT05, which was added at `a`.

**Here-document receivers (#8326).** The receiver read steps over a grammar opener (`(`, `{` or a reserved word), and `cat` joins a pre-pass-only receiver list under a whole-command no-consumer condition. The closer rule, narrowed by the operator at Stage 6 (DEV-10), keeps a body when a `)` closes an opener the receiver's head sits inside. Its declared costs are refusals or records where nothing runs (corpus row HM09 and two arms); the residuals the receiver set carries are declared in the readiness reference, and the Stage 9 decision accepted them.

**The option-run latch (#8493).** The plain set is measured on bash, sh, dash and zsh as suite arms (`LATCH-SWEEP-*`), with a splitting control. The conservative route's refusal names its gate (`opaque`, `cluster` or `opaque-arg`), and its block-log row carries `features.route`.

**The work ceiling (#8327).** A 120-second per-command deadline is checked at every loop on the rule's surface, and a 65,536-character length gate runs ahead of the hook's first whole-command pass. Four cubic quote counts take a linear pass. Once an arm that reads enclosure positions enforces, the enclosure view's two budget exits refuse rather than lose a reading (D-8327-3). ADR-150 gains a dated amendment for the rule's one refusal no phase governs (D-8327-5). The suite's loop-coverage arm fails closed on a `do` it cannot place. Its known limits went to the release's follow-ups on the operator's override at Dev Testing pass 6.

**The block-log row.** A -022 refusal from the conservative route, or from the ceiling, now carries a `features` object on the block-log row (D-8327-4 for the ceiling). The row is written pretty-printed; two rows, compacted, with placeholder values:

{"ts": "<utc>", "hook": "block-destructive", "rule": "BLOCK-DESTRUCTIVE-022", "tool": "Bash", "input_digest": "<16 hex>", "cwd": "<dir>", "features": {"schema_version": 1, "route": "<gate>", "subject": "first"}}
{"ts": "<utc>", "hook": "block-destructive", "rule": "BLOCK-DESTRUCTIVE-022", "tool": "Bash", "input_digest": "<16 hex>", "cwd": "<dir>", "features": {"schema_version": 1, "ceiling": "chars"}}
