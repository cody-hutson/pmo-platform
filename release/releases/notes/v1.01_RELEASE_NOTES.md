# Pipeline-discipline capability slice — intake symmetry, signed-annotated tags, mid-pipeline divergence handling

2026-06-01 · v1.01

This release codifies five governance and protocol improvements within the v1.* Pipeline Discipline arc. Intake routing becomes symmetric content-shape routing (not one-way fallback); Stage 12 tag prescription matches repo signing policy; mid-pipeline divergence is detected and routed before Stage 9 GO; intake AC temporal metrics route to Notes; QA-side AC-drift verdicts are formalized.

## Who this affects

- Anyone authoring an intake Issue (observation vs. proposal tier selection now uses symmetric content-shape routing)
- Anyone running a Stage 12 release tag (now uses signed-annotated form matching repo `tag.gpgsign=true` policy)
- Anyone planning a release while a concurrent release is mid-pipeline (now detected at Stage 7/8 entry warn-only + Stage 9 Phase A6.5 HALT-eligible)

## What changed for everyone using the platform

- **Symmetric intake-tier routing.** Filing an Issue now routes by what the insight IS (observation vs. proposal — symmetric content-shape rubric), not by what fields can be filled (one-way fallback). The observation tier is no longer a fallback for unsatisfied improvement-tier — both tiers carry positive triggers. *Why it matters:* observations like "X drifts / is missing / is suspect" are filed first-class instead of being shoehorned into the proposal template, improving signal quality at triage.

- **Stage 12 tag command works with repo signing policy out-of-the-box.** The Stage 12 Phase B tag prescription is now `git tag -a -m "..." v<X.Y> "$MERGE_SHA"` (signed-annotated) matching the repo's `tag.gpgsign=true` policy. The prior lightweight `git tag v<X.Y>` form would fail with `fatal: no tag message?` under the policy. *Why it matters:* release executors no longer need to know to bypass or work around — the documented command produces a signed annotated tag on the first try, no signing bypasses required.

- **Mid-pipeline divergence detected before Stage 9 GO.** When a concurrent release merges to main during a subject release's Engineering/DT/QA window, the Stage 4 baseline-pin is no longer the only check — a new G-PR8 check fires at Stage 7 entry (warn-only), Stage 8 entry (warn-only), and Stage 9 Phase A6.5 (HALT-eligible if release-plan File Change Matrix files were touched). *Why it matters:* divergence-caused Stage 9 GO voids are caught at the cheapest gate (Stage 9 pre-GO) instead of surfacing only at Stage 12 Phase A.5.

- **Intake temporal-metric AC discipline.** A new Anti-pattern D rule classifies AC bullets like "30-day rescore", "60-day adoption" as Notes-tier monitoring commitments (not AC), since they are not verifiable at merge time. *Why it matters:* Stage 8 QA can render a binary verdict at merge time without inheriting AC bullets that require post-close measurement windows.

- **QA-side AC-drift verdicts formalized.** When QA encounters an AC referencing changed assumptions (stale version refs, moved files, deferred features), the verdict is one of `N/A-WITH-RATIONALE`, `REINTERPRET-WITH-RATIONALE`, or `FLAG-UPSTREAM` (closed enum, non-overlapping conjunctive predicates). *Why it matters:* drift handling is no longer ad-hoc — three deterministic verdict options + Planning-side AC-currency prevention at Stage 4 Phase A0.

## Known limits

- The G-PR8 mid-pipeline divergence check fires on the *next* release after v1.01-intake — v1.01-intake itself is exempt per reflexive-pipeline-loop discipline (the rule shipping in v1.01-intake cannot retroactively fire on v1.01-intake).
- The AC-Drift Handling Protocol fires on the *next* release after v1.01-intake for the same reason — v1.01-intake's own temporal ACs (#66 AC #3 + #4) continue to render N/A under the pre-protocol pattern.
- Temporal AC outcome-window: #66 AC #3 (observation-share target 20-50%) and #66 AC #4 (label/template mismatch spot-check) are scheduled for empirical verification at 2026-07-01 (30d) and 2026-08-01 (60d).
- `core/CLAUDE.md.template` lines 311-314 retain the legacy one-way "IFF ... Otherwise" wording — operator-instance CLAUDE.md generated from this template would carry the legacy framing until a follow-up sync (filed as separate Issue).

Report issues via the standard intake at the GitHub Issues page.
