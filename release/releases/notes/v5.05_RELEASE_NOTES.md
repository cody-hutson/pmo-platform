# Guards now give a command the same verdict however it is spelled

2026-11-08 · v5.05

The platform's command guards now read a guarded command the way the shell will run it, so writing that command differently no longer gets it past a guard that refuses, or logs, its plain form. Ordinary commands are unaffected: a command changes verdict only when it is another way of writing one the guards already judge, or when it only looked like one and never ran it.

> **Skip the rest** unless your sessions run shell commands through wrapper programs or inside conditions, use the GitHub API from a session, or you review what the guards refuse and log.

## Who this affects

- Anyone whose sessions run shell commands on a workspace that has taken this release's guard bundle
- Operators who read the guards' refusals and their logged-but-not-blocking records, or who maintain the guards

## What changed for everyone using the platform

- **A wrapper in front of a command no longer hides it.** When a command runs through a wrapper program, the guards now step over the wrapper's own options and arguments, recognise the wrapper by its name even when it is written with its full path, and know three wrapper programs they used to miss. *Why it matters:* putting a wrapper in front of a command the guards refuse no longer turns the refusal into a silent run.

- **A command used as a condition is checked like any other.** A command that decides an `if`, `while` or `until` block is now read as a command in its own right. *Why it matters:* a guarded command gets the same verdict whether it stands alone or decides a branch.

- **The guards that protect your settings judge a setting however it is placed.** The guard that stops a session from changing where programs are looked up, and the guard that stops a session from changing the guards' own bypass and boundary settings partway through, now refuse the same setting when it is handed to a wrapper, written after another setting, placed inside a group or a condition, given to a declaration command, or added to rather than replaced. *Why it matters:* the protection no longer depends on where in a command the setting is written.

- **Another spelling of a guarded GitHub write gets the plain spelling's verdict.** The outbound guard now reads a GitHub API write the way the shell resolves it, whether its words are escaped, quoted, split, braced, broken across lines or written in different letter case, whether a redirection comes first, or whether its method option is written in short form. At the start of a command, such a write to an unlisted path is refused, as the plain spelling is; behind a prefix command it is logged, as the plain spelling is. *Why it matters:* the outbound guard's verdict no longer depends on how the command is typed.

- **Commands that only looked guarded are judged by what actually runs.** Some commands named a guarded program only as a setting's value or as a wrapper's argument, and never ran it, yet were refused; each such class is now declared and gets the verdict of the command that does run. *Why it matters:* fewer false refusals for commands that never run what the guards protect.

## Known limits

- Some spellings still reach a guard without the plain form's verdict, and each is owned by an open card: settings that the two settings guards do not yet judge, such as one carried as a program's own option or reached indirectly ([#8652](https://github.com/cody-hutson/pmo-platform/issues/8652)), and the spellings of a GitHub write that the outbound guard still admits without a record ([#8650](https://github.com/cody-hutson/pmo-platform/issues/8650)).
- Behind a prefix command, the outbound guard logs a GitHub write rather than refusing it, for every spelling, as it does for the plain one. When those logged writes start being refused is owned by [#6195](https://github.com/cody-hutson/pmo-platform/issues/6195).
- A command carried as a string for another shell to run, and a few positions the shared command reader does not reach, are declared limits of its design rather than gaps this release closes.
- Two classes found in review are carried to public follow-up cards filed at this release's close: a command run inside a nested shell, and a guarded command word written in different letter case in the guards other than the outbound one.
- A declared class of commands still costs the guards more work than before this release. It is accepted, and its general remedy is owned by [#8660](https://github.com/cody-hutson/pmo-platform/issues/8660); the work bound on the script check that predates this release is owned by [#8327](https://github.com/cody-hutson/pmo-platform/issues/8327).
- A workspace picks up this release when an update refreshes its guard bundle. The version this workspace reports changes to v5.05 on the first update after this release closes.

Report issues at https://github.com/cody-hutson/pmo-platform/issues, and report a suspected vulnerability privately as the [Security Policy](https://github.com/cody-hutson/pmo-platform/blob/main/SECURITY.md) describes.

## Reversibility

MODERATE / HIGH. Reverting the single release merge restores the four guards and the shared command reader as they were, and a workspace runs the restored guards only after an update refreshes its guard bundle; the version tag is kept as the record that the version was claimed. A revert reopens every gap this release closes, and the two decision records, Accepted at this close, change only through records that supersede them.

### Operator and engineering detail

**The shared command reader (#8314, ADR-235).** The command-position canonicalizer, `core/hooks/lib/command-position.awk`, which four always-on hooks consume, now walks each transparent wrapper's own option grammar from a field-for-field copy of the script-execution rule's getopt rows, which a suite arm holds equal to the rule's own. It matches a prefix word on its basename, adds `nice`, `stdbuf`, `timeout` and the `if`/`while`/`until` condition keywords, steps over the append form of a prefix assignment as it steps over the plain form, and reads a prefix-run assignment or redirection before it looks a word up as a wrapper. The deletion hook's two allow-on-match exits read a frozen exit view, so they keep the verdicts they had, and one run of the canonicalizer now serves both of the views that hook reads.

**The settings rules (#8444).** BLOCK-DESTRUCTIVE-020 and -023 ride the canonicalizer's assignment branch, so a `PATH` assignment, or a mid-session setting of the hook-bypass or scope-guard variable, is judged at every position the canonicalizer resolves, in a declaration builtin's argument list, and with the append operator. The positions and spellings -023 newly refuses are a declared tightening. Each rule's registry row states a verdict for every spelling the card named, and routes the rest to #8652.

**The egress rule (#8315, ADR-234).** BLOCK-EGRESS-007 keeps its own walk and reads a respelled `gh api` write as the shell resolves it, across ten spelling classes. A respelling takes the rung of the position the shell resolves it to: refused on day one at the head of a segment, and recorded at the unchanged `shadow` phase behind a prefix command. A respelled invocation counts on its own first-invocation counter, so no day-one refusal of a later plain write is withdrawn, and the unparseable branch and the fast-path gate read the same spellings. The respellings still admitted with no record are routed to #8650, and the graduation of the recorded writes to #6195.

**Cost on a long command.** Most of the return passes decided at Stage 7 went to cost rather than to verdicts. The egress scanner's substitutions, quote walk, continuation join, ANSI-C decode and word normalization, the script-execution rule's segment split and quote scan, the filesystem guard's refusal renderer and the canonicalizer's own walks now read a long command once, as linear passes that equivalence arms hold byte for byte to the code they stand in front of, so their work grows with the command as `main`'s does. The egress brace step bounds the expansion it builds and reads a group past the bound as written, as `main` reads every brace group. A class that costs a constant multiple more than `main` is an accepted residual, with #8660 its systemic remedy; `main`'s own sites of the cost class are routed to #8327 and to the filesystem guard's later milestone.

**The differential.** The tracked corpus `core/hooks/tests/fixtures/walk-payload-corpus.txt` gained seed blocks for #8444 and #8315, and for the later passes on #8314 and #8315, and the destructive and egress suites re-grade every row on each run. #8314's own wrapper faces are graded by the suite arms of all four consuming hooks rather than by a corpus block, which the operator accepted at Stage 9 under an override. The release's differentials recorded no refused shape moving to allow apart from the declared precision classes, the shapes that never run the guarded program.

**How it shipped.** Three cards on one branch, built serially, then fourteen return passes to Engineering from Stages 7 to 9, most of them on cost and on how the release's public text describes it. Stage 8 returned all three cards as conditional, and the operator accepted each card's residual set with its successor owners at a Stage 9 GO WITH CONDITIONS. The release merged at `e58a77f0` and claimed `v5.05` with a signed annotated tag on the first attempt; its provisional display had been `v4.82`, and sibling releases claimed the versions between first. The two decision records were renumbered as sibling releases took their numbers, to ADR-235 and ADR-234, and were ratified Accepted at this release's Stage 13. Stage 12 re-laid the rules mirror, and the operator published the hook bundle from the primary checkout, because the script-execution guard refuses the hook carrier to an agent session; the five deployed files hash-equal the merged sources.
