# Internal governance-hygiene release: RCA coverage and version-step cleanup

2026-06-29 · v2.41

This release tidies the platform's own governance and reference documentation. It extends the root-cause-analysis method to every process surface that owns a failure, reframes a rule-computed version-numbering step so it no longer surfaces as an operator decision, and corrects two reference-document accuracy issues. Everything here is internal to how the platform governs and documents itself — there is no change to any skill output, command, file behavior, or stored artifact.

## What changed for everyone using the platform

No user-visible behavior changes — see operator detail below. All four changes are corrections and coverage extensions inside the platform's own governance and reference documents; nothing changes in skill output, command behavior, or how your artifacts are stored.

## Known limits

- This is a documentation/governance-internal release: it extends method coverage and corrects reference docs, but changes no runtime behavior, no schema, and no stored content.
- The root-cause-analysis coverage extension is a binding-by-citation of an already-decided method — it wires existing surfaces to the method; it does not introduce a new method or change how root-cause work is performed where it already ran.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `project:governance-hygiene` label.

## Reversibility

CHEAP / HIGH confidence. Every change is an additive or corrective edit to governance and reference documentation; reverting the integration PR restores the prior text in one step. No data migration, no stored-content move, no runtime or schema change. Standard rollback window.

### Operator and engineering detail

**RCA method coverage extended to every failure-owning surface (#1883).** The invokable root-cause-analysis method (`core/disciplines/root-cause-analysis.md`, shipped via #754) was invoked or handed-off at only four surfaces; its own §2 trigger table named others that lacked a recorded binding. This release wires the method to those surfaces by citation — `ppm-agent` (invoke-or-hand-off when a processed defect or blocker surfaces), `pmo-devops-sre` (originate an RCA record on a regression that triggers rollback, Mode 3), and the failure-owning pipeline stage(s) — extending the §4 invocation table and §7 consumer-binding alongside `five-function-spine-and-process-flows.md`, the two SKILL.md files, and the `release-process.md` post-failure/rollback lines. This is coverage-completion of an already-decided method (ADR-016) — binding by citation, no new ADR and no change to how root-cause work is performed where it already ran. The review-class linkage decision (review skills stay format-linked via `review-discipline-principles.md` §2, not method-linked) is recorded.

**D-Version reframed as a recorded determination rather than a click-gate (#1918).** In the release hub's Recurring D-decisions block, D-Version was rendered with the full A/B/C gate template — presented to the operator as a co-equal click-gate — even though the version *number* is rule-determined (`anchor()` + bump-class floor → next-free) and bound at the Stage 12 atomic claim. By default the hub now renders D-Version as a recorded determination: it states the bump-class, the rule-computed provisional number, and the re-verification rungs (Engineering Commit 0 + the Stage 12 atomic claim) without surfacing an operator gate. It escalates to an actual operator gate only under an override condition — (B) a deliberate version-less / forced-collision close-out, or (C) a known concurrent release claiming the computed slot — and the block now states the rule-determined-vs-judgment distinction explicitly (D-Version as rule-determined, D-ReleaseClass as judgment). The (B) and (C) override valves remain documented and reachable; this is a process-clarity refinement, not a change to the version-computation rule.

**Extinct-path correction in the practice-efficacy framework (#1562).** `core/standards/practice-efficacy-framework.md` carried the extinct `pmo-platform/engineering/tools/` directory prefix in a Drift practice-table cell. The cell now reads the bare `health-check.sh` form the same file already uses in its §9 reference, leaving zero `pmo-platform/engineering/` references in the doc — a single-cell link-text correction, internally self-consistent with the file's own usage.

**Corpus-hygiene sweep — malformed cell + PR-time gate-marker enumeration (#2218).** Two live findings landed: (a) the malformed escalation-cap cell in `core/schemas/handoff-coordinator-spec.md` (`(DT↔Engineering, )` with a dangling empty parenthetical and a double-space) is corrected to `(DT↔Engineering)` with single spacing; and (c) `core/ADRs/README.md` now enumerates every PR-time durable-corpus integrity/durability gate and its override marker (allow-memory-ref, allow-link, allow-version-ref, allow-url, and the no-marker bare-`#N` reference-block positional rule) in the repo-integrity authoring discipline, with a spoke-facing pointer from `hub-spoke-bridge.md` Procedure 3 and a cross-reference to `reference-durability-standard.md`. The originally-bundled sub-finding (b) (a Check 33 spec-vs-reality divergence) was trimmed — it does not reproduce at HEAD; the spec and `deploy.sh` already agree.

For full implementation detail see the [RELEASE_LOG.md entry](https://github.com/cody-hutson/pmo-platform/blob/main/release/releases/RELEASE_LOG.md#deployment-log-v2-41) and the [integration PR](https://github.com/cody-hutson/pmo-platform/pull/2438).
