# Triage and bundle protocol codification — triage cadence, pattern-review rhythm, roadmap-to-bundle cascade gate, management-task identification

2026-06-02 · v1.02

This release codifies four Triage/Bundle protocol improvements within the v1.* Pipeline Discipline track. Stage 2 triage now has a defined cadence tied to release rhythm; recurring observations get a scheduled pattern-review rhythm with split draft/execute skills; Stage 3 bundle planning validates against the active roadmap before approval; and management-tasks are now a recognized triage-output category instead of being mis-filed as platform work.

## Who this affects

- Anyone filing or triaging Issues (triage now runs on a defined cadence; management-tasks route to a distinct output category)
- Anyone running a Stage 3 bundle (bundle composition now validates against active roadmap intent before approval)
- Anyone authoring observation Issues (recurring patterns now get a scheduled review rhythm rather than ad-hoc handling)

## What changed for everyone using the platform

- **Triage now runs on a defined cadence.** Stage 2 triage has an explicit rhythm integrated with the release cycle, with a separate fast-path for P1 items and a batch cadence for everything else. *Why it matters:* filed Issues get a predictable time-to-first-look instead of waiting for an undocumented, ad-hoc triage pass.

- **Recurring observations get a scheduled pattern-review.** Observations now feed a Pattern Review rhythm with a clear draft-then-execute flow, so themes that show up repeatedly are reviewed on a schedule rather than only when someone notices. *Why it matters:* repeated signals turn into action on a rhythm, instead of accumulating unreviewed.

- **Bundle planning checks the roadmap before approval.** Stage 3 bundle composition now validates the bundle against the active roadmap's Now/Next/Later before the bundle is approved. *Why it matters:* a bundle that drifts from current roadmap intent is caught at planning time, before engineering effort is spent on it.

- **Management-tasks are now their own triage category.** Triage explicitly recognizes management-tasks (coordination, scheduling, decisions to make) as a distinct output category instead of folding them into platform-change work. *Why it matters:* coordination items no longer get mis-filed as engineering work, so each lands in the right queue.

## Known limits

- The roadmap-to-bundle cascade gate (G3-13) fires on the *next* bundle after v1.02 — v1.02 itself is exempt (the gate shipping in v1.02 cannot retroactively fire on its own bundle).
- The triage cadence's P1 service-level value carries a calibration marker and is reviewed after three cycles of real use; the initial value is a starting estimate, not a measured target.
- Three minor follow-up findings surfaced during the release and are tracked for a later v1.* cleanup (see operator detail); none affect the shipped behavior.

Report issues via the standard intake at the GitHub Issues page.

## Reversibility

CHEAP / HIGH. All four issues land via a single release PR (#493); `git revert <merge-sha>` reverts the slice atomically. Documentation and protocol-definition changes only; no schema migrations with data impact; no breaking interfaces.
