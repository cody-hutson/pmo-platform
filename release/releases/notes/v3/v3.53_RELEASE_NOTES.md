# ADRs gain a canonical frontmatter schema, and the durability lint stops mis-flagging colors

2026-07-02 · v3.53

The ADR corpus now has one authoritative frontmatter + body-section schema instead of duplicated prose in two READMEs, and several long-standing lint and gate rough edges are fixed. This is internal engineering hygiene — nothing changes in how you use the platform day to day.

## What changed for everyone using the platform

No user-visible behavior changes — this release is corpus and governance hygiene. See operator detail below.

## Known limits

- **The operator name in ADRs is now *permitted*, not yet *applied*.** This release ships the scoped carve-out; applying the literal name across the existing ADRs is a tracked follow-up (#1488).
- **Two accepted, monitored lint residuals** (neither is present in the corpus today): the durability classifier will not flag an issue reference written colon-abutted to 3–8 hex digits (e.g. `word:#900`); and a line that literally begins `deciders:` inside an ADR *body* would be treated as the frontmatter field.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

MODERATE / HIGH confidence. The whole release reverts as a single `git revert` of the merge commit — text and config diffs only, no data migration. The `domain`-value change ships as a forward-only alias, so existing artifacts keep resolving during and after a rollback.

### Operator and engineering detail

Five delivery slices on milestone `100-adr-and-frontmatter-schema` (RELEASE_LOG anchor `#100-adr-and-frontmatter-schema`), one release PR, `routine` class:

- **#2156** — a new canonical schema doc, `core/schemas/adr-schema.md`, defines the ADR frontmatter *data contract* (seven fields + six body sections + the supersession-in-prose representation). Both ADR READMEs now cite it instead of restating the field list, which also resolved the dangling "Canonical ADR Format" pointer (#2155 item 2). The boundary with the ADR *authoring guide* (#431) is recorded: this schema owns the data contract; the guide owns the when/how/lifecycle policy and references the schema rather than re-inlining it.
- **#2155** — the frontmatter-schema header now reads "Seven categories" to match its seven category headings.
- **#2157** — `domain` values become human-readable (`source` / `managed` / `generated`) via a forward-only alias across seven consumers (the SQLite `CHECK` accepts the union during the migration window); `generated_by` is kept with a minimal inline decision, no new ADR.
- **#2068** — the reference-durability classifier no longer misreads hex-color prefixes (`#28A745`) as bare issue references, via a companion `HEXCOLOR_RE` mask in the shared awk classifier (`ISSUEREF_RE` stays byte-identical across its three enforcement surfaces); the process-flow-diagram allowlist stopgap is removed.
- **#1487** — a scoped depersonalization carve-out permits the operator's literal name only on an ADR `deciders:` line (ADR path **and** `^deciders:` both required); every other identity surface stays blocked.

**The canonical ADR frontmatter schema (#2156):**

```yaml
title: <short imperative decision title>
status: <Proposed | Accepted | Superseded …>     # leading enum token + optional prose tail
date: <YYYY-MM-DD>
release: <vX.YZ>
deciders: <architect-of-record>                  # operator literal name permitted here only (#1487)
tags: [<topic>, …]
source_observations: [<issue-or-note-ref>, …]
```
