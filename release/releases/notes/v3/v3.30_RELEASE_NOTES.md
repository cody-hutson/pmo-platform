# Software-domain specialist skills now share one best-practice anchor

2026-06-30 · v3.30

The five software-domain specialist agents — architect, principal engineer, software engineer, DevOps/SRE, and technical program manager — now ground their work in one shared software best-practice guide instead of asserting practices ad-hoc. The platform's build-philosophy coverage map was also corrected so it no longer claims grounding that didn't yet exist.

## What changed for everyone using the platform

- The software-domain specialist skills now cite a shared best-practice guide (design patterns, ADR discipline, YAGNI) as their design-time anchor. *Why it matters:* their guidance is grounded in one consistent source rather than per-invocation judgment.
- No new commands, no workflow changes, and nothing breaking — this is a consistency and governance-accuracy improvement. <!-- impact:foundational -->

## Known limits

- The **governance** and **process** best-practice guides are authored but not yet wired to their specialist skills (that lands in sibling releases); the coverage matrix now honestly marks those two as *skill-wiring pending* rather than implying they are done.
- No tracking issue yet exists to flip those two matrix cells to *wired* once the sibling anchoring ships — a follow-up will be filed.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH confidence.** Every change is an additive reference pointer or a matrix-cell correction; rolling back is reverting the release PR with no data migration.
