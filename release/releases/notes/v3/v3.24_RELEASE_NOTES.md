# A control plane for releases: point it at a milestone, get a coordinated run

2026-06-30 · v3.24

This release adds **`release-hub`** — a skill that orchestrates a whole release from one place. You point it at a milestone and it drives that milestone through the release pipeline by composing the per-stage skills: it owns the order the stages run in and the readiness checks between them, but it never re-does the stage work itself — each stage is still handled by the skill that owns it. It comes in two modes: a pre-flight that tells you whether a milestone is even ready to start, and a full orchestration mode that runs the release end to end and stops for you only at the real decision points.

## What changed for everyone using the platform

- **Run a release from one control plane.** A new skill takes a milestone and drives it through the release pipeline by composing the per-stage skills, owning the sequencing and the readiness-gating between stages while delegating the actual stage work to the stage skills. *Why it matters:* a release is coordinated end to end from one place, so the stages run in the right order and you do not have to hand-drive each stage yourself.
- **Check a milestone is ready before you start (Mode R).** Before a run is committed, the skill composes duplicate/triage, staleness, dependency, and bundle-coherence checks into a single GO / NO-GO answer with a per-finding disposition list. *Why it matters:* a milestone that is not actually ready — stale tickets, unresolved dependencies, a bundle that does not hang together — is caught up front instead of failing partway through the pipeline.
- **Run the full release end to end (Mode O).** The skill runs the whole hub-and-spoke release, spawning each stage in order and stopping for you only at the named checkpoints (the plan-review go/no-go and the execute step). *Why it matters:* you approve the plan once and the run proceeds on that approval, rather than reopening a fresh approval at every phase.

## How to use it

Invoke the skill by name with a milestone. Ask it for a readiness check ("is this milestone ready to start?") to run the Mode R pre-flight, or ask it to orchestrate the release to run the full Mode O hub-and-spoke run. It does not fire on a bare mention of the word "release" — you invoke it deliberately.

## Known limits

- **It coordinates; it does not replace the stages.** The skill owns sequencing and gating, but each pipeline stage is still performed by the stage skill that owns it — the hub composes them, it does not re-implement them.
- **You are still gated at the real decision points.** Orchestration stops for you at the named checkpoints (plan-review go/no-go, execute); it does not run a release past those without you.
- **Readiness is a pre-flight, not a guarantee.** Mode R tells you whether a milestone looks ready to start; it is a gate before the run, not a promise that nothing will surface mid-run.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `release-hub-orchestrator-skill` milestone.

### Operator and engineering detail

**Mode R — Milestone Readiness (#2115).** A pre-flight that confirms a bundled milestone is ready to START before a run is committed. It composes four readiness lenses — triage/duplicate detection, staleness/architecture reconciliation, dependency analysis, and bundle-coherence — into a single GO / NO-GO verdict with a per-finding disposition list. The value is catching an unready milestone (stale tickets, unresolved dependencies, an incoherent bundle) before the pipeline run begins rather than mid-flight.

**Mode O — Orchestrate Release (#2212).** The full hub-and-spoke orchestration. It takes a milestone and drives it through the pipeline by spawning the per-stage spokes in dependency order, owning the sequencing and the readiness-gating between stages while delegating the stage work to the composed stage skills — it is a control plane, not a re-implementation of any stage. Operator gating happens at the named pipeline checkpoints (plan-review go/no-go, execute) rather than per action, consistent with the platform's autonomy-tier model. Both child issues shipped on one branch and one merge per the milestone-as-one-PR model.

The skill ships with four references — the milestone-readiness checklist (the Mode R lens contract), the orchestration playbook (the Mode O stage-sequencing contract), the spoke-launch contract (the spoke-spawn contract), and the decision-briefing format (the operator decision-briefing) — plus a deploy-roster entry and the built skill package.

For full implementation detail see the [RELEASE_LOG.md entry](https://github.com/cody-hutson/pmo-platform/blob/main/release/releases/RELEASE_LOG.md#deployment-log-v3-24) and the [integration PR](https://github.com/cody-hutson/pmo-platform/pull/2497).
