# Skill guidance now cites its canonical escalation and best-practice sources

2026-07-02 · v3.51

Two small documentation fixes make skill guidance point to the platform's single source of truth: RAID "stale log" escalation now matches the canonical type-split thresholds, and the tier-2 support skill now names its best-practice references in one place.

## What changed for everyone using the platform

- **RAID "stale log" escalation guidance now distinguishes issues from risks.** The RAID templates previously said "escalate anything older than 30 days"; they now reflect the platform's real thresholds — issues warn at 14 days and escalate at 30, risks warn at 30 and escalate at 60 — and point to the canonical escalation-thresholds reference. *Why it matters:* you get the same escalation timing whether you read the RAID templates or the escalation reference, so stale items are chased on a consistent clock.
- **The tier-2 (escalation / root-cause) support skill now lists its reference guides in one place.** It points to the root-cause-analysis method it runs and to the support best-practice guide. *Why it matters:* the skill's design-time references are discoverable in a single "Reference docs" section instead of scattered or missing.

## Known limits

No carry-forward items. This release closes the last documentation tail of two skill-quality efforts (skill-function-hardening and skill-bp-anchoring); no behavior, schema, or stored data changed.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP · HIGH confidence.** Both changes are additive documentation cross-references plus a deterministic skill-package rebuild. Rollback is a `git revert` of the release merge and a package rebuild — no data loss and no stakeholder impact.
