# Methodology-aware trackers + stale-artifact detection

2026-07-24 · v3.86

This release makes the platform's records keep themselves honest: your trackers and status roll-ups now render the work-item kinds and fields that match each project's methodology, and a new check flags analysis artifacts that have gone stale instead of leaving them to pile up unnoticed. Three small integrity fixes, all additive — nothing you do changes.

<!-- skip-gate: this release affects some users (non-default methodologies) and operators, not everyone uniformly. -->

## What changed for everyone using the platform

- **Trackers and weekly status now speak your project's methodology.** If a project runs anything other than the default (Kanban, SAFe, Waterfall, PRINCE2, or a hybrid), the tracker and the weekly status roll-up now read that methodology and render the right work-item kinds and cadence — no per-project reconfiguration. *Why it matters:* status and tracker output stops silently defaulting to Scrum framing on projects that aren't Scrum.
- **Stale analysis notes are now detected, not assumed.** A new operator-run check flags analysis write-ups that are past their sunset date (or whose linked work item closed weeks ago), and offers a one-pass archive — it never changes anything without your confirmation. *Why it matters:* the analysis workspace stops quietly accumulating out-of-date material.

## Who this affects

- **Projects on a non-default methodology** — you'll see correctly-framed work-item kinds and status cadence in tracker and weekly-status output automatically. Projects on the default methodology see no change.
- **Operators who use the analysis workspace** — a new opt-in staleness check is available; it is operator-run and non-blocking (it is not a CI gate).
- Everyone else: no visible change.

## Known limits

- The staleness check is **operator-run and advisory** — it surfaces stale artifacts for you to act on; it does not auto-archive or block anything.
- The Layer-1 boundary-violation work (#681) landed as a **detection signal reconciled into the existing safeguards doc**, not a new enforcement tool: the originating flow is outside this repository (an operations-side link-rewrite), so it can't be reproduced or blocked from inside the repo — the risk is accepted and the detection convention is now correctly homed. The hard-enforcement "structural teeth" (a settings deny-rule and a push-guard hook) remain deferred, as noted in the governance self-check.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

Rollback is a single `git revert -m 1` of the release merge plus removing the `v3.86` tag and RELEASE_LOG entry; no data migration and no downstream consumer depends on these changes.

### Operator and engineering detail

Routine class, 8 points, three independent items shipped on one branch (PR #3797), full audit at RELEASE_LOG `#structure-records-and-review-signals`.

- **#2225 — analysis-workspace staleness lint.** New `release/tools/check-analysis-staleness.py`, a sibling to the existing `check-*.py` family (deliberately **not** wired into `deploy.sh`, which sidestepped a latent same-file collision with the concurrent `deploy-and-tooling-defect-cleanup` release). Reads the frontmatter of every `analysis/*/SUMMARY.md`, flags `now > sunset` **or** (`work_item` closed + >30d) and any missing required field; embedded `--self-test` (22 cases). The analysis-workspace standard itself is untouched — this closes the enforcement half that was deferred when the standard shipped.
- **#2021 — methodology-consumer read-refit.** `tracker-manager` and `weekly-status-rollup` were wired to read the methodology type-pack at invocation via the already-shipped OPERATIONS.md Methodology Awareness Protocol (prose citation, no new contract authored). A Stage-5 design fork on `weekly-status-rollup` — its documented methodology-neutral scope boundary vs. the read-refit — was ratified **in-scope (thin-wire)** at Collective Review, with the boundary preserved verbatim. `delivery-engine` and `ppm-agent` were confirmed already-conformant (verify-only); both edited skills' `.skill` packages were rebuilt.

During Stage 5, adversarial verification **overturned two premises** the plan had carried (that the governance home was out-of-repo and that a relocated safeguards doc had been retired); both were corrected against live state before Engineering, and AC2's off-git originating flow was recorded as accept-risk.
