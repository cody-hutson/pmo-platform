# v2.26 — people-graph activation

Activates the functional people-graph that shipped *structurally* in v2.23. The capability is now active, adoptable, and verified on a fresh install — not dormant.

## What changed
- **Install seeds the roster (create-once, never-clobber).** A fresh install creates your operator-instance `people-roster.yaml` from a de-identified template, wired at three sites (setup-workspace, install, update) behind a single `pmo_people_roster()` resolver; updates never overwrite a filled roster. (#2040)
- **Adoption is documented.** GETTING_STARTED gains a people-graph adoption section: create -> fill -> wire the per-tier owner-to-Person reference fields -> how the four skills consume the composed view. (#2041)
- **Consumption is verified.** A binary-judge eval proves comms-writer, tracker-manager, ppm-agent, and delivery-engine each resolve a real answer from a populated roster, read-only. (#2042)

## Safety
The filled roster is operator-instance state — out-of-tree, gitignored, never committed. The never-clobber guard is the load-bearing protection: a fresh install seeds it once and never regenerates it.
