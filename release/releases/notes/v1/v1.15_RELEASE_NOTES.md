# The platform now measures and improves its own agent quality

2026-06-13 · v1.15

The platform gains the methods to check and raise the quality of its own agents: a quality auditor that audits base-vs-build compatibility drift on a regular cadence, a data-driven target for how many failure modes a complex skill should document, a single root-cause method anyone can invoke on a defect, and a playbook for migrating between approaches. A verified triage of a month-old quality audit reconciles its findings to current state.

## Who this affects

- Anyone authoring or auditing a platform skill — the failure-mode standard now states a target range (not just a floor), and the quality auditor can run a base-vs-build health audit on a cadence
- Anyone diagnosing a defect or running a migration — a named root-cause method and a migration playbook are now available to invoke, with a defined handoff from intake and the pipeline
- The workspace operator — a stale harness-quality audit has been triaged to current state, with the few still-live findings routed onward

## What changed for everyone using the platform

- **The quality auditor can now run a platform-health audit on a cadence.** A new `platform-health` mode checks for compatibility drift between the underlying model behavior and what the platform's skills assume, and runs on a registered schedule rather than only on request. *Why it matters:* drift that would silently degrade agent quality gets caught on a regular cadence instead of surfacing as a surprise.
- **Skill authoring now targets a data-driven number of failure modes, not just a floor.** The failure-mode standard now states a target range (6–10 for complex skills) instead of only a minimum of three. *Why it matters:* complex skills get failure-mode coverage sized to their real risk surface, so the auditor's coaching points authors at an evidence-based target rather than the bare minimum.
- **A single root-cause method is now available to invoke on a defect.** Root-cause analysis is now a named, invokable method with defined steps and handoff points from intake and the pipeline, rather than a principle scattered across guidance. *Why it matters:* defects get a consistent, repeatable diagnosis instead of an ad-hoc one that varies by who looks at it.
- **A migration playbook is now available.** A new playbook lays out how to move between approaches with a defined intake and pipeline handoff. *Why it matters:* a migration has a referenceable, repeatable path instead of being reinvented each time.

## Known limits

- This release lands the quality *methods* and reconciles the stale audit; it does not itself fix every individual finding the audit surfaced. Two findings remain live and are routed onward as separate follow-up work: a residual missing evals-results directory, and a triage call on an install-path presence check that can only be confirmed against an operator's install root.
- The platform-health audit mode ships with its registered cadence; the scheduled task itself is registered by the operator.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

CHEAP / HIGH confidence. A single `git revert -m 1` of the release pull request removes the new audit mode, the target-range addendum, and the two new discipline documents; the change is additive (a new skill mode, a standard addendum, an invokable method, a playbook, and an analysis artifact) with no data migration to unwind. The standard 30-day outcome window applies.
