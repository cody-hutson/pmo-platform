# Every skill now documents failure modes in all five categories

2026-06-12 · v1.10

Every skill in the catalog now documents its own worst-case behaviors in all five failure-mode categories — what not to run on, what inputs to distrust, what steps not to skip, what output shapes to avoid, and how not to drop a handoff. 45 new entries close every remaining gap, each one written against the skill's real working surface and quality-graded before merge.

## What changed for everyone using the platform

- **Every skill now documents what it must not do.** All 23 skills carry at least one domain-specific failure-mode entry in each of the five categories: wrong-invocation (TRIG), bad-input (INPUT), skipped-step (PROC), output-shape (OUT), and handoff (HAND). *Why it matters:* skills are likelier to catch their own worst-case behaviors — declining the wrong job, flagging a bad input, finishing a handoff — instead of failing silently.
- **Boundary behaviors got the biggest upgrade.** Wrong-invocation coverage rose from roughly half the catalog to all of it (20 new entries), and handoff coverage from two-thirds to all of it (9 new entries). *Why it matters:* the two most common real-world failures — a skill running on the wrong job, and work dropped at the seam between skills — now have documented, skill-specific countermeasures everywhere.
- **Two high-volume skills gained reference checklists.** Project setup now ships a scaffold-output verification reference, and the weekly roll-up ships an input-coverage checklist. *Why it matters:* their highest-volume outputs get a citable completeness check instead of relying on authoring memory.
- **Nothing was removed or rewritten.** The release is additions-only — every existing failure-mode entry, mode, and output contract is untouched, verified by diff review at two independent quality stages. *Why it matters:* nothing you rely on changes; the guidance only gets more complete.

## Known limits

- The new entries are agent guidance enforced by review gates (each entry passed an LLM-graded domain-specificity check with per-file means at or above 4.0 of 5), not runtime enforcement — a skill can still err; it is now documented when it does.
- Five follow-up items discovered during the release were filed for future releases rather than fixed here: a deploy-check detection gap, a legacy mis-routing entry in one release skill, a tooling locale pin, a fixture-contract reconciliation, and a 15-file stale-path sweep. None affects current behavior; numbers are in the References below.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

CHEAP / HIGH confidence at the repository level: the release is additive-only, so a single `git revert` of the release pull request's merge restores all 23 skill files, both new reference docs, and every version field. The runtime level is MODERATE per the release plan's rollback model: after a repo-level revert, re-run the skill deploy and package rebuild at the reverted state so installed skills match source. Standard 30-day outcome window for this release class.
