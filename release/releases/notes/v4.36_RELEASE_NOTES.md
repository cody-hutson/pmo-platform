# Release notes are reachable again, and eight documents stopped lying about the platform

If you clicked a **Full notes** link in the changelog over the past several months, there is a good chance it went nowhere. Of the 165 such links, **84 were broken** — the majority of the platform's release history was unreachable from the place people actually look for it.

They broke quietly. Notes had been moved into per-version folders while the changelog kept pointing at where they used to be, and the check that exists to catch exactly this had been switched off.

## What changed

**The notes moved back.** All 100 versioned release notes are flat again, in one folder. Every broken changelog link now resolves without a single link being rewritten — the links were always right; the files had wandered.

**The broken-link check works again.** It had been suppressed by a rule written when the platform genuinely had only a handful of notes. That rule was true when it was written and false within about six weeks, but nobody re-checked it — so the check quietly passed on 84 broken links. It is now on, and it fails when a link does not resolve.

**Seven documents that described the platform incorrectly now describe it correctly.** Among them: the installer guide described a setup step the installer stopped performing months ago; a governance file listed two of the three places skills are built from; a maintenance note described a check as sampling data it never reads; and the release log recorded a version tag for a release that was never tagged.

## Why this kept happening

Every one of these started as a true statement. A count that was right when written. A rule whose premise held at the time. A folder layout that was current. None of them were wrong when they were made — they were left behind by changes elsewhere, and nothing was watching.

Two habits came out of the work and are now applied where it matters. Counts are no longer written down where they can be derived instead, so they cannot go stale. And where a document makes a claim about how the system behaves, that claim is now checkable rather than merely stated.

## What is not fixed yet

**Twenty-six published release pages on GitHub still differ from their source notes** (#4747). The repair is written and tested but cannot run yet — it depends on a separate piece of tooling being made available first (#5227). Nothing is lost; the source notes in the repository are correct and always were. It is the published copies that drifted.

**One governance file still describes the old folder layout** (#5892). It contradicts the standard this release just corrected, and because that file ranks higher in the platform's hierarchy, it currently wins on the point. Correcting it requires a person rather than an agent, by design — the text is written and waiting.

## What you need to do

Nothing. No configuration changed, no command changed, and nothing you have written needs updating.
