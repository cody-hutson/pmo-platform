# Release notes are reachable from the changelog again

2026-08-23 · v4.36

Of the 165 **Full notes** links in the changelog, 84 went nowhere — the majority of the platform's release history was unreachable from the place people look for it. They broke quietly, because the check meant to catch exactly this had been switched off.

## What changed for everyone using the platform

- **Release notes are reachable again.** All 100 versioned notes returned to a single flat folder, so every broken changelog link now resolves. *Why it matters:* release history is navigable from the changelog instead of dead-ending.
- **Broken links now fail the build.** The link check had been suppressed by a rule whose premise stopped being true about six weeks after it was written. *Why it matters:* the next broken link surfaces immediately rather than after several months.
- **The installer guide matches the installer.** It described a setup step the installer stopped performing months ago. *Why it matters:* following the guide no longer produces a configuration the platform does not create.
- **A release record no longer claims a version tag that was never cut.** *Why it matters:* the release log can be read as a record of what happened rather than what was intended.
- **Four maintenance documents stopped describing behaviour the code does not have** — a check said to sample data it never reads, a governance file listing two of three build sources, a stale package count, and eight ambiguous references. *Why it matters:* someone implementing against these documents inherits fewer wrong assumptions.

## Known limits

- Twenty-six published release pages on GitHub still differ from their source notes. The repair is written and tested but depends on separate tooling being made available first. The notes in the repository are correct and always were; only the published copies drifted.
- One governance file still describes the old folder layout and outranks the standard corrected here, so it currently wins on that point. Correcting it requires a person rather than an agent, by design.

Report issues at the repository issue tracker.

## Reversibility

MODERATE / HIGH. Every change is a documentation or configuration edit revertable with `git revert`; the notes relocation is a pure file move with no content change. Window: unbounded — nothing here mutates state outside the repository.

---

Eight cards shipped, all of the same shape: a document asserting something the code contradicted. Each began as a true statement — a count correct when written, a rule whose premise held at the time, a folder layout that was current — and was left behind by a change elsewhere with nothing watching.

Two habits came out of the work. Counts are no longer written where they can be derived, so they cannot go stale; the package count in the deployment rule now delegates to the roster rather than stating a number. And the link check that had been suppressed is re-armed with its self-test rewritten and mutation-tested, so it fails when it should rather than passing silently.

The recurring lesson was about verification rather than documentation: a sweep keyed on the presence of a token cannot find a defect defined by that token's absence. Several of the errors found late in this release were invisible to every earlier pass for exactly that reason.
