# Corpus-integrity enforcement — a reference-durability standard + three-primitive enforcement spine, and three PR-time repository-integrity gates

2026-06-03 · v3.18

This release ships automated, forward-prevention enforcement for two corpus-integrity disciplines that were previously enforced only by reviewer attention: **reference durability** (don't let non-durable references — markdown links, version-cutover apparatus, load-bearing bare `#N` — accrete in the governance corpus, where they rot on every repo migration or renumber) and **repository integrity** (don't let operator/collaborator PII, unresolvable issue references, or dead file links enter at PR time).

## Who this affects

- **Anyone authoring or editing the durable governance corpus** (`core/rules`, `core/standards`, `release/references`, skills, …): a new authoring standard plus a warn-mode harness hook now flag net-new markdown links, version-cutover clauses, and mis-placed bare issue references at write time.
- **Anyone opening a PR to `main`**: three new CI gates check changed files for operator/collaborator PII (in governance domains only), issue-reference validity, and dead file references.
- **Fork operators**: the depersonalization gate needs an `OPERATOR_IDENTITY` repo secret to function (see Operator action).

## What changed for everyone using the platform

- **A reference-durability standard plus a three-surface enforcement spine (#538).** `core/standards/reference-durability-standard.md` codifies a durability ladder (prose rule > self-describing boundary > registry entry > version label > issue # > SHA/URL) and a self-containment test. Three primitives enforce it forward-only: a PreToolUse harness hook (`block-fragile-refs.sh`, warn-mode), a `deploy.sh --check` check (Check 31), and a CI backstop (`reference-durability.yml`). *Why it matters:* the gradual accretion of links + version-cutover clauses + load-bearing `#N` in governance docs is now caught at authoring, deploy, and PR time — with detection precision gated by a checked-in fixture (23 labeled cases) so it cannot silently regress.

- **Three PR-time repository-integrity gates (#410).** `repo-integrity.yml` adds three jobs. **Depersonalization** scans for operator/collaborator PII in the C6 governance domains (`core/ release/ operations/ packages/`), on added lines only, exempting intentional-identity files (LICENSE, CODEOWNERS, README, SECURITY) and release-tracking files. **Issue-reference validity** requires a `#N` to resolve to a real issue and sit in a designated reference block (PR-numbers and transferred issues handled correctly). **Dead-file references** flags markdown link + image targets that don't exist. *Why it matters:* the three highest-value public-readiness integrity checks now run on every PR, teach the rule in their failure output, and carry per-line override markers for legitimate exceptions.

## Operator action

The depersonalization gate detects committed operator PII by scanning for the operator's literal identity — which cannot live in the repo (that would be the leak it guards against). It reads an `OPERATOR_IDENTITY` repo secret (full name + emails, one per line); the GitHub handle is auto-resolved from `github.actor`. On the canonical repo the gate fails loud until the secret is set. `COLLABORATOR_NAMES` is optional (unset = solo-operator). Forks opt out via a `REPO_INTEGRITY_FORK_OPTOUT` variable or a committed `.repo-integrity-fork` sentinel.

## Known limits

- **Warn-mode-initial.** The harness hook and deploy-check ship in warn-mode; flip-to-enforce is a later, separate operator action after shakedown.
- **Forward-prevention only.** Every gate scans the net-new added-line delta; pre-existing rot (legacy cutover clauses, private-upstream references, internal-ID residue) is out of scope and tracked as backfill.
- **One deferred consistency fix (#572).** The reference-durability CI's positional `#N` check is position-blind where the harness hook is position-aware; non-blocking, to be aligned before any flip-to-enforce.

## Process note

This release was merged ahead of the formal Stage 7–9 / 12 gates by operator decision, with all 11 CI gates green; the per-stage QA / Plan-Review ceremony was abbreviated. During the build and close-out the gates surfaced and fixed three scope boundaries — whole-file → added-line scoping, C6-domain scoping (intentional-identity exemption), and a `release/releases/` tracking exemption (#574) — each found by real use rather than by design.
