# A stalled project migration now has a deadline, a score, and a way to finish

2026-08-23 · v4.37

Moving existing projects onto the newer structure had no finish line: nothing said when a migration was late, nothing measured how far it had come, and nothing happened when one quietly stopped. This release supplies all three, and closes two gaps where a newly created project was invisible to filing and a closing project could take unsorted work down with it.

## What changed for everyone using the platform

- **A late migration is now defined rather than assumed.** There is a written rule for when a project's move onto the newer structure counts as late, and for when it counts as stalled — no progress across two consecutive checks. *Why it matters:* a migration that quietly stopped is now a stated condition someone can act on, instead of something noticed by chance months later.
- **Project audits can score how complete a project's records are.** The audit gained a structure check that measures entity extraction, record completeness, and whether the project has been reshaped into the newer form. *Why it matters:* "is this project actually migrated?" becomes a number you can look at rather than a judgement call.
- **A stalled migration is reported by name, with a link to the fix.** The audit emits a failure naming the specific project and pointing at its remediation steps, never a bare count of how many are behind. *Why it matters:* you learn which project needs attention and what to do next, instead of learning only that something somewhere is behind.
- **There is now a guided way to finish a migration the score flags.** Project setup gained a migration mode that remediates exactly what the score reports. *Why it matters:* the tool that tells you a project is behind can now also walk you through bringing it current.
- **Creating a project now registers it as a destination work can be filed into.** *Why it matters:* a newly created project starts life as a known place for incoming material rather than an unknown one.
- **Closing a project surfaces whatever is still unsorted instead of archiving it silently.** Anything left in the unsorted hold is now presented with a disposition choice before the project is archived. *Why it matters:* items waiting to be filed can no longer disappear into an archive because nobody looked in the hold on the last day.
- **New projects arrive carrying their own filing guidance.** The orientation cards that explain what belongs in each folder are now copied in at creation; previously the router assumed they were there and nothing put them there. *Why it matters:* the guidance is present when a project starts, rather than missing in every project that was ever created.

## Known limits

- **A newly created project is not yet resolvable end-to-end as a filing destination.** This release ships the writing half of that registration only; the reading half was deliberately held back and is tracked as follow-up work. Creating a project records it correctly, but the lookup that would resolve it is still to come.
- **Finishing a migration is never automatic.** A migration finding always requires a person to decide, and is deliberately kept out of the auto-approved section of the audit, because remediation rewrites a project tree that has no undo history.
- **No calendar date is set for when the older folder vocabulary stops being accepted.** This release defines the deadline rule and what happens when it passes; scheduling the changeover itself is a separate, still-open decision.

Report issues at the repository issue tracker.

## Reversibility

MODERATE / HIGH. Everything shipped here is a document or skill definition that can be reverted with `git revert`, and none of it rewrites project data on its own. One asymmetry is worth stating: a project a person has already migrated using the new mode stays migrated — reverting the release removes the tooling, not the change it was used to make. Window: unbounded for the release itself.

### Operator and engineering detail

**Why a migration can read zero after real progress.** The completeness score is a product of three factors, not an average, so any single factor at zero forces the whole score to zero. A project still on the older narrative-table shape is pinned to a zero factor by definition, which means it reads 0 no matter how far entity extraction and record completeness have advanced. This is intended and is stated in the protocol rather than left to be discovered: a migration is not partially done in a way that adds up across the target states. It is also the case that fires for most of the existing population, so a first run across a portfolio should be expected to return a wall of zeros rather than a gradient.

Here is the shape a run reports for one project, and the same project once the reshape lands:

```text
project: <name>
  MM-1 Entity extraction        0.80
  MM-2 Record completeness      0.95
  MM-3 Reshaped into new form   0.00   <- pinned: still on the old shape
  MM-0 Migration completeness      0   (0.80 x 0.95 x 0.00)
  state: STALLED — no MM-0 movement across 2 consecutive runs
  -> Decisions: FAIL for <name>; remediation: migration mode

after the reshape lands:
  MM-3 Reshaped into new form   1.00
  MM-0 Migration completeness     76   (0.80 x 0.95 x 1.00)
```

**Scope held deliberately.** The routing-target registration shipped writer-side only, by an operator decision taken before engineering began rather than as a discovery during it. The milestone's own outcome statement was reworded at close to match what shipped, because its prior wording claimed the end-to-end capability. The reader half has a named owning item created as a condition of that decision, so the deferral has an owner rather than a note.

**Escalation routing is imposed, not inferred.** A migration finding routes to the operator-decision section regardless of the confidence the audit assigns it. That is a rule the protocol imposes on any instrument implementing it, precisely so a high-confidence score cannot promote an expensive, unversioned tree rewrite into a section an operator approves at a glance.
