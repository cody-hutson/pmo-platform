# Seven authoring conventions each get a disposition you can check

2026-10-24 · v4.78

Each of the seven authoring conventions this release covers now has a recorded disposition you can check, and none of them is retired. One is enforced by a check that fails when the convention is broken; the other six are restated with the surface each one binds.

> **Skip the rest** unless you plan or run releases on the platform, apply size labels to work items, or use the release-hub skill.

## Who this affects

- Anyone who plans, runs or reviews releases on the platform, including any release plan that schedules a memory eviction
- Anyone who applies a size label to a work item
- Anyone who uses the release-hub skill

## What changed for everyone using the platform

- **One convention now fails when it is broken.** An aside in parentheses in the event record's subtype column no longer creates a subtype that does not exist: both tools that read that column now drop text in parentheses before reading it, and each tool's self-test fails if that stops being true. *Why it matters:* a note an author adds to the schema can no longer turn into a phantom category in the release event record.

- **Memory evictions keep no archive by default.** When a release plan schedules a memory eviction, nothing is copied by default. A copy is kept only where the operator elects one, and it is made outside the memory store and outside every git working tree. The close does not run an eviction row that names any other destination, and takes that row to the operator instead. *Why it matters:* evicted memory content can no longer land in a tracked file, an issue, a pull request or a comment.

- **Size labels say what each size means.** The five size labels now carry a one-line description: the size's points, what a change of that size looks like, and where the rubric lives. The rubric that assigns a size is now written down, read from the files a change touches. *Why it matters:* whoever applies a size label can see what it means without opening the planning documents.

- **The release hub asks for an evidence label on every grounded claim.** If you use the release-hub skill, its contract now asks that every grounded claim in what it tells you carry an evidence label, such as `[SOURCE]` or `[INFERRED]`. Nothing checks this yet. *Why it matters:* you can tell what the hub read from what it inferred, but a missing label is not caught for you.

- **The signal-tag decision is recorded, with its reasons.** For the short tags such as `[ADJUST]` and `[SCOPE CHANGE]` that mark a change to a release's plan, the platform now records that each tag is owed in a named kind of durable record, and that a message posted nowhere owes no tag. Carrying that out is a follow-on story's work. *Why it matters:* there is one written answer to where a signal tag is owed, and so to where a later check has to look.

- **Two cross-document conventions have one form and one home.** The rule about what belongs in memory and what belongs in the corpus is now cited by its section's name rather than its number, and the list of deliverable classes lives in one place. *Why it matters:* a renumbered section or a new deliverable class can no longer leave two documents giving different answers.

## Known limits

- Two of the six restated conventions are not checked by anything yet: the hub's evidence labels and the signal tags. Each has a follow-on story: [#8376](https://github.com/cody-hutson/pmo-platform/issues/8376) takes a dated first reading of the evidence labels, and [#8375](https://github.com/cody-hutson/pmo-platform/issues/8375) owns the first check on the signal tags.
- The size rubric's cut points are provisional. They bind only once a backtest made before delivery is recorded, so the size labels describe each size in words, with no numbers of files.
- The section-name citation rule is stated but no detector checks it. An alternative form, citing headings by an explicit id, is routed for separate evaluation ([#8228](https://github.com/cody-hutson/pmo-platform/issues/8228)).
- This release evicts no memory entry, so the close has not yet declined a real eviction row. A related archive question about expired corrections is open ([#8373](https://github.com/cody-hutson/pmo-platform/issues/8373)).
- Three skills and the records policy still forbid every in-place edit to an accepted decision record, against the authoring guide's hygiene exception ([#8389](https://github.com/cody-hutson/pmo-platform/issues/8389)).
- The version this workspace reports changes to v4.78 on the first update after this release closes.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

CHEAP / HIGH. Reverting the single release merge restores the earlier text and tools, and the two skill packages are rebuilt on the revert. The five size-label descriptions are repository state that a revert does not reach; the same five label edits with an empty description restore them. The two decision records are superseded rather than deleted, and the version tag is kept as the record that the version was claimed.

### Operator and engineering detail

**The seven dispositions.** Each row names where the convention is now stated and what, if anything, fails when it is broken.

| Convention | Disposition | Where it binds | What fails when it is broken |
|---|---|---|---|
| Event-schema column 3 | Enforced | `pipeline-event-log-schema.md` § 3; `append-pipeline-event.sh`; `check-event-record-integrity.sh` | Each tool's seeded self-test arm |
| Memory-eviction archive | Restated, with a runner | `knowledge-architecture.md` encode-and-evict lifecycle; the release-plan template; `stage-13-close.md` B-OPS | The Stage 13 executor's stop rule declines a non-conforming row; no CI job runs it |
| Memory-boundary citation form | Restated | `reference-durability-standard.md`; 24 lines in seven files | Nothing yet: a named gap in the gate-coverage register |
| Deliverable-class list | Restated, one home | the project schema's `deliverable_type` field reference | No second copy remains to disagree |
| Size-class rubric | Restated; method ratified, cut points held as seeds | `bundle-composition-doctrine.md` Step 5, cited by G3-09 at both sites; the five label descriptions | Nothing yet: the cut points bind after an ex-ante backtest |
| Hub evidence labels | Restated, unenforced | the release-hub contract's ninth Output Contract requirement | Nothing yet: a named gap in the gate-coverage register; #8376 owns the first reading |
| Signal tags | Restated, unenforced; option (C) | `release-process.md`; ADR-222 | Nothing yet: a named gap in the gate-coverage register; #8375 owns the first check |

**The parser change.** The writer, `append-pipeline-event.sh`, and the integrity validator, `check-event-record-integrity.sh`, read the subtype tokens from the event schema's § 3 column 3. Both now drop every balanced parenthetical span before they extract a token, so a parenthetical aside can no longer register a phantom subtype, and the two cannot disagree about the same cell. Each tool carries a seeded self-test arm that fails on a regression, over two new fixtures, and § 3 states the authoring constraint. The validator was narrowed together with the writer by the Collective Review's choice.

**The memory-eviction entry contract.** ADR-221 supersedes ADR-045's archive-first property in part. The release-plan template's memory-eviction sub-table gains an `Archive disposition` column, one row per tie, never one per entry. Its value is `none` by default, or `operator-local` where the operator elects a copy; no value names a tracked file, an issue, a pull request or a comment. At Stage 13 manifest validation, the executor does not run a row that names a destination for entry content or carries any other value. It records the row as not executed and returns it to the hub for the operator's decision. The absorption gate is a test of the post-state, and the close-out record names evicted entries by tie and count only. Two rows of the sub-table, with the long cells abbreviated:

```markdown
| # | Tie | Corpus homes | VERIFY-CORPUS probes | Planned count | Executor | Trigger | Archive disposition |
|---|---|---|---|---|---|---|---|
| 1 | #N, the codification card | the standard section | git grep -c -F on origin/main | 2 | Stage 13 Phase B-OPS | Post-merge | none |
| 2 | #N, a card whose entries the operator keeps | the standard section | git grep -c -F on origin/main | 1 | Stage 13 Phase B-OPS | Post-merge | operator-local |
```

**Citations, classes and sizes.** The memory-boundary section is now cited by its heading as the link label over a plain file link with no fragment, on 24 lines in seven files. A renumber therefore cannot re-split the corpus, and the rule is stated once in the reference-durability standard. The deliverable-class list moves to the project schema's `deliverable_type` field reference, with a membership definition. The registry row and the Stage 4 paragraph cite it, the Stage 7 example list is removed, and no count of the classes is written anywhere. The size-class rubric is Step 5 of the bundle-composition doctrine. It is read from the tracked files a change touches, and G3-09's remedy cites it at both sites. Its five one-line anchors became the five label descriptions at this close, written verbatim from the doctrine; all five were empty before.

**The hub contract and the signal tags.** The release-hub contract's ninth Output Contract requirement binds every grounded claim in an operator-facing emission to an evidence label, in the rubric's Conversational class terms, with an emission-time question. For the signal tags, ADR-222 records option (C), with its measurement. The 18.8% adherence figure the card cited measured a surface the protocol never bound, so the binding is restated and registered as a gap rather than enforced on conversational turns or retired. The gate-coverage register gains four rows: one with a resolving runner, the memory-eviction executor, and three named gaps.

**How it shipped.** Seven cards on one branch, merged at `aa1e8ffe` and claimed as `v4.78` with a signed annotated tag. Sibling releases claimed `v4.74` to `v4.77` while this one was in flight, so the provisional version moved from `v4.74` to `v4.75` and then to `v4.78`, and the memory-eviction record was renumbered from ADR-217 to ADR-221 at a sync with `main`. Four of the seven cards took a Dev Testing fix iteration. Stage 12 deployed the `release-hub` and `release-planner` skills with their packages and regenerated the composed workspace charter. At this close, the five size-label descriptions were written, and ADR-221 and ADR-222 are ratified `Accepted` by the operator.
