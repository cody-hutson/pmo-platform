# Writing down an architecture decision is now a guided, one-command step

2026-07-03 · v3.62

Recording an architecture decision used to mean copying an old decision record by hand and learning the rules by tripping over a failing check. This release makes it a guided step: a single canonical guide tells you when a decision is worth recording and how, a new helper scaffolds the decision file for you at the moment you make the call, and the decision index is now complete so past decisions are actually findable.

## What changed for everyone using the platform

- **A canonical guide for architecture decisions is now in place.** It says plainly when a decision is worth recording, gives a copy-paste template, and sets the rule that a recorded decision is never edited in place — it is superseded by a new one. *Why it matters:* you no longer reverse-engineer the conventions from an old record or discover them only when an automated check rejects your work.
- **A helper now scaffolds the decision file for you.** Ask for it at the moment you make an architecture call and it drops a correctly-structured, correctly-numbered decision record in place, citing the guide's rules. *Why it matters:* the friction of starting a decision record drops to near zero, so decisions get captured when they happen instead of being skipped.
- **The decision index is now complete.** Two decisions that had shipped but were missing from the index (ADR-017 and ADR-019) are now listed. *Why it matters:* browsing the index shows the full history — a decision that exists but isn't indexed is effectively invisible.
- Several older cross-references that pointed at the scattered, now-superseded decision guidance were repointed to the single canonical guide. *Why it matters:* following a link about ADR conventions lands you on the one authoritative page, not a dead or outdated pointer. <!-- impact:foundational -->

## Known limits

- The helper scaffolds and numbers the decision record and cites the guide's rules; **you still write the decision's substance** — the context, the options weighed, and the consequences. It removes the boilerplate, not the thinking.
- This release does not change any decision that was already recorded; existing records are untouched.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH.** The release shipped as a single pull request and is fully git-revertable. It adds a guide, a helper skill, and index rows — no existing decision record or other content was rewritten — so rollback is simply reverting the pull request, with no data-loss surface.

Four work items closed the immutable-ADR-system slice of the Knowledge Architecture epic (RELEASE_LOG `#31-immutable-adr-system`, **Outcome: SUCCESS**), taking ADR mechanics out of operator memory and into a citable, low-friction workflow.

The same change repointed the previously-scattered ADR-governance references — in `decision-discipline.md`, `initiative-roadmap-framework.md`, the `release/ADRs/README.md`, the Stage-5 solutioning reference, and the `adr.yml` issue template — at this single authority. QA verdict ACCEPT (8/8 completion conditions MET).

**Helper skill (#15)** — a new `adr-helper` skill (`core/skills/adr-helper/SKILL.md` + a `scaffolding-procedure.md` reference) scaffolds `ADR-NNN.md` at decision moments, deriving the next platform-wide-unique number and citing the #431 guide's triggers and template as its authority. It is registered in the skill registry and the deploy roster, and its `.skill` package was built inside the release PR (no separate post-merge rebuild step). QA verdict ACCEPT (5/5 acceptance criteria MET; the ADR-number integrity gate stays green).
