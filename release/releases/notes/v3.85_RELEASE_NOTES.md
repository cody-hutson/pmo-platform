# Release close-out now guards its published notes, packages, and ledgers

2026-07-24 · v3.85

Closing a release now checks its own outputs instead of trusting them: the published notes page is verified against the source, changed skill packages are rebuilt before the release is marked done, and the release-history records are completed. One previously-advisory check now stops a release when it finds a problem.

## Who this affects

- Anyone who runs a release close-out or runs `deploy.sh --check` on this repository. Project and operations work is unaffected.

## What changed for everyone using the platform

- **The published release page is now verified against its source note, and a mismatch stops the release.** The check that compares the two used to only log a warning; it now fails. *Why it matters:* the page people read can no longer silently drift from the source of record — but be aware this is a posture change, not a silent addition. A `deploy.sh --check` run that passed before this release can now fail if a release published from v3.78 onward has a page that no longer matches its note; the fix is to reconcile the page to the note, not to disable the check.
- **Changed skill packages are rebuilt as part of closing a release.** When a release edits a skill, the packaged copy of that skill is now rebuilt and shipped in the same step that finalizes the release. *Why it matters:* a release can no longer close while leaving a skill's packaged copy out of date with the source it was built from.
- **Release notes for a format or schema change must now include a real example of the new shape.** *Why it matters:* you see what the new format looks like directly instead of inferring it from the description.
- **A release that was missing from the four release-history records (v3.57) has been restored, and a broken link was repaired.** *Why it matters:* the release history is complete and its links resolve, so an audit of past releases no longer has a silent gap.

## Known limits

- The published-page verification covers releases from v3.78 onward; earlier releases are outside its scope by design, so a drift in an older page is not flagged.
- Some older published pages are known to differ from their notes and are handled separately because correcting them changes public content (#3699); a related cleanup of historical foldered notes is also tracked separately (#3698).

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE** · confidence **HIGH**. The verification flip reverts as a one-line cutoff change plus a one-line helper swap; the new close-out rebuild step and the new lint check are additive; the v3.57 restoration is data-only, adding rows that were always meant to exist. Whole-release rollback is `git revert -m 1` of the release merge, with no historical record rewritten.

### Operator and engineering detail

**The release-body drift gate flips to enforcing (#3118).** `deploy.sh` Check 47 previously logged a body-drift finding and waved it through; it now fails, gated by a committed complete-token cutoff (`v3.78`) chosen so every release in its scope is verified clean at ship time. The close-out tool's post-emit drift phase blocks the milestone close on a genuine mismatch; the capability-absent and artifact-missing states — a release mid-close, before its page is published — resolve to N/A, which is why this release's own close-out does not trip the gate it ships. Full audit detail in the [RELEASE_LOG row](https://github.com/cody-hutson/pmo-platform/blob/main/release/releases/RELEASE_LOG.md#deployment-log-v385) and [the release plan](https://github.com/cody-hutson/pmo-platform/blob/main/release/releases/plans/v3.85-close-out-hardening-wave-2_RELEASE_PLAN.md).

**Package rebuild rides the close-out chore (#3322).** The close-out now rebuilds any skill whose source changed in the release, staged into the same commit that transitions the release-history row and before the milestone closes — closing the window where a package rebuilt after close could not attach to the already-closed milestone. This release is that phase's own first live target: its single skill-source edit (the eval-writer release-notes rubric) staled the eval-writer package, which this close-out rebuilds.

**Sample-block mandate for schema/format changes (#2600).** A release that adds or changes a shape someone must produce or parse now carries one short, real example of that shape in its note, placed in this operator section rather than inside the user-facing bullet list. A new advisory lint check verifies it — declared from the release plan's file-change matrix, not auto-detected — and the eval rubric was synced to the new check count. This release is itself a format-change release, so it dogfoods the mandate below — one sentence naming what it shows, then the fenced instance of the §2.8 shape (an operator-section theme line followed by a fenced example of the new or changed shape):
