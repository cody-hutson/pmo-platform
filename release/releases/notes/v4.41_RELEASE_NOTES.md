# Nine checks that reported clean without measuring anything now measure

2026-08-28 · v4.41

Nine of the platform's automated checks stated a guarantee their mechanism did not deliver — a licence gate that could not fire on the one change that breaks every package, a citation resolver reporting correct references as broken, a search that returned "nothing found" because the search itself was invalid. Each now discharges its guarantee by a mechanism instead of a promise, and each ships a test that fails when the check stops working.

## What changed for everyone using the platform

- **The licence check can now fire on the change that would break every package.** The gate that compares all 55 packaged skills against their licence file only ran when certain files changed, and the licence file itself was not on that list. *Why it matters:* the single edit that would invalidate every package was the one edit that could not trigger the check built to catch it.
- **Correct citations are no longer reported as broken.** The resolver that validates section references dropped the letter from numbers like 2c and 2d, collapsing both to 2 and then failing to find them. Two of its four live findings were correct references misreported. *Why it matters:* a check that is wrong about a failure is a check people learn to ignore, which costs more than the check saves.
- **A parsing defect that quietly recoded 216 citations into the wrong status is fixed.** An empty field shifted every later field one position left, so a section number landed in the path slot and was recorded as an unreadable target. Both counters stayed plausible and the totals still reconciled, so nothing looked wrong. *Why it matters:* totals cannot tell you the parts are wrong — only reading the parts can, and now the parts are read correctly.
- **A search that returned nothing because it was invalid now says so.** Word-boundary patterns were being executed literally by the search tool in use, so sweeps came back empty and read as clean. *Why it matters:* an empty result now means the search ran and found nothing, rather than that the search never worked.
- **Impact estimates stopped counting files nobody ships, and stopped showing an unmeasured zero.** The tracer that estimates how far a change reaches walked ignored directories, inflating every denominator, and reported "no further references" identically whether it had looked or not. It now excludes ignored trees, and withholds a number it did not measure instead of printing zero. *Why it matters:* a scope estimate you are about to act on now distinguishes "we looked and found none" from "we never looked".
- **Every one of these nine checks now ships a test that fails when the check breaks.** Each fix carries a case the check must flag and a near-miss it must not, both recorded on the merged change. *Why it matters:* the next time one of these silently stops working, something says so instead of reporting clean.

## Known limits

- **Nothing catches a citation that points at the wrong record.** A reference whose target exists but is the wrong document passes every check, because existence is what the checks test. One such reference was found by reading during this release and is tracked separately; no mechanism found it and none would.
- **One checker still advertises two finding categories it cannot produce.** Its usage text names three kinds of finding; exactly one has code behind it, and the other two are restated in several governance documents that instruct readers to rely on them. Tracked separately, not fixed here.
- **Whether a check works can depend on the machine it runs on, and the standard that classifies checks has no way to record that.** Removing one environment setting from a test suite leaves it passing under one configuration and failing under another, with no change to the code. This was proven by running it, and is now tracked as an open gap with no owner assigned yet.
- **A skill's installed copy is left stale after a release that changes it.** The step that refreshes it falls outside the authority of every stage in the release pipeline, so it is recorded as owed rather than performed. This release left one such skill stale and tracked the gap.

Report issues at the repository issue tracker.

## Reversibility

MODERATE / HIGH confidence. `git revert -m 1` on the release merge commit reverses all nine cards together: every change is a script, workflow, or tracked-text edit, the new checker is additive, and there is no data migration and no file move. One asymmetry is stated rather than hidden — the release changed checks that run during its own close, so a revert would not un-run a close that already happened. Standard rollback window.

### Operator and engineering detail

**The release's own artifacts reproduced the defect family they were correcting.** A grading contract inherited an incorrect figure from the stage before it, which had inherited it from the stage before that. An adjudication correctly identified a file-versus-line unit confusion and then committed one in the adjacent sentence. A tool header declared post-fix figures while still pinned to the pre-fix commit. This is the reflexive shape worth naming: a release about controls that do not measure what they claim produced, inside its own corrective artifacts, three claims that did not measure what they said.

**Twelve population and unit discrepancies surfaced, and not one was a counting error.** Every one was a correct number attached to an unnamed population — the arithmetic was right and the denominator was unstated. Three resolved to *exact* agreement the moment the population was written down, which is the diagnostic: two parties measuring different sets, both correctly. One was produced by a grader that had been explicitly warned about that precise miss, and the orchestrator produced four, including one at a gate briefing. The remedy is not more careful counting; it is stating the revision, the unit, and the scope flag with every magnitude.

**Concurrent releases allocating from global counters collide at merge, and the merge cannot see it.** This release allocated a check number and four decision-record numbers while sibling releases allocated from the same counters. Allocation happens at authoring; collision detection happens at merge. Three collision cycles occurred in one release: the check moved from 71 to 72 across 18 tokens in 6 files, and two decision records moved twice each. Structural three-way merge is blind to this class by construction — each duplicate pair is two different file paths claiming one global slot, so there is no textual conflict to detect. The asymmetry decides the handling: a duplicate number is mechanically renumberable, whereas a gap blocks the repository, so allocation stays optimistic and reconciliation happens before the merge rather than after. Numbering was re-verified after the merge rather than inferred from a clean merge — 154 decision records, contiguous 001 through 154, zero duplicates and zero gaps.

**A degraded measurement is now structurally unable to present itself as a clean one.** The impact tracer previously emitted an identical envelope whether it had attempted a traversal and found nothing or never attempted it at all — the two runs differed at exactly one byte, an echo of the caller's own input. The fix adds a measurement state as one optional merged object rather than bumping the schema version, and the emitting library enforces the absence rule itself: when a status reads `degraded` or `not-run`, the paired count key is deleted rather than left at zero. A caller cannot forget to withhold the number, because the caller does not perform the withholding. This is a real depth-1 run against a tracked file:

```json
{
  "total_files_scanned": 1497,
  "first_order_count": 0,
  "filtered_mirrors": 0,
  "elapsed_seconds": 1.0,
  "second_order_status": "not-run",
  "second_order_status_reason": "depth<2: second-order traversal not attempted (--depth=1)",
  "unreadable_files": 0,
  "scan_scope": "tracked",
  "scan_scope_status": "fetched"
}
```

`second_order_count` is absent, not zero. A consumer that reads it must branch on the status first.

**The release's own new check ran in production against a real outage during the close.** The graduation check hit a genuine API rate limit and emitted its withheld-verdict form — every per-item verdict withheld, no counter emitted, and the explicit statement that this is not a clean result — rather than reporting a clean zero. That is the release's thesis behaving correctly against an unplanned failure rather than against a fixture.

**Four decision records were authored on one branch, and their numbering provenance is recorded in the records themselves.** ADR-151 through ADR-154 carry their own renumbering history in their `status:` fields, including which branch-local number each held and why it moved. In-release citations that name the earlier numbers denote the same records. Ratification state is verified by reading each file's `status:` field, never inferred from milestone closure.
