# Security hooks stop blocking work they were never guarding

2026-08-09 · v4.20

A broken or out-of-date support file used to hard-block every command and every file write, even for operators who had explicitly turned the relevant check down to logging. That stops here — and the platform now states, in one place, what may be quoted from its own private working notes onto a public page.

## Who this affects

- **Operators who have turned one or more security checks down to logging or off.** Those checks now degrade instead of hard-blocking when their support file is missing or stale.
- **Operators running every check at full strength.** Nothing changes for you — the strictest setting still refuses to run, by design.
- **Anyone whose work reaches a public issue, pull request or release page.** There is now a stated rule for what may be quoted there from private notes.

## What you need to do

1. **Re-run the workspace setup with the hook-wiring re-home** — `docs/scripts/setup-workspace.sh --rehome-hook-wiring`. Until this runs on your machine, the checks in this release do not load in sessions rooted inside a repository copy, so the new path-leak guard is *available but not in force*. Nothing in the repository can perform this step for you or detect that you skipped it.
2. **Read the install validator's hook-wiring verdict before you read any log result.** An empty log after step 1 means clean. An empty log before step 1 means the instrument was never connected — the two look identical, and only the validator tells you which one you are looking at.
3. **Update your prompt-composition surface** so the new pre-launch brief scan actually runs. Until you do, the scan is present but never fires on your machine.

## What changed for everyone using the platform

- **A broken support file no longer blocks work unrelated to it.** Nine security checks used to refuse every command and every file write when a shared helper was missing or out of date — regardless of how the operator had set that check. They now step aside for operators who set them to logging or off, and say on screen that they did, naming the file to reinstall. *Why it matters:* an operator on a partly-updated install can work again instead of being stopped by a guard that was never watching the thing it blocked.

- **The strictest setting still refuses, and you can check that rather than take it on trust.** Every one of the nine checks still fails hard at full strength, asserted individually. Four further checks that have no reduced setting at all were deliberately left untouched. *Why it matters:* the change loosens exactly the cases an operator asked to be loosened, and cannot quietly lower the floor for anyone who did not ask.

- **There is now a written rule for quoting private working notes onto a public page.** It says which material may cross from the platform's own private analysis area onto an issue, a pull request or a release page, and which may not. It found a real leak the week it landed — in a reviewer's own draft, before that draft was posted. *Why it matters:* the boundary was previously a matter of individual judgement exercised under time pressure, and a public page cannot be un-published.

- **An agent that hits a blocked action now has two named legitimate moves, and no third one.** It may reword the request when the objection is to the wording, or report the block and stop. Disguising a word to slip past a check is now named as prohibited, with a catalogue entry describing how that failure looks. Every agent run reports whether any check fired, including when none did. *Why it matters:* the rule was written after an agent disguised a word to get past a check, and nothing in writing said not to — a clean run and an evasive one used to produce identical output.

- **The public-path check can now be turned up or down on its own.** It reads its own setting file instead of sharing one dial with seven other checks, so changing it no longer moves them too. It ships set to record-only. *Why it matters:* tightening this one check previously meant tightening seven unrelated ones with no trial period.

## Known limits

- **This release delivers two of the three outcomes it was bundled to deliver, and the third was never in it.** The bundle promised that a certain lexical matcher would stop flagging ordinary prose and code comments. **No change in this release touches that matcher, and it is not fixed.** The work item behind that promise always delivered the agent-conduct rule described above — how an agent responds when a check fires — which is a different thing from making the check itself precise. The bundle description mis-named the item when it was written, before any work began; this is a description error, not work that fell short. Matcher precision remains open.
- **The public-path check records rather than blocks.** What ships is the ability to set it independently — not a decision to tighten it. Tightening is deliberately held until there is real log data to read.
- **That log data does not exist until you run step 1 above, and nothing forces you to.** The check does not load in repository-rooted sessions until the re-home runs, so its log stays empty in a way indistinguishable from a clean result.
- **The pre-launch brief scan does nothing on your machine until you update the composition surface** (step 3). It is shipped and correct; it is simply not wired in yet.
- **Two rules stated as universally required are still not checked by anything.** They now say so plainly instead of reading as guarantees. One of the two predates this release and was found while correcting the other.
- **One acceptance criterion closed as partially met** and awaits a recorded decision on whether to accept it as-is.
- **One remedy that would confirm the agent-conduct rule reached each launch cannot be built yet** — the platform does not currently expose the finished prompt text that would have to be inspected.

Report issues at [github.com/cody-hutson/pmo-platform/issues](https://github.com/cody-hutson/pmo-platform/issues).

## Reversibility

MODERATE / HIGH confidence. Every repository change comes out together by reverting the release merge commit, and reverting restores the old always-refuse behaviour — the safe direction, so a rollback carries no security regression. Two things do not come back that way: the public-path check's operative setting lives in a file outside the repository, so a revert restores the shipped template rather than your setting (record it before you change it); and the hook-wiring re-home is an operator action outside the repository that a revert cannot unwind. Rollback is operator-authorised; nothing rolls back on its own.

### Operator and engineering detail

**The mode read is hoisted into a read-only value above the dependency guard, and that ordering is the security property.** The guard sources an untrusted helper library inside its own condition. A hostile or corrupted library that defines a permissive mode reader would overwrite a merely-hoisted definition and yield a success exit with `enforce` on disk — so the mode is snapshotted into a value the sourced library cannot redefine. The degrade path also had to emit on stderr rather than exit silently: the agent-conduct rule gives a spoke exactly two moves when a control fires, and a silent success leaves nothing to surface, making the sanctioned move unavailable by construction.

**The path-leak rule left the shared cohort, which is why a scoped posture change is possible at all.** The shared mode file covered eight hooks; flipping it would have promoted seven out-of-scope hooks with no shakedown. Three hooks already carried their own mode file, so per-hook scoping is established precedent rather than invention. The cohort now reads seven, reconciled by deriving the set with grep and diffing it against the enumerated names in both directions. This is the shape of the new operator-local file and of the notice the guard now prints instead of hard-blocking:

```
# .gh-path-leak-mode — operator-local, git-ignored, one bare word.
# Shipped template content, and the hook's own default when the file is absent:
warn

# What the guard prints on stderr in warn / off, instead of refusing to run:
[CLAUDE-HOOK:block-gh-path-leak:LIB-MISSING] WARN (degraded, .gh-path-leak-mode=warn):
dependency helper lib/dep-resolve.sh unavailable or invalid; ALL rules for this hook
are skipped this run. Reinstall the hook bundle (re-run docs/scripts/setup-workspace.sh)
to restore enforcement.
```

**The over-block clears rather than relocating, and it initially relocated.** The first build moved the hard-block from one condition to another while still hard-blocking; that was found and fixed mid-pipeline. What ships removes the over-block for the version-skew case the work item's own problem statement describes. It is *not* removed for the library-absent case, and cannot be while three always-enforce hooks retain an unconditional non-zero exit on a missing library — those hooks have no reduced state to degrade into, and inventing one would weaken a floor. The acceptance criterion was restated to the achievable outcome and the second case recorded as a deliberate retained residual, rather than left implying a removal that did not happen.

**One stated rationale for the change was found false, and the change shipped anyway with the rationale corrected.** The dependency-backstop invariant does not hold: a syntactically-valid but corrupt library makes all three always-enforce guarantors exit zero silently, because a syntax precheck checks syntax, not meaning. The coupling work is correct; only its justification was overstated. The defect is pre-existing and is filed separately at [#5071](https://github.com/cody-hutson/pmo-platform/issues/5071) rather than folded in here.

**A companion obligation fired that the plan had recorded as not-applicable, and the plan's reasoning was incomplete rather than wrong.** No new executable script was added — but the brief-path convention makes an *existing* source-only script agent-executed, which triggers the same allowlist obligation. Without it the new pre-launch guard is blocked on every launch and the feature is dead on arrival. It was found empirically, by the control firing on the authoring session's own invocation. The generalisable rule: the obligation triggers when a script becomes agent-executed, not only when one is added. The same class recurred at this close — the tool the close is mandated to run for its throughput figure carries no allowlist entry either, so that figure was computed from the written definition instead.

**The decision record collided across two directories in a way git cannot see.** A sibling release merged first and took `ADR-129` under the release directory while this branch carried `ADR-129` under the core directory. Because the paths differ, a merge preview exited zero with no conflict, and the merged tree would have carried two `ADR-129`s and no `ADR-130` — silently, with the integrity gate then failing every subsequent pull request. It was renumbered to [ADR-130](https://github.com/cody-hutson/pmo-platform/blob/main/core/ADRs/ADR-130-lib-missing-guard-is-mode-coupled.md), which supersedes the prior fail-closed determination. The renumber tool's citation sweep then rewrote three *historical* sentences in the release plan's decision log — statements about which number was free at a past instant, which must not move — leaving the log contradicting itself. They were restored verbatim and the event recorded separately, and the tool's dry-run discrepancy is filed at [#5080](https://github.com/cody-hutson/pmo-platform/issues/5080). An automated citation sweep over prose is safe for references and unsafe for history, and a decision log is mostly history.

**Post-deploy operator actions, restated here because the release is not fully realised without them.** The hook-wiring re-home extends hook loading to repository- and worktree-rooted sessions; until it runs, the path-leak guard is inactive at any setting and its log is empty for the wrong reason. The composition-surface update is what makes the pre-launch brief scan fire. Neither is visible to the repository, so neither can be gated by it — they are tracked operator actions with a stated verification, not deferrals. The related gap that two tracked hook mode templates have no install call site is filed at [#5073](https://github.com/cody-hutson/pmo-platform/issues/5073).
