# Stage 3 Bundling becomes a self-triggering composer

2026-07-02 · v3.56

Stage 3 — the step where approved work gets grouped into a release — becomes more automated and self-aware. It can now notice on its own when enough approved work has piled up to warrant a release, derive the order releases should sequence in from their dependency graph, and declare whether a given release carries a version number or ships "version-less" — without an operator hand-cranking those steps.

## What changed for everyone using the platform

Mostly internal pipeline automation — no change to day-to-day project work. For operators running releases:

- **A queue-depth monitor** now warns when the approved-but-unbundled backlog crosses the bundling threshold (≥5). *Why it matters:* a release-worthy pile-up surfaces on its own instead of sitting unnoticed until someone thinks to check. (Logged, not blocking, for now.)
- **Milestone positions** (the order releases sequence in) can now be derived automatically from the dependency graph. *Why it matters:* the sequence comes from the actual dependency edges rather than a hand-set value that can drift stale.
- **Version-less releases** are now a first-class, documented choice. *Why it matters:* releases that legitimately ship without a version number are handled explicitly instead of as an exception the pipeline fights.

## Known limits

- The version-identity *enforcement* across the gate/taxonomy/protocol surfaces is a separate follow-up (#3016) — this release codifies the Stage-3 declaration; the downstream enforcement is not yet wired.
- The queue-depth monitor's priority reporting is label-derived (canonical priority lives in a Projects field it can't read yet).
- The new deploy checks (52, 53) are logged but not blocking initially.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

MODERATE / HIGH confidence. Additive tooling + standards; `git revert -m 1` of the integration PR reverses the release cleanly. No data migration. Standard rollback window.
