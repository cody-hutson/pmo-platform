# The deploy step again detects and syncs the skills an update changed

2026-06-20 · v2.06.1

A patch release fixing the platform's own deploy tooling. The deploy step had stopped reliably detecting which skill files an update changed, so on macOS some edits could be left unsynced after a deploy. This restores correct detection.

## What changed for everyone using the platform

- **The deploy step again detects and syncs every changed skill on macOS.** Two defects in the deploy step's change-detection — a sidecar-file mis-enumeration and a text substitution that did nothing under the macOS version of its text tooling — were repaired. *Why it matters:* a deploy now propagates exactly the skill files you changed, so what runs in your workspace matches what you edited; before this fix an edit could silently fail to sync.

## Known limits

- This is a fix to the deploy step only. It changes no skill's behavior or output, and no project content.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `project:ci-and-deploy-reliability` label.

## Reversibility

CHEAP / HIGH confidence. The change is confined to the deploy step's change-detection logic; `git revert -m 1` of the integration PR reverses it. Standard rollback window.

### Operator and engineering detail

**Deploy-detection repair (#1475).** The `--deploy` change-detection pass mis-enumerated skill sidecar files and relied on a `sed` alternation that is a no-op under BSD `sed` (macOS), so it could under-report which skills an update had modified — leaving edited skills unsynced. The fix corrects the sidecar-enumeration anchor and rewrites the substitution to a BSD-safe form, restoring the intended detection on macOS. Patch release on top of the `36-ci-gate-trustworthiness-and-parallel-pr-safety` milestone.
