# Your people directory is set up for you on install

2026-06-26 · v2.26

The platform now creates a people directory for you when you install it, and the getting-started guide walks you through filling it in and putting it to use. The people-aware features that arrived in the previous release now work out of the box instead of sitting dormant on a fresh install.

## What changed for everyone using the platform

- **Your people directory is created for you, and never overwritten.** A fresh install adds a starter people file for you to fill in with your team, and updates leave a filled-in copy untouched. *Why it matters:* the people-aware features work from the start, and the real contact details you add are safe across every future update.
- **The getting-started guide now walks you through adopting it.** A new section covers creating the directory, filling it in, and pointing each project's, portfolio's, and program's owner at a person in it. *Why it matters:* you can roll it out across your projects straight from the guide instead of reverse-engineering how it fits together.

## Known limits

- The people directory is yours to maintain — it lives only on your machine and never enters the codebase. Until you fill it in from the starter file, the people-aware features fall back to the previous per-project behavior; nothing breaks, but the directory has nothing to resolve against yet.
- The directory is for functional coordination — who does what and who covers whom — and is explicitly **not** an HR or performance system.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `cluster: data-architecture` label.

## Reversibility

MODERATE / HIGH confidence. `git revert -m 1` of the integration PR reverses the release; a directory you have already filled in is preserved by the never-overwrite guard rather than regenerated, so reversion is clean. 30-day outcome window.

### Operator and engineering detail

**Seed mechanism (#2040)** — the roster is seeded create-once from the de-identified template at three sites: `docs/scripts/setup-workspace.sh` (the primary scaffold, with the rollback ledger), `install.sh` (an idempotent belt-and-suspenders guard), and `update.sh` (preserve-on-update), all resolving the path through a new `pmo_people_roster()` accessor in `lib-instance-path.sh`. The never-clobber `[ -f ] -> PRESERVED` guard is the load-bearing protection; a QA hard-gate confirmed a filled roster is byte-unchanged after re-running install and update, because a clobber of real contact data would be unrecoverable.

**Consumption verification (#2042)** — a binary-judge eval exercises `comms-writer`, `tracker-manager`, `ppm-agent`, and `delivery-engine` resolving a specific value from a populated fixture roster, asserting read-only and non-triviality (an empty roster must resolve nothing).

**Version note** — v2.26 was claimed manually as the verified-free version after a concurrent release published v2.24 and a live-but-unpublished v2.25 tag sat on mainline; the claim tool's blindness to a mainline tag without a published Release is tracked in #2075.
