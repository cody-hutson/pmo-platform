# Two editing disciplines are now part of the platform's core

2026-06-20 · v2.10

This release writes down two working disciplines that were previously informal, and links them into the place where decisions get made. Neither is a user-facing feature — they are rules the platform follows when it edits and decides — but they change how the agent behaves when it touches your artifacts.

## Who this affects

- Anyone whose work the platform edits or maintains — the two disciplines govern how the agent handles a stale or contradictory document it is touching, and how rigorously it applies a "canonical form" when one is required.
- Nothing changes in how you invoke the platform; the disciplines take effect on deploy.

## What you need to do

1. Run `update.sh` to deploy this release — this lands the two new discipline docs and the updated CLAUDE.md template into your workspace.
2. (Optional) Re-sync your local `CLAUDE.md` from the template if you keep it in sync — three preference entries (Surgical edits / Verify before recommend / No status theater) now cross-link to the new reconcile-don't-annotate discipline.

## What changed for everyone using the platform

- **"Reconcile, don't annotate" is now the default when the agent touches a stale artifact.** When the platform edits a document that carries out-of-date or contradictory content, the rule is now to fix it to current state — not to leave a "this looks stale" comment and move on. *Why it matters:* you get the document reconciled, not a pile of correction notes that still leave the body wrong.

- **A canonical-form framework replaces all-or-nothing formalization.** When a required "canonical form" applies (an ADR, a retro, a decision record), the discipline lets the agent either produce that artifact or document partial conformance with an explicit reason — instead of over-formalizing everything or skipping the form silently. *Why it matters:* the right amount of structure gets applied, and any shortfall is stated, not hidden.

- **A 7-frame registry points to each canonical-form template without duplicating it.** The framework names the seven recognized forms and points to where each one's template lives, rather than copying them. *Why it matters:* one place to find which canonical form applies, with no drift between copies.

- **Both disciplines surface at the moment you are deciding or editing.** They wire into the platform's decision discipline (and the reconcile rule cross-links from the CLAUDE.md preferences), so they fire at the decision and edit point rather than sitting in a doc no one reads. *Why it matters:* the disciplines actually get applied, because they appear where the work happens.

## Known limits

- The seven per-frame templates themselves (for five of the frames) are referenced but not yet built — they ship as follow-on items.
- Two finishing touches for the reconcile discipline are operator-side: condensing the corresponding memory note to a pointer, and syncing the cross-links into your local `CLAUDE.md`.
