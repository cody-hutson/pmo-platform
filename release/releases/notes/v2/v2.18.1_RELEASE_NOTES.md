# Operator-instance path decoupling (v2.18.1)

2026-06-22 · v2.18.1

The operator-instance and PII-needle paths were resolved by several inconsistent hardcoded paths across the deploy tooling and the PII pre-commit guard — so relocating the instance silently degraded the guard (it failed *open*). This release converges them onto one resolver and closes that gap.

## What changed for everyone using the platform
- **One resolver.** All instance/needle path reads in the deploy tooling and the PII hook go through `core/deploy/lib-instance-path.sh` (`${CLAUDE_WORKSPACE_ROOT:-$HOME/Claude}` per ADR-032; `PMO_INSTANCE_PATH`/`PMO_LOCALIZED_NEEDLES` still honored as overrides). No new variable invented. *Why it matters:* relocating your workspace no longer silently breaks the PII guard, because every tool now reads the same one place for where your instance lives.
- **Template + create-once scaffold.** The repo ships `core/config/localized-context-needles.txt.example`; install/update create your local needle file from it only if absent — your names live local + gitignored, never committed (the `.env` / `.env.example` pattern). *Why it matters:* you get a fillable starting point and your private names stay out of the repo, instead of having to hand-build the file or risk committing it.
- **Persistence.** `update.sh` never regenerates your needle file (pre-update backup + a byte-identical round-trip test guarantee it survives updates). *Why it matters:* running an update can no longer wipe or overwrite your local PII-guard list.
- **Fail-closed guard.** When an operator instance exists but the needle file is missing or still the untouched example, the PII pre-commit guard now fails **closed** (distinct messages) instead of silently skipping; a genuinely fresh clone only warns. Ships warn-mode-initial, flips to enforce after a shakedown window. *Why it matters:* a misconfigured guard now stops you with a clear message rather than quietly letting your names through to a commit.
