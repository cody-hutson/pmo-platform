# Intake checks more of a work item's form, and keeps its priority in sync

2026-06-20 · v2.12

This release tightens how work items are filed and graded. The intake readiness check now covers more of a work item's form, a work item's body-stated priority is kept in sync with its tracker field, and the improvement form gains an optional domain tag. The new form-level checks ship in warn mode — they flag, they do not yet block.

## What changed for everyone using the platform

- **The intake readiness check now covers more of a work item's form, in warn mode.** The Stage 1 readiness criteria gained a hard-stop / soft-warn split across all nine checks, shipping as a warning for now. *Why it matters:* a thin or malformed work item is flagged when you file it, so gaps are caught early — and because it is warn mode, nothing you file is blocked during the shakedown.
- **A work item's body-stated priority stays in sync with its tracker priority field.** The body is treated as the source of truth and its priority is reflected onto the tracker's Priority field. *Why it matters:* the priority you write and the priority shown on the board no longer drift apart.
- **You can tag an improvement's domain when you file it.** The improvement form gains an optional Domain dropdown. *Why it matters:* improvements can be grouped and routed by domain from the moment they are filed, instead of being inferred later.

## Known limits

- The new form-level enforcement ships in **warn mode**; the warn → block flip is a deliberate follow-on after a shakedown period.
- The priority-sync is a narrow first slice of the broader field-first direction (body fields over label/text parsing), not the whole of it.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `project:intake-governance` label.

## Reversibility

MODERATE / HIGH confidence. The changes are additive and the new enforcement is warn-mode, but the priority-sync touches how a tracker field is written, so a rollback should confirm no field was left stale. `git revert -m 1` of the integration PR reverses the release; standard rollback window.

### Operator and engineering detail

A `field-first-intake-enforcement` release on milestone `12-field-first-intake-enforcement` (#197), three cards on one release PR (#1699), D-C SINGLE topology — no `SKILL.md` and no packages touched (deploy no-op; validation carried by green PR CI).

**#27 — G1 enforcement-layer split.** `core/schemas/gate-criteria-spec.md` gains a HARD-STOP / SOFT-WARN policy across the nine G1 readiness criteria; `core/deploy/deploy.sh` Check 22 is extended to evaluate all nine (evaluate-9 / enforce-5 / recommend-flag-4) behind a new decoupled `g1-enforcement.mode` knob that ships **warn**. The decoupling is what lets the future warn → enforce flip touch only Check 22.

**#54 — body → Projects priority sync.** A new G2-12 gate plus a Priority-Model block establish the work-item body as canonical for priority and sync it onto the Projects Priority field — a narrow, observed-slice deliverable of the larger field-first data architecture.

**#344 — Domain on the intake form.** The improvement issue template gains an optional Domain dropdown; the three `.github/ISSUE_TEMPLATE/` forms also pick up stale-path corrections.

**Versioning note.** The number re-versioned `v2.12 → v2.14 → v2.12` as concurrent siblings tagged v2.13 and v2.14 mid-flight; on re-verification at tag time v2.12 was the free sub-ceiling gap with no plan-file collision, so it settled back to v2.12 (operator-directed, re-verified free at tag time).
