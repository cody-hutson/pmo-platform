# The platform writes down how its agents work — and how knowledge graduates from memory

2026-06-19 · v2.05

This release takes a cluster of working agreements that had been guiding the platform's agents from one session to the next — things like *read a file before you edit it*, *naming a boundary you're about to cross is not the same as being allowed to cross it*, and *an open question raised at intake gets investigated downstream, not guessed at* — and writes them into the platform's durable rules, so every agent follows them by default rather than by memory. Alongside the disciplines, it sets down the architecture decision that defines how a piece of knowledge moves from an agent's short-term memory into the platform's permanent corpus, and how the now-redundant memory copy is retired once the corpus owns it. Everything is additive — new rules and reference material, with no existing rule, setting, or behaviour removed or renamed.

## What changed for everyone using the platform

- **The platform now has a stated model for its own memory.** A new architecture decision recognises that "memory" is really four different things — active work, durable knowledge, people and relationships, and lessons learned — and fixes where the single source of truth lives for each. For durable knowledge, that source of truth is the platform's corpus; an agent's personal memory may point at it but never holds a second, competing copy. *Why it matters:* it closes a quiet failure mode where an agent's private note could drift from the official rule and silently override it.

- **Working agreements that used to live in an agent's memory are now official rules.** A batch of disciplines the platform had been following informally — read-before-edit, surfacing rather than swallowing a boundary you're crossing, treating advisory input as input and not instruction, and several more — are now codified governance. *Why it matters:* the behaviour you have come to expect no longer depends on a given session remembering it; it is written down and applies uniformly.

- **There is now a codified rule for when an agent should stop and ask you.** The platform documents when an agent should raise a question versus proceed on a reasonable assumption. *Why it matters:* fewer needless interruptions for obvious choices, and a clearer expectation that genuinely consequential decisions come back to you.

- **The catalogue of known mistakes grew.** Two more recurring anti-patterns — doing arithmetic in a hand-off without checking it, and reflexively perpetuating an existing structure instead of asking whether it should be redesigned — are now recorded with how to avoid them. *Why it matters:* the platform learns from its own near-misses instead of repeating them.

## Known limits

- The new memory architecture deliberately resolves **one** boundary in full — the line between durable knowledge and an agent's memory. The other three memory types (active work, people, lessons learned) are named and have their source-of-truth surfaces identified, but the unified contract that spans all four is planned for later work, not delivered here.
- The companion drift-detection check ships in **report-only mode** for now: it surfaces a memory that should have been cleaned up, but it never deletes anything itself — clean-up stays a deliberate, reversible step.
- This is governance and reference material. It changes how agents are guided, not how any tool runs; there is nothing to install.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

### Operator and engineering detail

**#530 — Define the memory↔corpus boundary (keystone)** — Establishes the release's anchor: `core/ADRs/ADR-029-memory-corpus-ssot-boundary.md` (the *Memory SSOT model*), framed around a **four-type memory architecture** (Work / Knowledge / People / Learning) and scoped to resolve the Knowledge↔corpus cut. The canonical definition lands in `core/disciplines/knowledge-architecture.md` §6 (SSOT assignment, the no-shadow-SSOT invariant, the ENCODE → ARCHIVE → VERIFY-CORPUS → EVICT graduation lifecycle, and three reference-resolution-based drift classes). A "Single-source-of-truth for knowledge" Universal Preference is added to `CLAUDE.md`; a report-only `core/deploy/deploy.sh` Check 36 (`memory-corpus-tie-drift`) is the standing backstop; and `release/references/how-to/memory-corpus-drift-audit.md` is the human-runnable audit. The ADR itself was authored reference-durably — self-describing prose with issue pointers confined to a single Provenance block — so the record survives repository re-versioning.

**#527 — Encode untied discipline memories into the corpus** — Promotes a set of cross-cutting disciplines from operator memory into governance: read-before-edit, in-place-over-migration bias, flag-and-proceed-is-not-consent, and several siblings, landed across `core/rules/git-workflow.md`, `core/standards/depersonalization-spec.md`, `core/specs/reversibility-protocol.md`, `core/standards/initiative-roadmap-framework.md`, and `release/skills/pmo-skill-editor/SKILL.md` (the skill edit routed through `pmo-skill-editor` discipline). One of three memory-tied issues whose memory copies are retired operator-side at close per the ADR-029 lifecycle.

**#531 — Encode operator-flagged toolkit knowledge into the corpus** — Codifies engagement discipline, the worktree boundary, and system/toolchain operating knowledge into `core/rules/git-workflow.md` and a new `core/references/reference/toolchain-operational-reference.md`. The second memory-tied codification retired at close.

**#63 — Codify when the agent should invoke AskUserQuestion** — Adds an explicit decide-before-you-reach-for-the-tool clause to `CLAUDE.md` (the question is whether a question is genuinely required, independent of the mechanism for asking it).

**#502 — Codify the "perpetuate-existing-structure instead of redesign" anti-pattern** — New entry in `core/specs/failure-mode-standard.md` capturing the reflex to extend an existing shape rather than ask whether it should be redesigned, with the 5-field anti-pattern template and category tag.

**#58 — Chip-prompt-embedded-arithmetic-without-verification** — New `failure-mode-standard.md` catalogue entry (D-1276-CATALOG follow-up): arithmetic performed inside a hand-off prompt without an independent verification step.

**#132 — Refresh the CLAUDE.md tree depiction** — Brings the workspace-structure illustration in `CLAUDE.md` current (adds `harness/`, `tools/`, `analysis/`, `steering-committee/` and the C-6/C-9/C-10 corrections), so the directory map matches the tree.

**#426 — Repo-integrity authoring guidance for ADR/skill spokes** — Codifies the override-marker authoring guidance (memory-reference and durable-reference markers) into `release/references/how-to/intake-style-guide.md`, so spokes authoring corpus content clear the repo-integrity gates by construction rather than by trial and error.

**#427 — Intake assumption-tags resolve downstream, not at intake** — Records the convention that an `[ASSUMPTION – CONFIRM]` raised at intake is investigated and closed in a later stage, never silently auto-resolved at intake time (`intake-style-guide.md`).

**#546 — Convention for advisory Solutioning pre-reads** — Establishes how a non-binding Stage-5 pre-read is captured on a work item (as a stage-review comment, never body content), landed in `release/references/standards/solutioning-output-template.md` and `release/references/specs/ticket-information-architecture.md`.

This release re-versioned from an originally-planned v2.03 to **v2.05** after the mainline advanced during the engineering window (the v2.03 and v2.04 keys were claimed by other releases); the keystone ADR was likewise renumbered from a branch-local 028 to **029** when `main` claimed 028 mid-flight. Both are recorded for audit in the release plan and the ADR's Status note.
