# On-demand health-check rollups, sharper skill-routing conflict detection, and a clearer SKILL.md sizing rule

This release hardens the skill suite in three independent ways: you can now refresh a project-or-portfolio rollup on demand instead of waiting for the scheduled cadence, a new audit catches skill-routing collisions the old word-overlap check missed, and the guideline for how long a SKILL.md may be is now written down clearly so compliant skills stop reading as "too big."

## What changed for everyone using the platform

- **Refresh a rollup whenever you need it (#155).** `health-check` gains a `rollup` mode. `rollup --scope portfolio` re-composes the portfolio snapshot from every active project's rollup; `rollup --scope project --depth full|status` refreshes a single project from its own milestones, RAID, plans, and resources. It always **stages** the proposed `PORTFOLIO.md` into `08-Generated/_health-check/` for your review — it never edits the live portfolio file for you.
- **Catch skill-routing collisions that look different but mean the same thing (#2699).** A new audit (`run_routing_audit.py`) compares what each skill *means* it activates on — not just the words it uses — so two skills that would both fire on the same request get flagged even when their trigger phrasings barely overlap. It runs offline by default with no extra setup; a richer semantic pass is available opt-in.
- **A clear rule for how long a SKILL.md may be (#3114).** The "keep it under ~500 lines" guideline is now documented as an *advisory* authoring aid, distinct from the hard rule (a skill that grows past the threshold must carry a `references/` folder). Skills that legitimately need to be longer — and already offload detail to `references/` — are compliant, and no longer flagged as oversized.

## Known limits

- The routing-conflict audit ships with an offline stand-in backend by default; finding *real* semantic collisions requires opting into a live embedding backend (an operator-configured step). A default run proves the pipeline works, not that the skill catalog is collision-free.
- The `rollup --scope portfolio` composition is a **proposal** staged for review; promoting it into the live `PORTFOLIO.md` remains a human step, by design (the portfolio file is owned outside this tooling).

## Reversibility

**CHEAP / HIGH confidence.** Every slice is additive — a new skill mode, two new audit scripts, one new ADR, and one additive governance-doc paragraph — with no change to existing behavior (the seven prior `health-check` modes and the shared output contract are byte-identically preserved, and the lexical audit script is untouched). A single revert of the release restores the prior state cleanly. Standard rollback window.

### Operator and engineering detail

**Three disjoint slices, one PR (#3540), re-anchored to v3.77.** The bundle shipped as one release branch with three non-overlapping file sets. **#2699** builds `run_routing_audit.py` — a three-tier pipeline (Jaccard pre-filter imported read-only from `run_eval_audit.py` → embed + cosine on the sub-floor candidate set → optional agent-runtime judge) with a **lazily-imported, pluggable embedding backend and a stub fallback**, so the module imports and its tests run with no pip install and no network (the zero-dependency offline CI contract of the eval-scripts corpus is preserved by construction). The dependency posture is recorded in **ADR-084** as the corpus's first optional-heavy-dependency precedent. **#3114** adds a `### Threshold semantics` subsection to `canonical-skill-structure.md §5` separating the soft ~500-line authoring guideline from the hard, script-enforced `references/`-requirement (`C6_LINE_THRESHOLD=400`); additive only, no skills were edited or split. **#155** extends `health-check/SKILL.md` with the `rollup` mode under a **compose-not-absorb** scope-lock (ADR-019): `--scope portfolio` invokes `weekly-status-rollup` Section 6 for the actual `PORTFOLIO.md` composition rather than re-implementing it, and honors the bridge-file boundary by staging the proposal to `08-Generated/_health-check/` and never writing the live file.

**Re-anchor from provisional v3.75 → v3.77.** While this milestone ran Stages 6–9, two concurrent releases claimed `v3.75` (skill-and-data-entity-hygiene) and `v3.76` (knowledge-corpus-hygiene); the version is bound only at the Stage-12 tag-claim, so this release re-anchored forward to the next-free minor with no content change — only the version labels and one ADR number (083→084, to clear a collision with a concurrent release's canonical-install ADR) shifted. The commits were re-signed so the merge landed on a `CLEAN` branch-protection state with no admin override. All three slices carried a Stage-8 acceptance verdict of ACCEPT (#2699 4/4, #3114 3/3, #155 6/6) and a Stage-9 GO.
