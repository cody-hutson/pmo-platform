# The checks the platform promises now actually run

2026-08-07 · v4.13

The platform advertised self-checks on dozens of its own tools and automatically ran six of them, so a recorded "check passed" was a claim someone had made rather than something anyone had observed. This release makes every advertised check run on its own, and repairs three checks that were silently missing what they existed to catch.

## What changed for everyone using the platform

- **Every self-check the platform advertises now runs automatically.** A hand-maintained list of six tools was replaced by a search that finds all of them — 57 today, across both tool folders and every file type they use. *Why it matters:* a "check passed" line in a release record now means something ran, rather than that someone remembered to add that tool to a list.

- **The new gate caught a missed registration during this very release, without being asked.** A companion piece of work added a new tool and did not register it; the gate's own record of what it found last time refused to match, and the tool was registered mid-release. The enforced count moved from 56 to 57 on real work, not in a test. *Why it matters:* this is the first evidence that the two failure directions are both covered — the search catches what is newly added, and the recorded count catches what quietly disappears.

- **The work-hierarchy check stopped losing findings to apostrophes.** It read an apostrophe as the opening of a quoted passage and skipped past everything that followed, and it never looked at two whole folders. It now examines 727 places where it previously reached 540. *Why it matters:* a check reporting "nothing found" is only worth reading if it actually looked, and this one was looking at three-quarters of what it claimed to cover.

- **The impact tracer finishes instead of dying quietly.** Asked to trace two steps out from a heavily-referenced file, it could run roughly half an hour and then exit reporting success with an empty result. The same trace now takes 32 seconds where it used to take 282, and a scan that has to stop early now says so. *Why it matters:* an empty answer that looks like a clean answer is worse than an error, because nobody re-runs it.

- **Nine scripts and test suites are no longer blocked from running.** They are now registered in the platform's list of runnable commands, in all four ways a command can be written. *Why it matters:* an agent asked to verify something can run the check instead of reading the file and reporting on what it claims about itself.

- **The gate's first run found a check that had been passing without measuring anything.** A check that runs at the close of every release reports "no drift" on the platform's build machines regardless of whether there is any drift, because of how it strips a file header there. *Why it matters:* it is now known, tracked, and being fixed — but until it is, a green result from that one check is not evidence.

## Known limits

- **One of the 57 self-checks is found but not enforced.** It cannot reach a verdict on a build machine, so it is carried as a deliberate exclusion with a standing warning on every run rather than quietly dropped. Tracked in [#4913](https://github.com/cody-hutson/pmo-platform/issues/4913).
- **Three tools can only run their self-check on one kind of machine** and are routed there by name. Two of the three are waiting on the header-stripping fix described above. Tracked in [#4912](https://github.com/cody-hutson/pmo-platform/issues/4912).
- **One self-check guards part of its tool and not the rest** — it pins the piece that resolves paths but not the guard beside it, so that guard could be deleted and the check would stay green. Tracked in [#4914](https://github.com/cody-hutson/pmo-platform/issues/4914).
- **Six committed test suites are referenced by no automated run.** They sit outside what this release's search covers by design; the run reports them by name on every pass so the gap stays visible rather than assumed closed.
- **The tracer's safety cap has never fired.** It is set above the busiest file in the repository today, so it protects against future growth rather than anything currently present.

Report issues at [github.com/cody-hutson/pmo-platform/issues](https://github.com/cody-hutson/pmo-platform/issues).

## Reversibility

CHEAP / HIGH confidence. Every change is added content, a single-sentence correction in place, or a contained fix inside one tool; nothing is renamed and no identifier moves, so reverting the release commit restores the previous behavior with no residue. The one asymmetry worth naming: reverting the new gate after fixes have landed under it would leave those fixes in place with nothing running them — a quieter state than before the release, not a broken one.

### Operator and engineering detail

**Discovery with a committed floor, because neither half works alone.** [ADR-119](https://github.com/cody-hutson/pmo-platform/blob/main/release/ADRs/ADR-119-selftest-coverage-is-discovered-with-a-committed-manifest-floor.md) records the decision. Discovery alone cannot detect a deletion — a tool whose self-test is removed simply stops being discovered, and the set shrinks silently. A committed manifest alone cannot detect an addition — it is the hardcoded roster this release exists to retire, one level up. The two are load-bearing together: the scope directives declare where to look, the recorded paths are what that look found last time, and the two are co-located on purpose so narrowing a directive forces the deletion of its paths in the same diff, in the reviewer's eye. Precision lives in a separate exclusions file where every suppression costs a written, attributable reason; the discovery predicate itself is deliberately recall-biased, because a false negative is an unenforced self-test — silent — while a false positive is one line and loud.

The three shapes this release introduces, all machine-read:

```
# scope: release/tools/*.sh              <- the manifest declares WHERE to look
release/tools/blast-radius.sh            <- and records what that look found
release/tools/claim-version.sh

# exclusions file: the reason is mandatory; an entry without one is a parse error
release/tools/cleanup-orphan-state.sh  # F4 non-hermetic: unreachable on a CI runner

# a tool's own header: declares which runner can execute its self-test
# selftest-runner: macos
```

**A stated root cause was refuted by instrumentation, and the fix changed accordingly.** The tracer card attributed the hang to results being filtered after the scans rather than before them — implying work was being repeated. Instrumentation measured 49 invocations, 49 distinct, 0 duplicates against a control of 5/5/0: nothing rescanned, so the proposed remedy would have saved exactly zero. The real cost was one line the card never named, forking a separate search process per file — roughly 212,000 of them on the exemplar. The delivered fix batches that search and adds a deterministic fan-out cap; a wall-clock timeout was rejected on principle, because non-reproducible output disqualifies an artifact that feeds acceptance review. The card's line references were all exact — they described the wrong mechanism.

**A spec'd self-test suite was blind to a third of its own fix.** The suite was designed at 34 cases and shipped at 35, and the gap was not in the count — it was that the case list came from the specification written before the fix rather than from the fix's own change set. That is this release's recorded *would-change*, and it generalizes past this one suite: a regression net derived from the plan tests the plan, not the change.

**Two findings are properties of artifacts, not of the agents that hit them.** Four independent spokes misread the same runtime-suite selection map in four separate sessions; four independent misreads of one document is evidence about the document. Separately, the authoring harness's default search silently skips paths excluded from version control, which under-counted a reference census at 13 when the true total was 17 — the methodology note that outlives this release is that a completeness probe must use an explicitly-scoped search and must state whether its scope is tracked-only.

**The gate's first live run surfaced a genuine fail-open in a check trusted through prior closes.** The release-body drift check strips a file header using an idiom that empties the whole file under the version of the text tool installed on Linux runners, at four separate call sites — so it compares an empty body to an empty body and reports a match. It has been reporting "no drift" on every Linux run regardless of drift. It is pinned to macOS runners as an interim measure and tracked in [#4912](https://github.com/cody-hutson/pmo-platform/issues/4912); the pin is a containment, not a fix.

**Ratify rather than rename.** The documentation-link allowlist's name no longer described its role, and the reference-cascade cost of renaming it was measured at 13 references in tracked files and 17 in total. The decision was to ratify the identifier and move the rationale into the rule that governs it — which also removed this release's last file-contention surface with a sibling milestone.
