# Checks now measure everything they claim to cover

2026-08-15 · v4.28

Several platform checks were quietly measuring less than they claimed. One skipped part of the skill corpus, one answered to two different setting names, and one stopped a release from closing whenever it found a folder that was not a skill. All three now do what their descriptions say.

## What changed for everyone using the platform

- **A folder that is not a skill no longer stops a release from closing.** The close step used to treat any unexpected folder as a broken skill and halt. It now checks whether a folder actually resolves to something it can package, and reports problems per skill instead of failing the whole run. *Why it matters:* a release no longer stops for a reason that has nothing to do with your release, and the report tells you which skill is actually at fault.

- **Turning a check on or off now works from one setting.** One check read its on/off setting from four different names, so changing the obvious one appeared to do nothing. All four now resolve to the same setting. *Why it matters:* when you change a check's mode, the change takes effect — you no longer have to find the one name out of four that the check happens to read.

- **A citation check now scans the whole corpus.** It previously skipped a portion of the files it was described as covering, so anything in the skipped portion read as clean. *Why it matters:* a clean result now means the check looked everywhere, rather than that it looked at part and found nothing.

- **Skills now report the release they were actually validated at.** Twelve skills carried a version older than the release in which their behavior last changed, so they described themselves inaccurately. *Why it matters:* the version on a skill is now a fact you can rely on when deciding whether it has been checked against your current platform.

## Known limits

Five further skills carry the same stale version and were deliberately left alone — they had not been reviewed by any work item in this release, and correcting them unreviewed would have asserted a validation that never happened. They are recorded in [ADR-133](https://github.com/cody-hutson/pmo-platform/blob/main/release/ADRs/ADR-133-the-material-edit-test-names-an-effect-not-a-field.md) so the number is not lost.

Nothing yet prevents the same version staleness from recurring. The rule is now correct and the twelve instances are fixed, but a correct written rule is not an enforced one — the automated gate that would enforce it was deferred rather than dropped.

Report issues at the repository issue tracker.

## Reversibility

MODERATE / HIGH. The check changes revert cleanly on their own; reverting the twelve skill version corrections re-stales twelve skill packages and returns the corpus to describing itself inaccurately.

### Operator and engineering detail

**The unifying defect shape.** Every card in this release turned out to be an instance of one pattern: a required condition held by convention rather than by construction, whose omission produces a state indistinguishable from a healthy one. A predicate that scanned a subset returned zero and read clean; a mode knob read from a name nobody set, and its default looked deliberate; a close gate failed on a folder it could not classify, which looked like a broken skill. The pattern recurred often enough during the release to be worth naming, and four further instances were filed rather than fixed here — package-freshness regrowth, unwired test enumeration, and two gate-composition gaps.

**The pattern reached this release's own plan.** The release plan declared an architecture decision record and named a verification row to confirm it, worded *"contiguous, no duplicates, no gaps, with the new ADR present."* The tool that row invokes validates the numbering of records that exist and cannot fail on one never authored — so the record was forgotten, the check returned PASS, and every gate read green. It was caught at the Stage 13 action-item gate and authored before close as [ADR-133](https://github.com/cody-hutson/pmo-platform/blob/main/release/ADRs/ADR-133-the-material-edit-test-names-an-effect-not-a-field.md), which records the decision, its rejected options, and its own lateness.

**The material-edit rule now names an effect rather than a field.** The bump rule listed *frontmatter changes (description, name, other metadata fields)* alongside *behavior changes*, and a skill's `description:` is the field that carries its trigger phrases — so a length trim made to fit a character bound read as material, while a measured routing change could hide behind the ambiguity. The first bullet now fires on the effect (a change to which requests reach a skill), the cosmetic case is named explicitly in the does-not-bump list, and both are anchored to worked commits.

**Package rebuild scoping.** The package builder's change detection is now filtered by resolvability against its own module arrays rather than by directory shape, and a fixture arm was added that fails if the filter is ever removed. A second live non-skill directory was found during design, so a hardcoded exclusion would have shipped already broken.

**Verification.** 67 of 67 checks passed at merge; the renumber-tool suite went from 82 passed / 2 failed to 87 passed / 0 failed, the count rising because arms were added rather than because assertions were deleted. Fifteen skill packages moved, and their installed copies are stale until a deploy runs — deliberately not run from the release session, because the deployed allowlist was observed to revert three times during this release depending on which branch was deployed ([#5554](https://github.com/cody-hutson/pmo-platform/issues/5554)).

For full implementation detail see the RELEASE_LOG.md entry and [the release plan](https://github.com/cody-hutson/pmo-platform/blob/main/release/releases/plans/skill-suite-conformance_RELEASE_PLAN.md).
