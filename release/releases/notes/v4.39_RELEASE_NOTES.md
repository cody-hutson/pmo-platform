# The platform's self-checks can now actually fail

2026-08-28 · v4.39

Nine of the platform's automated self-checks were reporting a pass they could not have withheld — each would have said the same thing whether or not the behaviour it named was working. Every one of them now fails when its subject is broken, so a green result from these checks is evidence rather than noise.

## What changed for everyone using the platform

- **Nine self-checks can now report a failure.** Each had a way of passing that did not depend on its subject: one ran against a stand-in rather than the real thing, one started from a value identical to the one it was checking for, one was unreachable behind its own safety guard, and two pinned behaviours that could be deleted with the check still green. *Why it matters:* a green result from these checks now tells you the platform works, not just that the check finished.
- **A skipped check no longer reads as a passed one.** The package-freshness check returned the same verdict whether it compared a package or skipped the comparison entirely; a skip is now counted and stops the run. *Why it matters:* you can tell "verified good" apart from "never looked".
- **The release-cleanup tool's own test suite now runs.** The guard that stops that tool deleting branches and working copies outside the intended folder was also blocking its 16-check suite from running anywhere else, so the suite had been carried as a standing exception with a warning printed on every run. The guard now accepts the tool's own copy of the repository as a second valid location. *Why it matters:* the one tool that performs real deletions is covered by tests that actually execute, instead of by a warning nobody can act on.
- **Three test suites that nothing invoked are now wired in.** They had been written, reviewed and merged, and then run by nothing at all. *Why it matters:* the behaviours they cover were unguarded the entire time, with no signal that they were.
- **The coverage report now sees suites whose names do not follow the convention.** It previously looked only for files carrying the usual test-name prefix, so a suite called anything else was invisible to it. *Why it matters:* a test can no longer drop out of the coverage report because of what someone named it.

## Known limits

- **One change's main effect has never been observed in practice.** The package-freshness check now stops the run when a comparison is skipped, but on a healthy machine nothing skips — the most recent run reported zero skips, so that path was never entered. The behaviour rests on a purpose-built fixture and on the logic itself, not on a real run that exercised it.
- **The coverage report still cannot fail on its own.** Widening what it looks at did not change its result: it reports and stops nothing. Read the list of unwired suites it prints, not its pass or fail.
- **The long-running suite was re-diagnosed, not made fast.** It was believed to hang indefinitely; it finishes in roughly 42 minutes and had been stopped at about its own completion time. It is wired behind a fast selector and a time limit, so the full version is not what runs on every change.
- **The release-cleanup tool's guard was widened, not removed.** Its suite runs behind the same safety boundary as before, with one additional accepted location — nothing was exempted from the guard.

Report issues at the repository issue tracker.

## Reversibility

CHEAP / HIGH. `git revert -m 1` on the release merge commit reverses every change at once; nothing is migrated and no stored data changes shape. The two automated-workflow files are the only wide-blast surface — a bad edit there affects every pull request in the repository until the revert lands.

### Operator and engineering detail

**Verification was by mutation, not by inspection.** Every one of the nine assertions was shown to FAIL under a change that breaks its specific subject and to PASS unmutated, with both results recorded; recording only the passing direction was treated as not discharging the criterion. Mutations were targeted — each reddens one assertion while its siblings keep passing, which is what establishes that an assertion binds to its real subject rather than to a shared banner. Where a card repaired an assertion that previously could not fail, a counterfactual arm additionally ran the old assertion against the same mutation, so the record demonstrates the defect and not merely the fix.

**Three defects of this release's own class were caught inside the fixes for it, before commit** — a guard no mutation could falsify, a comment duplicating an exit-contract literal that would have silently disabled a shipped probe, and three probes whose markers matched a green run and would therefore have passed permanently. Each was found by the author mutating their own work, which is the practice this release is about rather than an incidental detail of it.

**Three cards carried premises that were false on live mainline**, established by measurement rather than assumed: the cleanup tool's defect is reachability rather than hermeticity; the "hangs indefinitely" suite terminates near 42 minutes and had been killed at approximately its own completion time; and the re-bootstrap card's "no runtime coverage" was wrong — coverage had shipped six days before the card was filed, and the real residual was that the coverage itself had never been shown able to fail in the direction that mattered. Issue bodies were left unamended as historical record; the corrected premises live in the Stage 5 and Stage 6 records.

**One architecture decision was recorded, because it diverges from a visible in-repo convention.** Two sibling tools dispatch their self-test before their destructive-scope guard, treating the fixture run as exempt. This release deliberately does the opposite for the cleanup tool and widens the guard instead, because that tool's self-test creates nine working copies and runs real branch, worktree and remote deletions — it is the one self-test in the corpus that performs genuinely destructive git operations, which is precisely the case the guard exists for. Both accepted roots are separator-anchored **in this tool**, closing a pre-existing prefix-match defect where a sibling directory whose name merely extended the root was accepted; the same defect is present in the two sibling copies of the predicate and is not fixed here. See [ADR-142](https://github.com/cody-hutson/pmo-platform/blob/main/release/ADRs/ADR-142-resolve-the-root-do-not-exempt-the-fixture.md).

**Limbs that were not measured are named rather than filled in.** All nine cards carry a two-arm record, and all nine additionally carry at least one limb that is single-source, report-only, or unexecuted. Those are enumerated in the release plan's *Arms not established* section instead of being substituted with a nearby measurement — including the skip-to-red chain that has never been observed in the automation, the coverage arm whose exit code is invariant by design, and two arms that could only be re-established by mutating tracked source, which the reviewing stages are scope-barred from doing.

**Scope discipline.** Findings surfaced outside the locked bundle were routed rather than absorbed: eight follow-up work items were filed and one security finding is being handled outside this release. No card widened past its acceptance criteria, and one design that specified four wiring targets was held to the three its own criteria name.
