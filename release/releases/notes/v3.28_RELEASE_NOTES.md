# The label taxonomy now matches its live labels — and a check keeps it honest

2026-06-30 · v3.28

## What changed for everyone

The platform's label taxonomy now matches the labels that actually exist on GitHub — and a new check keeps them in sync.

- **Cluster labels have a clear rule now.** "Domain" clusters (architecture, automation, security, …) name *what area* an issue touches — one per issue. `cluster: cross-cutting` is a separate span-marker for issues that cross several domains, and it now composes *alongside* a domain cluster instead of competing with it. The cluster color table was reconciled to the live colors, and the previously-undocumented `cluster: security` label is now registered. *Why it matters:* triage and the similarity-detection that reads the cluster axis now operate on labels that mean one thing, not a mix of naming conventions.

- **Promoted observations lose their `[Observation]:` title prefix.** When an observation graduates to a full proposal, its title no longer keeps the stale prefix — and a new parity rule makes that auditable. *Why it matters:* a promoted issue's title and its category label no longer contradict each other, so the backlog reads honestly and the rule is machine-checkable.

- **A new deploy check catches label drift.** `deploy.sh` Check 51 compares the documented label set against the live GitHub labels and flags mismatches — a canonical label missing from GitHub, or a GitHub label not yet documented. It ships in warn-mode and immediately surfaced real drift to clean up, including the missing `status: in-progress` / `status: done` labels behind a known work-item lifecycle bug. *Why it matters:* a gate that references a label which doesn't exist fails silently — it forced an ad-hoc label creation mid-triage on 2026-06-13 — and the check turns that drift into a visible warning before it can hide a broken gate.

Internal governance-hygiene release — no user-facing workflow changes.

## Follow-ups surfaced

Check 51's first run flagged pre-existing drift that is tracked separately, not fixed here: the missing `status:` labels route to #1828 (the work-item lifecycle bug they cause), the unregistered `type:*` family to #1777, and one ambiguous prefix-strip case (#153) to triage.
