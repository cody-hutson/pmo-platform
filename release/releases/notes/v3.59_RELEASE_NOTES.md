# One structural vocabulary for docs, backlog, and release records

2026-07-03 · v3.59

This release cleans up how the platform's own documentation, backlog, and release records are structured — no new features, just consistency. Everything now follows the single shipped modular-monolith layout instead of three competing vocabularies, and the release-plan and notes folders are organized so they stay easy to navigate as releases accumulate.

## What changed for everyone using the platform

- Release plans and notes are now filed under per-major-version subfolders instead of one flat pile. *Why it matters:* finding a specific release's record stays quick even as the corpus grows past a hundred releases.
- A written git-tracking-decision policy now records what belongs in the repository and why. *Why it matters:* tracking decisions are consistent and documented rather than made case-by-case.
- Internal documentation now refers to one structural vocabulary. *Why it matters:* less confusion when reading the corpus, and automated tooling resolves file paths correctly.

Most of this release is internal hygiene with no change to day-to-day platform behavior.

## Known limits

- A broad sweep of obsolete path references living in governed tooling comments (hooks, scripts, allowlists) was scoped to per-file judgment and largely deferred to a follow-up.
- A false-positive in the commit-message depersonalization gate — it flagged a legitimate in-repo filename as if it were a private-upstream reference — was fixed as its own separate change so this release could land.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

MODERATE · HIGH confidence. The documentation, policy, and vocabulary edits are plain git-revertable text changes; the ~190-file folder reorganization and the two version-bumped skill edits (the self-test canary and the skill refiner) would need a revert plus re-flattening and a version-bump-down to fully undo — a clean rollback is days, not hours.
