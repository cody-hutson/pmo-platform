# The platform now catches its own governance drift at PR time

2026-06-29 · v3.26

This release adds three new automatic checks that run when you open a pull request, each one watching for a kind of drift the platform has hit before: the file map in `CLAUDE.md` pointing at files that no longer exist, the `Projects/` folder name creeping back in the wrong capitalization, and a handful of platform conventions being broken. It also hardens the existing cross-reference checks so they are ready to be tightened later. All three new checks start in **warn-mode** — they report what they find but do not block your PR — so they can settle in without getting in your way.

## What changed for everyone using the platform

- **The governance file map is now checked against reality.** A new check reads the `## Governance File Map` table in `CLAUDE.md` and confirms every path it claims exists actually resolves on disk. *Why it matters:* the map is how the platform decides where new files belong — if it quietly points at a moved or deleted file, that bad guidance is now caught at PR time instead of misdirecting a later change.
- **The `Projects/` folder name is protected from drifting back.** A new check flags any newly added line that reintroduces the capital-`P` `Projects/` path that was already canonicalized to lowercase `projects/`. *Why it matters:* the casing was fixed once; this stops it from silently creeping back in and re-splitting the same content across two spellings.
- **Common platform conventions are now linted.** The `deploy.sh --check` family gained a new convention linter covering four residual areas — naming, Layer-2 paths, evidence labels, and leftover placeholders. *Why it matters:* small convention slips that used to pass unnoticed are now surfaced in the same place all the other platform checks already run.
- **The cross-reference checks are hardened.** The existing cross-reference-integrity checks were tightened up so a malformed test row fails loudly instead of passing silently, and a hand-copied threshold now comes from a single shared source. *Why it matters:* the checks you already rely on are made more trustworthy before they are tightened further in a later release.

## How to use it

You do not have to do anything. The three new checks run automatically on every pull request and in `deploy.sh --check`. Because they all start in warn-mode, they report findings without blocking — you will see what they catch in the check output. They are scheduled to be tightened to blocking in a later release after a short settling period.

This release changes the shape of CI / `deploy.sh` output. A new governance-drift finding looks like this in the check output:

```text
[Check 49: platform-convention] WARN — core/example/foo.md:12
  evidence-label missing on a factual claim
  (warn-mode: reported, not blocking)
```

## Known limits

- **Warn-mode means report-only, for now.** The three new checks do not block a PR yet — they surface findings without failing the build. A drift they catch will be visible in the output but will not stop a merge until the checks are tightened to blocking in a later release.
- **The file-map check reads the existing table, not a separate list.** It parses the `## Governance File Map` table in `CLAUDE.md` directly, so the table remains the single source — but a path the table does not list is not checked.
- **The convention linter covers four areas, not every convention.** It lints naming, Layer-2 paths, evidence labels, and placeholders; other conventions are still covered by their own existing checks.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `39-governance-drift-canonicalization-ci` milestone.

### Operator and engineering detail

**#135 — `Projects/` casing reconcile + gate.** Two parts on one branch in dependency order. First, a reviewed reconcile commit fixes the 6 genuine `Projects/_governance/` → `projects/_config/` drift hits across `core/schemas/frontmatter-schema.md`, `core/governance/OPERATIONS.md`, `operations/OPERATIONS.md`, `release/governance/RELEASE_PROTOCOL.md`, and `operations/skills/project-initiator/SKILL.md` (two historical 2026-03-19 changelog entries are deliberately left untouched — editing them would falsify the dated record). Then a net-new casing gate is appended to `repo-integrity.yml` that forbids newly-added capital-`P` `Projects/` lines, with `<!-- repo-integrity: allow-* -->` markers on the legitimate exceptions (the `block-destructive.sh` guard, its test, and the `Projects/[Project]/` operator-instance schema). The gate scans net-new added lines only, so the reconcile commit (which removes capital-`P` lines) does not self-trip.

**#133 — governance-file-map cross-check.** A new job on `repo-integrity.yml` regex-parses the `## Governance File Map` table and asserts each claimed path resolves on disk — one source per fact, parsing the existing table rather than a curated machine-readable block. Strictness is asymmetric: FAIL on an unresolvable claimed path, WARN on an unmapped on-disk file. It ships with a `--self-test` fixture carrying a labeled expected-match that hard-fails independent of warn-mode, so the parser's own correctness is gated even while findings are warn-only. #133 is the first writer to `repo-integrity.yml`; #135's casing job is appended after it — the one same-file contention, resolved by build sequence on a single branch.

**#228 — platform-convention linter.** `deploy.sh` Check 49 plus a new `core/deploy/tools/check-convention.sh` engine covering four residual convention dimensions (naming / Layer-2 path / evidence-label / placeholder); delegated dimensions are documented in-tool. It extends the `deploy.sh` check family rather than adding a pre-commit hook, because CLAUDE.md forbids normalizing `--no-verify`. Warn-mode-initial.

**#757 — pre-flip-to-enforce hardening.** Three hardening edits to the cross-reference-integrity gate surfaces, no flip: the skill-count detector's recall bound is documented as accepted-residual; `minwords` is sourced from the shared `$MIN_SELFDESCRIBE_WORDS` rather than a hand-copied scalar; and the `ISSUEREF-POS` fixture coordinates are numeric-validated so a malformed row fails loud. The gates stay warn-mode — this hardens them for a clean later flip-to-enforce.

All three new gates ship warn-mode-initial per `core/rules/bypass-mode-readiness.md`. The release ships as one PR / one merge; rollback is a single `git revert -m 1` of the merge.
