# Citations now point at files that exist, and say when nothing writes them

2026-08-15 · v4.27

Documentation that tells you where to look is worth less than nothing when the place it names has never existed — you conclude the output is missing rather than that the pointer is wrong. This release reconciles four such divergences, so no citation, check, or tool anchor asserts a path, count, or mapping that reality does not match.

## What changed for everyone using the platform

- **Pointers to gate output lead somewhere real.** Documentation across seven files directed readers to log files that nothing has ever written; those pointers now name the one log the deploy check actually writes. *Why it matters:* following a citation to inspect a gate's output now finds the file instead of an empty directory.

- **A pointer now tells you whether the thing it describes was ever built.** Nineteen of those pointers describe output that no check produces, and each one now says so in the same sentence rather than reading as though the output should be there. *Why it matters:* you can tell a wrong address from a capability that was written down but never built, instead of assuming your setup is broken.

- **A correctly-written release plan no longer fails its own provenance check.** The check accepted only one of the two forms the platform's planning guidance permits, and failed nearly half of the plans that were already correct. It now accepts both. *Why it matters:* a finding from this check now means the provenance is genuinely missing, so it is worth reading instead of waving through.

- **The release-velocity tool reports a real files-changed figure.** Its repository anchor resolved one directory above the repository, so that component came back empty and was reported as unavailable rather than as an error. *Why it matters:* the velocity output you read is measured, rather than quietly missing a piece it never announced losing.

- **The re-review's operator options name statuses that exist.** Two decision options directed an operator to statuses the platform has no label for; they now name live lifecycle positions and cite the label taxonomy as the authority rather than restating a fixed list. *Why it matters:* you no longer have to invent the mapping at the moment you are executing the decision.

## Known limits

- **The anchor guard covers one tool, not the class.** The fix adds a two-sided self-check to the tool that carried the defect, and that check does fail when the defect is reintroduced there. The wider promise — that the same mistake cannot silently reappear in another tool — is not enforced by anything today: no executable refers to the new rule, and one of the twenty-three tools in that directory carries the assertion. The coverage mechanism this needs is tracked at [#5287](https://github.com/cody-hutson/pmo-platform/issues/5287).
- **Four pointers are deliberately left as they are.** They belong to two gates owned by separate in-flight work and are excluded by gate identifier rather than by position, so a later edit that moves lines cannot pull them into scope. Owned by [#4214](https://github.com/cody-hutson/pmo-platform/issues/4214).
- **Two further path families were not touched.** Citations under a different hook directory, and the mode-file family, were ruled out of this release's scope and routed rather than folded in.
- **Nothing detects a stale "not built yet" note.** When a gate's output is finally built, the note has to be removed by the same change that builds it. Every site is enumerated in the release plan and a named owner holds the obligation, but no check enforces the removal.
- **Half of the anchor check runs only by hand.** Automated testing exercises it in one environment; the second environment, where the same defect produces a plausible wrong answer rather than an empty one, is verified by an operator run.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

CHEAP / HIGH. Reverting the release merge restores every file. Eleven of the twelve changes are corpus text and the twelfth is a single-token path edit in release tooling; nothing holds state, nothing migrates, and no consumer reads the corrected paths — that absence is the defect being fixed.

### Operator and engineering detail

**The class split was re-derived from source and came back inverted.** The card was written expecting roughly five citations backed by a real emitter and fifteen without. The operative test used at Solutioning is narrower than the card's: a citation is class-1 only if a coded emitter exists *whose predicate is the owning gate's predicate* — emitter existence alone does not qualify, and neither does sink existence. Under that test the split is **1 / 19**, and the card's own two exemplars were 0-for-2 as written. The card's safety rationale was strengthened rather than weakened: the risk it named — a blanket find-and-replace silently relabelling citations as though the behaviour had shipped — is now the dominant case, not a minority one. The census unit was also restated from lines to occurrence strings, because one line carries two citation strings and a line-keyed plan drops one of them.

**The nineteen class-2 sites carry one fixed, greppable clause.** The grammar adapts per site; the token and the stated fact do not. The clause is worded *"no check emits this gate's FAIL row"* rather than the looser *"no check writes this row today"* because four sites sit beside a true "Backed by Check N" statement — those checks exist and do append to the shared log; what they do not emit is the row the citation describes. This is the shape at all nineteen sites:

```
… log to the shared deploy-check warn log
(`$(pmo_instance_path)/deploy-check-warn-log.jsonl`) and proceed —
specified, not yet emitting: no check emits this gate's FAIL row.
```

The token doubles as the enumeration surface for the gate cohort that is specified but not emitting: one search now lists every such gate, and the owning card inherits both the inventory and the obligation to retire each clause in the same change that lands its emitter.

**No schema version was claimed on the gate criteria file, and the counter-argument is recorded rather than skipped.** The file states a bump rule under which "self-repair refinements" increment the minor version, and six in-scope citations sit on self-repair rows — the strongest objection raised. It was answered on evidence over the full denominator of thirty-six recorded bump blocks, not a truncated read: no mechanical consumer reads the value, no gate requires a bump for this edit class, and none of the thirty-six was ever recorded for a reference correction. Every recorded "self-repair refinement" changes what the remediation *prescribes*; correcting a sink path inside a remediation cell adds no branch and removes none. That the determination also dissolved the release's only line-level collision with a sibling branch is recorded as a consequence of the ruling, never its basis.

**The fourth acceptance criterion on the anchor card shipped at a narrowed guarantee, under a recorded operator decision at the plan-review gate.** Its "cannot silently reappear in a third tool" clause was graded NOT MET at dev testing and accepted as-worded rather than held. The narrower guarantee that did ship is real and two-sided: exactly one shared predicate is called by both the assertion arm and the known-bad-anchor arm, and mutating the predicate to always-accept fails the control while always-reject fails the assertion. The class-level guarantee is not enforced — re-measured at close-out, zero of two hundred twenty-two executable source files reference the new check identifiers (control: a sibling identifier from the same standard *is* referenced by one), and one of twenty-three tools at that directory depth carries the assertion while nineteen of them assign the anchor. The standard says as much itself, recording the category as a citation surface with no reachable trigger. The durable fix is a cross-tool coverage mechanism and is out of this card's file matrix by construction; it is routed to [#5287](https://github.com/cody-hutson/pmo-platform/issues/5287) rather than re-promised here.

**The census that scoped this release was defective in the same way the release exists to fix.** The original acceptance criterion specified a search pattern whose character class excluded digits, so it silently skipped every citation whose filename carries one. The undercount propagated from the criterion into the plan and then into the readiness briefing, each time producing a clean-looking, smaller number. The corrected pattern returns twenty-four; the control confirms it matches lines the original returned zero on. Every count in this release's evidence carries a named control arm with its observed result, and a zero whose control also returns zero was treated as a broken probe rather than a clean result.

For the merge, tag and claim record — including the version slot moving twice under this branch and being re-derived from the post-merge commit rather than carried — see the deployment log block for this release in the release log, and the release plan for design determinations, probe records and verification evidence.
