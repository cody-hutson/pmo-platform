# Deploy toolchain runs deterministically — eleven defects fixed

2026-06-14 · v1.22

The platform's deploy and governance toolchain is repaired across eleven defects on its most-edited file plus one folded-in same-class fix. Checks that used to crash on a counting expression, swallow a read-only install error then fail opaquely later, clip a configured path at a `#`, or crash on a non-English character now run cleanly and report what they find. A new check also flags when a multi-mode skill's modes are no longer machine-recognizable.

## What changed for everyone using the platform

- **The deploy check no longer crashes on its own counting step.** Two governance checks counted matches in a way that could emit two values instead of one and fail the whole check with a math error; both were fixed to capture a single number. *Why it matters:* running the deploy check completes and reports its findings instead of aborting partway with a confusing `syntax error in expression`. ([#76](https://github.com/cody-hutson/pmo-platform/issues/76), [#1058](https://github.com/cody-hutson/pmo-platform/issues/1058))
- **A read-only leftover from a prior install is now handled and explained.** When a previous install left a read-only folder behind, deploy used to hide the failure and then fail later with an unrelated, opaque error; it now clears the leftover where it can and, where it cannot, reports exactly what is wrong and how to fix it. *Why it matters:* a failed deploy tells you the real cause — a read-only leftover — instead of an unrelated error several steps downstream. ([#88](https://github.com/cody-hutson/pmo-platform/issues/88))
- **A configured install path with a `#` in it is read correctly.** The reader that picks up the install path used to cut the value off at the first `#` character; it now reads the whole quoted path. *Why it matters:* an install path that legitimately contains a `#` is honored in full instead of being silently truncated. ([#332](https://github.com/cody-hutson/pmo-platform/issues/332))
- **The dependency-graph tool no longer crashes on non-English characters.** The blast-radius tool failed with an "illegal byte sequence" error on any file containing a non-ASCII character; it now sorts those files cleanly. *Why it matters:* a file with an accented name or non-English content can be analyzed instead of crashing the tool. ([#92](https://github.com/cody-hutson/pmo-platform/issues/92))
- **A new check flags when a multi-mode skill's modes drift out of recognizability.** A new deploy check confirms that each skill offering multiple modes still exposes those modes in a machine-recognizable way, and flags one that has drifted. *Why it matters:* a skill whose modes can no longer be detected is surfaced before it causes a mode-routing surprise, rather than failing silently later. ([#26](https://github.com/cody-hutson/pmo-platform/issues/26))
- **The `--report` view now matches the `--check` view.** A governance check that ran under `--check` was missing from the `--report` summary; the report now carries the same pass/fail row. *Why it matters:* the report you use for close-out evidence reflects the same checks the deploy actually ran, with no silent gap. ([#104](https://github.com/cody-hutson/pmo-platform/issues/104))

## Known limits

- The new multi-mode-drift check starts in a logged-but-not-blocking mode during its shakedown window — it reports a finding for review rather than stopping a deploy, until it has been observed clean and switched to blocking.
- This release repairs the deploy and governance toolchain; it changes no skill behavior and ships no skill or package update (the toolchain scripts and two reference docs are the whole changed set).
- Several smaller cleanups (an environment-variable rename, an install-script edge case, and comment corrections) are internal to the toolchain and are not separately observable — see the operator detail below.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `cluster: deploy-toolchain` label.

### Operator and engineering detail

**Two `grep -c … || echo 0` arithmetic double-emits — Check 19 (#76) and Check 28/29 (#1058)** — both sites used `var=$(grep -c … || echo 0)`, which on a no-match emits the `grep -c` zero *and* the `echo 0`, producing a two-line `0\n0` capture that breaks the subsequent arithmetic with `syntax error in expression`. Both were replaced with the robust `var=$(grep -c … || true); var=${var:-0}` form. #76 fixed the Check-19 pipeline-event-log block; #1058 (folded in at re-baseline) fixed the identical pattern at the Check-28 `_has_section`/`_has_field` and Check-29 `_has_h2`/`_has_xref` capture sites — out of scope for the original Check-19 work because it lived in two different checks. The #1058 fix originally landed on the legacy branch as an unsigned foreign commit from a concurrent session; that commit was dropped on re-baseline and the identical change re-applied here as a signed commit. Post-merge `deploy.sh --check` confirms zero `grep -c … || echo 0` patterns remain and no `syntax error in expression` is emitted.

**`references/` read-only self-heal + fail-loud (#88)** — the mirror-subtree cleanup used `rm -rf … 2>/dev/null || true`, which swallowed a read-only Cowork-install orphan and then hard-failed opaquely on the later `cp -R`. It was replaced with a `remove_mirror_subtree` helper that self-heals the read-only orphan where it can and, where it cannot, surfaces an actionable read-only-perms error plus remediation and routes into the failure path rather than continuing into the opaque downstream failure. The happy path is byte-unchanged.

**`cowork_install_path` `#`-clip (#332)** — the reader's `[^"#]+` capture pattern clipped a quoted path at a literal `#`. The pattern was fixed at the scattered reader sites and the Check-8 reader so a quoted `#`-bearing path passes through whole.

**Check 35 mode-invocation drift + Mode Provenance (#26)** — a brand-new Check 35 was appended to `core/deploy/deploy.sh` after the shipped Check 34: it verifies each multi-mode SKILL.md exposes a machine-recognizable mode-enum and emits a finding when one has drifted, reusing the existing `flag_warn_or_issue` / `DEPLOY_CHECK_MODE` / `deploy-check.mode` warn-mode machinery (no new helper, flag, or mode file) and shipping warn-mode-first per the established shakedown precedent. Its `cmd_report` parity block was added, and a `### Mode Provenance` block was added to the Procedure 3 Spoke Template in `release/references/how-to/hub-spoke-bridge.md` to close the observability gap (mirroring the existing `### Model Provenance` block). The check was authored as `Check 34`; because the concurrently-shipped governance-as-code-quality-gates release (v1.21) had already authored its own template↔schema `Check 34`, this release's check was renumbered to Check 35 and appended after it, with the in-function locals renamed `c34_*`→`c35_*` / `c34r_*`→`c35r_*` to avoid a same-function variable collision. Post-merge `--check` confirms both Check 34 and Check 35 run.

**Check-18 `cmd_report` parity (#104), Check-17 rename (#111), blast-radius locale (#92), four LOW findings (#331)** — a Check-18 PASS/FAIL row was added to `cmd_report` for Stage-13 evidence parity; the Check-17 override env var was renamed `C15_THRESHOLD_OVERRIDE_FILE` → `C17_*` to match the post-renumber namespace; `release/tools/blast-radius.sh` pinned `LC_ALL=C` on the dependency-graph `sort` to stop the `sort: Illegal byte sequence` + broken-pipe crash on non-ASCII input; and four LOW findings landed — `update.sh` EX_NOCHANGE now considers a Phase-5 redeploy, `validate-install.sh` A9 honors `PMO_PLATFORM_DEPLOY_ROOT`, `notify-version-skew.sh` lost a dangling spec cross-reference, and a `deploy.sh` DEPLOY_ROOT comment was corrected.

**Issue dispositions, re-baseline, release class** — nine issues (#88 / #76 / #332 / #111 / #104 / #26 / #331 / #92 / #1058) auto-closed at the release-PR merge. Two stale-against-the-tree issues were evidence-closed at Stage 13 with no code change: #343 (the skill-deployment session-UUID refresh — both literal UUIDs are absent tree-wide, `core/rules/skill-deployment.md` is fully tokenized, and ADR-013 already re-pointed deploy.sh Check 8 off the doc-UUID-grep mechanism) and #122 (the file-router Check 10 trailer — file-router's last non-merge commit already carries a Skill-Editor-Audit-Trail trailer, so Check 10 already passes; the v11.04 finding was superseded by that later edit). #106 (status-label) stays open as the operator/hub's operational follow-up — its Check-16 framing is stale (Check 16 was re-scoped to scan `--label improvement` issues only and no longer scans sub-tasks). This release ships as **v1.22** after a double re-baseline (v1.20 → v1.21 → v1.22): authored as v1.20, re-versioned when two concurrent releases consumed the tracked numbers, then re-versioned again when a third concurrent release took v1.21 and its Check 34. Unlike the prior legacy-branch-name precedent, a fresh `release/v1.22-deploy-toolchain-defect-cleanup` branch was cut off current `main` so the version identity, branch name, plan file, tag, and RELEASE_LOG row all agree on v1.22. `routine` class, CHEAP reversibility, 30-day Stage 13 outcome window. This is a text/tool-only release with no `SKILL.md`, no `packages/`, and no `core/rules/` mirror or hook touched, so there is no skill-mirror deploy-sync to run (deploy no-op).
