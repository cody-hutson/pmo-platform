# Reference docs now read in step with the sources they describe

2026-06-26 · v2.29

Ten places where a reference or governance doc had drifted from its canonical source — a stale rule count, a divergent list, an old field name, an imprecise term, an incomplete enumeration, and a duplicate file — are corrected so the docs say what the platform actually does. No behavior changes; this is documentation and governance accuracy.

## What changed for everyone using the platform

- **The configuration field for delivery method reads `delivery_approach` everywhere.** The navigation-layer schema had one lingering reference to the old `methodology` field name; it now matches the canonical `delivery_approach` used in PROJECT.md. *Why it matters:* if you configure a project's delivery approach, the field name in the docs matches the field you actually set, with no stale alias to second-guess.
- **The deploy-check reference points you at the live check list instead of a frozen copy.** The `skill-deployment.md` Drift Check section stopped listing checks by hand (a list that had fallen behind the real set) and now tells you how to read the current checks straight from `deploy.sh`. *Why it matters:* the reference can no longer tell you a different set of checks than the one that actually runs.

## Known limits

- This release corrects documentation and governance text only — no skill behavior, schema, or runtime check changes for any user.
- Two skills (build-reviewer, pmo-skill-editor) had a one-line text edit and a single-sourced reference; their packages are rebuilt here, but their behavior is unchanged.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `cluster: documentation` label.

## Reversibility

CHEAP / HIGH confidence. `git revert -m 1` of the integration PR reverses every fix; all changes are text corrections to existing docs with no data migration. Standard rollback window.

### Operator and engineering detail

**Count and enumeration drift (#127 · #1100 · #2095 · #107).** Three drifts traced to an enumeration falling behind its source. `CLAUDE.md.template` Review-discipline preference dropped the hardcoded "10 anti-laziness rules" for the count-agnostic "its anti-laziness rules" (the rule set grew 10→14, so a hardcoded count re-drifts on the next addition; the count is owned by `review-discipline-principles.md`). `build-reviewer/SKILL.md` Section 1 likewise drops the stale "(10 rules)" summary and now defers to the canonical set, scoping its original ten explicitly while noting rules 11+ come from the shared discipline. `core/rules/skill-deployment.md` replaces its hand-maintained Drift Check enumeration — which had left Checks 16/17/19/21/22/24/26/27/31/32/34–46 unlisted — with a derivation rule pointing at `deploy.sh` as the single source of truth (and likewise reads enforcement mode from `.claude/hooks/deploy-check.mode` rather than restating it). `lifecycle-states-canonical.md` §6.2 drops a forward-consumer row ("Knowledge Architecture doc") that had already been satisfied, so the planned-consumer table no longer lists a shipped consumer as pending.

**Reference-term and field-name reconciliation (#49 · #305 · #857).** `stage-06-engineering.md` corrects its CI/CD compression analogy from the imprecise "pre-commit hooks" to "PreToolUse hooks (`.claude/hooks/`)" — the platform's actual hook surface (the architecture-overview half was already resolved, so the fix narrowed to the one remaining line). `core/CLAUDE.md.template` syncs its intake tier-selection wording to `stage-01-intake.md` § 5 Path A, making explicit that the proposal and observation tiers are symmetric content-shape routing (route by what the insight is, not by which fields happen to be fillable). `core/schemas/navigation-layer-schema.md` reconciles its remaining `methodology` field reference to the canonical `delivery_approach`.

**Persona-card reconciliation (#881).** `release/references/specs/release-personas.md` updates the Stage 8 QA persona's "no conditional pass" anti-pattern to match the evolved `stage-08-qa-testing.md` spec — a CONDITIONAL ACCEPT is now a defined Phase E verdict that lists specific defects and carries an Override Record per NOT-MET/PARTIAL criterion; only an unconditioned or undocumented conditional pass remains the anti-pattern.

**Duplicate-basename single-source (#94).** `release/skills/pmo-skill-editor/references/regression-checks.md` was a near-duplicate (a small localization diff) of `core/standards/regression-checks.md`; the source copy is removed and the canonical is single-sourced into the package at build time via a new `TEMPLATE_SYNC_MAP` entry and the explicit-basename resolver rule. A scope note on the canonical distinguishes it from `release/references/specs/skill-suite-regression-checks.md` (different basename, different purpose — the two are not duplicates and are not single-sourced to each other). The close-out also re-aligned the parallel resolver in `core/deploy/tools/build-skill-packages.sh`, which the #94 merge had left without the new basename rule.

**Validator-surfaced corpus cleanup (#498).** The corpus-content drift surfaced by the v3.20 release-corpus validators is cleaned up — five historical release notes (v2.17, v2.18.1, v2.19, v3.18, v3.19) corrected against the §3.2 note-content rules plus a v1.03 INDEX-drift and filename findings.

The two edited skills' `.skill` packages (build-reviewer, pmo-skill-editor) are rebuilt at release-cut via this close-out chore PR; `deploy.sh --deploy` of those two skills is the operator/hub post-merge step.
