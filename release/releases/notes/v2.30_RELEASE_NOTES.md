# Stale internal links across the docs and skill files are corrected

2026-06-26 · v2.30

The platform was reorganized in an earlier release, but many documents and skill files still pointed at the old folder locations. This release updates those references to where the files actually live now, so links you follow inside the platform's docs and skill definitions resolve instead of leading nowhere.

## What changed for everyone using the platform

- **Internal links in the docs and skill files now resolve.** References that pointed at the platform's pre-reorganization folders are corrected to their current homes. *Why it matters:* if you read the platform's documentation or open a skill file and follow a path it cites, you reach the right file instead of a dead one. No action is needed on your part — the fixes are already in place.

## Known limits

- This release corrects references inside the platform's own files (docs, skill definitions, standards). It does not change any skill's behavior or output.
- A separate cleanup of stale references inside older GitHub issue descriptions was scoped and measured this release but deliberately left for a dedicated follow-up — those references do not affect anything you run, and correcting them safely needs work that is out of scope here.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `project:governance-hygiene` label.

## Reversibility

CHEAP / HIGH confidence. Every change is a reference correction in a document or skill file — no behavior, schema, or data changes. `git revert -m 1` of the integration PR reverses the whole release. Standard rollback window.

### Operator and engineering detail

**Path-citation reconciliation across the corpus (#121, #677, #399).** The modular-monolith restructure flattened the old `pmo-platform/{reference,skills,governance,engineering}/…` tree into `core/`, `release/`, and `operations/`, but display-text path citations across the corpus still named the old locations. This release reconciles them to verified live homes — each target was located and confirmed to exist before rewriting (no blind prefix swaps): the 13 catalog `SKILL.md` files (#677) went from 67 stale `pmo-platform/…` citations to zero, and a 28-file non-release-corpus sweep (#399) rewrote genuine display-text drift while deliberately leaving legitimate occurrences (immutable ADR history, deploy-path globs, the rewriter's own tool-usage examples, test fixtures, frozen audit line-references, and operator-instance roadmap paths). One single-token internal-consistency fix harmonized a QA↔Dev-Testing escalation threshold (`≥3` → `>3` round-trips) in `core/disciplines/operating-model.md` (#121). The user-facing API reference (`docs/module-apis.md`) had two standards files mis-listed under Specs with dead links; they were moved to the Standards list where the files actually live.

**A scope correction worth recording.** #677's acceptance check named the `reference/specs/` path prefix, but the drift it described (failure-mode-standard.md citations in skill failure-mode sections) actually used `reference/standards/`, and the issue's stated destination (`core/specs/failure-mode-standard.md`) does not exist — the file lives at `core/standards/`. Verifying each destination against the live tree (49 corpus references agree on `core/standards/`) caught this before any rewrite; the operator approved folding all of the 13 files' path drift into #677 so nothing was orphaned between the two sweeps.

**Two backlog items closed without code (#2081, #2080).** #2081 asked for an automatic check that fails a pull request citing an issue number that does not resolve — this is already enforced by the repository-integrity "Issue-reference validity gate" (required, blocks the merge, scans only added lines) and is documented in the git-workflow rules; no second check was added. #2080's one-time sweep of stale issue-number references inside issue descriptions was re-measured live (419 open issues; 176 distinct unresolvable references across 273 descriptions, replacing a stale prior catalog); because the old-to-new number mapping from the re-versioning is unrecoverable per reference, the residual is documented and kept rather than guessed at (a wrong reference is worse than a dead one), and the recurrence it guarded against is already prevented by the gate above. The umbrella issue (#753) closes once both children are done.

**Versioning note.** The number drifted from a planned v2.28 to **v2.30** during the run as two concurrent releases shipped v2.28 and pushed a v2.29 tag ahead of this one; the version was re-confirmed free at each step and claimed at merge. The edited skills' distribution packages rebuild at release-cut as part of this close-out.
