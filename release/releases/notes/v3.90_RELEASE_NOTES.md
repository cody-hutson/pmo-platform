# Accurate release-impact analysis: path-true counts + directory-move detection

2026-07-25 · v3.90

The tool that estimates "what could this change break?" during release planning now counts consumers accurately and catches a class of silent breakage it previously missed. Stage-5 impact analysis is trustworthy on any checkout, with no manual flags.

## Who this affects

Anyone running the release pipeline's Stage-5 impact analysis (`blast-radius.sh`). The fixes apply automatically — no action needed. Everyday platform use is unaffected.

## What changed for everyone using the platform

- **Impact counts are no longer inflated by local worktrees.** The tool scans the canonical repository tree only, excluding agent worktree copies by default. *Why it matters:* on a machine with active worktrees, counts were inflating roughly 10–14× (and deep scans could break outright); results are now correct without any manual flag.
- **Consumers are matched by full path, not just filename.** A file like `README.md` no longer over-counts every other same-named file in the repo. *Why it matters:* impact estimates for common filenames are precise instead of alarmingly overstated.
- **Results are stable regardless of your system's language/locale.** *Why it matters:* the tool no longer risks a sort failure on non-ASCII paths, and output ordering is deterministic across machines.
- **New: directory/path-move impact detection.** When a change moves or renames a directory, the tool can now surface the scripts, configs, and allowlists that hard-code the old path. *Why it matters:* this catches the exact silent breakage where a folder move quietly broke downstream automation for several releases before anyone noticed — now flagged at review time.

## Known limits

- **Deep (depth-2) analysis on high-fan-in "hub" files can still be slow** (issue #3197, now tracked as a bug). This release's worktree-exclusion did not resolve it — the slowness is inherent to those files' fan-in, not worktree inflation. Use depth-1 for those files for now.
- The new directory-move detection deliberately over-includes (it flags any literal mention of the old path, including historical comments); it ships in a **report-only "shadow" mode** where each flagged item is reconciled as "update" or "not-a-consumer" — it does not block a merge.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE** · confidence **HIGH**. The release is a single pull request (#3924); a `git revert` of the merge commit cleanly restores the prior tool behavior. The one moderate-reversibility element (the new merge-gate) ships in report-only shadow mode as an isolated commit, so it can be rolled back independently without touching the correctness fixes.
