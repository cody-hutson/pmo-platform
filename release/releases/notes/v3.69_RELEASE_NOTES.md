# Platform maintenance: deploy-check validation cleared to green

2026-07-11 · v3.69

Routine housekeeping. This release clears accumulated drift in the platform's internal `deploy.sh --check` validation — rebuilding stale skill packages, deduplicating a governance file down to a single source of truth, and fixing two skills that could not be packaged — so the check passes cleanly again. How you use the platform is unchanged.

> **Does this affect me?** Only if you run `deploy.sh --check` locally or maintain the platform's governance files. Day-to-day skill users are unaffected.

## What changed for everyone using the platform

No user-visible behavior changes — this is internal maintenance. See the operator detail below.

## Known limits

- The stale-package drift this release drained is **recurring** — it re-accumulates whenever a skill is edited without rebuilding its package. The durable prevention (CI-enforcing the check subset, #1485) lives in a later milestone; until it ships, periodic drainage like this will recur.
- Two skills (`context-budget-auditor`, `skill-compliance-auditor`) were found unpackageable mid-release — their descriptions exceeded the packager's size limit — and were fixed in-scope (#3375).

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**MODERATE / HIGH confidence.** Every change is governance or package content under version control; whole-release rollback is `git revert -m 1` of the merge commit, with no data migration and no stored-content move.

### Operator and engineering detail

See the `#94-deploy-check-drift-remediation` RELEASE_LOG row for the full audit trail. Four delivery slices on one branch/PR (#3376), sequenced source-edits-first / package-rebuild-last per the #3198→#2217 build dependency:

- **#3198** — split two oversized role-Specialist `SKILL.md` files (`pmo-program-coordinator`, `pmo-tier-2-support`) into `references/` subdirs, clearing the Check-6 D-Refs size threshold (mirrors the earlier #2069 split).
- **#2213** — designated `core/governance/OPERATIONS.md` as the single source of truth and reduced the drifted dual-home copy (`operations/OPERATIONS.md`, ~105 KB) to a 1 KB pointer stub, after verifying it was a lossless stale subset with no content-loader. Reshaped the `deploy.sh` Check-9 mirror-pair into an SSOT+pointer duplicate-home check, and tokenized 29 hardcoded operator-instance analysis paths.
- **#2217** — the terminal step: re-measured the stale set on the assembled branch and rebuilt 32 content-stale `.skill` packages — 7 more than the plan anticipated, because #2213's canonical edits re-staled additional packages. Re-measuring on the live branch (rather than trusting the plan-time list) caught them.
- **#3375** — an unpackageable-skill defect discovered *by* the #2217 rebuild; folded into scope at the Stage-9 gate and fixed (two over-limit descriptions trimmed below the 1024-char cap with every trigger phrase preserved, then packaged), clearing the final two FAILs to reach literal `--check` green.

Ran on the Claude Code path with a proportionate scaffold (the release PR + git history as the audit surface; no per-stage sub-task issues). Both human gates were honored — Stage-9 GO with an operator scope-expansion decision (folding in #3375), and Stage-12 Execute; the merge used `--admin` per the branch-protection convention.
