# A formal home for findings, plus an ownership-collision guardrail

2026-07-17 · v3.75

This is a housekeeping release: it tidies how the platform models the outputs its review and audit skills produce, and adds an automatic check that catches when two agents both claim to own the same output. Nothing you do day-to-day changes — the payoff is fewer silent ownership gaps and a cleaner data model underneath.

## What changed for everyone using the platform

- **Findings (from QA, reviews, and audits) are now a first-class tracked item with a single accountable owner.** *Why it matters:* a finding raised by any review skill is now governed consistently — it has a defined lifecycle and one maintainer — instead of living as an ad-hoc note that could be dropped.
- **A new build check flags "ownership collisions" — cases where more than one agent is recorded as owning the same output.** *Why it matters:* it prevents the ambiguity that lets a piece of work fall through the cracks or get done twice; the check ran clean across all 19 tracked entities on release.
- The remaining changes are internal cleanup with no visible behavior change (a shared lookup used by one packaging script, and a diagram converted to the standard format).

## Known limits

- No carry-forward issues. The concurrent v3.76 release was in flight during this close-out; the two resolved to separate versions with no shared content.
- The new ownership check ships in warn-mode alongside the existing deploy checks; it reports but does not block.

## Reversibility

**MODERATE / HIGH confidence.** Everything here landed as one squashable set of commits on `main` behind branch protection; rollback is a standard `git revert` of the release merge plus the tag, with no data migration to unwind. The one lasting change is the entity roster growing from 18 to 19 entities — reverting that is a corpus edit, not a data loss.

```yaml

  finding_title:  string       # required
```
