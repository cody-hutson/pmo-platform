# Orchestration disciplines move into the reference the platform reads at runtime

2026-06-26 · v2.25

The orchestration patterns the platform had been learning by trial and error — how to launch sub-tasks, when to push back on their recommendations, how to keep a number consistent everywhere it appears — are now written into the reference the platform consults while it coordinates work. A class of cross-ticket, cascade, and consistency failures is now caught while the work is being authored, rather than after a failed check or a mis-routed sub-task.

## What changed for everyone using the platform

- **A number you change in one place no longer leaves stale copies elsewhere.** When a piece of work changes a count, a list, or a threshold, the platform now prompts itself to find and update every other place that value appears. *Why it matters:* you stop seeing the kind of inconsistency where one document says "5 checks" and another still says "4".
- **The platform pushes back on busywork instead of rubber-stamping it.** When a sub-task returns a recommendation, the platform now weighs whether it actually adds value before adopting it. *Why it matters:* accurate-but-pointless suggestions get filtered out rather than acted on.
- **Cross-cutting scope creep is caught while the work is happening.** When work on one item starts touching the scope of another, the platform now notices and raises it rather than letting the change land silently. *Why it matters:* a fix for one thing no longer quietly redefines another without anyone deciding that was intended.
- **The coordination know-how lives in one consulted place, not scattered notes.** Hard-won practices — how to phrase a launch, how to keep work safe from accidental data loss, how to recover when two parallel efforts collide — are now in the reference the platform reads, not in loose operator notes. *Why it matters:* the behavior is consistent and durable instead of dependent on whoever remembered the lesson.

## Known limits

- These disciplines govern how the platform coordinates its own multi-step work; they are internal orchestration improvements, not a change to any project artifact you author.
- The empirical check on sub-task behavior confirmed that security rules are inherited as expected in the main workspace, but found a residual gap in one isolated-worktree session context; that gap is named and tracked rather than hidden, and is followed up separately.
- Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `cluster: hub-spoke-orchestration` label.

### Operator and engineering detail

**Cascade-completeness + necessity/value-add (#78, #210)** — `release/references/how-to/hub-spoke-bridge.md` (the runtime hub reference) gains a Procedure-3 Spoke-Template cascade block: a spoke whose spec changes a count / enumeration / threshold must enumerate every stale occurrence (parallel to the existing R1). Procedure 4 Step 5 gains a 7th hub-evaluation dimension — a necessity/value-add test that lets the hub diverge from accurate-but-inert spoke recommendations instead of rubber-stamping them.

**Four chip disciplines lifted memory→corpus (#1669)** — verbatim chip-source, issues-as-spoke-contract-not-chat-blocks, hook-safe git idioms, and concurrent-spoke contention recovery are codified as four discipline subsections in `hub-spoke-bridge.md`, with Stage-6 anti-pattern bullets in `release/references/specs/release-personas.md`. The four operator-local memory files that previously held these lessons are evicted on merge (operator-side; not a repo change).

**Mid-Stage-5 cross-ticket detection + de-fragile authoring (#31, #879)** — #31 adds a mid-build cross-ticket scope-detection heuristic plus a hub escalation handler to `hub-spoke-bridge.md`, a Phase-0.7 protocol section to `release/references/pipeline/stage-05-solutioning.md`, and is anchored by founding **ADR-041** (slim-kernel). #879 lands a durable-corpus de-fragile authoring pre-check at both the bridge's Stage-6 chip guidance and `core/standards/reference-durability-standard.md`, so fragile reference constructs are caught at authoring time (the reference-durability CI gate is the load-bearing Stage-9 check for this release).

**Empirical hook-inheritance suite (#189, ADR-042)** — Spoke B reports the empirical truth about whether the subagent-tier PreToolUse mechanisms fire in a spoke's worktree context. It ships a Layer-A CI regression (`core/deploy/tests/test_agent_tools_conformance.sh` + three `agent-tools-conformance` fixtures wired into `.github/workflows/install-tests.yml`), a Layer-B operator probe (`core/hooks/tests/subagent-hook-inheritance.test.sh` + a probe doc), the new **Check 46 `agent-tools-list-conformance`** `deploy.sh --check`, a `core/standards/subagent-security-posture.md` §1/§3 reconcile, and founding **ADR-042**.
