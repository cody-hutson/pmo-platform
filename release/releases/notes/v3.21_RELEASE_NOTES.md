# Terminology glossary refreshed: actor terms, fuller tier table, canonical Initiative/Roadmap

2026-06-29 · v3.21

The platform's controlled vocabulary now defines its own moving parts clearly enough that an automated agent can read the glossary cold and know who acts at which level, and what "Initiative" and "Roadmap" mean. This is a documentation and governance release — it sharpens the words the platform uses about itself; it changes no skill output, command, file behavior, or stored artifact.

## What changed for everyone using the platform

No user-visible behavior changes — see operator detail below. Every change here is an addition or correction inside the platform's own terminology glossary and governance reference docs; nothing changes in skill output, command behavior, or how your artifacts are stored. The benefit is indirect: the agents that act on your behalf can now resolve the platform's own roles and grouping terms from one canonical glossary instead of inferring them.

## Known limits

- This is a documentation/governance release: it adds and reconciles terminology, but changes no runtime behavior, no schema you interact with, and no stored content.
- The new canonical `Initiative` and `Roadmap` definitions describe grouping and sequencing concepts that already existed in practice; they name and reconcile those concepts — they do not introduce a new planning primitive or a new tracker field.

Report issues at https://github.com/cody-hutson/pmo-platform/issues with the `project:knowledge-corpus` label.

## Reversibility

MODERATE / MEDIUM confidence. Every change is a `git revert`-able edit to governance and reference documentation; reverting the integration PR restores the prior text in one step. The release is MODERATE rather than CHEAP only because the canonical Initiative/Roadmap wording ripples into the initiative-roadmap framework, the label taxonomy, and a new decision record; runtime blast radius is none — no code consumes the terms. No data migration, no stored-content move, no schema or runtime change. Standard rollback window.

### Operator and engineering detail

**Glossary refresh for AI-agent comprehension (#68 — keystone).** `core/specs/terminology-glossary.md` was written before the Autonomy Tier framework existed: it carried no frontmatter, named no first-class actor terms, and left the word "agent" overloaded. This release gives it discoverable YAML frontmatter, anchors the `Role` term to the Autonomy-Tier framework, and adds four first-class actor terms — **Hub**, **Spoke**, **Skill**, and **Sub-agent** (the `{#term-hub}` / `{#term-spoke}` / `{#term-skill}` / `{#term-sub-agent}` anchors) — plus an Appendix-A resolution row disambiguating the overloaded "agent". The Total-terms count rises 19 → 23. The four actor terms are the keystone: they give an agent reading the corpus cold the vocabulary to resolve who-acts-at-which-tier from the glossary alone, and they establish the frontmatter + anchor convention that #432's canonical terms build on.

**Tier Disambiguation Table extended to cover Hierarchy Tier (#128).** `core/specs/autonomy-tiers.md` carried a Tier Disambiguation Table that resolved only four of the platform's named "tier" conventions, omitting Hierarchy Tier — so a reader hitting "Tier" had no single place that disambiguated every convention. This adds a Hierarchy Tier row, a namespace-overlap collision note, and out-of-scope prose stating each named convention's disposition, and cascades the convention count four → five (with the matching `core/CLAUDE.md.template` cross-reference; the template's other "four", which counts Autonomy's own 0–3 tiers, is preserved). The table now covers every named tier convention, so the Hierarchy-Tier-vs-Autonomy-Tier overlap is resolvable from the table rather than by inference.

**Canonical Initiative / Roadmap vocabulary + ADR-049 (#432).** The glossary's Appendix B still declared "Initiative … not modeled" while the initiative-roadmap framework scoped a roadmap to "one initiative" and referenced an `initiative:*` label namespace that had since been retired in favor of `epic:*`. This release adds two canonical glossary terms — **Initiative** (`{#term-initiative}`: a multi-milestone grouping theme — a cross-milestone grouping label, never a container tier or `parent_ref` target) and **Roadmap** (`{#term-roadmap}`: an architected path across milestones that may span one or more initiatives) — rewrites Appendix B to drop the "not modeled" assertion, and lifts Total-terms 23 → 25. It adds a surgical canonical-scope note to `core/standards/initiative-roadmap-framework.md` (preserving the one-initiative narrative), reconciles `core/specs/label-taxonomy.md` by citing the canonical term on the grouping-mechanism line and replacing three dead `initiative:*` rows with the live `epic:*` / `project:*` grouping namespaces, and records the canonical vocabulary plus the `initiative:` → `epic:`/`project:` label mapping in a new decision record, **ADR-049** (registered in `core/ADRs/README.md`). The canonical-vocabulary wording was rendered at a Stage 5 Collective Review (multi-spoke consensus), with the ADR as the governance record per the glossary's add-new-terms requirement.
