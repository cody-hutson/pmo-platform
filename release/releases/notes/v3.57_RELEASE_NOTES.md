# Impact analysis reads code, and git-native releases stop dead-ending

2026-07-02 · v3.57

Two release-pipeline improvements: change-impact analysis can now trace through the code import graph for non-documentation work (not only the markdown reference tree), and git-native releases no longer stall at a dry-run step written for the older Cowork flow.

> **Skip the rest** unless you run releases or review change impact.

## What changed for everyone using the platform

Internal pipeline improvements — no change to day-to-day project work. For operators running releases:

- **Domain-aware impact analysis.** For code changes, a new analyzer follows the import graph — which modules import what you changed — instead of the documentation reference tree, emitting the same structured surface the design-review step already consumes. *Why it matters:* the blast-radius review for code reflects real code dependencies, so an impactful change isn't mis-scored as low-impact just because it has few doc references.
- **Git-native releases run end-to-end.** The dry-run-record halt no longer dead-ends git-native releases (where the PR diff *is* the dry-run review); only Cowork-lineage plans still route to the planner. *Why it matters:* a git-native release proceeds through the pipeline instead of stopping at a step meant for a different workflow.

## Known limits

- The code-graph path applies only to `domain: software` deliverables; the markdown-tree analyzer is unchanged (the two now share a common emitter).

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

MODERATE / HIGH confidence. Additive tooling plus a routing-condition fix; `git revert` of the integration PR reverses both cleanly. No data migration.
