# Records handling, file naming, and generated-folder cleanup are now governed

2026-06-30 · v3.35

Record handling across the workspace stops being ad-hoc: a single records-management policy now defines how long records are kept, what class they hold, and how they are disposed; PM artifacts and project folders follow one POSIX-safe naming standard that `project-initiator` enforces at folder-creation time; and clearing out `08-Generated/` now runs through an approval-gated cleanup workflow instead of by hand.

## Who this affects

- Anyone who creates a project (folder names are now validated at creation).
- Anyone who relies on generated-artifact filenames or cleans up `08-Generated/`.

## What changed for everyone using the platform

- **Folder names are validated when you create a project.** `project-initiator` now rejects underscore-prefixed names (reserved for infrastructure like `_config/`), special characters, and non-human-readable names, with a clear message telling you what is wrong and the expected format. *Why it matters:* a malformed project folder is caught at creation instead of breaking globs, link checks, and search later.
- **One canonical file- and folder-naming standard.** Generated artifacts and project folders now follow a single naming standard — no spaces, no shell-hostile characters, ISO dates, a controlled artifact-type vocabulary, and an explicit folder-naming rule. *Why it matters:* listings sort and scan predictably, and every artifact-emitting skill points at the same rule rather than improvising.
- **A records-management policy now governs retention, classification, and disposition.** Records are classified into four classes (vital / important / reference / transient) with a retention schedule and disposition rules; nothing is destroyed — aged-out or closed records are archived to a named log. *Why it matters:* there is now one answer to "how long do we keep this and where does it go," referenced from the governance entry points.
- **Cleaning up `08-Generated/` runs under a mandatory approval gate, paired with the existing `artifact-lint`.** Run **`artifact-lint`** to *see* what's accumulating — a read-only report of orphaned, duplicate, stale, and superseded generated files. Then run the new **`generated-cleanup`** to *act*: it reads that lint report, groups retirement candidates (promoted-and-stale / approaching-timeout / superseded), and removes nothing until you approve the list; archived items move to `_archived/`, never deletion. *Why it matters:* the linter shows what's wrong and the cleanup turns it into a reviewed retire-or-keep decision — you never clean by hand or act blind.

## Known limits

- The file-naming **migration** of existing operational `projects/` files (renaming files that still contain spaces) is an operator-side step in the operations workspace — the platform delivers the standard and the enforcement; the one-time rename of pre-existing files is run separately.

Report issues at https://github.com/cody-hutson/pmo-platform/issues.

## Reversibility

**CHEAP / HIGH confidence.** Every change is additive (a new policy, a new standard, a new skill, and one validation gate); rolling back is reverting the release PR with no data migration.

### Operator and engineering detail

See the `#20-records-management-naming-and-cleanup` RELEASE_LOG row for the raw audit trail. The release shipped four cards on one branch / one merge (PR #2610 at `47228d5`), and re-versioned forward v3.34 → v3.35 at the Stage-12 atomic claim after a concurrent telemetry release claimed v3.34 between this release's Stage 9 GO and Stage 12 Execute (the pre-merge version-freeness check caught the collision and the branch was relabeled before merge). Notable points:

- **Records policy (#372, ADR-054).** `core/governance/RECORDS_POLICY.md` implements the ISO 15489-1 value-based records model over the platform's existing frontmatter fields and `01-08` folders — a retention table keyed by record class, a total four-class classification with a `DEFAULT = Reference` fallback, disposition rules (archival trigger; destruction = none; named archive log), and authenticity markers. It owns no mechanism an existing protocol already owns; the governance entry points reference it.
- **Artifact-naming standard (#369, ADR-055).** `core/standards/artifact-naming-standard.md` unifies the syntax layer (charset / separators / ISO date / project code; merged from the former #369) and the semantics layer (controlled type vocabulary derived from the artifact catalog and cross-referenced to mature PMO frameworks; merged from the former #117). It states the filename-vs-frontmatter boundary explicitly (versioning / status / lineage stay in frontmatter), covers folder names with the `_`-prefix reservation for sanctioned infrastructure folders, carries a validation regex and a retroactive-rename protocol, and is wired into the seven artifact-emitting skills + `OPERATIONS.md` + a `pmo-qa-auditor` conformance check.
- **08-Generated cleanup (#277, ADR-056).** A new `operations/skills/generated-cleanup/` skill consumes the reconciled lifecycle states (`lifecycle_state` / `promotion_state`) and the `artifact-lint` report — it does **not** read the deprecated `artifact_state` field, and does not re-implement lifecycle or lineage logic. The pairing is a producer→consumer pipeline: `artifact-lint` runs five graph-integrity checks and writes a dated `artifact-lint-YYYY-MM-DD.md` report; `generated-cleanup` consumes that report's version-chain findings for its *superseded* group, derives *promoted-and-stale* and *approaching-timeout* itself, gates every removal behind unconditional approval, and cedes the >10-business-day staged population to the artifact-generator Auto-Archive sweep. It is deliberately distinct from `cleanup-orphan-state.sh` (which cleans orphaned state files, a separate concern). The `.skill` package was rebuilt from source and committed in this release so the content-freshness check passes.
- **project-initiator folder enforcement (#232).** Mode A gains a pre-scaffold validation gate that rejects `_`-prefixed project names, special characters, and non-human-readable names with an actionable failure message, citing the folder-naming rules now owned by #369's standard (the `_`-prefix infrastructure carve-out keeps `_config/` / `_pmo/` valid). Enforcement points at the single naming home rather than carrying an inline rule.
- **QA + review.** Stage 8 QA returned ACCEPT on all four cards (#372 5/5, #369 8/8, #277 5/5, #232 5/5; zero FAIL/CONDITIONAL); Stage 9 Plan Review rendered GO.
