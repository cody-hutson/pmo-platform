## Change Description

### Outcome
v3.58 stands up the **Systems-Owners** domain as a reusable capability. It ships a **parameterized System-Specialist template** whose single source of truth is a *learn-a-system method* — ingest a system's supplied docs, build an internal model, then answer and act as that system's principal owner, grounded only in the ingested corpus. The template carries no per-system facts; each system gets its own instance that resolves the template's placeholders and attaches its own document corpus. A **WMS pilot** (`pmo-wms-specialist`) validates the template end-to-end. As a prerequisite, the release **ratifies ADR-019** (Specialists compose, not absorb) from Proposed to Accepted.

### Issues resolved
- **#2934** — ADR-019 stuck at Proposed after its ratifying review closed. Ratified to Accepted with provenance (COMMIT 0).
- **#407** — Build the System-Specialist learning-methodology template (one instance per system). Template + instantiation procedure + WMS pilot + deploy.sh Check 5(a) extension + registry registration.

### Key decisions
- **D-Templates-Location = A** — the template lives at `operations/skills/_templates/system-specialist/`, extending the live `_shared` convention (underscore-prefixed, non-deployed, sibling-consumed). The template is exempt from deploy.sh Check 5(a) roster-drift via a one-line allowlist extension and is never in a roster array or the registry; an **instance** is. This keeps AC-1 (no pre-baked facts) and deploy-safety both true.
- **ADR-019 ratification is COMMIT 0** and is **INDEPENDENTLY NON-REVERTIBLE**: 13 live Specialists already depend on ADR-019 = Accepted.

### Reversibility
**MODERATE · confidence HIGH** overall — additive template + pilot skill + a one-line allowlist edit; `git revert`-clean. **Exception:** COMMIT 0 (ADR-019 Proposed→Accepted) is INDEPENDENTLY NON-REVERTIBLE — a v3.58 rollback reverts the template/pilot/deploy.sh/plan commits only and must preserve ADR-019 = Accepted.

### Downstream impact
- New non-deployed template dir under `operations/skills/_templates/` — no inbound references to break (additive).
- `deploy.sh` Check 5(a) allowlist now exempts `_templates` alongside `_shared` (behavioral, one line).
- New deployed skill `pmo-wms-specialist` — added to `OPERATIONS_SKILLS`, one new `registry.md` CI row, one new `.skill` package. Binds Check 6/7/10/13 as a normal skill.
- The Business-Ad-Hoc "Account-Specialist" template is a later generalization of this template — not in scope here.
