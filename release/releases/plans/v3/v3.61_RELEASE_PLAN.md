## Rollback Strategy

**Single release PR** (`release/v3.55-pda-tail-closeout` → mainline). Rollback = operator-authorized revert of the merge commit (per RELEASE_PROTOCOL.md § Rollback protocol; git history IS the snapshot on the Claude Code path).

- **Whole-release rollback (pre-Layer-2-execution):** `git revert -m 1 <merge-sha>` restores prior state. LOW complexity — the Layer-1 tool is net-new; no operational-corpus state is mutated until the Stage-12 gated execution runs.
- **Layer-2 execution rollback (post-execution):** the backfill is additive + idempotent and every stamped key set carries `lifecycle_trigger: retroactive-backfill` — the unique reversal marker. Rollback = remove the marker-tagged keys (a scripted reverse pass). EXPENSIVE by blast radius (~749 files) but mechanically reversible.
- **Version:** if rolled back after tag, the version number is permanent (numbering gaps are benign per bundle-composition-doctrine § 5.3); a re-release takes a new next-free slot.
