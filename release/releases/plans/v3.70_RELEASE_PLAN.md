## Summary

Four operations-module skill-behavior changes that jointly realize the **Project Data Architecture (PDA)** for the operations domain: a uniform closed-set folder taxonomy (**#2374**), a single-inbox intake+extraction engine (**#2375**), generated-artifact provenance + promotion-preservation (**#2376**), and the tracked-layer schema + raw→tracked provenance bridge (**#2377**).

**Headline finding (the value only file-reading surfaces):** there is **zero direct file-level contention** — every issue's blast radius edits a disjoint set of skill/schema files. The coupling is entirely **contract-level**: all four consume one **closed-set folder-taxonomy contract** (defined by #2374) and one **provenance vocabulary** (`domain` / `source_inputs` / `GENERATES`, already SHIPPED in `frontmatter-schema.md`). Because the files are disjoint but the taxonomy reshape must land in lockstep across all four skills, this is genuinely **one atomic vertical slice** — the operator size-override is well-founded; splitting would fracture a coherence surface. The dependency analysis **confirms** the recorded internal sequence `#2374 → #2377 → #2375; #2376 ∥`.

**Stage-5 scope expansion (the load-bearing amendment):** Stage-5 Solutioning discovered the artifact `folder` frontmatter enum **is** this taxonomy (not a separate concern) — the bin rename is an **8→5 reshape** with a cross-schema blast radius the Stage-4 plan under-modeled. Per operator scope-lock (2026-07-10), **#2374 now also carries the additive-union `folder`-enum migration under ADR-079** (see § ADR-079 Scope-Expansion Note). Existing-project migration remains deferred.

## ADR-079 Scope-Expansion Note

**ADR-079 — Project folder taxonomy is a uniform closed 5-bin set (reshape from the legacy 8-folder structure).** Status: **Accepted** (operator-ratified at the Stage-5 Collective Review scope-lock checkpoint, 2026-07-10). Installed at `core/ADRs/ADR-079-project-folder-taxonomy-closed-5-bin-set.md` by Engineering Wave 0.

- **Decision:** adopt a uniform, closed, methodology-agnostic taxonomy — five canonical numbered bins (**1-Governance, 2-Delivery, 3-Operations, 4-Evidence, 5-Reference**) + two transient underscore areas (**`_inbox/`**, **`_generated/`**). The set is CLOSED: agents route into it and never create new bins.
- **8→5 mapping:** `01-governance→1-Governance`; `02-design`+`03-testing→2-Delivery`; `04-operations→3-Operations`; `05-transcripts`+`06-emails→4-Evidence`; `07-reference→5-Reference`; `08-generated→_generated/`; new `_inbox/`.
- **Migration mechanism:** the `folder` enum and its consumers migrate via the platform's established **additive-union deprecation-alias migration-window** pattern (the same rails proven for `domain` A/B/C→source/managed/generated and `synthesis_scope→source_inputs`). During the window, enum-validating consumers accept the **union** {legacy 8, new 5-bin + `_generated`/`_inbox`}; the legacy vocabulary is NOT retired in this milestone; convergence completes over the window. **Existing-project migration is deferred** (out of scope).
- **Reversibility:** MODERATE / Confidence HIGH while the window is open and no existing project has been reshaped (git-revert of the enum-union addition + scaffold change). Rises to EXPENSIVE once convergence retires the legacy vocabulary.
