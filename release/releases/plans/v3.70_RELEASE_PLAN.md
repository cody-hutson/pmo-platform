## Change Description

### Outcome

v3.70 makes the release pipeline re-verify freshness at bundle entry and constrains hub-spoke write authority, plus two targeted fixes. Four work-streams, all edits to existing files (one new ADR):

- **Bundle-entry freshness gate (#1960 + #2083).** Stage-4 Planning gains Phase A0.8 / **G-PL4**, a batch gate that re-runs each bundled card's own repro/AC against a pinned live-main baseline before per-card spoke fan-out, routing every verdict through one 3-outcome table (admit-still-valid / close-resolved / re-scope-changed). The general facet re-runs cards with a runnable check (others pass through to per-spoke PT-1/PT-2); the drift/reconciliation-class facet is a no-skip tightening within the same gate — one routing table, no card double-gated. Mirrored into `release-process.md` and cross-referenced from `triage-design-rereview.md` as the batch, earlier-firing sibling of the per-spoke PT-1/PT-2 checks.
- **Hub-spoke write-authorization safety (#2215).** Sub-task-close ownership moves from the spoke to the hub: the spoke posts its output and returns `output-posted` (renamed from `closed`); the hub closes the sub-task after consuming it. Because a spoke closing a hub-created sub-task was the trigger for the external-write guardrail warning (#1342), relocating the close removes the false-positive **in-git**, with no harness change. The sibling read-only-write-prohibition clause bounds the cross-issue-write vector (#1888). Both land in `hub-spoke-bridge.md`; **ADR-078** records the close-ownership reversal.
- **Check-22 warn-log path fix (#1685).** The Stage-02 triage doc and the `gate-criteria-spec.md` G3-11 citation now point at `$(pmo_instance_path)/deploy-check-warn-log.jsonl` (matching `deploy.sh:2793`) instead of the stale `core/hooks/` path.
- **Release-learnings self-test fix (#1561).** `synthesize-release-learnings.sh --self-test` was red at "per-release source-events count wrong". The root cause was fixture coupling, not logic: the data-dependent self-tests read the live, gitignored, append-only operator-instance `pipeline-event-log.md`, and Test 5 hard-asserted "v2.10 has exactly one learnings-triple event" — a count that drifted to zero as the live log rotated (and is absent entirely in CI). The self-test now drives its per-release + pattern-detect assertions against a hermetic in-tmp fixture (via the reader's `EVALS_RESULTS_PATH` override); production synthesis behavior is unchanged. Self-test PASSES (exit 0).
