## Change Description

### Outcome

v2.42 introduces a net-new `health-check` skill — an intent-driven project-state drift auditor that audits a single project for drift between its tracked state and its canonical sources (the MCP-connected systems plus the local artifact set) and emits a categorized 5-section punch list (`## Confirmed` / `## Auto-Actionable` / `## Decisions` / `## Unknowns` / `## Rollup-Diffs`) that is **never auto-applied**. This release (the #1125 slice) builds the full 7-mode contract once and implements the three v1 foundation modes — `full` (total drift sweep), `timeline` (date/milestone drift with day-of-week validation and a refusal of generalized dates), and `attribution` (owner/assignment drift with missing-owner flagging). The four v2 modes are declared in the contract but implemented in the #1126 slice on later commits on this same branch.

| #1126 | v2 extended modes (`comms`/`plan <name>`/`raid`/`sources`) | DEFERRED — implemented on later commits on this branch (v2 slice) |

### Key decisions

- **ADR-050 (Accepted)** — MCP-primary {Confluence/Jira/Smartsheet/SharePoint-when-available} / local-fallback canonical source set; drift resolves by recency with audience-facing MCP drift flagged at higher priority; an unreachable MCP → continue local-only + a `[MCP UNAVAILABLE]` banner, and any uncross-validated finding caps at MEDIUM and never enters `## Auto-Actionable`. Reversibility MODERATE / confidence MEDIUM (the SharePoint-no-MCP gap is a named residual).
- **DEC-3 (confirmed)** — the skill projects findings onto the canonical `S0-NONE..S3-STRUCTURAL` band scale (`staleness-confidence-standard.md`, ADR-043); the #161 placeholder `staleness-thresholds.md` is **not** created (superseded).
- **Phase 0.5 C2 (handled in-design)** — the SKILL.md `## Role` carries a name-disambiguation block distinguishing this skill from `health-check-specification.md` (the document-ecosystem integrity engine) and the Platform Health Check (governance/skill drift).
