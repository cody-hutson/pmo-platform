## Change Description

**Outcome.** Stage 8 QA can grade a PR against its originating GitHub Issue's acceptance criteria using a defined `acceptance` assertion type — computing a consistent, machine-readable acceptance score per criterion and per release — and emit that verdict as a standardized, three-tier acceptance report rendered from a reusable template; and pmo-qa-auditor gains a gate (G11) that catches an ask-when-ambiguous skill silently losing its AskUserQuestion fallback. This ships the first *executors* of the Stage-8 acceptance machinery whose *process* `stage-08-qa-testing.md` already defines; it lands the framework ahead of #219 (the QA acceptance-*review mode*, milestone #161), which consumes it.

**Issues resolved.** #218 (acceptance assertion framework) · #217 (acceptance-report template) · #197 (pmo-qa-auditor G11 AUQ-presence gate).

**Key decisions (LOCKED at Collective Review, 2026-07-03).**
- **Score = ALL-DRIFT-OUT (§5-uniform):** `acceptance_score = MET / (total − N/A-WITH-RATIONALE − REINTERPRET-WITH-RATIONALE − FLAG-UPSTREAM)`. Locked into both #218's roll-up and #217's matrix footer. All three drift verdicts leave the denominator (uniform with `stage-08-qa-testing.md` §5, where all drift verdicts are out-of-gate). This is net-new (NOT "§5-verbatim") — the Stage-8 process defines the verdict enum, not the score formula.
- **#217 placement = `operations/templates/qa-acceptance-report-template.md`.** The `*-template.md` deploy resolver maps the name here; `template-storage.md` §2.1 + card #71 concur. A release-side `*-template.md` would be a `deploy.sh --check` sync failure — the placement is mechanically required.
- **R-1 #218/#219 split ratified.** #218 owns the framework (assertion type + parse contract + rubric + score); #219 (milestone #161) consumes it and redefines nothing.
- **R-4 #197 regression set = the live 8-skill ask-when-ambiguous roster** (delivery-engine, change-management, pmo-process-designer, pmo-qa-auditor, pmo-skill-editor, pmo-technical-analyst, comms-writer, eval-writer), read live from `OPERATIONS.md § Mode Selection Protocol`, never hardcoded. An always-ask unconditional gate is a named residual (deferred).
- **ADR-071 records a two-judgment grading contract** (gradability-class + binary satisfaction), NOT "binary → projection". Two judgments per criterion: first, is the criterion gradable as-written (gradable / not-applicable / needs-reinterpretation / blocked-upstream); second, for a gradable criterion, is it binary-satisfied (PASS/FAIL). The pair projects to the Stage-8 six-value verdict enum.
- **DOC-ONLY runner scope.** #218 ships schema + grader-honored clause + one worked-example eval set (fixture + `evals/.../evals.json`). `run_eval.py` is NOT wired (a known residual — the checked-in runner grades triggers, not assertions).

**Reversibility:** CHEAP. All three issues are additive doc/schema edits — no code, no data migration, no irreversible surface. Whole-release rollback = single-PR `git revert`; the provisional-version gap becomes permanent per the forward-only re-version rule. `.skill` rebuild reverts with the SKILL.md revert.

**Downstream impact.** #219 (milestone #161, OPEN — lands after v3.64) consumes #218's assertion type and #197's gate via native `Blocks` edges; v3.64 lands the framework ahead of it. #217 has a soft placement dependency on the operational-document template architecture (#128 / #71), resolved to `operations/templates/` at scope-lock.

**Cross-references.** Stage-4 plan: #3129 first comment. Scope-lock: #3129 (Collective Review, 2026-07-03). Stage-5 designs: #3145 (#218), plus the sibling Stage-5 sub-tasks for #217 and #197. ADR: ADR-071. Stage-8 verdict enum SSOT: `release/references/pipeline/stage-08-qa-testing.md` §5.
