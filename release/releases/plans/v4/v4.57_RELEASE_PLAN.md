### Issue #6905: c3 §9 justifies the never-write invariant on an allowlist fact that is false against a live install

**Change Specification:**

- **Files modified:** `core/standards/c3-external-sync-path-b.md`, `core/hooks/allowlist-add.sh`, `core/hooks/tests/allowlist-add.test.sh` (new), `core/rules/bypass-mode-readiness/_cross-cutting.md`
- **Change description:** Scope is **option (b)** — correct the standard AND fix the tool — rendered by the operator at D-Scope-6905.
  1. **§9 reason (b)** stops asserting a per-install allowlist-contents fact and instead names where live control state is actually read (the deployed `<deploy-root>/.claude/` surface), with the two read commands a future auditor executes. Reasons (a) and (c) are preserved byte-unchanged. The replacement decouples the invariant from configuration entirely, reusing §8's existing frame — C3 self-limits regardless of enforcement posture — so no future config change can falsify §9 again.
  2. **§9's sibling site** (the "if a future capability genuinely needs external write-back" paragraph) stops naming the in-repo test fixture as where live write verbs would be added, and names the deployed allowlist instead. Rendered YES by the operator at D-2: leaving it makes §9 name two different files as "the allowlist" thirteen lines apart, immediately after an edit whose purpose is to make that surface legible, and it is a plausible CIAC-2 miss.
  3. **`allowlist-add.sh`** inserts the entry immediately before the first `END OPERATOR ADDITIONS` marker that follows the first `BEGIN` — the exact span `compose.py::extract_operator_additions()` preserves — instead of appending at EOF where the extractor silently drops it at the next regeneration. A target with no marker region degrades to the existing EOF append; a target with a marker but no usable span appends and **warns**. The marker grammar is a line-anchored transliteration of `compose.py`'s `_fence_re` and a deliberate strict subset of it **at the level of marker spellings** — the subset relation is scoped to what a marker looks like on a line, not to which pair each reader binds when a file carries several (see § Risk Register, risk 12).
  4. **A new test suite** asserts the property the card is about — the entry survives the authoritative extractor — rather than a line-position proxy, and carries a RED regression witness, a detector-reachability control, and a marker-spelling agreement arm.
  5. **The operator guidance** in `_cross-cutting.md` § Allowlist Maintenance tells an operator their entry now survives regeneration, and corrects the 8-vs-9 count defect in that same paragraph (the helper validates against 9 known allowlists; the registry table enumerates 8, and the ninth is assigned to another discipline by that file's own § Allowlist Maintenance boundary note).

## Change Description

(Authored by the Stage 6 release-engineering spokes at PR-creation time, and reconciled by the second and final pass to the set that actually shipped. Operator-facing, pre-merge. Distinct from the user-facing release note authored at Stage 13 Close.)

### Outcome

This release turns external-seam conduct from an operator correction the agent happens to be carrying into a governed discipline that fires, and it fixes a silent-loss defect in the tool operators are told to use when granting an allowlist permission.

**The conduct half.** An agent writing to an external seam — a work-item record or knowledge page in a connected system, and their comment streams — had no rule governing the *shape* of that write, and in practice posted dated, bolded, audit-trail blocks: it used the seam's comment stream as a register. That idiom is *correct* on this platform's own work tracker, where a dated evidence-bearing comment is the audit trail of a governed pipeline. It is being carried onto a surface with the opposite contract, where the record body is the state and the comment stream is conversation between people. The new discipline states that root cause so the idiom stops transferring, and then states the five rules that follow from it — routing, the register prohibition, the authorship-not-staleness discriminator, never-write fields as a category, and a confidence gate.

**What makes it fire, which is the part the diagnosis turned on.** The adjacent discipline this one is a sibling of binds to **zero** skill definitions — corpus-only, with no execution path, which is the likeliest reason the behaviour reproduced. So this one ships with four bindings rather than a document: six skill definitions cite it, the charter carries a one-line signpost, the decision-time checkpoint index gains a trigger row, and a warn-mode content-shape hook detects the register signature on the one surface where a payload carries it. The hook is deliberately the *smallest* of the four, and its own registry block says so: it reaches two of the six normative sections, and two more are unreachable in principle from a pre-tool-use hook because authorship and confidence are simply not in the payload.

**The allowlist half.** Before this release, an entry added through `allowlist-add.sh` landed at end-of-file — outside the region the update path preserves — so it disappeared at the next regeneration with no error and no log line. After it, the entry lands inside the preserved region, and a target whose markers are broken says so on stderr instead of failing quietly. The accompanying legibility fix is on the boundary itself: the standard stating the never-write invariant justified it partly on what one install's allowlist happened to contain, which was false against a real deployment. It now names where the live control state is actually read and states that the invariant does not depend on it.

### Key decisions

- **D-Scope-6905:** option (b) — correct the standard *and* fix the tool. Relocating the misplaced entries alone would have held only until the next marker-unaware append re-broke them.
- **D-2:** include the §9 sibling fix, so the section does not name two different files as "the allowlist" thirteen lines apart.
- **D-CascadeRows:** update the operator-facing allowlist guidance, so an operator learns their entry now survives regeneration.
- **D-CollectiveReview-ScopeLock:** scope hard-locked through Stage 9, with the single release-level index regeneration assigned to #6904's pass.
- **D-SHARD (operator-rendered):** the hook declares the *discipline* as its owner and ships **no** per-hook readiness shard. This is a mechanical read, not a preference — the readiness check classifies a hook as bypass-mode **iff** its declared owner is that shard, so a discipline owner and a shard cannot both be true. The shard's intent is met by a registry block inside the discipline itself, which is how all four existing standalone hooks are already documented. The nine bypass-mode hooks stay nine.
- **Verb-anchored surface gate (binding, Collective Review instruction 3):** the gate keys on a write **verb**, never a comment-class noun. A noun-only key matches read-family tool names, which carry no content field and would therefore trip the fail-loud arm on every comment *read* — noise at warn, a blocked read at enforce.

### Reversibility

**CHEAP — HIGH confidence.** `git revert` of the release merge restores prior behavior exactly for every corpus limb; the helper's CLI contract is byte-identical before and after, so nothing downstream has to change back. Two limbs need a word each. The hook additionally needs `./deploy.sh --deploy` to un-deploy the runtime copy, and it ships **warn**, so a defective detector logs rather than blocks; writing `off` to its mode file is the immediate kill switch, and that write is an **operator** action — the runtime mode file sits inside a path the autonomy floor blocks, so the governed form is the user-side handoff. The other is the six rebuilt skill packages, which are tool output and regenerate from source on revert.

### Downstream impact

- Every future `allowlist-add.sh` invocation, on all nine known allowlists, writes into the preserved region — this is the fix that makes the pending operator-instance repair (AI-001) durable rather than temporary.
- The new discipline is the citation target for future external-seam work; its warn-mode gate is the shakedown input for a later flip-to-enforce decision. **One of its five rules never graduates:** the comment budget is warn-only permanently, because the justification that makes exceeding a ceiling legitimate is not in the payload.
- **Reach.** The charter line composes into every workspace's `CLAUDE.md` at install, so it lands in every session in every work area. The six skill citations are the load-bearing binding; the checkpoint row reaches an ad-hoc conversational turn where no skill is loaded.
- `core/rules/bypass-mode-readiness.md` is regenerated once, at the end of the release; consumers of that index see one change, not two.
- **Deployed-instance propagation is required and is not automatic.** The six edited skills, their packages, the new hook, and the mirror-pair rule file all read DRIFT against the installed copies until `./deploy.sh --deploy` runs at Stage 12. The hook additionally needs its `mcp__.*` matcher row to reach a session that resolves the settings surface — on a repo- or worktree-rooted session it will not, which is a pre-existing hook-layer condition this release inherits rather than introduces.
