Reversing would force re-touching the same lines twice.

## Locked Stage 5 Design Summary (the shared `Check 5(d)` block)

Operator-locked at the Collective Review scope-lock gate (2026-06-27) on #2235. The design-note of record:

- **Block structure:** ONE new sub-check `Check 5(d): Registry-currency`, appended inside `cmd_check()` directly after Check 5(c) and BEFORE the Check-5 summary OK. It reuses Check 5's already-built roster resolution (one roster resolution, structurally impossible to drift from Check 5's). Two nested layers: an **outer row-level loop** (#1811) and an **inner field-level assertion** (#1658). They cannot fork because #1658's field loop is nested inside #1811's row loop.

- **Row-currency (#1811 — always-enforce):**
  - Parse registry row names: `grep -E '^\| \[' registry.md | sed -E 's/^\| \[`([^`]+)`\].*/\1/'` (verified: 43 names at baseline; canary returns 0 rows).
  - Build `DEPLOYED_ROSTER` = `OPERATIONS_SKILLS + RELEASE_SKILLS + CORE_SKILLS` only — **`CANARY_SKILLS` NOT unioned in** (ADR-04: the source-only canary has a source dir but no CI row).
  - (i)+(ii) symmetric set-membership: FAIL on any registry row with no roster member and any roster member with no registry row (both directions).
  - (iii) live-SKILL.md: for each row name, resolve its module and FAIL if `<module>/skills/<name>/SKILL.md` is absent.
  - Audit-baseline guard: if the row parse yields 0 rows, emit a single loud FAIL and skip the membership diff (do not FAIL-storm).
  - Inherits Check 5's `set +e` body discipline + `set -u` empty-array guards (ADR-008 FM-1).

- **Field-currency (#1658 — warn-mode-initial, EXTENDS the block second):** per-field match strategy — `modes` → set-equality on the ` · `-split member set; `dependencies` → skill-name-set equality (cell strips `DEPENDS_ON`/`RELATES_TO` prefix + splits ` · `; source harvests roster-name tokens from the `Composes` clause); `trigger surface` → **presence-only** (non-empty for role-Specialist, `—` otherwise) — NOT content-match, because the cell is a lossy hand-paraphrase of `description:`. **Accepted boundary: trigger-surface content drift is not caught in-104** (future epic-#1824). Routes divergence via a `flag_registry_field` helper switching on `resolve_check_mode "registry-field-currency"` (falls back to the shared `warn` default). For non-role-Specialist rows: assert all three field cells == `—`.

- **Canary + dash-cell handling:** canary excluded from the roster (ADR-04); `—` field-cells are VALID for non-role-Specialist rows (a non-`—` value there is itself the drift → correct FAIL).

- **Design-note, no ADR:** the field→source mapping is already decided in ADR-038 (registry §Sources of truth) + ADR-008's canary exemption; Check 5(d) *asserts* an existing contract rather than deciding one. Keeping it a design-note preserves `routine`.

**Load-bearing carry-forward (BR-1):** the 43/43 clean-exit is a transiently-true baseline pinned to commit `6079be7` (2026-06-27; 0 open PRs touch `registry.md`/`deploy.sh` at that anchor — itself a transiently-empty population, so the pre-merge re-run is the load-bearing guard). Stage 6 records "row-currency green at `6079be7`, 43/43" and re-runs `./deploy.sh --check` against the release-branch HEAD immediately before merge; verified at Stage 9.
