## Rollback Strategy

Release-whole rollback.

- **Reversibility of the release: CHEAP-to-MODERATE.** Cluster A (#307/#47/#59) + #1642/#1351 are additive text/spec/ADR edits — `git revert` of the release PR restores prior state byte-for-byte with zero data loss (CHEAP). The single MODERATE surface is #1639's executable hook edit: a revert is still clean, but if a *wrong* base-derivation shipped and #1531 had already flipped enforce, worktree edits would be blocked in the interim — hence R1's ordering mitigation.
- **Mechanism:** SINGLE-branch, one PR, one merge → **one revert restores the entire release.** Because the topology is SINGLE (not per-issue branches), there is no partial-merge state to reconcile.
- **Per-surface rollback granularity:** if only the hook change (#1639) regresses, `git revert` the specific Commit-0 hook commit (the serial P0 history makes the hook commit unambiguous — P0 rollback semantics: `git revert` of any single commit, linear history). The doc/ADR commits need no rollback.
- **Version-slot rollback:** v3.42 is claimed atomically at Stage-12 merge; if the release is pulled pre-merge, no tag is claimed and the slot is simply not taken. If pulled post-tag, follow the post-tag re-version recovery doctrine.
- **Enforce-flip coupling:** the ONLY rollback that is NOT self-contained is the #1639↔#1531 interaction — document to the #1531 hub that reverting #1639 requires NOT having flipped enforce (or reverting the flip first).
