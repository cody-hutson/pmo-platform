# v1.04-planning Release Plan

**Release class:** routine (Deep design review applied to the methodology-design ADR).
**Branch topology:** single release branch with sequential Engineering commits and one release PR; this plan is committed as the first Engineering commit.
**Composition:** capability-slice on the Pipeline Discipline arc; 22 points.

## Scope — three pipeline-discipline changes

This release codifies three Stage-4 / pipeline-discipline protocols.

1. **Stage 4 Phase A0 currency + crisping disciplines** (size M). Make the Stage-4-entry AC/substrate currency check and the pre-plan ticket-crisping gate mandatory, named phases — A0.5 (currency) and A0.6 (crisping) — with gate criteria, in the Stage 4 pipeline shard and the release-planner skill. This replaces prompt-dependent options with structurally enforced gates. Targets: `release/references/pipeline/stage-04-planning.md` and `release/skills/release-planner/SKILL.md`. (The skill is the tracked home for the persona behavior; the legacy agent-definition path the original ticket cited is not a tracked governance file.)

2. **Release-plan versioning protocol** (size S). Add a protocol section to the release-process governance file: the release plan is a committed file; its revisions are git commits (git history is the version trail — no in-file version number); and a decision rule for when a mid-flight change requires re-planning versus a minor adjustment. Target: `release/governance/release-process.md`.

3. **Analysis-class methodology-design treatment, via ADR-011** (size L). Resolve, by ADR, how analysis-class releases (research-artifact deliverables) get methodology-design treatment that the architecture-assessment Stage 5 persona fits awkwardly. Decision: a Stage 5 persona variant (not a new pipeline stage), given methodology-design gate criteria and a Stage 5→6 handoff schema. Targets: `release/references/specs/release-personas.md`, `release/references/pipeline/stage-05-solutioning.md`, and the ADR file under `release/ADRs/`.

## Implementation sequence

Foundation → infrastructure ordering: the currency/crisping disciplines, then the versioning protocol, then the methodology-design variant. Single release branch. The three changes are near-file-disjoint, so the sequence is for ordering rather than to resolve contention.

## Decisions of record

- **Release class:** routine, with Deep design review applied to the methodology-design ADR (it introduces a new persona variant plus an architectural decision — novel-equivalent ceremony for that item while the release aggregate stays routine).
- **Methodology-design form:** Option B (a Stage 5 persona variant with in-stage gate-teeth), not Option A (a new pipeline stage). Rationale, alternatives, and reversibility are recorded in ADR-011. Because Option B carries no stage-count change, no corpus renumber sweep is needed — the pipeline stays 13 stages.
- **Scope decomposition:** the methodology-design work was split before Engineering into a design core (the ADR and authoring) and a renumber sweep contingent on Option A; the Option B decision voided the sweep.
- **Stage 5 activation:** the methodology-design item's structural-design and multiple-approaches triggers activate Stage 5 release-wide which, under the all-or-nothing rule, pulls all three changes through Solutioning and a Collective Review scope-lock before Engineering.
