## Change Description

*Authored when the draft PR opened and extended as each card landed; all four have landed, and it is complete for them.*

### Outcome

How a repository's system documentation is modelled is now a recorded, `Accepted` architecture decision on this branch: {{ADR:system-documentation-is-a-generated-process-catalog}} chooses one generated catalog of text process pages, with each page's visual written as text beside its prose, one page per node plus generated views, in a folder outside the durable-corpus paths. The design-artifact standard now governs that catalog: where it lives (`core/process-catalog/`), which page levels exist and what earns a node a page, the fields every page carries, seven link types, the generated index, graph and views, and how a page is retired. It also gains a state and lifecycle flow class. No page exists yet; the folder holds only its README. Every work-item form that can ship a change — improvement, bug, epic and story — now asks its author what the change does to documentation, and the answer can now retire a document as well as link, create or update one. A retirement is verified at close by document class: a document that carries the platform-doc `status` field moves to DEPRECATED or SUPERSEDED and stays in place, one without it is deleted, and either way no live document may still name it. What counts as documentation is stated once, in the G-CL8 gate row, and now includes the user-facing `docs/` tree; every other place that used to restate the list cites that row. Planning now reads the documentation a change would alter: Stage 2 Triage and Stage 5 Solutioning each cite the current-state process pages for the areas a change touches, by page ID and last-verified commit, or record that none covers the area — the expected answer until pages are published. And close-out now runs its two documentation gates instead of only specifying them: one probe, `deploy.sh --check-doc-gates`, grades the release plan's declared design artifacts (G-CL6) and each issue's Documentation Impact declaration (G-CL8) over the release's own commit range and its whole issue population, and writes one warn-mode row per failing subject; each gate graduates to enforce by its own committed sentinel, against a deadline Check 28 reads.
