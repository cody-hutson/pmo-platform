## Scope — three solutioning-arc issues

A three-issue capability slice in the Solutioning / Pipeline Discipline arc. After the Stage 4 staleness re-triage, the three issues are **file-disjoint** (zero contention) and carry one hard directional dependency (#216 → #220). All three are internal pmo-platform artifacts (pipeline shards + a Stage-5 standard + a new shared standard); no external best-practice sourcing is required (pipeline-internal exemption).

1. **#220 — Dev Testing finding-disposition decision-weighting** (size M). Creates the platform's **first** fix-now / defer / accept decision-weighting framework for Dev Testing finding disposition (factors / weights / signals + decision logic), integrated with the existing Phase D/E flow and the DT↔Engineering iteration loop. `stage-07-dev-testing.md` had **no** such matrix before this release (net-new). Per the Option-C amendment, the stage-agnostic core is extracted to a new shared standard (see the File Change Matrix); stage-07 references it and owns only the Stage-7 Step 0 gate + worked example + Phase D/E pointers + the Automation Trajectory row.

2. **#216 — QA Testing finding-disposition adaptation** (size M). Adapts the #220 framework for Stage 8 QA finding disposition with the hard rule that a **NOT-MET acceptance criterion cannot be deferred or accepted without a recorded operator override** — strictly stronger than the Stage 7 Blocker gate. #216 edits `stage-08-qa-testing.md`, which **references** the shared standard #220 creates → #220 must land on the release branch first.

3. **#120 — Stage-5 spec-template BLOCK-DESTRUCTIVE-022 callout** (size S). Hardens the Stage-5 design-spec output template with a BLOCK-DESTRUCTIVE-022 callout (4 invocation forms) in the `## Blast Radius` content bucket, so any Stage-5 design that introduces a new in-tree bash CLI lists its required allowlist entries. Prevention-only, file-disjoint, ordered last. (The underlying allowlist defect for `blast-radius.sh` is already remediated in `core/config/allowlists/script-execution-allowlist.txt`; #120's remaining scope is purely the template hardening — see Risk R5.)

## Change Description

### Outcome

v1.06 gives the pipeline a **finding-disposition WHEN-axis**: a consistent fix-now / defer / accept decision for every Dev Testing and QA finding, layered on top of the existing severity/routing WHERE-axis. The stage-agnostic mechanics (a 5-factor weighted matrix + decision logic) live once in a new shared standard; Stage 7 and Stage 8 each reference it and add only their own precedence gate. It also hardens the Stage-5 design-spec template so any design that introduces a new in-tree bash CLI must enumerate its BLOCK-DESTRUCTIVE-022 allowlist entries.
