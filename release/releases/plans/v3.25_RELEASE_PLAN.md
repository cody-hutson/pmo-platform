## Scope — the milestone bundle and the coordinated unit

The milestone `28-corpus-frontmatter-standardization` bundles three work issues delivered as ONE release PR / one merge across three sequential slices on one branch. It closes the platform-doc-frontmatter gap end-to-end:

1. **#295 — Define the platform-doc frontmatter standard (size L, NEW; this slice authors the standard).** Author the net-new `core/standards/platform-doc-frontmatter-standard.md` — the frontmatter required-field rule for authored K1 platform-repo docs under `core/**`. It defines required + optional fields **per file class** (standard, schema, spec, discipline, rule, protocol, how-to, template, reference; the ADR class defers to the ADR README convention per #2156). REQUIRED on all classes: `title`, `purpose`, `type` (canonical singular enum — resolves the `standard`/`standards` drift), `status`, `reversibility`. REQUIRED-by-class: `framework_version_anchor` for docs cataloged in `framework-catalog.md`; `consumers` for `standard`/`schema`/`spec`. The standard records the unify-vs-registry decision (one unified standard with per-class field extensions, NOT a dialect registry — resolved per #67) as a slim Design-rationale section, distinguishes its scope from `core/schemas/frontmatter-schema.md` in one explicit paragraph, and names its downstream children. The standard's own frontmatter conforms to itself (it is a `type: standard` doc). **This card ships ONLY the standard — it does not backfill files (#109 + #2221) or gate them (#2220).**

2. **#109 — Backfill Tier A frontmatter (size L, BACKFILL).** Apply the standard's per-class field-set to the Tier A governance-class dirs (`core/standards/`, `core/schemas/`, `core/disciplines/`, `core/rules/`, `core/specs/`, `core/governance/`), normalizing `type: standards` → `type: standard`. Additive-only (frontmatter blocks added at top; zero body/prose change). Re-derive the live Tier A miss-count at execution time → 0. On any backfilled doc cataloged in `core/specs/framework-catalog.md`, set a correct `framework_version_anchor` (not just the core required fields), or the doc newly-fails `check-version-anchors.py` Check 18.

3. **#2220 — Add the CI gate (size M, GATE).** Wire a new frontmatter gate into `deploy.sh --check`. **Per the Collective Review scope-lock (D-4, 2026-06-29): the gate ships WARN-mode across all of `core/` (Tier A included) — NOT enforce-immediately on Tier A.** Build the enforce-flip mechanism (`resolve_check_mode` / `.mode` file, per the Check-42 host-binding-leak model) so graduation is a single-file flip later, but ship it warn. The **enforce-flip (now including Tier A) folds into #2221's existing "flip CI gate to global enforce" scope — deferred to that card.** #109 still backfills Tier A to 0; the warn-mode gate makes any residual/new gap visible. Adds a new Check + a catalog row in `core/deploy/tools/README.md`.

The dependency is hard-sequential (#295 → #109 → #2220): #295 creates the standard; #109 and #2220 only read it. #109 writes the Tier A doc bodies; #2220 reads them as gate input. The strict serial order resolves the within-bundle file contention (every shared path has exactly one writer).

`#67` is **CLOSED** — its unify-vs-registry design decision folds into #295's Design-rationale section (recorded there, NOT restated as a standalone ADR). `#2221` (Tier B/C backfill + flip-to-global-enforce) is `status: deferred`, milestone `null` — correctly out of scope; #2220 carries a one-line flip-to-global-enforce forward-pointer into #2221's AC.
