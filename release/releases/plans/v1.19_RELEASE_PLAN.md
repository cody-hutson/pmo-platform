## Delivery Strategy

**D-C SINGLE.** One `release/v1.18` branch (name legacy/cosmetic; release identity is v1.19), created off `origin/main` at the first Engineering chip. All commits land on that single branch, write-serialized — the hub routes one Engineering chip at a time, so no two chips write the same branch concurrently. One release PR (draft) is opened by the first chip and accumulates all four items; subsequent chips fetch and check out the existing branch rather than creating a new one. Commit convention: `release(v1.18): <description> (#N)` (the as-authored historical prefix; left unchanged at re-versioning), one logical change per commit. No force-push; no `--no-verify`; pre-commit hooks respected.

The single-branch topology is the correct choice for this release because the two dependency chains, while independent at the file level, both serialize cleanly on one branch with no merge-conflict surface (four disjoint files plus the one mirror-pair edit), and a single release PR gives the operator one reviewable diff at Stage 9.
