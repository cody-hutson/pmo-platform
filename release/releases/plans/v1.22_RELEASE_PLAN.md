## Re-baseline note (v1.20 → v1.21 → v1.22)

This release's version identity has been re-rendered twice under concurrent-release pressure. The lineage:

1. **Stage-4 gate selected v1.20.** At planning time (read-only from `main`), the next-free v1.x was v1.20.
2. **v1.20 → v1.21.** During flight, two concurrent releases shipped to `main` and consumed the tracked numbers — v1.19 = sior-escalation-discipline, v1.20 = health-and-raid-determinism. The first Engineering chip (references-mirror self-heal) caught it at Commit 0 (fresh `origin/main` fetch), BLOCKED rather than overwrite the shipped v1.20 plan, and the operator re-versioned to next-free **v1.21**.
3. **v1.21 → v1.22 (this re-baseline).** A third concurrent release — **governance-as-code-quality-gates** — then shipped to `main` and took **v1.21**, including authoring its OWN `Check 34` in `core/deploy/deploy.sh` (a template↔schema contract-fidelity check). Re-baselining off current `main` (`32ce030`) and re-rendering to next-free **v1.22** is the next-free rule applied to updated facts a third time.

**Collision resolved at re-baseline:** the mode-invocation-drift check this release adds was authored as `Check 34`. Because the shipped v1.21 already occupies `Check 34` (template↔schema), this release's check is **renumbered to `Check 35`** and APPENDED after the shipped Check 34; the in-function local-variable prefix was renamed `c34_*` → `c35_*` (and the report-form `c34r_*` → `c35r_*`) to avoid a same-function variable collision with the shipped template↔schema block. The companion `hub-spoke-bridge.md` Mode Provenance cutover note is updated to cite Check 35.

**Folded in at re-baseline:** the Check-28/29 `grep -c … || echo 0` double-emit defect (same defect class as the Check-19 fix, but in two different checks so out of scope for the original Check-19 work) is still live on `main`. Its fix originally landed on the legacy branch as an UNSIGNED foreign commit from a concurrent session; that commit was dropped on re-baseline and the identical change is re-applied here as a signed commit. (Tracked by the folded-in defect issue — see References.)

**Branch naming:** unlike the v1.18→v1.20 / v1.20→v1.21 precedent (which kept a legacy branch name), this re-baseline cuts a **fresh** `release/v1.22-deploy-toolchain-defect-cleanup` branch off current `main` so the version identity, branch name, plan file, tag, and RELEASE_LOG row all agree on v1.22. The legacy `release/v1.20-deploy-toolchain-defect-cleanup` branch is superseded.
