## Change Description

### Outcome

v2.02 adds a **risk-weighted release-capacity model** to the bundle size-check so a higher-ceremony release's raw story points count for more against the same target band, and consolidates the previously-scattered sizing guidance (item-count vs point-band) into one cross-referenced source. It pairs that target with a **per-milestone size-bound gate** that enforces it, a **Mode-A parse-rate gate** that holds intake-body conformance to a floor, and a **RELEASE_LOG velocity instrument** that supplies the empirical actuals to recalibrate the heuristics after three releases. The release is governance/spec/schema authoring — no application logic changes.

### Key decisions

- **Risk-weight axis = Release Class, not a new per-issue Tier field.** The shipped Release Class (`routine`/`novel`/`cross-cutting`/`hotfix`) already declares ceremony weight and is gate-enforced per milestone; choosing it over a net-new per-issue field is the lowest-blast-radius canonicalization (ADR-027).
- **Multiplier over additive budget.** Scale-invariance is the deciding axis — ceremony cost scales with scope, which an additive constant cannot express. Weights `{routine 1.0 / novel 1.15 / cross-cutting 1.3 / hotfix 0.9}` ship as explicitly-labelled MEDIUM-confidence seeds, `[CALIBRATE-AFTER-3]`, config-resident.
- **Rounding mode pinned round-half-up at the definitional home** (doctrine §3 Step 5) so the producer (#290), the enforcer (#294), and the recorder (#281) cannot diverge at half-integer boundaries.
- **Warn-then-enforce gates** with `[CALIBRATE-AFTER-3]` thresholds; gate-ID set `{#293 → G3-14, #294 → G3-15, #292 → G3-16 reserved}`; schema v1.11→v1.12.
