### Release Outcome Statement

**AFTER** — pmo-qa-auditor carries three new modes: a Stage-7 dev-testing mode (Mode G) that ingests a PR + release plan, runs the structural→contract→content-quality→integration eval ladder, and posts a quality report as a PR comment; a Stage-8 acceptance-review mode (Mode H) that ingests GitHub Issue AC and renders per-criterion verdicts under the Stage-8 enum by consuming the acceptance-assertion contract; and a Mode F release-process fitness audit emitting a dated audit artifact with UNTRACKED/PARTIAL/ALREADY-TRACKED classification. At least two pipeline stages invoke evals automatically, with operator escalation only on FAIL/EXCEPTION.

**BEFORE** — pmo-qa-auditor has five modes (A–E), all Cowork-skill-output reviewers; the Stage 7/8 shards name dev-testing and acceptance modes the skill does not have; DT/QA runs conversation-based with no automated eval invocation; the release-process fitness audit has no skill home.

**Actor(s):** pmo-qa-auditor (the three modes); Stage 7/8 spokes + hub (automated eval invocation); the shipped audit-cadence runner (Mode F deep-dive dispatch).

**Success Indicator:** the SKILL.md mode-selection table lists the three new modes with distinct triggers, AND ≥1 existing eval invocation runs automatically at a named pipeline stage with its FAIL/EXCEPTION escalation path recorded (pilot conformance evidence in this plan's Verification Evidence section).
