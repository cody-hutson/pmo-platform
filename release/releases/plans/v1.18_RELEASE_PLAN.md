## Summary

Consolidate SIOR (Situation / Impact / Options / Recommendation) escalation discipline across four migrated skills into one canonical source. **#179 is the keystone** — it authors the net-new `core/standards/sior-escalation-protocol.md` (the single-source SIOR format spec, severity-threshold policy, 5+ escalation-class examples, and decision-owner-mapping pattern), re-specs comms-writer's named Escalation type to emit named SIOR sections with an explicit Recommendation + confidence (stripping the prior Ask-conflation), carries SIOR into the name-keyed Escalation output-contract entry, reconciles the `channel-formats.md` forward-pointer, and adds one failure mode. comms-writer is the **reference implementation** of the doc. **#178** (ppm-agent Section 5 [COMMS] routing), **#177** (pmo-technical-analyst CRITICAL/HIGH emission), and **#934** (delivery-engine — folded in at Stage 5 discovery) are mutually-independent consumers that all reference the doc #179 authors. ## Change Description

> Authored per [`release/governance/RELEASE_PROTOCOL.md`](../../governance/RELEASE_PROTOCOL.md) § Change Description Protocol. Operator-facing voice. This section is committed before the PR is marked ready-for-review so it is visible at Stage 9 Plan Review in the PR diff. (Section grows as #178/#177/#934 land their consumer commits on this branch.)

**Outcome.** The platform gains a single canonical home for its SIOR escalation discipline. Before this release, the Situation/Impact/Options/Recommendation format lived inline in eight files with divergent structure, no shared severity-threshold policy, and — in comms-writer's case — no Recommendation component at all (a 2026-04-18 skill-review P1 gap). After #179, `core/standards/sior-escalation-protocol.md` is the single source: it defines the four mandatory SIOR components, the canonical severity-threshold policy (CRITICAL always / HIGH with an authority check / MEDIUM conditional-on-blocks-downstream), five worked escalation-class examples, and the decision-owner-mapping pattern. comms-writer becomes the reference implementation — its Escalation type now emits named SIOR sections with an explicit, mandatory Recommendation and confidence level, and the Ask is demoted to a closing call-to-action rather than a substitute for the Recommendation.

**Issues resolved.** #179 (keystone) lands in this release PR. #178, #177, and #934 land their consumer reconciliations in later commits on this same branch; all four are marked closed at Stage 13.

**Key decisions.** Consumption mechanism is LINK-REFERENCE (ADR-025): consumers reference the canonical by relative markdown link rather than having it injected into their packaged `references/`. This keeps the canonical out of the Check-13b same-basename collision surface, requires no `deploy.sh` change, and eliminates the only cross-issue file contention. The decision-owner mapping reads the existing free-text `## Key People` table and warns-and-routes-to-PgM when authority data is absent (option c) — degrading gracefully against verified live state, since no structured authority field exists yet. Both decisions are recorded in ADR-025.

**Reversibility.** CHEAP. All changes are additive and land on one release branch; reverting the merge commit removes the canonical doc, the comms-writer edits, the output-contract edit, and the ADR atomically. The net-new doc has no prior consumers, so deletion carries no orphaned-reference risk. (The inline SIOR copies in the consumer skills are only *reconciled to* the doc at the consumers' Stage 6 — a revert restores their pre-release inline state in the same commit.)

**Downstream impact.** comms-writer's Escalation output gains structure (additive — no contract break); pmo-qa-auditor G7/G4 gains a SIOR required-element + checklist line (additive validation). ppm-agent's [COMMS] cascade to comms-writer stays compatible (it now receives SIOR-structured escalation). No external/Anthropic-upstream surface.

**Cross-references.** ADR-025 (this release's decision record); ADR-007 (core-module boundary — places cross-skill standards in `core/standards/`); `duplicate-source-discipline.md` §1 (single-source rule applied); `core/standards/sior-escalation-protocol.md` (the artifact).
