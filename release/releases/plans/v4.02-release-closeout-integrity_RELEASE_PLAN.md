## Change Description

### Outcome

The release close-out surface stops contradicting itself. After this release, a Stage-13 close-out report can be read at face value: verification check 5 reports post-close truth rather than a pre-close count, no delivered issue is silently auto-excluded from the open-issue scan, every shipped CHANGELOG and DIGEST entry carries real prose instead of an unfilled scaffold placeholder, and the release-corpus ledgers declare which date anchor they use. Separately, the two version-collision guards that decide whether a release number is free both stop failing open — one was silently disabling half its collision set whenever it could not reach the host, the other was reading the wrong ledger column entirely and could never see an in-flight release at all.

### Issues resolved

| Issue | What landed |
|---|---|
| #3724 | The version-claim adapter now resolves the repo host identity itself instead of depending on the caller to remember it, and refuses to claim a version when it cannot evaluate its own collision set — including when the host API fails, which is the more probable trigger than the unset variable the card names. The parallel claimed-set builder in the deploy checker, which read the ledger's Tag column while treating it as State, now resolves that column by header name so the same off-by-one cannot recur silently. |
| #3586 | *(landed by the sibling Stage-6 spoke on this branch)* |
| #3665 | *(landed by the sibling Stage-6 spoke on this branch)* |
| #3587 | *(landed by the sibling Stage-6 spoke on this branch)* |
| #3718 | *(landed by the sibling Stage-6 spoke on this branch)* |
| #3701 | *(landed by the sibling Stage-6 spoke on this branch)* |

### Key decisions

- **Resolve the host identity inside the adapter, env-first — and reject git-remote parsing.** Environment-variable-first resolution is what keeps the caller cascade at zero: every governed invocation keeps its existing prefix working verbatim, and the adapter simply stops depending on the caller remembering it. Parsing the git remote URL was explicitly rejected, because a fork or a mirror resolves a *different* repository, whose releases form a plausible-looking but wrong collision set — that is the same fail-open class, re-introduced by the fix.
- **The resolver and the guard ship together, resolver first.** Shipping the fail-closed guard on its own would convert today's silent fail-open into a live pipeline halt for any caller that omits the environment prefix — and three release runs are in flight, all of which reach the claim step.
- **Pin the ledger column by header name, not by position.** The same off-by-one has now occurred twice in two parallel implementations of the same logic. A positional read is what allowed it to drift silently the first time; naming the column removes the failure mode rather than correcting one instance of it.

### Reversibility

**CHEAP / Confidence HIGH** for the release as a whole — every path is additive or prose-level, with no schema migration, no data transform, and no external state. Per-card reversibility is tabulated in § Rollback Strategy; #3718 is the one **MODERATE** case, because a published standard extension acquires citers.

### Downstream impact

The close-out report becomes usable as evidence rather than as a starting point for hand re-verification, which is what the next release's own close-out depends on. The two version guards become genuinely load-bearing at the merge moment, which matters immediately: three release runs are live and all reach the claim step. The extended date-anchor standard gains a new emission-time surface that downstream ledger writers cite.
