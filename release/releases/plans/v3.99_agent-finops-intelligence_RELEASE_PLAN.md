## Risk Register

**R1 — #4044's field rename silently breaks attribution tiers T1 and T3.** The mechanism is **worse than first stated and was reproduced at Stage 5**: `base(null)` returns **`null`** (not `""`), indexing an object with null is a jq **hard error** (exit 5), `do_emit` swallows it via `2>/dev/null` with an unchecked exit status, and the roll-up over an empty resolution set hits its own `if $grand>0 … else 1 end` guard. Observed signature: **exit 0**, one `unattributed` row with `session_count: 0`, and `coverage` reporting `attributed_token_fraction: 1` / `health: "OK"` — every session's spend vanishes while the fail-visible instrument certifies perfect health. **Owner:** Stage 6 engineer. **Mitigation:** `rollup-attribution.sh` is in #4044's edit set; the catching mechanism is `--self-test` check (A), whose ground-truth oracle asserts T1 and T3 tier-by-tier. *CHEAP to prevent / EXPENSIVE to detect post-ship (silent) / **HIGH** — reproduced.*

**R1b — store skew is caught by nothing.** Distinct from R1 (code skew). Upgraded code run against an operator's existing on-disk store that still carries `cwd` produces the same fail-open, and `--self-test` cannot see it. **#4044 is what creates this hazard.** **Owner:** Stage 6 engineer. **Mitigation:** a new **store-shape preflight (exit 3)** in `do_emit()` before Pass 1, plus its own self-test case (J). Scope-locked IN at Collective Review. *CHEAP to build / EXPENSIVE to detect post-ship / **HIGH** — reproduced.*

**R2 — A NUL byte makes plain `grep` silently blind on `extract-usage.sh`.** Exactly one `0x00` at byte offset **8559** (line 161), inside the jq sidechain-walk where a printable sentinel was intended. Plain `grep 'cwd'` returns **no output, exit 1** even when the pattern is present; `grep -a` returns the real matches. Every grep-verified AC on this file therefore passes **vacuously**. Functionally benign in jq — a *verification* hazard, not a runtime bug. **Owner:** Stage 6 engineer (replace the sentinel); Stage 7 DT (use `-a`). **Mitigation:** every method in this plan uses `grep -a`; the one-byte repair is in scope. *CHEAP / **HIGH** — reproduced by byte-offset probe with a control.*

**R3 — #4044 is a breaking change to a frozen v1.0.0 kind.** The schema's own rule makes a frozen-kind break a **major** bump plus a coordination event across consumers pinned at `>= 1.1.0`. Read literally that forces v2.0.0, invalidating the pin across three sites for zero safety gain. **Owner:** operator at **D-SchemaVersioning** (rendered). **Mitigation:** one minor bump to v1.2.0 with the `## Versioning` section **amended** to name three conjunctive, individually-falsifiable exemption conditions, so the next frozen-kind break *with a live consumer* still takes the major bump. **ADR-099.** *MODERATE / MEDIUM.*

**R4 — Bundle is over-band.** 28 raw × `novel` weight → **32 effective** against a 15–25 ceiling. **Owner:** operator at the Stage-4 D-Gate (**dispositioned: one release, over-band, recorded exception**). **Mitigation:** Checkpoint B re-validated before **every** parallel wave; may route SERIALIZE / DEFER / REDUCE-scope mid-release. *Accepted.*

**R5 — `by_skill` is partially populated and could be presented as complete.** A by-agent report rendered without its coverage label mis-slices spend and reads as authoritative. **Owner:** #4043 (emit), #3912 (render). **Mitigation: CIAC-2** — an always-present reserved `"unknown"` bucket giving `Σ by_X.* == session.tokens`, plus `session.dimension_coverage`. *Evidence caveat: the population figures are `[SOURCE: #4043 body]`, **not re-verified** — data hygiene forbids reading the operator-local store from a spoke. The design is correct at any coverage level because both mechanisms are computed per session, not calibrated to a global rate.* *CHEAP / MEDIUM.*

**R6 — Phase-progression semantics are retired by #4044 (DR-8).** The schema currently encodes *which phase has run* in the version number (`extraction-only ⇒ 1.0.0`, `rolled-up ⇒ 1.1.0`). #4044 changes the **extraction** phase's own output shape, so extraction must now emit `1.2.0` — silently retiring the implicit "`>= 1.1.0` ⇒ a roll-up has run" guarantee that today protects a consumer from reading an extraction-only store as if it had rollup rows. **Owner:** #4044 (schema rewrite), #3911 / #3912 (consume). **Mitigation:** replacement predicate **`any(.record=="coverage")`** written into the schema and binding on the in-PR consumers. **Not deferrable** — #3911/#3912 are the first real consumers and ship in this PR. *CHEAP / HIGH.*

**R7 — #3912's "by project" dimension has no store field.** Re-grounded at the Stage-4 gate; `session.worktree` is the anchor. **Owner:** #3912. *CHEAP / HIGH.*

**R8 — Two shipped K1 docs route an undelivered capability here.** The deferred hub-emitted spawn-ledger marker is routed to *this* milestone as an undelivered future in `finops-usage-store-schema.md` and `finops-attribution-convention.md`. **Owner:** #4043. **Mitigation: CIAC-5** — re-route to the durable owner, parent epic #1494. **Scope note (DR-9):** the same pointer also appears in ADR-096 / ADR-097 and the v3.96 release corpus; those are **immutable historical records** (ADR-062) and are **not** edited. CIAC-5's edit set is exactly 3 live files. *CHEAP / HIGH.*

**R9 — Cross-PR contention baseline is transiently empty.** **INVALIDATED and re-pinned.** The original zero-open-PR baseline at `d0e06ef6` did not hold; at least four other releases went in flight during this session, producing three concrete collisions (version slot, ADR number, design-principle register). **Owner:** hub. **Mitigation:** re-run at Stage 6 entry (done — see Contention Map), Stage 9 A6.5, and Stage 12 A.5. *CHEAP / HIGH.*

**R10 — Version-slot collision.** v3.97 and v3.98 were both claimed by concurrent releases during this run — two forward-only re-versions before Engineering even started. **Owner:** hub / Stage 12. **Mitigation:** three rungs — Commit-0 re-verify (single detect-and-HALT; executed, PASS at v3.99), the Stage-12 pre-merge freeness check, the atomic claim. *CHEAP pre-Engineering / MODERATE after Commit 0 / HIGH.*

**R11 — ADR-number race.** `ADR-098` is already double-claimed: it is on `origin/main` (`ADR-098-portability-seventh-first-class-value.md`) **and** carried by open PR #4167 under a different slug, which must renumber — most naturally to 099. **Owner:** Stage 6 engineer. **Mitigation:** recompute next-free immediately before authoring, globally across `core/ADRs/` **and** `release/ADRs/` **plus** in-flight PR claims; run `release/tools/check-adr-numbers.py`; cite the ADR downstream by **slug**, never by number. *CHEAP / HIGH.*

**Rollback complexity: EXPENSIVE (infeasibility stated).** `git revert -m 1` takes the whole merge including the FinOps half; a partial unwind is a hand-authored reverse diff against a schema version line and a skill package later commits build on. Rollback is whole-release-or-manual — there is no clean partial path. The store itself is a derived cache, so no data migration is involved: one `extract-usage.sh --rebuild` resolves the on-disk field skew in either direction, and the new store-shape preflight makes the *forward* skew loud rather than silent.

## Rollback Strategy

**Tier: EXPENSIVE / Confidence HIGH. Infeasibility of a partial unwind is stated, not assumed.**

- **Pre-merge:** delete the branch. Zero residue.
- **Post-merge:** `git revert -m 1 <merge-sha>` takes the **whole** merge, including the FinOps half. A partial unwind is a hand-authored reverse diff against a schema version line and a skill package that later commits build on — there is no clean partial path.
- **Store state:** the store is a **derived cache** and was never the source of truth, so **no data migration** is involved in either direction. One `extract-usage.sh --rebuild` (the default mode) resolves the on-disk field skew.
- **Field-skew direction matters and is now loud in both directions.** Forward skew (upgraded code, pre-v1.2.0 store carrying `cwd`) is caught by the new **store-shape preflight → exit 3** with a message naming `--rebuild`. Reverse skew (reverted code, v1.2.0 store carrying `worktree`) resolves by the same rebuild. Neither is silent.
- **The one non-CHEAP element is the version line** — v1.2.0 identity propagates into the emitted store, the Version History, and the consumer pins.

## Recommendations

1. **[REQUIRED — highest severity]** Build the **store-shape preflight (exit 3)** plus self-test (J). Without it, #4044 ships a change that can silently zero an operator's roll-up while `coverage` reports `health: OK` / 100 % attributed. This is the one place the design adds scope beyond the two tickets, and it is added because **#4044 is what creates the hazard**. Scope-locked IN. *CHEAP to build / EXPENSIVE to detect post-ship / HIGH.*
2. **[REQUIRED]** Use the **corrected fixture edit set** — rename **2** store fixtures, not 7. The 3 `proj-*` source transcripts and `test-fixtures/README.md` keep `cwd`; renaming them breaks extraction outright. *CHEAP / HIGH.*
3. **[SCOPED OUT — operator-dispositioned]** #4043's *optional* "`rollup` consumes `by_skill`" is dropped: it would add a field to the frozen v1.1.0 `rollup` kind and break **CIAC-1's byte-unchanged predicate**. #3912 joins `rollup.session_ids` → `session.by_skill` instead, which is strictly more honest because per-session coverage survives the join. *CHEAP / HIGH.*
4. **[FOLLOW-UP — out of scope]** File the `do_emit` silent-failure pattern: four `jq` calls run with `2>/dev/null` and no exit-status test; any abort produces a structurally valid, semantically empty store. The preflight closes the one path this release opens; **the class remains.** Suggested intake: `observation.yml`, `bug` category. Not fixed here — it is a behavioral change to a shipped script beyond both tickets' scope, in an already over-band release.
5. **[FOLLOW-UP — out of scope]** Re-visit `coverage.health`'s thresholds. The enum can report **OK on total data loss** because a zero grand total short-circuits the attributed fraction to 1. ## Change Description

### Outcome

**AFTER:** planned work gets a history-based token estimate that names its comparables and states a confidence level; spend reports slice by work item / worktree / skill / model / time with trend views and an honest coverage label on every best-effort dimension; and the estimate-vs-actual calibration loop closes — accuracy is measured at close and fed back into future estimates. The usage store retains only the worktree **basename**, never an absolute working-directory path.

**BEFORE:** the store holds attributed per-session spend at milestone grain, but nothing estimates, reports, or compares it — and it captures no skill, model, tool-call, or stop-reason dimension to slice on, while persisting a full absolute `cwd` no consumer reads.
