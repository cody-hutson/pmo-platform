## Scope-Locked Issues (4) — accepted designs

Collective Review scope-lock recorded 2026-07-16. Build order: #1477 → #1476 → #2158 → #1471.

### #1477 — block-fragile-refs.sh has no test (hook↔test parity) [mechanical; Solutioning SKIPPED]
Add `core/hooks/tests/block-fragile-refs.test.sh` — a fixture-based test consistent
with the sibling `block-*.test.sh` set and the `test-runner.sh` "Total/PASS/FAIL"
contract. It runs the real hook at its deployed path (so its co-located `lib/`
primitives and allowlist resolve naturally) and toggles the shared `.mode` file
through enforce/warn/off, restoring it on exit. Asserts a positive case per detector
class (Class L link, Class V cutover, positional bare issue-ref, Class U raw URL) plus
clean-inline, out-of-scope-path, wrong-tool, allow-marker, and bypass pass-throughs.
Restores 12 `block-*.sh` ⇄ 12 `block-*.test.sh` parity.

### #1476 — Fully drop-in the hook ownership manifest (4 non-bypass hooks / 2 arrays)
Recommended design: a line-anchored `# hook-owner: <repo-relative-path>` magic-comment
in each `core/hooks/block-*.sh` header; Check 37 rewritten to derive ownership by
enumeration; BOTH shared arrays (`C37_BYPASS_HOOKS` + `C37_OTHER_OWNERS`) deleted.
Bypass membership is DERIVED (owner == bypass index path), not separately declared.
Scope refinement (locked): the mechanism must own 4 fragment-less non-bypass hooks
(`block-skill-direct-edit`, `block-fragile-refs`, `block-gh-path-leak`,
`block-draft-files`) — not the 2 the original framing assumed — and eliminate both
arrays, not just `C37_BYPASS_HOOKS`. Adjacent in-band reconcile: `_header.md`
"Two further scripts" → 4 (regenerate index; keep Check 38 green). `build-hook-registry.py`,
the generated index, Check 38, and Check 9 are UNCHANGED (blast radius = Check 37 only).

### #2158 — Single-source the two template-sync resolvers [option (a)]
Recommended design: extract the resolver to a shared sourceable fragment
`core/deploy/lib-template-sync-source.sh` (functions-only, modeled on the already-sourced
`lib-instance-path.sh`); `deploy.sh` and `build-skill-packages.sh` both source it and
delete their inline copies; retain the function name `resolve_template_sync_source` so
deploy.sh's 3 call sites are untouched (build-skill-packages.sh renames its 1 caller).
This completes an established single-sourcing trajectory (build-skill-packages.sh already
derives 5 arrays from deploy.sh). Parity-check fallback (option b) remains one decision
away if Stage-7 DevTest surfaces sourcing fragility (AC-1's "OR" blesses it). New
regression test sources the fragment + asserts the #94 fixture case + a drift guard;
wired into `install-tests.yml`. bash-3.2-safe (source + case + local).

### #1471 — Reconcile the two link-checkers on one canonical rule [option (b): retire-fallback]
Scope-locked to option (b) — retire the bare module-prefix fallback. Canonical rule:
a markdown link resolves relative to the source file's directory; a leading `/` denotes
the workspace root (matching GitHub's rendered-blob behavior); there is NO bare
module-prefix fallback. Both checkers implement it identically. Scope escalation ACCEPTED
(no longer pure-routine): supersede the fallback-establishing ADR (new ADR via adr-helper),
rewrite 19 workspace-rooted links in `core/CLAUDE.md.template` (bare → leading-`/`), edit
both checkers, and update `doc-link-maintenance-protocol.md` + `core/rules/doc-link-maintenance.md`
(correcting the "matches GitHub rendering" attribution — fidelity is the leading-`/` clause,
not the bare fallback) + `core/deploy/tools/README.md`. No workflow-posture changes.
