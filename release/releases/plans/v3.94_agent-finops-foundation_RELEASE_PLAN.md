## Change Description

### Outcome
Establishes the **data foundation** for Agent token-spend FinOps (epic #1494): a config-resolved, git-ignored, operator-local usage store populated by a new `finops-usage-extractor` skill that reads local Claude Code session transcripts and normalizes per-session (and per-in-transcript-subagent) token counts — input / output / cache-write (tier-split) / cache-read / tool-use — plus cost-determining `service_tier`, into a versioned JSONL derived cache. Exact `message.usage` counts are authoritative; #16's word→token heuristic is a fallback for usage-less records only. C1 (#3909, this foundation) freezes the store schema at v1.0.0; C2 (#3910, same PR) adds attribution + work-item roll-up (schema v1.1.0, additive) on top.

### Issues resolved
- #3909 (C1) — token-usage data foundation: extraction, normalization, the frozen v1.0.0 schema, the config token, the optional provider connector. **Lands first on this branch.**
- #3910 (C2) — attribution + work-item roll-up. **Lands second on this branch (sibling spoke), after the schema-freeze checkpoint.**

*This is a draft PR carrying both slices; closure of #3909 / #3910 occurs at Stage 13, not by PR auto-close. Do not merge until Stage 12.*

### Key decisions
- **Store = derived JSONL cache**, not an append-only log — one record per `session_id`, rebuilt deterministically from source; no `.template` seed shipped.
- **Schema authority = tracked K1** `core/schemas/finops-usage-store-schema.md`, frozen v1.0.0 (`meta`/`session`/`subagent`; `provider` reserved-optional); C2 extends additively.
- **Cost fidelity folded pre-freeze (r2 PR-2):** cache-write tier split + `service_tier`.
- **Fail-closed exfil control (r2 FM-2):** resolve-time `git check-ignore` guard (exit 4) refuses to write a store path that is inside a repo but not git-ignored.
- **Reuse-not-re-derive (#16):** `est_tokens_from_words()` copied verbatim behind a provenance citation; fallback only.

### Reversibility
**CHEAP–MODERATE / Confidence HIGH.** Net-new + content-only; a single `git revert -m 1` of the release merge restores prior behavior. The MODERATE element is the store schema (consumed by C2 + downstream `agent-finops-intelligence`) — mitigated by the v1.0.0 freeze. No data migration; the operator-local store is operator-deletable.

### Downstream impact

Downstream pins `schema_version >= 1.1.0` after C2's additive `rollup`. No existing skill, hook, or governance surface changes behavior; the new skill deploys via the `CORE_SKILLS` roster.
