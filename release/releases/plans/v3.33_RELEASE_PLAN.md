This release gives the workspace its first coherent records-management policy and unifies artifact/folder naming and `08-Generated/` cleanup. `core/governance/RECORDS_POLICY.md` canonicalizes a retention schedule keyed by record class, a **total** 4-class classification (vital / important / reference / transient) that resolves every `01-08` project folder plus a named `DEFAULT = Reference` fallback, disposition rules with a **destruction = none** stance and a named archive log, and ISO 15489-1 authenticity markers mapped onto existing frontmatter fields (no new field minted). ### Key decisions

- **Classification is derived, not minted** (#372): a record's class is read off its governed home + existing `trust_category` + `lifecycle_state` — no `records_class:` field (duplicate-source-discipline §1). Made **total** over all 8 homes + a `DEFAULT = Reference` fallback (CDF-1 Option B).
- **Destruction = none** (#372): least-destructive-disposition adopted verbatim from the corpus-wide stance; file deletion stays an out-of-scope operator-authorized decision-class. Reversibility MODERATE / HIGH.
- **Archive log is the disposition base case** (#372): `RECORDS_ARCHIVE_LOG.md` is permanent/append-only by axiom — never itself disposed, terminating the self-classification recursion.

### Reversibility

**CHEAP / Confidence HIGH** for the release as a whole — all edits are additive governance/doc + skill-wiring; rollback = `git revert -m 1 <merge-sha>` of the single PR, with `.skill` packages rebuilding from reverted source. The #372 destruction-stance decision is MODERATE (a future destruction clause would be a governance-gated amendment). The operator-side `projects/` migration (#369, R3) reverses independently on the operator instance and is not in the PR.
