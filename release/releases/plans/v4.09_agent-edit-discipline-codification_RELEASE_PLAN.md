## Change Description

*Operator-facing. Authored at Stage 6 Phase C1 per RELEASE_PROTOCOL § Change Description Protocol.*

**Outcome.** The agent-behavior blind-spots surfaced by the 30-day transcript analysis and the 2026-06-24→2026-07-25 session-review retrospective are addressed on **both halves**. Four disciplines that previously lived only as operator-memory pointers become named, checkable rules in the governance corpus. Alongside them, a **decision-time adherence mechanism** closes the enforcement half: a bounded index of observable trigger signatures that surfaces an already-held discipline at the moment a derived observation is about to be promoted into a load-bearing claim. The QA scoring instrument that grades the resulting agent responses becomes surface-aware, so a conversational turn is scored against conversational markers rather than against markers that presuppose a deliverable.

**The core insight the release acts on.** The most frequent failure class is not a *missing* rule but a *held* rule that fails to apply at the decision point. Three of the four disciplines whose non-firing the retrospective reports are **already** bullets in the charter's Universal Preferences list. A twenty-ninth bullet is therefore the intervention already falsified for this failure class. What was missing is a **trigger** — something that says *when* the gate must fire — and a **deployed surface** that the running agent actually loads.

**Issues in scope (6).** #3926 (the decision-time adherence mechanism — leads) · #3126 (unrequested memory saves) · #3127 (rename without reference cascade) · #3128 (over-capitulation under pushback) · #3927 (read-only / analysis intent answered with execution) · #4017 (Push-to-Resolve rubric surface-awareness).

**Key decisions.** Placement was decided **once for all cards** at the plan gate: the disciplines land in `core/rules/`, because that is the only tracked corpus surface with a governed mirror contract to the running agent. The mechanism **extends** the existing Decision-Confidence Protocol at the one layer it structurally lacks — an objective trigger predicate — rather than paralleling it with a second pre-action gate. And the release adds **no bullet** to the charter's Universal Preferences list: all five governance cards independently reached that determination.

## Rollback

Single `git revert -m 1 <merge-sha>` on the release merge commit. All changes are additive text in tracked files plus one package rebuild; no data migration, no schema change, no consumer contract broken. **CHEAP / confidence HIGH.**

**Two caveats that a bare revert does not cover:**

1. **TEMP-memory evictions (R-1).** If the release is reverted *after* the three evictions have run, the disciplines are held nowhere. The evictions must be **restored** as part of the revert.
2. **The operator-side rules mirror.** If the operator has mirrored the new rules into the workspace rules directory, a revert of the repo leaves the mirror ahead of source — which Check 9 will correctly report as drift. Re-running the deploy check after a revert is part of the rollback procedure.
