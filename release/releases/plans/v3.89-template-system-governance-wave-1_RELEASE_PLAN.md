## Rollback Strategy

- **Topology:** D-C SINGLE — the whole milestone ships as **one PR / one merge** on one release branch.
- **Pre-merge:** abandon the branch — nothing is on `main`; zero blast radius. Per-slice drop is clean:
  because the three issues are logically independent, dropping any one slice's commit(s) before merge leaves
  the others valid with no cross-dependency fixup.
- **Post-merge:** `git revert -m 1 <merge-sha>` atomically unwinds all 7 files (both new templates + the CSV
  header + the three registry/taxonomy edits + this plan file). CHEAP · confidence HIGH.
- **Deploy-sync (#2855):** re-run `./deploy.sh --deploy project-initiator` after the revert so the deployed
  mirror re-syncs to the reverted canonical (Check 13 parity).
- **No IRREVERSIBLE actions, no external-system state, no data migration** — git fully unwinds. The `v3.89`
  tag, if already claimed, is superseded by a follow-on patch release per standard practice (tags are not
  force-moved).
