## Rollback Strategy

**Single release PR** (`release/v3.52-83-eval-framework-completion` → mainline). Rollback = operator-authorized revert of the merge commit (per RELEASE_PROTOCOL.md § Rollback protocol; git history IS the snapshot on the Claude Code path).

- **Whole-release rollback:** `git revert -m 1 <merge-sha>` restores prior state. LOW complexity — no data migration, no external state; re-deploy via `deploy.sh` after revert if the release was already deployed.
- **Per-card partial rollback (pre-merge, on-branch):** the four cards are near-independent commits — #209 (doc-only) and #367 (net-new test file) are the cleanest to drop; #199 and #279 share the eval-home so drop them together if the home resolution is the failure. This is a Stage-9 [SCOPE CHANGE] disposition, not a post-merge action.
- **Version:** if rolled back after tag, the version number is permanent (numbering gaps are benign per bundle-composition-doctrine § 5.3); a re-release takes a new next-free slot.
