## Release Outcome Statement
**AFTER** — The people-graph capability that shipped *structurally* in v2.23 (milestone #188) is *activated* end-to-end: a fresh install seeds the operator-instance `people-roster.yaml` create-once, an update preserves it, the adoption flow is documented, and an eval proves an agent resolves a name from a populated roster. Capability is usable, not merely present.

The create-once seed idiom exists for the localized-context-needle file only (~15 lines away in the same scripts), not for the roster.

## Risk Register
Each risk carries a reversibility tier and confidence.

| ID | Risk | Reversibility / Confidence | Mitigation |
|---|---|---|---|
| R1 | **Roster clobber** — the seed overwrites an operator's filled `people-roster.yaml`, destroying real names/contact data. | **IRREVERSIBLE / HIGH** (filled roster is real PII; no undo) | 3-layer defense, all verified to exist: (1) create-once `[ -f "$roster" ] && PRESERVED; return 0` guard at every site; (2) out-of-tree instance path (`$(pmo_instance_path)` resolves to a sibling of the repo); (3) `.gitignore` backstop. AC-2 (re-run does NOT overwrite) is a non-waivable Stage 8 HARD gate — fill a fixture roster, re-run install + update + a second setup, assert byte-unchanged. IRREVERSIBLE surface gets operator sign-off + rollback-infeasibility statement at Stage 9. Posture: prevent, don't recover (the create-once guard IS the rollback substitute). |
| R2 | Seed writes to the wrong path under `PMO_INSTANCE_PATH` / `CLAUDE_WORKSPACE_ROOT` override — creates an orphan roster the skills never read. | **CHEAP / MEDIUM** | Resolve the target ONLY via the accessor (`pmo_people_roster` / `pmo_people_roster_for`), never a hardcoded `~/Claude/...`. Stage 7 DT runs a non-default `PMO_INSTANCE_PATH` install and asserts the roster lands where the skills read. |
| R3 | Dependency-order violation — #2041/#2042 built before #2040, so docs describe a non-existent flow / the eval has no populated roster. | **CHEAP / HIGH** | The sequence makes #2040 a hard gate; siblings do not start until the seed mechanism is on the branch. |
| R4 | Version collision — v2.26 claimed by a concurrent release between D-Version and Engineering Commit 0. | **MODERATE / MEDIUM** (after Commit 0 the number propagates into branch name + plan path + frontmatter) | Defer-to-merge: declare bump-class minor as durable; treat the number as provisional. Commit-0 re-verify HALTs on collision; the Stage 12 atomic claim is the final guard. |
| R5 | Eval is a no-op pass — the judge "passes" without exercising the roster read. | **CHEAP / MEDIUM** | Author per eval-writer discipline: assert a specific resolved value from the populated fixture AND assert zero graph-write (read-only). Stage 8 QA reviews the judge against the rubric, not just the PASS. |

**Rollback strategy (release-level):** All changes are git-reverts of a small PR set — CHEAP at the repo level. The ONE non-reversible element is runtime data on an operator machine (R1): a deployed seed that clobbered a filled roster cannot be git-reverted. Rollback posture is therefore prevent-don't-recover; the create-once gate is the rollback substitute for R1. No schema change, no ADR, no migration.

## Engineering note (#2040)

Stage 6 executes hub-inline / spoke-in-worktree; Stage 9 PR review is the independence/review gate.

## Deviation Log
Departures from the Stage-4 release plan (#2051), recorded at Engineering Commit 0.

- **D1 — File Change Matrix refined from 2 sites to 3 (added `docs/scripts/setup-workspace.sh`).** The Stage-4 matrix listed only `install.sh` + `update.sh`. Stage 5 established that the localized-context-needle idiom #2040 mirrors is *three* sites, not two: `setup-workspace.sh` `scaffold_localized_needles()` is the functional PRIMARY (called from `fresh_install` + `rebootstrap`, integrates the `rm-file:` rollback ledger), with `install.sh` as the idempotent belt-and-suspenders guard and `update.sh` as the preserve-on-update site. Mirroring all three is what makes the card's "extend the idiom" framing literally true; a 2-site implementation would silently drop the rollback ledger. Classification: **Tier 1 [ADJUST]**; operator-accepted at Stage 5 Procedure 4 (2026-06-26).
- **D2 — `pmo_people_roster()` accessor added to `core/deploy/lib-instance-path.sh`.** The Stage-5 spoke's default recommendation (Finding 3 / D4) was to ship the unparameterized path literal `$(pmo_instance_path)/people-roster.yaml` to stay byte-consistent with `extract-roster-needles.sh`, deferring an accessor to a separate improvement. At Stage 5 Procedure 4 the operator chose instead to **add `pmo_people_roster()` within #2040** (DRY; mirrors the existing `pmo_localized_needles()` accessor; the 4 consuming skills and the extractor reuse it), accepting the in-card single-resolution-site convergence. Two accessors are added to mirror the existing `pmo_instance_path` / `pmo_instance_path_for` pair: `pmo_people_roster()` (default base) and `pmo_people_roster_for()` (explicit workspace root, for the sandboxed `--workspace-root` install path). Classification: operator-approved scope addition (2026-06-26).
