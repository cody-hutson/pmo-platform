### Outcome

The pipeline now carries a codified **author-association trust boundary** at its comment-as-stage-I/O seam. Any comment authored outside the trusted set (`OWNER` / `MEMBER` / `COLLABORATOR`) is treated as untrusted third-party content: it is surfaced to the operator (thread + author association + timestamp) and is never read as stage content, instructions, requirements, or evidence by any pipeline reader. The gate runs BEFORE feedback tier-mapping — it keys on repository relationship, never on content plausibility, which is exactly the prompt-injection shape it exists to defend against. A standing moderation posture (Stage-13 lock-at-close of finished sub-task threads) shrinks the window in which third-party comments can land inside active release threads.

The parent improvement is resolved (both gaps: no codified trust boundary for third-party comment content; no standing moderation posture). It is marked closed at Stage 13 via the PR's Issue References block. See the PR's Issue References block for the reference.
