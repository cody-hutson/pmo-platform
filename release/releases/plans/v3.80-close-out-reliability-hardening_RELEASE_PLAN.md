## Release Outcome Statement

AFTER — The Stage-13 automated close-out surface is CI-enforced and naming-robust:
`claim-version.sh` and `deploy.sh` Check 5(d) self-tests run in CI, `extract_milestone_slug`
resolves pure-alpha theme-named milestones (including hyphen-less single words), and
`check-release-body-drift.sh` compares against `origin/main` — so a close-out defect is
caught pre-merge instead of surfacing at operator-local close-out or in a shipped public
artifact.

BEFORE — The highest-stakes close-out tools rely on manual/local self-tests, a slug resolver
that mis-falls-through to the Version field for pure-alpha names (Phase-B manual fallback
required), and a drift check that reads the working tree — so defects reach main and are
caught late.

Success Indicator: a pure-alpha-named milestone closes out fully via the tool (no Phase-B
manual fallback); the claim-version + Check 5(d) self-tests gate PRs in CI; the drift check
reads origin/main.

## A6.5 Locked Conditions (Collective Review scope-lock — binding)

All three designs were LOCKED as amended by their Phase A6.5 adversarial conditions. Every
condition is CHEAP and lands inside the already-frozen File Change Matrix (no scope widening).

### #2539 (implemented by this spoke)
1. **True-count semantics** — the spec'd `subn(count=1)` body makes D-3 return n=1 for exactly
   the over-match it exists to catch; use `findall`-equivalent true-count (verified: n=2/n=3
   catches; capped count=1 passes → phase 6 silently flips on the wrong key). Without this, D-3
   ships as a believed-but-absent mitigation.
2. **Classify + fixture the armed `phase_detect_open_issues` consumer BEFORE Stage 12** — the D6
   gate has been a silent false-negative on all 32 prior pure-alpha releases (`gh issue list
   --milestone <mis-resolved Version>` → empty + exit 0). Once the resolver lands, the gate arms.
   Operator ruling: **verify, do not assume the count drains to zero by Stage 13.**
3. **Strike "position-independent"** from the resolver doc-comment — the claim is false (insert
   one kebab-valued column before Milestone → a4 returns the wrong field). Replace with the true,
   narrower invariant: a4 is safe only because exactly one contractually-dot-bearing column
   (Version) precedes Milestone.

### #2540 (later Engineering chip)
1. **4-line array-shape guard** — the one-line `NAME=(a b)` form makes `extract_roster_array()`
   return non-empty garbage → finding storm → exit 1 → warn-mode GREEN. `deploy.sh:172
   SUPPLEMENTARY_SKILLS=(...)` proves the form is live in the parsed file.
2. **`WARN_MODE:'false'`** — the stated warn-mode rationale is factually false (branch protection
   carries 9 required contexts, the skill-mirror is not among them). AC-1 says "turns the check
   red"; warn-mode ships it green.

### #2678 (later Engineering chip)
1. **exit-2 handling** — the change adds two new producers of exit 2 (git-guard, corrupt-object);
   3/4 consumers mis-handle it (`automated-closeout.sh:2053` + `deploy.sh:5305` hard-code
   "gh offline/unauthenticated" false diagnosis; `deploy.sh:652` returns no finding at the
   fail-closed gate).
2. **`REPO_ROOT` seam; DROP `DRIFT_CANONICAL_REF`** — the knob is production-reachable and
   undocumented as test-only, so `DRIFT_CANONICAL_REF=HEAD` would silently re-create the exact
   defect #2678 fixes. Net −1 seam.
