### Rollback strategy

- **Pre-merge (Stages 5–11):** revert the release branch or drop the offending commit; no external state exists. **CHEAP**, confidence HIGH.
- **Post-merge, pre-deploy:** `git revert` the merge commit on a fix branch. The change is **purely additive** — two new checklist groups, two new Composition rows, two new Process steps, one new Output-Contract element. No group is renumbered, no existing check is modified, no schema column is added, so a revert restores the exact prior 7-group behavior with no downstream migration. **CHEAP**, confidence HIGH.
- **Post-deploy:** rollback = revert commit + `build-skill-packages.sh` + redeploy. The only non-trivial component is the disposition enum: if the new value shipped and any consumer persisted a finding carrying it, revert leaves an orphan enum value. Mitigation: Mode R is **read-only and mutates nothing**, so no persisted state carries the value — the enum lives only in transient briefings. **CHEAP**, confidence MEDIUM (MEDIUM only because #2719's cache-read consumer is planned-not-shipped; if it ships before this release deploys, re-assess to MODERATE).
- **Rollback authority:** operator-authorized per RELEASE_PROTOCOL.md § Rollback protocol. Not self-authorized at any stage.
