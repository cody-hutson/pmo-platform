## #64 per-flow-type backfill scope + sequencing (AC#2 — the decision the follow-up slice executes)

#64 ships a pilot plus a per-flow-type scope definition; the bulk corpus backfill is fissioned to #398 (the follow-up slice). This table is the AC#2 deliverable — it bounds, per flow type, which existing processes get diagrams, whether each centralizes or embeds, and the order #398 executes them in. Only the architecture row ships in v1.05 (the pilot); the rest are #398 scope.

| Flow type | Backfill population (existing processes) | Centralize or embed? | Pilot in v1.05? | #398 follow-up order |
|---|---|---|---|---|
| Architecture | Platform top-level structure; layer model; module-API surfaces | Centralize (`core/diagrams/`, ≥3 parents) | **YES — pilot (this release)** | — (pilot lands it) |
| Concept model | knowledge-architecture (K-tiers); five-function spine; operating-model role taxonomy | Centralize if ≥3 parents, else embed in the owning `core/disciplines/` doc | No | 2nd (high cross-cut, stable) |
| Agent process | 13-stage pipeline flow; hub-spoke routing | Centralize (the pipeline is cited everywhere) | No | 3rd |
| Decision tree | bundle/refresh routing; version-management gate logic; triage re-review branch | Embed in the owning standard | No | 4th |
| Skill flow | per-skill mode-routing (the deployed skill roster) | Co-locate (`<module>/skills/<skill>/diagrams/`) — skill-owned | No | 5th (largest count; batch by module) |
| Human process | operator gate workflows (Stage 9 GO/NO-GO, Stage 12 execute) | Embed in the pipeline docs | No | 6th |
| Data flow | stage-io-contracts; per-skill-output-contracts; tracker-schemas | Embed (already tabular in the schema docs) | No | 7th (mostly already-tabular; lowest marginal value) |

Sequencing rationale: land the architecture anchor first (it validates the structure and does real de-stale work), then the highest-cross-cut concept and agent-process artifacts, then the long-tail skill-flow batch (mechanical, module-partitioned), then data-flow last (largely already-tabular, lowest net-new). Each #398 increment is independently shippable and independently sized.
