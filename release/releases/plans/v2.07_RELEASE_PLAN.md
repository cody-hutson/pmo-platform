## 1. Release Outcome (goal-conformance target for Stage 9)

**AFTER** — Operators govern all ambient intake automation from one plain-language `automation_level` dial in `operator.toml` (`off` / `recommend` / `bounded_auto`) that acts as a **ceiling** — `effective = min(automation_level, per-action max)` — enforced by a PreToolUse hook that blocks any action above the ceiling (warn-mode-initial; hard after the operator flips it post-shakedown), while never unlocking the irreducible Tier-0 set. Scheduled Path-A sweeps (ambient inbox + drive transcripts/emails) and Path-B external-sync (Jira/Confluence/Smartsheet MCP) capture, classify, register, reconcile, and propose evidence-gated closes on a cadence, rolling up into one consolidated daily-status digest with a sweep-health heartbeat so a silent sweep failure is impossible.

**BEFORE** — Ambient intake is manual and unguarded: the operator launches each daily processing cycle by hand; there is no watched inbox or dedup cursor, no scheduled Path-A/Path-B sweep, no operator-set autonomy ceiling (let alone enforcement), and no consolidated sweep digest or heartbeat (a stalled sweep fails silently).

**Success Indicator (Stage 8 + Stage 9 gate):** `core/config/operator.toml.template` carries an `[automation]` table with `automation_level`; `core/deploy/deploy.sh --check` exits 0 with the C5 hook registered in `core/settings.json.template` PreToolUse; and a fixture sweep at `automation_level: recommend` yields zero Tier-1 writes plus ≥1 surfaced draft, rendered in the consolidated digest heartbeat.

## 3. Implementation Sequence (D-C SINGLE, write-serialized)

```
C0  →  C1  →  C5  →  C3  →  C2  →  C4
```

Rationale for the order:
1. **C0 first** — the keystone dial every other card reads; nothing clamps to a dial that does not exist yet.
2. **C1 second** — the inbox + cursor C2 reads to skip already-processed files.
3. **C5 third (before C3/C2)** — defense-in-depth: the enforcement hook lands warn-mode-initial *ahead* of the scheduled sweeps that produce mutations, so the advisory→hard window is closed atomically by the single-branch deploy rather than left open between sweep-ship and hook-ship (FMF-3 mitigation).
4. **C3 then C2** — C3 freezes the run-record schema as the C3↔C4 contract; C2 aligns to it (one-schema heartbeat guarantee). C2 also reads C1's cursor and C0's dial.
5. **C4 last** — consumes both sweeps' run-records; it can only render a heartbeat for producers that already exist.

- Intake/sync via the **governed MCP channel** (not Bash/WebFetch — `block-egress.sh` is Bash/WebFetch-scoped); READ/poll external + LOCAL-write only; NO `mcp__*` write verb against any external system.
