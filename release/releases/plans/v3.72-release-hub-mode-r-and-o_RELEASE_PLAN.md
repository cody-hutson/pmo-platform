## Summary

A **self-modifying release** that hardens the `release-hub` skill along five additive slices — no net-new capability, all edits scoped to `release/skills/release-hub/`. The release closes five known conformance gaps in Mode R (Milestone Readiness) and Mode O (Orchestrate Release):

1. **#2680 — Mode R read-only guardrail.** Mode R is spec'd read-only ("mutate nothing") but has no failure-mode entry or output-contract clause naming the boundary-crossing protocol required before ANY state mutation. Add the failure-mode entry + make the recommend-only contract explicit.
2. **#2657 — Mode R verdict → next-action routing.** Mode R terminates at the GO/NO-GO verdict with no owned transition to the operator's actual next step. Add terminal routing (GO → Mode O; NO-GO → dispositions-as-cleanup-checklist + the R → cleanup → re-run R → Mode O loop).
3. **#2576 — methodology-neutrality + structural-cascade checklist group.** Mode R has no architecture-conformance gate for (a) hardcoding a methodology archetype into the neutral toolkit vs. shipping a config-selected pack (ADR-033), or (b) a rename/restructure blast radius reconciled against operational-taxonomy epic #2373. Add checklist **group 7** (compose-only, zero inline logic).
4. **#2355 — Mode O per-wave concurrent-PR check.** Mode O Procedure 2 spawns build spokes without checking for an existing open PR against the target issue; a mid-run collision was only caught at Stage 7/8. Add a per-wave, pre-spawn `gh pr list` check.
5. **#2428 — Mode O Stage-12 tail routing.** Mode O drove Stage 12 as a bare `gh pr merge` (Phase B1 only), skipping the version-claim/tag (B3) and DEPLOYED-row chore PR (B5), leaving the release "merged but not version-claimed". Route Stage 12 through the pmo-release-manager tail + add a guard.

**Outcome Statement:** *release-hub's read-only Mode R stops being able to mutate state and always routes the operator to the next action; Mode O stops forking on concurrent PRs and stops landing releases merged-but-not-version-claimed — the two modes enforce their own contracts.*

**Deferred (owner-extension scope):** #2574 (ownership scan / DROP-OR-REHOME) and #2575 (problem-validity + altitude) — the two other co-designed Mode R checklist groups — are deferred out of this release; #2576's neutrality group is the sole new checklist group (numbered **group 7**), and the closed disposition set is unchanged.
