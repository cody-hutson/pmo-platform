## Scope — the milestone bundle and the coordinated unit

The milestone `release-corpus-verification-surface` bundles four work issues: #425 (label-token correction in `release-executor` SKILL.md — routed through `pmo-skill-editor`, handled separately), #291 (`bundle-issues-parser.py` conformance — handled separately), and the **coordinated deploy-check unit #83 + #85 + #459**, which is the subject of THIS release plan and ships as ONE release PR per the operator's MERGE decision.

The three coordinated issues share one root cause: the deploy-check tools under `core/deploy/tools/` were authored **pre-restructure** and hardcode the dead `pmo-platform/...` path prefix. The modular-monolith move to `core/`, `release/`, `operations/`, `docs/` left them stranded, and a silent-pass anti-pattern (a check reads GREEN while its target surface does not resolve) masks the breakage.

1. **#83 — `lint_release_corpus.py` + Check 20 + docs (size M).** The release-corpus validator EXISTS and is richer than the issue assumed (6 check modes, wired to Check 20 — Check 15 is RETIRED in v2). BUT it points at dead paths, so Check 20 vacuously passes against a non-existent notes dir while 11 real notes go unchecked. RE-SCOPE: path-rewire the validator + reset the note-content cutover so Check 20 demonstrably lints the live notes + reconcile three docs.

2. **#85 — `generate_release_index.py` (size XS, re-scoped).** The generator is LIVE (invoked by `automated-closeout.sh`, Check 23, `release-process.md`), NOT orphaned. BUT it is fully broken: hardcoded dead `RELEASE_LOG.md` path, and its emitted schema (8-col) matches zero of the live 6-col INDEX rows. The `#N`-token Scope-count bug the issue was filed for is MOOT under the chosen fix. RE-SCOPE to Option (a): rewire paths + reconcile the generator's emitted schema to the live 6-col INDEX (`Version | Milestone | Date | Theme | Release PR | Release Notes`).

3. **#459 — fail-loud contract across the deploy-check family (size M).** The silent-pass-on-path-resolution-failure root cause behind #83/#85, generalized. Adopt the exit-code contract 0=clean / 1=findings-or-drift / 3=path-config-error (matches `cross-module-audit.sh`); apply exit-3-on-unresolved-path to the corpus tools AND `check-version-anchors.py` and `check-doc-links.py`; fix both wrong catalog paths; fix the `automated-closeout.sh` generator-hook fallthrough; harden the `deploy.sh` Check 14/18/20/23 PASS branches so a non-zero exit / unresolved target surfaces as FAIL/DRIFT, never silent PASS.
