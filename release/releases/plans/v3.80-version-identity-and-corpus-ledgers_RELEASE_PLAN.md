## Release Outcome Statement

**AFTER** — A platform builder running a release can declare it `version-less` and have every
enforcement surface agree: the Gate-3 spec asserts release-identity-mode validity in place of a
version claim, the release-class taxonomy handles the hotfix case without assuming a version string,
and both protocol surfaces describe the identity mode consistently. Concurrently, the corpus's
pure-additive ledgers (RELEASE_INDEX / RELEASE_DIGEST / CHANGELOG) merge without textual conflict via
a union merge-driver, so a long-running release branch reconciles against a moving mainline instantly
instead of losing its version slot to a faster sibling — and RELEASE_REVERSIONS is slimmed to the one
case it still serves.

**BEFORE** — The `{versioned, version-less}` identity mode is declared in the Stage-3 shard but
enforced nowhere: the Gate-3 spec carries no version criterion at all, the release-class taxonomy
assumes every release has a version string, and neither protocol surface mentions the identity mode.
Separately, no merge configuration exists for the corpus ledgers, so every concurrent release pair
conflicts textually; the resulting slow reconcile costs the branch its version slot, forcing a
re-version cycle. RELEASE_REVERSIONS instruments that churn with a reaper that has never fired.

**Actor(s)** — Platform builders (release managers, DevOps) driving releases through the 13-stage
pipeline, and the hub/spoke automation that reconciles a release branch against `main`.

**Success Indicator** — Two concurrent release branches reconcile and merge with zero corpus conflict
on the pure-additive ledgers; a `version-less` release passes Gate 3 without a version claim; no
release re-versions solely due to a corpus conflict.
