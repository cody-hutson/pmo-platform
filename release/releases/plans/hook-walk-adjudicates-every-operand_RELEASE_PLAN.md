## Rollback Strategy

**Per issue.** Each card is its own run of commits on a linear branch, so one card reverts with `git revert` of its commits. A revert of #7019 or #7018 restores the pins that card flipped and the corpus verdicts it moved; a revert of #7028 restores the "tracked separately" wording.

| Path | When | Steps |
|---|---|---|
| Partial revert | one card misbehaves after merge | revert that card's commits on a fix branch; republish hooks; re-run the suites |
| Full restore | a refusal storm or a fail-closed loop on an instance | revert the merge commit; republish hooks; confirm by hash that the deployed copies equal the reverted sources. The version tag stays — it is never deleted |
| Forward fix | a narrow, understood defect | a fix branch through the pipeline |

What a rollback costs, stated plainly: every escape this release closes re-opens, and a graduated phase constant returns to `warn`, restarting Check 71's clock against the original arming date — so a rollback after a graduation needs its own recorded decision. Reversibility: MODERATE for the walk changes (a revert plus a republish); EXPENSIVE for a graduation, per #7026.

It is distinct from the user-facing release note authored at Stage 13.

### Outcome

The script-execution rule (BLOCK-DESTRUCTIVE-022) now adjudicates the script behind two kinds of flag it used to step past without reading. **Slice 1 (#7019):** a flag token whose leading quote closes early no longer hides the script behind it. `bash ""-x <script>`, `bash -n ""+n <script>`, `zsh ''-x <script>` and the rest of that family were allowed while their unquoted spellings were refused; they now take the unquoted spelling's verdict, so a script missing from the allowlist is refused and an allowlisted one still runs. Since the iteration for Stage 7 finding F-01, that includes a flag word whose quote closes inside the script suffix — `bash '-x.s'h <script>`, which the shell reads as `-x.sh` — and fourteen measured spellings of it under `bash`, `zsh`, `source`, `python3`, `perl`, `ruby` and `node` that had been allowed where their unquoted spellings were refused or warned on. A quote-led flag word whose value the hook cannot know — a `$` expansion, a command substitution, an unquoted brace, glob or tilde character, or a token longer than the reader's limit — is no longer taken for the operand: the walk goes on, and the script behind it is checked. **Slice 2 (#7018):** a bare `-n` is a parse-only grant only where the interpreter really reads it as a flag. A `-n` behind a word that is not an option (`zsh -s -O extglob -n <script>`, `bash <wrapper> -n <script>`), behind an option the walk cannot read exactly (`bash --rcfile"" -n <script>`), or behind an option argument that may be no word at all (`bash --rcfile $X -n <script>`) was exempted while the shell ran the script; those invocations are adjudicated again, as they were before the parse-only exemption existed. A cluster carrying the command-string letter (`bash -ec '<program>'`, `sh -xc`, `bash +ec`) now opens a program string whose words are checked, as a bare `-c` always did, and an option the walk cannot read no longer hides an unlisted script behind an allowlisted one. A program fed to a shell on standard input stays outside the rule's reach, and the readiness doc now says so. **Slice 3 (#7020):** a transparent wrapper's own options no longer stop the walk. `nice`, `stdbuf` and `timeout` join the walked set, and every wrapper's options and operands are read from a per-wrapper row of its option grammar, so `nice -n 10 bash <script>`, `stdbuf -o 0 bash <script>`, `sudo -u <user> bash <script>`, `env -u NAME bash <script>` and `timeout 5 bash <script>` take the verdict of `bash <script>` — a script missing from the allowlist is refused and an allowlisted one still runs. Since the iteration for Stage 7's findings on the slice, a wrapper's long option is read the way its program's parser reads it, unique prefixes included: `env --split=<script>` keeps the record `env --split-string=<script>` has, and `nice --adj 10 bash <script>` is refused as `nice --adjustment 10 bash <script>` is. Since its second iteration, an attached split string that carries no command word of its own — empty, a flag, or an assignment — no longer hides the command that follows it: `env --s= bash <script>` and `env -S-i bash <script>` take the verdict of `bash <script>`, because GNU env runs that command. That holds for a value written without shell quotes and carrying no slash: a split value written with shell quotes and a split value carrying a slash stay open, and in both the program the guard models runs an unlisted script while the guard allows the line, as the guard before this release also did; both are declared, and #8491 owns their fix. `if`, `while` and `until` join the keyword arm. An `xargs` that feeds an interpreter from standard input is refused behind `xargs`'s own options as it was without them. The four lists of this vocabulary — this walk's, the egress walk's, the shared canonicalizer's and a continuous-integration lint's — are now compared word by word on every run. What stays open is declared and pinned: an option a row does not list that takes a value, an interpreter flag after `xargs <interpreter>`, a command line written as one string, launchers outside the set, and a quoted assignment value ahead of the verb. **Slice 4 (#7028):** a verb behind an enclosure opener is now adjudicated. A substitution, backticks, a process substitution or a parenthesised group is not a separator, so the verb inside one — `echo $(bash <script>)`, `` echo `bash <script>` ``, `cat <(bash <script>)`, `(bash <script>)` — never reached command position, and an unlisted script ran with nothing refused or recorded. A second view of the same segments now opens a command position after every `(` and every backtick and runs the same walk there; it runs after the first view has finished, so it can add an adjudication and never remove one. A shell interpreter or `source` found there follows a third rollout family, `DESTRUCTIVE_022_ENCL_PHASE`, which enters at `warn`: the call proceeds with a would-fire row (arm `shell-enclosure`, `pos` `enclosure`) and a notice, and is refused once the phase graduates — a decision still owed, which Check 71 forces from 2026-12-15. A direct execution or a non-shell interpreter there is recorded at its own arm's phase. Two exemptions written for the head of the line are now read at the enclosure too: a carrier's quoted-argument exemption no longer reaches a command inside an enclosure (`echo $(bash -c 'cd /tmp; bash <script>')`), and a here-document is excised only when the receiver read from the innermost open enclosure is a carrier as well (`echo $(bash <<'EOF' … )`). What the view does not reach, and what it adjudicates although nothing runs, is declared in one open list in the readiness text and pinned. **Slice 5 (#7004):** the egress rule (BLOCK-EGRESS-007) now evaluates a `gh api` write behind a prefix command's own option, option argument or operand. Its walk stepped over a prefix command — `env`, `sudo`, `xargs`, `timeout`, `nice`, `stdbuf` and the rest of its bounded list — with that command's dash-led tokens, and read the next word as the command, so `env -u NAME gh api -X POST <path>`, `timeout 5 gh api -X POST <path>` and `env a-b=1 gh api -X POST <path>` were never examined while `env gh api -X POST <path>` was. Behind the unchanged walk, the rule now looks for the first adjacent `gh` and `api` words later in the same segment and adjudicates that invocation. It interprets nothing it passes over, so an option the rule has never seen cannot strand the write. Every such position follows the rule's rollout phase, still `shadow`: the write is recorded with a would-fire row, which now carries `pos: "look-ahead"`, and nothing is refused until that phase graduates. No phase constant moved. A write found this way never moves a later write at the head of a segment out of its day-one refusal.
