## Risk Register

Each entry: risk → mitigation → *reversibility / confidence*.

**R1 — The G3 override produces a release bundle that cannot reach its own gate. (SCOPE / STRUCTURAL — highest)**
Two of four issues are `status: proposed` and dependency-unmet on an external milestone, so this bundle cannot reach Stage 9, let alone Stage 13. Partition A will sit built-but-unshipped on a release branch with no version claim and no deploy, for a window bounded by #295's ship. Every day in that state accrues re-baseline cost, and a milestone structurally unable to close distorts the release log and the cycle-time surfaces. **Mitigation (preferred):** re-home #4027 + #4028 to a follow-on milestone, making Partition A a complete 2-issue release that can reach Stage 13 on its own. **Mitigation (if held):** record explicitly that goal-conformance and goal-attainment are *deferred*, not waived, and set an unpark trigger on #295's merge rather than leaving the resumption implicit. *Reversibility MODERATE / Confidence HIGH.*

**R2 — Live cross-release coupling to #295, on the artifacts #4027 consumes AND on its oracle source. (DEPENDENCY)**
#295 is scaffolded and running now, editing the event-log schema, the query and append tools, and — via #3723 — the release-hub skill definition, which is where #4027's oracles live. Building #4027 against a moving schema *and* a moving oracle is the compounded version of the premature-build risk #4027 already names. **Mitigation:** hard-order #295 before #296 Partition B; re-run the structural sub-audit at Partition B entry; pin the oracle by SHA (R3). *Reversibility MODERATE / Confidence HIGH.*

**R3 — Oracle drift, with a live count mismatch already present. (SCOPE — verified)**
#4027's premise cites thirteen named failure modes. A section-scoped structured count over the whole population returns the hub set at eight and the release-executor set at thirteen — **twenty-one total**, not thirteen. The cause is not determinable from this repository (the originating analysis artifact is operator-local), so whether the original analysis miscounted or the executor set has since grown is `[ASSUMPTION – CONFIRM]`. Either way the finding stands: a cached oracle cardinality does not reconcile against live state, which is precisely the failure mode a repeatable decision audit must not inherit. **Mitigation:** #4027 must **derive** its oracle set from the corpus at run time and **pin it by SHA** in the window input, never carry a hardcoded count. Applied to #4027's body under #4024 AC-2 and recorded as a standing requirement in the host ADR and the mode spec. *Reversibility CHEAP now / EXPENSIVE once the audit ships against a wrong oracle / Confidence HIGH on the count, MEDIUM on the cause.*

**R4 — #4027 and #4028 rest on evidence that is not in the repository. (EVIDENCE)**
#4027's reproduce-the-prior-findings criterion and #4028's stated seam baseline both cite the operator-local analysis workspace, which is git-ignored by design. A tracked acceptance criterion whose oracle lives at a git-ignored path is ungradable by any spoke, by construction. **Mitigation:** the host design resolves this by adopting the two-surface emission precedent — the audit writes the git-ignored dated folder **and** a committed summary handoff, so a tracked criterion has a tracked oracle. At #4027 Stage 5, transcribe the prior anchors, finding signatures, and seam baseline grades into the tracked rubric. *Reversibility CHEAP if done at Stage 5 / Confidence HIGH.*

**R5 — #3705 partial-fix trap: fixing the sampling source alone buys green tests and no working hook. (CORRECTNESS)**
Both defects reproduce at the pinned base: the predicate reads counter fields the `Stop` payload does not carry and the fail-quiet path maps missing to zero, so under the shipped default the predicate always skips; independently, the sentinel is written on the skip path while the guard exits on any later `Stop`, so the decision is frozen at turn one. **Mitigation:** the multi-`Stop` guard test is the gating criterion — it must assert a retro fires at an actual session boundary under the shipped default. Stage 8 grades the three sub-criteria as a conjunction; a PARTIAL on any one is not a pass. *Reversibility CHEAP (hook ships inert) / Confidence HIGH.*

**R6 — #3705's durable-record criterion is very likely already satisfied — scope-reduction finding. (SCOPE)**
The hook-class decision is already recorded in an existing ADR, which also explicitly scopes out the per-instance activation decision — the half #3705 says belongs there. Two live sub-risks: an unreconciled #3705 may author a **duplicate ADR** (a duplicate-source violation and an avoidable ADR-number burn), and that ADR carries `status: Proposed`, so a criterion graded against "recorded durably" can read ambiguous. **Mitigation:** extend the existing ADR's Consequences in place, or home the activation conditions in the sampling-and-trigger reference; do not open a new ADR. Verify the ADR's `status:` field directly rather than inferring ratification from milestone state. *Reversibility CHEAP / Confidence HIGH on the duplication risk, MEDIUM on satisfaction.*

**R7 — The new self-test may repeat the premise-sharing defect it exists to fix. (SYSTEMIC)**
A test built from the same mental model as the code cannot falsify that model. Nothing structurally stops the new test from sharing the fixed code's premise. **Mitigation:** the extended self-test must be an **integration driver** (multi-`Stop`, real payload shape, sentinel state observed across invocations), not another pure-function assertion. Stage 7 grades whether the test *could fail* if the ordering fix regressed. *Reversibility CHEAP / Confidence MEDIUM.*

**R8 — Version collision probability is HIGH, and unusually so for this release. (COORDINATION)**
Multiple sibling release runs sit at the same base and several milestones are open concurrently. Because this run parks before Stage 9, the interval between provisional selection and the Stage-12 atomic claim is far longer than a normal release. **Mitigation:** treat the version as a *provisional display value* for the branch name and plan-file path only; the Commit-0 re-verify and the Stage-12 atomic claim (forward-only re-version-up) arbitrate. **R12 — Cross-release ADR-number contention, discovered at Commit 0. (COORDINATION — new)**

### Key decisions

- **Extend rather than create.** The standalone-skill alternative fails the skill-boundary test's distinct-primary-role conjunct — the decision audit and the architecture-conformance audit occupy the same primary role (retrospective cross-release audit against corpus-defined oracles, emitting a six-deliverable set into a dated analysis folder). When a conjunct fails, the capability belongs in the existing specialist by rule, not by preference.
- **The size objection is governance-refuted, not merely outweighed.** The canonical skill-structure standard states the line and byte thresholds are triggers rather than caps, and that a skill crossing one while carrying a non-empty references subtree is compliant however far it exceeds the trigger. The decision-relevant quantity is the per-mode increment, not the absolute file size.
- **The oracle set is derived and pinned at run time, never hardcoded.** A cached cardinality that does not reconcile against live state is exactly the failure the capability exists to detect.

### Reversibility

**CHEAP / Confidence HIGH.** The mode addition is additive and per-commit revertable; no existing mode's contract changes, no data migration, no consumer breaks. Extracting the mode into a standalone skill later would be **MODERATE** (a skill-directory creation plus a deploy-roster entry plus package machinery) — recorded so the asymmetry is explicit.

### Downstream impact

The capability build story and the coverage-scorecard task now have a settled change surface. The cadence protocol joins the audit-cadence set and cross-references its three siblings. The registered mode is host-declared and reports its own provisioning state until the capability build lands its scoring rubric — it does not fabricate a scorecard.
