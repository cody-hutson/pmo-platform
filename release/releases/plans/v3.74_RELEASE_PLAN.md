## Summary

Milestone **build-security-hardening** (#271) bundles **four regression-prevention controls** for two already-fixed advisories (GHSA-9cjm hook fail-open; GHSA-rw36 eval-viewer stored XSS). Verified live: the point-fixes are MERGED on `main` (`586b968`, `eb90e67`, `075390e`), so these issues add **tests/lint/checks + two paired governance standards** — they do not re-fix. Delivery = **one release branch, one PR, four slices** (milestone-one-PR discipline). Release Class **`novel`** (new standards S1/S2 + D-class decisions). One sharp contention point — `.github/workflows/security.yml` (#3409 definite, #3408 possible) — mitigated by routing #3408's jobs into a new `eval-viewer-tests.yml`. Two paired standards (S1 in #3409, S2 in #3407) stay **bundled inside their enforcer PRs** — splitting them out re-creates the "shelf standard with no gate" failure the retro indicts. Rollback is **CHEAP** (all-additive; revert the single PR) except the S2 build-philosophy charter edit (**MODERATE**, governance).

Issue → retro-item map: **C1 = #3407** (P0, size:M, +S2) · **C2 = #3408** (P1, size:M) · **C3 = #3409** (P1, size:M, +S1) · **C4 = #3410** (P1, size:S).

**Outcome Statement:** *the security perimeter can no longer fail open on a missing dependency without a red test; the eval-viewer XSS surface is regression-locked by both a runtime test and a static lint; the platform charter names Security as a first-class value with an enforced Hooks cell; and the deploy path fails closed on a missing sourced lib — the four controls each catch a distinct class via a distinct mechanism.*
