# Stage 9: Plan Review

> **Part of:** [13-stage pipeline](README.md) — [Process layer](../../../core/disciplines/execution-framework.md) of governance hierarchy.

## 1. Purpose
Final review of the release plan, implementation, and test results before deployment authorization. The operator renders a Go/No-Go decision with full evidence — this is the last human gate before production state change. Stage classification note: Plan Review is a gate stage — the hub presents evidence to the operator, no spoke is launched.

## 2. Reference Model Alignment

| Ref Model Attribute | Part 6 Definition | Our Implementation | Compression Note |
|---|---|---|---|
| Purpose | Plan review; deployment authorization | Same — Go/No-Go decision with evidence package | — |
| Governance Focus | Deployment readiness, stakeholder sign-off | Operator reviews PR diff + quality reports | Single operator = single sign-off |
| Artifact Inputs | Test results, deployment plan, risk assessment | Complete PR, release plan, Stage 7-8 reports, risk register | — |
| Artifact Outputs | Go/No-Go decision, deployment authorization | Decision record with verdict, rationale, conditions | No separate deployment authorization document |

Key compression: Ref Model assumes multi-stakeholder sign-off with deployment readiness review board. Single-operator PMO: one person reviews all evidence and renders the decision. PR diff review IS the deployment procedure validation (Stage 10 compressed into Stage 9).

## 3. Persona

| Role | Skills-Map Ref | Autonomy |
|---|---|---|
| Decision maker: Human operator | Portfolio Mgr Skill 1, Mode 3 | Tier 3 (Human-only — renders Go/No-Go) |

## 4. Inputs
From Dev Testing: quality review report, finding list, escape rate, verdict.
From QA Testing: acceptance report, acceptance matrix, fitness assessment, Stage 7 escape log.
From Engineering: PR with committed changes, deviation log, self-verification evidence.
From Planning: release plan, risk register, verification plan.

Set at Stage 9: Go/No-Go verdict, decision rationale, conditions (if GO WITH CONDITIONS), deployment authorization.

## 5. Process
**Phase A — Evidence Assembly (Tier 1):**
A1 Upstream report synthesis (Stage 7 quality report + Stage 8 acceptance report). A2 PR scope summary (files changed, additions/deletions, issues addressed). A3 Release plan compliance check (all planned items implemented). A4 Risk register status (all risks mitigated or accepted). A5 Deployment readiness checklist (PR mergeable, branch current, metadata complete, rollback available, **install/onboarding regression gate green** — the `install-tests.yml` `install-regression` job, which runs the standing install/onboarding/update regression suite, is passing on the release-branch head; **Automation Tier 2 (Bounded Auto)** — CI fires the suite automatically within its declared sandbox boundary and the operator consumes the verdict here, it is not a per-run human approval and does not itself authorize the deploy). A6 Release Readiness Scan per [release-readiness-scan-spec.md](../specs/release-readiness-scan-spec.md) — 13-dimension aggregation over A1-A5 outputs (the install/onboarding regression-gate CI status is one A5 input the scan reads); escape detection absorbed as dim-13. Cutover: applies to all Stage 9 reviews going forward. A7 Goal-conformance check (per G-PR7) — see Phase A7 below.

**Phase A3.5 — Chain-by-chain integration validation (Tier 1; conditional).** Where prior Stage 9 evidence assembly read each issue's acceptance flat (per-PR / per-issue), this sub-step adds a **chain-oriented** pass: the hub groups the release's issues into **dependency chains** (transitive closure over native `blocked-by` + the release plan's § Dependency Graph directional edges), then for each chain confirms that **every integration AC authored at Stage 5 (Phase A4.2) was graded `MET` at Stage 8**. Output — a per-chain integration verdict:

- **CHAIN-CONSISTENT** — all of the chain's `INT-N` integration ACs graded MET at Stage 8;
- **CHAIN-INCONSISTENT** — ≥1 integration AC graded NOT MET, or PARTIAL without an Operator Override Record;
- **N/A — no multi-issue chain** — the chain is a single node (no cross-issue dependency).

Each per-chain verdict folds into the Phase A6 Release Readiness Scan and surfaces in the Procedure 5 Decision Briefing. A **CHAIN-INCONSISTENT** verdict is a **NO-GO recommendation input** (the operator may override with recorded rationale, consistent with the existing G-PR7 DIVERGED-WITH-RATIONALE precedent). This sub-step consumes the Stage-5 Phase-A4.2 output and the Stage-8 per-criterion verdicts using the **Stage-8 verdict enum verbatim** — it authors no new verdict values.

**Single-node degeneracy (regression guarantee):** a release whose issues have no cross-issue dependencies produces only single-node "chains"; Phase A3.5 then reduces to the existing per-issue read and emits **N/A — no multi-issue chain** for each. It adds evidence *structure* for chained releases; it removes nothing for unchained ones — existing per-issue Stage 9 behavior is byte-for-byte unchanged when no integration ACs exist. *Cutover (introducing-release-exempt): applies to releases entering Stage 9 strictly AFTER this sub-step's introducing-release merge SHA; the introducing release is itself exempt.*

**Phase A3.6 — Release-node cross-issue integration validation (Tier 1; conditional).** Where Phase A3.5 validates cross-issue *chains* (dependency-linked issues via `INT-N`), this sub-step validates the release's **Cross-Issue Acceptance Criteria (CIAC)** — release-scoped predicates spanning ≥2 issues with **no dependency edge required**, authored at Stage 4 (per [stage-04-planning.md](stage-04-planning.md) § Cross-Issue Acceptance Criteria). Mirroring Phase A3.5's **read-only posture** (A3.5 reads the Stage-8 per-criterion verdicts; it does not re-grade), **the hub reads the CIAC verdicts the release's verification-execution executor emitted at Stage 6/7 (Verification-Evidence), confirming each CIAC-N is graded PASS** — it does NOT itself run the CIAC's declared grep / anchor / runtime-dispatch method. The single-runner discipline is deliberate: the verification-execution executor is the sole runner of each CIAC's declared method and the sole emitter of the verdict; Stage 9 consumes those verdicts so a predicate is evaluated in exactly one place, never re-run by a second runner that could diverge. For each CIAC-N the hub renders a per-CIAC verdict using the Stage-8 per-criterion verdict enum verbatim (no new verdict values). Output:
- **RELEASE-CONSISTENT** — all CIAC-N verdicts read PASS (MET);
- **RELEASE-INCONSISTENT** — ≥1 CIAC-N NOT MET, or PARTIAL without an Operator Override Record;
- **N/A — no cross-issue criteria** — the plan declares zero CIACs.

**Evidence-freshness guard (mirrors the G-PR9 baseline-currency discipline).** A consumed CIAC verdict is only trustworthy if it was emitted against the **final PR head SHA**. Before reading the verdicts, the hub confirms the SHA the executor recorded each CIAC verdict against equals the current release-branch / PR head SHA. If a commit landed after the verdict was emitted AND that commit touched any file the CIAC's shared surface / verification method reads, the verdict is **stale** → the hub re-triggers the executor to re-emit the CIAC verdicts against the new head SHA before the gate reads them. A stale-but-unrefreshed verdict is not a valid PASS input — this is the CIAC analogue of G-PR9's staleness predicate (a GO baseline invalidated by a later mover-set), applied to the intra-release commit that post-dates the emitted evidence.

Each verdict folds into the Phase A6 Release Readiness Scan and surfaces in the Procedure 5 Decision Briefing. A **RELEASE-INCONSISTENT** verdict is a **NO-GO recommendation input** (the operator may override with recorded rationale, consistent with the existing G-PR7 DIVERGED-WITH-RATIONALE precedent). This sub-step consumes the Stage-4 CIAC list and the executor's emitted verdicts; it composes with — and does not duplicate — Phase A3.5 (`INT-N` chain validation): A3.5 covers dependency-linked issue pairs, A3.6 covers release-scoped predicates over any ≥2 issues. **Empty-CIAC degeneracy (regression guarantee):** a plan with zero CIACs emits **N/A** and existing Stage-9 behavior is byte-unchanged. *Cutover (introducing-release-exempt): applies to releases entering Stage 9 strictly AFTER this sub-step's introducing-release merge SHA; the introducing release is itself exempt.*

**Phase A6.5 — Mid-Pipeline Divergence Re-Check (Tier 2; HALT-eligible on the file dimension, advisory on the version dimension):** Between Phase A6 (Release Readiness Scan) and Phase A7 (Goal-conformance check), the hub runs the mid-pipeline divergence re-check on two orthogonal dimensions against freshly-fetched `origin/main`. **File dimension (G-PR8 — HALT-eligible):** per [`release/governance/release-process.md`](../../governance/release-process.md) § Mid-Pipeline Divergence Re-Check (G-PR8 — Phase A6.5) — three verdicts: **CLEAN** (zero commits) → record `G-PR8 = CLEAN`, advance to Phase A7; **DIVERGED-RELEASE-FILES-UNTOUCHED** (commits exist on `main` post-baseline but none touch release-plan files) → record `G-PR8 = DIVERGED-RELEASE-FILES-UNTOUCHED` + informational note, advance to Phase A7; **DIVERGED-RELEASE-FILES-TOUCHED** (commits touch release-plan files) → HALT pre-GO via Tier 2 [SCOPE CHANGE] per § Inter-Stage Feedback Protocol. **Version dimension (advisory):** resolve this release's version via the version-claim adapter and check whether the provisional-display version the branch carries is still the free slot — do NOT re-derive the anchor or re-encode the claimed-set union (the host mechanism lives only inside the adapter per [`core/standards/repo-host-adapter-versioning.md`](../../../core/standards/repo-host-adapter-versioning.md) § 4 adapter discipline). Run `CLAIM_REPO="$(gh repo view --json nameWithOwner -q .nameWithOwner)" release/tools/claim-version.sh --bump <bump-class> [--patch-base v<X.Y>] --sha "$(git rev-parse origin/main)" --dry-run`, which computes the next-free version against the adapter's `anchor()` (highest claimed version in the mainline lineage, orphans excluded) and `claimed_set()` (published Release tags ∪ origin signed tags ∪ in-flight RELEASE_LOG `DEPLOYED`-not-`VERIFIED` rows, orphan-filtered, integer-tuple compared) WITHOUT pushing. Two outcomes: **version-freeness = FREE** (the dry-run's next-free equals the carried provisional-display) → record `version-freeness = FREE`; advance to Phase A7. **version-freeness = TAKEN** (the dry-run's next-free has advanced past the carried version) → record `version-freeness = TAKEN` + the recomputed next-free version in the Plan Review comment, surface it in the Procedure 5 Decision Briefing as a re-version signal, and advance to Phase A7. The version dimension is **advisory, not a hard HALT**: the version is not claimed until Stage 12 (defer-to-claim per [`core/standards/repo-host-adapter-versioning.md`](../../../core/standards/repo-host-adapter-versioning.md)), so a slot taken at Stage 9 is recoverable by recomputing the floor, which the operator folds into the GO (consistent with the G-PR7 DIVERGED-WITH-RATIONALE precedent below — a recorded Decision-Record disposition, not a block). The HALT-eligible authoritative version stop is Stage 12 Phase A.5.6 (the last pre-merge detection instant). **Posture ratification — advisory by design, ratified 2026-08-04 (Tue):** this version dimension is advisory **by design, not by pending graduation**. It is not a warn-mode gate awaiting an enforce flip, and no accumulation of drain evidence promotes it; a future release that reads this sentence should treat the posture as settled rather than as unfinished work. The architectural reason is that a release's version binds only at the **Stage 12 Phase B3 atomic compare-and-swap claim** (defer-to-claim per [`release/ADRs/ADR-036-version-claim-determinism.md`](../../ADRs/ADR-036-version-claim-determinism.md), extended to the plan file and the branch name by [`core/ADRs/ADR-092-plan-file-claim-time-stamping.md`](../../../core/ADRs/ADR-092-plan-file-claim-time-stamping.md)) — so before that instant the carried provisional-display version is, in the words of [`release/governance/RELEASE_PROTOCOL.md`](../../governance/RELEASE_PROTOCOL.md) § Versioning Phase 1, *a label, not a reservation*. A pre-claim layer cannot be authoritative over an identifier that is not yet bound: granting this dimension HALT authority would hard-stop a release on an artifact the governing contract declares non-binding, converting a **recoverable** signal into a false NO-GO. The predicate is also TOCTOU-inherent — two releases can both read `FREE` and realize the collision only at the merge — so it can **narrow** but never close the race window; only the compare-and-swap closes it, and enforce mode must never be sold as a collision guarantee. **The hard stops that DO exist**, in pipeline order, are: the **Engineering Commit-0 version re-verify** (Stage 6 — a single detect-and-HALT run immediately before the release plan file is written; this is the earliest detection rung, per [`release/references/how-to/hub-spoke-bridge.md`](../how-to/hub-spoke-bridge.md) § Canonical location), **Stage 12 Phase A.5.6** above, and the **Stage 12 Phase B3 atomic ref-CAS**. An earlier hard stop at Stage 9 is therefore redundant with a stop that already guards the *entry* to the Engineering-through-Stage-11 span, not additive to it. The durable decision record — including the conditions under which this ratification would be reconsidered — is the `version-freeness` row in [`core/standards/gate-efficacy-standard.md`](../../../core/standards/gate-efficacy-standard.md) § Flip-decision status. **Composition (no duplicate gate):** this version dimension is the *absolute* freeness predicate ("is the carried slot claimed at all, right now, per `claimed_set()`?"). It composes with — and does not duplicate — G-PR9 (Phase A7.5), whose `Δversion/<claim-key>` virtual-path token is the *relative* predicate ("did a sibling claim this slot *since the recorded GO baseline*?"): G-PR9 catches a sibling claim within the baseline→GO window via the staleness predicate; this advisory catches a slot already claimed independent of any baseline. Both read the same single claim the adapter's `atomic_claim()` arbitrates at the Stage 12 merge. **Cutover discipline:** Applies to releases entering Stage 9 strictly AFTER this dimension's introducing-release merge. The introducing release itself is exempt (the check shipping in this release cannot run on its own Stage 9).

**Phase A6.6 — Cross-release contention signal (NON-GATING; advisory on both dimensions).** Where Phase A6.5 above is **retrospective** — it asks what has *already happened* on `origin/main` and in `claimed_set()` — this sub-step is **prospective**: it asks what is *in flight and has not happened yet*. That population is read nowhere else in the pipeline. Every mid-pipeline re-check reads settled state: G-PR8 reads post-baseline commits on `main`, G-PR9 reads `git log <baseline>..origin/main`, the A6.5 version dimension reads `claimed_set()`, and Stage 12 Phase A.5.6 delegates to that same claimed set — all merged or claimed facts. The one surface that reads open PRs — the **Cross-PR Overlap Audit (A4 extension)** clause in [stage-04-planning.md](stage-04-planning.md), whose measurement is pinned in that spec's `### In-Flight Release Roster` — is **baseline-pinned and never re-checked**. The consequence is that a sibling release becomes visible to this release only at the instant it merges — which is precisely the late re-base this sub-step exists to pre-empt.

**Population `P` — measured fresh at Phase A6.6 entry, never carried from Stage 4:**
- **`P₁`** = open PRs whose head ref begins with `release/`, via `gh pr list --state open --limit 200 --json number,isDraft,headRefName,headRefOid,files`. **Drafts are IN SCOPE — do NOT filter on `isDraft`**: a draft PR is a real branch with real bytes and a real version intent. **`--limit` defaults to 30**, so set it explicitly or the population silently truncates and this sub-step returns a false `CONTENTION-NONE`. Match the head ref on the `release/` **prefix**, not as a substring — a dependency-bot branch can carry `release/` mid-path and is not a release branch.
- **`P₂`** = remote `release/*` heads with no open PR, via `git ls-remote --heads origin 'refs/heads/release/*'` minus the `P₁` head refs. This arm is **empirically load-bearing, not defensive**: a PR-less slug-primary release branch holds no claim and is invisible to every tag / Release / open-PR scan, and that branch class has caused a recorded version collision.
- **`P` = (`P₁` ∪ `P₂`) \ {this release's own branch and PR}.**

**Half A — shared-governance-file co-edit.** For each `s ∈ P`, the predicate is `EDITSET(s) ∩ FCM(this release) ≠ ∅`, where `FCM` is this release's plan File Change Matrix and `EDITSET(s)` is the path set changed on `s` against its merge-base with `origin/main` — `gh pr view <n> --json files --jq '.files[].path'` for `P₁`, `git diff --name-only $(git merge-base origin/main origin/<branch>)..origin/<branch>` for `P₂`. Classify each intersecting path with the **existing** ADR-005 `overlap_class` machinery — `python3 release/tools/check-line-range-overlap.py` per [`ADR-005`](../../ADRs/ADR-005-append-pattern-aware-cross-pr-contention-scoring.md) and the **Cross-PR Overlap Audit (A4 extension)** clause in [stage-04-planning.md](stage-04-planning.md) that already owns it — and author **no second classifier**: `line-range-overlap` is a mechanical merge-conflict class, `append-pattern` is informational, and disjoint hunks in a shared file are a **semantic** content-divergence class.

**Half B — provisional-version-slot overlap (advisory by construction).** `NEXTFREE(x)` is `CLAIM_REPO="$(gh repo view --json nameWithOwner -q .nameWithOwner)" release/tools/claim-version.sh --bump <BUMP(x)> --sha "$(git rev-parse origin/main)" --dry-run`, canonicalized to the integer tuple by the single parser `version_parse` in [`release/tools/version-grammar.sh`](../../tools/version-grammar.sh) so a `v2.06`-versus-`v2.6` spelling difference cannot manufacture a false negative; `BUMP(x)` is the bump-class declared in `x`'s release plan. The predicate is `SLOT-OVERLAP(s) := NEXTFREE(this) == NEXTFREE(s)`. **It keys on the recomputed next-free and NEVER on the carried provisional-display string** — the carried label is *reported* for the operator, never *compared*. That choice is load-bearing, not stylistic: a sibling's carried label goes stale the moment any release ships, so it recomputes **upward** onto this release's slot, and label equality therefore returns a **false negative exactly when the contention is real**; a sibling still carrying an unresolved release-version placeholder defeats label equality outright, and two siblings both carrying that placeholder compare *equal* on a token rather than on a version — right answer, wrong reason. Report `STALE-LABEL(s) := CARRIED(s) ∈ claimed_set()` alongside each row: a stale label means the sibling *understates* its true slot and will recompute upward at its own Commit-0 or Stage 12, making it **more** of a co-contender, not less. **Honesty property that must ship with the signal:** because every in-flight release computes next-free against the same `claimed_set()` at the same instant, any two sharing a bump-class off the same anchor **always** overlap. Half B is therefore an **enumeration** signal — a co-contender roster that merge order arbitrates — not a discriminating alarm, and its header must not claim more than its predicate delivers.

**Verdicts.** A new family, deliberately **not** reusing A6.5's `FREE`/`TAKEN`, G-PR8's `DIVERGED-*`, or G-PR9's `STALE-*`: those tokens name **settled** facts, and emitting `TAKEN` for an in-flight contention would assert a claim that does not exist.
- **`CONTENTION-NONE`** — `P` is empty, or neither half fires → record and advance to Phase A7. **Degeneracy guarantee:** an empty `P` is a byte-unchanged no-op. **`CONTENTION-NONE` asserts a measured negative and nothing else.** A sibling whose bump-class cannot be resolved — so `NEXTFREE(s)` is uncomputable — is recorded as **`UNRESOLVABLE`** against that member and named in the verdict line; it must NOT collapse into `CONTENTION-NONE`, which would report *no contention found* where the truth is *the comparison could not be made*. An unknown is not an absence, and this phase re-measures the population rather than reading the Stage-4 roster, so the roster's own unresolvable form does not reach here.
- **`CONTENTION-FILE`** — Half A fires → **WARN**, naming each intersecting path and both releases' intent. On a `line-range-overlap` classification, additionally emit an explicit **serialize recommendation** (a proposed merge order) — a range overlap is a mechanical conflict the operator can avoid cheaply by ordering. On semantic-only overlap, warn **without** a serialize recommendation.
- **`CONTENTION-SLOT`** — Half B fires → **WARN, explicitly provisional**: emit the co-contender roster (slug · PR number or `—` · carried label · recomputed next-free · bump-class · `STALE-LABEL`) together with the non-reservation statement below. Never a serialize recommendation on the slot axis alone — merge order already arbitrates it correctly and for free at the compare-and-swap.
- **`CONTENTION-BOTH`** — both halves fire → both dispositions, reported separately.

**Non-reservation statement — record verbatim in the Plan Review comment whenever `CONTENTION-SLOT` or `CONTENTION-BOTH` is emitted:** *This signal reads **intent, not claim**. A release's version binds only at the **Stage 12 Phase B3 atomic ref-CAS**; before that instant the provisional-display version is, per [`release/governance/RELEASE_PROTOCOL.md`](../../governance/RELEASE_PROTOCOL.md) § Versioning Phase 1,* a label, not a reservation *(defer-to-claim per [`release/ADRs/ADR-036-version-claim-determinism.md`](../../ADRs/ADR-036-version-claim-determinism.md), extended to the plan file and the branch name by [`core/ADRs/ADR-092-plan-file-claim-time-stamping.md`](../../../core/ADRs/ADR-092-plan-file-claim-time-stamping.md)). No pre-claim layer can be authoritative over a slot that has not been claimed, so this dimension is **advisory by construction — not advisory pending graduation**. The authoritative stops remain the Engineering Commit-0 detect-and-HALT (Stage 6), Stage 12 Phase A.5.6, and the Phase B3 CAS.* This is the same binding-moment ground on which the **Phase A6.5 version dimension above was ratified advisory-by-design**; A6.6 restates no part of that ratification, contradicts none of it, and adds no second gate beside it.

**Half A is advisory too — the deliberate call.** A co-edit on an *unmerged* sibling is a fact about bytes, so a HALT is conceivable. It is nonetheless rejected: the sibling may never merge, may drop the file, or may merge after this release and rebase itself, and blocking this release's GO on another release's draft would export one team's uncertainty into another's gate — a false-positive gate class that does not exist today. The serialize *recommendation* hands the operator the same lever at none of that cost.

**This sub-step is explicitly NOT a gate, enforced by three structural guarantees** (the same three that hold Phase A9 non-gating):
1. **Not in the gate table.** A6.6 produces **no row** in the Phase C GO/NO-GO criteria table and **no gate criterion ID**. It cannot drift into being a gate because it is never written into the criteria.
2. **Advisory-labeled at the source, surfaced only in the advisory lane.** Verdicts are recorded in the Plan Review comment and presented in the **Tier-1 advisory lane** of the 30-second summary and the Procedure 5 Decision Briefing — never on the blockers line. The operator folds the signal into the Tier-3 binding GO.
3. **Precedent-bound.** It rides the shipped record→surface→operator-folds mechanism of the Phase A6.5 version-dimension advisory and Phase A9, both already proven non-gating.

**Composition, not duplication.** Four surfaces, four populations, four vocabularies, no shared predicate: A6.6 reads the **in-flight** population; G-PR8 reads **merged commits touching File-Change-Matrix files**; G-PR9 reads **baseline currency** against merged `main`; the A6.5 version dimension reads **absolute freeness** against `claimed_set()`. A6.6 never writes to `claimed_set()` and never gates a claim — the arbitration layer stays the compare-and-swap, and detection stays separate from arbitration. **Cutover discipline:** applies to releases entering Stage 9 strictly AFTER this sub-step's introducing-release merge SHA recorded in the release log; the introducing release itself is exempt (the sub-step shipping in this release cannot run on its own Stage 9).

**Phase A7 — Goal-conformance check (per G-PR7):** Hub reads the `### Release Outcome Statement` H3 block from the GitHub Milestone description (`gh api repos/{REPO}/milestones/<N> --jq .description`), reads the PR scope (`gh pr view <PR> --json files,additions,deletions`), reads the release plan §Implementation Sequence + File Change Matrix, AND reads each release-scoped issue AC. Produces a 1-paragraph conformance narrative answering "does the assembled implementation deliver the AFTER state?" Verdict: **ALIGNED** / **DIVERGED-WITH-RATIONALE** / **MISALIGNED**.

- **ALIGNED** → no operator action; GO recommendation supported.
- **DIVERGED-WITH-RATIONALE** → operator documents in Decision Record before GO.
- **MISALIGNED** → NO-GO recommendation (operator may override).

LLM-graded judgment-recommend tier per gate-criterion G-PR7 in [gate-criteria-spec.md](../../../core/schemas/gate-criteria-spec.md#gate-9-plan-review). Recommend-tier matches the G3-04/G3-05 judgment precedent — a grep cannot reliably assert "release delivers the AFTER state"; the LLM scan provides the recommendation; the operator renders the binding decision. See [release-outcome-statement-template.md](../specs/release-outcome-statement-template.md) for the canonical Outcome schema and anti-pattern catalog the conformance check applies on read. **Cutover:** Applies to all Stage 9 reviews going forward.

**Phase A8 — Draft→ready-for-review transition (Tier 1):** The release PR was created in **draft** state at Stage 6 Phase C2 (per [`stage-06-engineering.md`](stage-06-engineering.md) § Phase C) so it stayed visibly work-in-progress through Engineering + Dev Testing + QA. Before Phase B tiered presentation, once evidence assembly (A1–A7) is complete, the hub transitions the release PR from draft to **ready-for-review** — `gh pr ready <PR>` — so the operator reviews the PR diff in its review-ready form, with the `## Change Description` section (committed at Stage 6 Phase C1) visible in the diff. Record the transition (`isDraft` → `false`) in the Stage 9 sub-task output. This is the single point in the pipeline where the draft→ready transition occurs; a still-draft PR reaching Stage 12 Phase B fails the pre-B1 draft-state guard (per [`stage-12-execute.md`](stage-12-execute.md) § Phase A.7 Release-PR draft-state guard) because a draft PR cannot merge. **Single-operator no-op:** in single-operator steady state (OPERATOR resolves to `@me`, `--reviewer` dropped) the PR is self-reviewed by its author — the draft→ready transition runs identically (a draft PR still transitions to ready with no external reviewer required), and the Phase C GO decision remains the review-discipline artifact per the § PR metadata single-operator reviewer convention. The transition is a lifecycle step, not a review-request; it does not require a second reviewer to fire.

**Phase A9 — Review-decision advisory input (NON-GATING; modeled on Phase A6.5 version-dimension advisory).** During evidence assembly the hub reads the release PR's native review-decision state — `gh pr view <PR> --json reviewDecision --jq .reviewDecision` → one of `APPROVED` / `CHANGES_REQUESTED` / `REVIEW_REQUIRED` / empty (commented-only or no review) — and surfaces it in the Phase B Tier-1 30-second summary **advisory lane** and the Procedure 5 Decision Briefing as an **advisory** signal. It rides the exact pattern of the Phase A6.5 version-dimension advisory above (record the signal → surface it in the briefing → advance to the next phase; the operator folds it into the Tier-3 binding GO) — the same shipped record→surface→operator-folds mechanism, which is proven non-gating.

**This input is explicitly NOT a gate, enforced by three structural guarantees:**
1. **Not in the gate table.** Review-decision state does **not** appear in the Phase C GO/NO-GO criteria table and produces **no** verdict row there — it can never *be* a gate criterion because it is never written into the criteria. The Phase C table is untouched by this input.
2. **Advisory-labeled at the source, surfaced only in the advisory lane.** The signal is recorded and presented in the **Tier-1 advisory lane** of the 30-second summary — never on the "blockers" line — and carries the "NON-GATING" label at its point of capture. A `CHANGES_REQUESTED` state is an **advisory prompt for operator attention, never an automatic NO-GO**; the operator's Tier-3 GO stays the sole binding authority. Presenting a `CHANGES_REQUESTED` as a blocker-colored signal is the specific failure this labeling forecloses — under the single-operator convention the operator's own earlier review comment must not read as a veto on their own final GO.
3. **Precedent-bound.** It is modeled on the already-shipped, already-advisory Phase A6.5 version-dimension advisory — the same non-gating record→surface→operator-folds shape — so it inherits a proven non-gating contract rather than inventing a new one.

**Single-operator steady state:** with OPERATOR == `@me` and `--reviewer` dropped, `reviewRequests` is empty and no *requested-reviewer* review-decision state is emitted — in steady state the advisory input is simply **absent** (an honest no-op, not a missing gate). On a public repository an *unrequested* third-party review can still set `reviewDecision`; the advisory lane surfaces any such state together with the reviewing author's association per the author-association trust boundary ([`release-process.md` § Inter-Stage Feedback Protocol](../../governance/release-process.md#inter-stage-feedback-protocol)) — an untrusted-association review state is surfaced-untrusted context, never a veto. No facet of Phase A9 requires a second reviewer to function; the advisory lane records "no review-decision state (single-operator)" and advances. **Cutover discipline:** Applies to all Stage 9 reviews going forward.

**Phase B — Tiered Presentation (Tier 1):**
Present evidence package to operator in three tiers: Tier 1 (30-second summary — verdict recommendation, key metrics, blockers), Tier 2 (5-minute detail — per-issue status, risk assessment, escape analysis), Tier 3 (full evidence — complete reports, PR diff, release plan).

**Phase C — Human Decision (Tier 3):**

| Verdict | Criteria | Next Step |
|---|---|---|
| **GO** | All quality gates passed, no unresolved blockers, risk accepted | → Stage 12 Execute |
| **GO WITH CONDITIONS** | Minor items accepted with documented rationale; conditions must not require code changes | → Stage 12 Execute (conditions tracked) |
| **NO-GO** | Unresolved blockers, unacceptable risk, quality below threshold | → Return to Stage 6/7/8 per finding |

GO WITH CONDITIONS boundary rule: if a condition requires code changes, it is a NO-GO. Conditions are documentation, tracking, or process items only.

**Ticket lifecycle:** Claim: set Stage→9-PlanReview. Execute: A-C. Resolve: post decision record, route per verdict. Per [ticket-information-architecture.md](../specs/ticket-information-architecture.md).

**Framework dimensions touched:** Handoff (Go/No-Go gate); Assignment (Portfolio Manager persona — operator). Per [execution-framework.md](../../../core/disciplines/execution-framework.md).
