# ADR-024 — Cross-release impact model (structural-blast-radius axis via F1–F6 ref-form sweep + GO baseline-currency)

## Status
Accepted (operator decision rendered at Stage 5 Collective-Review scope-lock; ADR authored at Stage 6 per the Stage 5 spec § Decision). Numbered ADR-024 as the next-free slot across `release/ADRs/` (max ADR-021) and `core/ADRs/` (max ADR-023); re-verified at Commit 0 of this release.

## Context
The release pipeline models each release in isolation. Stage 3 Bundle, Stage 4 Planning, Stage 5 Collective Review, Stage 9 Plan Review, and Stage 12 Execute each reason about *this* release's issues/files/baseline as if it were the only thing moving. There is no durable, queryable model of the concurrent + planned release set and its mutual impact. The 2026-05-16 four-milestone retro is the originating evidence: a file-mover release (a directory reorg) invalidated a sibling's Stage-9 GO with no ticket-dependency edge and no same-path overlap — every existing classifier declared them parallel-safe; the collision surfaced as a rename/modify conflict mid-pipeline and forced a full Stage-4 re-plan + fresh GO. The existing live mid-pipeline-divergence check (Phase A6.5) is the nearest prior art but is *syntactic* (does a commit touch a File-Change-Matrix file?) and blind to (a) the mover axis and (b) semantic GO-invalidation.

A first Stage-5 design proposed computing the mover-set blast radius with the inbound-discovery blast-radius CLI. An independent adversarial review established that this instrument cannot run on a moving set: it requires an extant target and is depth-capped, so it cannot enumerate a moving set's rewrite surface. The platform already owns the canonical moving-set protocol — the doc-corpus-reorg ref-form protocol (six ref-forms F1–F6), fired at Stage 5 Phase A3.2 whenever a release moves a corpus file. This ADR adopts F1–F6 as the detection substrate.

## Decision
Add ONE durable primitive — a cross-release impact model — consulted at five surfaces, built entirely on systems already in place:

1. **A third contention axis (Path-Invalidation / Structural-Blast-Radius), detected via the F1–F6 ref-form sweep.** It sits alongside the live ticket-dependency + same-path axes. Detection: a reproducible 4-token git mover-classifier (RENAME · RELOCATE · DELETE-RECREATE · DIR-RESTRUCTURE) produces the mover-set → the F1–F6 ref-form sweep (parameterized by the mover-set's old/new path pairs) produces the structural surface `SURFACE(R)` → serialization predicate = sibling edit-set ∩ `SURFACE(R)` ≠ ∅. **The cross-release `SURFACE(R)` is the union of F1 (module-rooted) + F2 (relative-inbound) + F3 (root-escape) + F5 (retained-sibling) + the in-tree half of F6 (governed mirror-pair). F4 (mover-internal-outbound) is EXCLUDED** — it is the moving release's own A3.2 rewrite obligation (it recomputes its own outbound links inside the moved file; it does not edit the target files), so a sibling editing those targets is not a cross-release contention, and including it over-serializes against high-traffic governance files. The blast surface is bounded to the mover-set's own rewrite/break surface (never the whole repo), and the cross-release axis **consumes** the A3.2 sweep when it has already fired rather than recomputing.
2. **Persistence in existing surfaces.** The axis EXTENDS the standing `## Parallelization Map` (milestone description; +Tier-S verdict, +`structural-blast-radius` edge type) — not a restated convention. The GO baseline SHA + revalidation predicate land in the release plan's existing `## Cross-PR Overlap Audit` → `### Baseline SHA` H3. No new datastore, no new file. Reconfirm at Stage 3 A7 + Stage 4 Phase A0 (existing) + a new sibling-merge self-invalidation trigger on the pinned audit.
3. **Gate-9 G-PR9 GO-currency criterion.** A GO records the baseline SHA it was rendered against; a **unified** sibling-merge revalidation predicate (`git log <baseline>..origin/main --name-status --find-renames`, intersected against `SURFACE(R)`) makes a GO falsifiable. Verdicts CURRENT / STALE-REVALIDATE / STALE-VOID. The predicate is `--name-status --find-renames`, NOT `--merges`, because the repo lands releases via squash/chore-PR non-merge commits.
4. **Stage 12 Phase A.5 semantic GO-invalidation check.** Inserted before the existing blind `git merge`; reads the recorded GO baseline and runs the **same unified predicate as G-PR9**; classifies GO-CURRENT / DIVERGED-SEMANTICALLY-CLEAN / GO-VOID-SEMANTIC. Catches a clean-merging sibling that nonetheless voids the GO premise (the rename-of-an-F2/F3-referenced-path class). G-PR9 and Phase A.5 share one predicate so the two defense-in-depth gates agree.

## Alternatives Considered
- **(A) Extend live Parallelization Map + release-plan Baseline SHA H3 (SELECTED for persistence).** Forced by the no-new-datastore constraint + the systems-already-in-place AC + repo-agnosticism. Composes with the existing A6/A7/A0 surfaces.
- **(B) New single registry file — REJECTED.** A new datastore (no-new-datastore breach); duplicates the live `## Parallelization Map` (duplicate-source-discipline); a new drift target with no reconfirm owner.
- **(C) GitHub Projects custom fields — REJECTED.** Requires operator-instance-specific field IDs, not repo-portable (repo-agnostic breach); conflicts with the no-Projects-board-on-public-repo posture.
- **(D) Detect the structural surface via raw mover-set path-prefix arithmetic (no sweep) — REJECTED.** Re-creates the originating blind spot: a path-set intersection captures neither the inbound-reference collision (the zero-edge class — a sibling referencing the renamed path by a relative link) nor F4/F5; and it re-derives a surface the F1–F6 protocol already owns (duplicate-source breach).
- **(E) Detect via a form-subset (inbound F1/F2/F3 + mirror F6 only, dropping F4/F5) — REJECTED.** Under-inclusive in the dangerous direction: a sibling editing a retained-sibling file (F5) sits in the genuine break surface but would be reported parallel-safe. (Note: F4 is excluded from the *cross-release* intersection for a different reason — it is the mover's own rewrite obligation, not a target-file edit — see § Decision.)
- **(F) Compute the inbound closure with the blast-radius CLI (the FIRST design) — REJECTED (Blocker).** The tool requires an extant target and is depth-capped; it cannot enumerate a moving set's rewrite surface. The worked example depended on tracing inbound refs to a renamed-from path the tool cannot reach.
- **(G) Reuse the live Phase-A6.5 syntactic check instead of a new gate — REJECTED.** That check is syntactic (File-Change-Matrix-file touch) and covers the Stage-4-pin→GO window; it does not record the GO's own baseline SHA, does not model the structural surface (a sibling deleting a path NOT in our matrix), and does not do the semantic check. G-PR9 composes with it (two axes / two windows).
- **(H) Sibling-merge predicate `git log --merges` (the FIRST design's G-PR9) — REJECTED (Major).** The repo lands releases via squash/chore-PR non-merge commits; `--merges` returns a false CURRENT for squash/fast-forward landings. Unified on `--name-status --find-renames` instead, shared with Phase A.5.

## Consequences
**Positive:** the four observed symptoms each get a systemic owner; the GO becomes falsifiable (records its baseline SHA); the mover axis (the zero-dep-edge collision class) is detected by the platform's canonical moving-set instrument (F1–F6); over-serialization is bounded by construction (`SURFACE` = mover-set's own surface, not the repo, and F4 is excluded from the cross-release intersection); detection composes with — rather than duplicates — the existing A3.2 sweep. **Negative:** the mover-classifier + F1–F6 sweep add a `git diff` + a parameterized grep fan-out at Stage 4/9/12 (cheap; git-native; and at Stage 5 the A3.2 sweep is reused, not re-run); a new gate row (G-PR9) is one more Stage-9 structural check; the semantic Phase-A.5 check adds a `git log --name-status` read before the merge. **Mitigation of negatives:** all additions bind to existing surfaces (A6/A7/A0/GO/Phase-A.5/A3.2) — no free-floating steps; the commands are deterministic + reproducible; warn-mode-then-enforce is available for G-PR9 if a shakedown is wanted.

## Reversibility
CHEAP — additive prose + one gate row + one edge-type enum value + a citation to an existing protocol; `git revert` of the single release PR restores prior state with zero data migration. The live Parallelization Map convention is extended (one row + one tier), not rewritten; the doc-corpus-reorg ref-form protocol is cited, not modified.

## Cutover (introducing-release-exempt)
The structural-blast-radius axis, G-PR9, and the Phase A.5 semantic check apply to releases entering the relevant stage strictly AFTER this protocol's introducing-release merge SHA recorded in the release log. **The introducing release itself is exempt** (reflexive-pipeline-loop discipline — the release that adds these criteria cannot gate itself). The introducing release's own Stage 9/12 run under the pre-existing checks (which predate this ADR and DO apply). All releases that entered the relevant stage prior to the introducing release are also exempt.
