# ADR-222 — Signal tags bind durable records, not conversational turns

## Context

The inter-stage feedback protocol gives each tier of mid-flight feedback a signal: one tag on a commit message for a Tier 1 correction, and one of two others on a sub-task comment for a Tier 2 scope change or a Tier 3 plan rejection. An audit of release-run conversations found the tags almost absent from the hub's turns and read that as abandonment of the vocabulary. The protocol never placed a signal on a conversational turn, so the audit measured a surface the rule does not bind.

Measured where the rule does bind, the picture differs by tier. Tier 1 corrections are written mostly by the building and testing sessions, and the tag sits on somewhat under half of the Stage 7 and Stage 8 fix commits, unevenly — most releases tag every such commit or none. A fix commit already names its tier in its subject prefix, so on that population the tag adds little, and a correction made outside that convention carries no marker by which to count it. Tier 2 deviations are recorded in two event-log families: scope-change rows, and the operator escalations the release hub records, which are most of them. Read against the comments those escalations name, the tag is missing more often than present. No Tier 3 rejection is recorded for this repository's releases.

Three further facts shaped the decision. The obligations had no runner and no row in the gate-coverage register. One review dimension carries the tag check, and no stage invokes it. And the binding is stated in more than one form: several passages outside the protocol state it differently, and inside it two clauses name a Milestone comment, which the Decision below reads as a comment on the release's planning sub-task, while a revision-commit example puts the Tier 2 tag on a commit message.

## Decision

1. **The binding is restated and is not extended to conversational turns.** Each tag binds a durable record: the commit that makes a Tier 1 correction, or the sub-task comment that records one where no file changes; a comment on the sub-task where a Tier 2 deviation arose, or on the release's planning sub-task for a release-level change, with the milestone description's bundle-amendment note permitted to carry the tag as well where the change amends the release's composition; and a comment on the sub-task whose plan a Tier 3 finding rejects.
2. **Each record is named by class and by write target.** In the push-to-resolve rubric's class terms the commit is a Deliverable and each comment is Conversational. A chat turn is Conversational too, so the class alone cannot separate a signal from a narration; the write target does.
3. **A turn posted nowhere owes no tag, and points at the record that carries one.** An operator-facing turn that narrates a tier event names that record, and the release hub's posted record of the operator's decision on a tier event carries the tag and names the comment that raised it.
4. **A hub-side obligation has one home.** Where an obligation in this disposition falls on an operator-facing emission of the release hub, it lands in the hub's Output Contract, beside the requirements every emission carries, and in no second prose emission-time question elsewhere in the hub's skill tree. That contract carries no signal-tag requirement when this record is written.
5. **The obligations are declared unenforced and registered as a named gap.** Their gate-coverage register row states a countable observable for each clause that leaves a record and states that the turn-level clause has none, because a turn posted nowhere cannot be re-read.
6. **The first runner is a follow-on story's choice.** That story chooses among the candidate shapes — a check on a pull request's commit messages, a check at the moment the hub records a tier event, the review dimension that already carries the predicate, and a tier slot on the hub's escalation and decision records — builds the one it chooses, and reconciles the passages that state another binding.

## Alternatives Considered

- **Enforce at emission.** Considered in four shapes. A requirement in the release hub's output contract was declined as the enforcement: it would be a second prose statement of an obligation with no runner, and the same mechanism on the same seam showed no measurable lift for a sibling convention at the sample size the paired review measured. It would also reach the wrong writer for Tier 1, whose corrections the building and testing sessions write — although for Tier 2 the hub records most escalations, which is why a hub-side slot stays among the follow-on story's candidates. Rendered tier slots on the durable records, and a check that reads them, were kept as candidates for that story and not as this record's claim, because recording "enforced" before a runner exists would state what is not yet true. A hook that reads a turn or a posted body was declined: nothing reads a turn, and a new conduct hook would be inert on a default install.
- **Retire or replace.** Retiring the bracket tags while keeping the tiers was declined: the tokens are written on their declared surfaces; the handoff coordinator's iteration tracking, an instrumentation field, a practice-efficacy signal and the Stage 7 fix-commit convention name them, and a telemetry reader counts their event-log subtypes; and removing them is a corpus-wide rename for no measured gain. Replacing the tag with its event-log row was declined because the event log is operator-instance state, so the signal would leave the hosted record a reviewer reads.
- **Restate only**, with no pointer clause and no register row, was declined because a passage that restates an unrun obligation without declaring its runner repeats the defect.
- **Name a check on fix-convention commits as the designed first runner.** Declined after the adversarial review. A fix-convention subject already states its tier, so such a check restates the subject on the population it reads and cannot see a correction made outside the convention; and a red raised on an already-pushed commit has no remedy short of rewriting a shared branch, which this platform's workflow forbids.

## Consequences

- **+** The record is true on the day it merges: it claims a binding, not an enforcement.
- **+** The next audit has populations to measure — the fix-convention commits and the Deviation-Log rows a clone can re-derive, and the two event-log families an operator instance holds — and a method to reuse.
- **+** The hub's narration is no longer scored against a rule that never applied to it. What the hub owes on a tier event is the pointer and, on its posted record of the operator's decision, the tag and the raising comment.
- **−** The gap stays open until the follow-on story ships. It is visible in the register meanwhile, and the turn-level clause has no observable at all.
- **−** The Tier 2 tag is missing from many of the escalations the hub records, and this record changes nothing that writes them.
- **−** Passages that state another binding remain until the story reconciles them — among them the protocol's two clauses that name a Milestone comment and its revision-commit example, which puts the Tier 2 tag on a commit message.
- **−** A parent initiative whose exit condition reads "enforced or retired" is not satisfied by this record alone.

## Reversibility

**CHEAP.** One protocol paragraph, this record and one register row revert with their commits; a later record may enforce more, or retire the tags, by superseding this one.
