# ADR-094 — Extend-before-create lands as a separately-triggered SR-G6 (non-T3), generalizing ADR-090; a Maintainability value-extension, not a new discipline

## Status

Proposed — to be ratified at the operator's Stage 9 plan-review gate for the intake-and-gate-protocol-hardening release. The flip to Accepted is verified against this file's `status:` field, never assumed from milestone closure.

**Stage-9 ratification recorded (2026-07-25):** at the v3.94 Stage 9 plan-review GO gate the operator ratified this decision AND exercised the Stage-9 graduation lever straight to **enforce** (see Decision § 5) — SR-G6 ships enforce from v3.94, not a shadow shakedown, while the sibling SR-G5 stays shadow (the intended asymmetry). Per the ADR ratification-flip convention (Stage-13 G-CL9), the `status:` enum remains **Proposed** until the release's Stage-13 Close flips it to Accepted; this note records the ratification event without pre-empting that flip.

## Context

Stage 5 Solutioning renders a design after reviewing whichever structures the design touches. The platform already gates two slices of the extend-vs-build question:

- **The extend branch** — [`planning-solutioning-handoff.md`](../../core/standards/planning-solutioning-handoff.md#structural-premise-review-obligation) §3.2 and its exit gate [SR-G1..SR-G4](../references/pipeline/stage-05-solutioning.md): *you perpetuated or extended an existing structure → record `reviewed → {retained|changed} because {evidence}`.*
- **The seam-altitude slice** — [`design-review-checklist.md`](../references/templates/design-review-checklist.md) §4.7: *name the seam; justify a new abstraction over extending the seam.*

Both are **riders on the T3 structural-premise obligation** — they activate only when the issue is a structural-premise design decision. Neither states the affirmative **net-new-branch** rule: *given that infrastructure already covers this capability, extend it before building a net-new surface beside it.*

The gap is not hypothetical. The standing exhibit is `deploy.sh` check-accretion — governance checks appended **net-new** to a single 2,572-line `cmd_check()` function (a +52% / +8-check growth) rather than extended through a check registry. Appending an inline check is **not** a T3 schema/naming/directory decision, and a monolithic function is **not** a "seam" — so the accretion escapes **both** existing controls on **both** counts. It is precisely the class that does **not** trip T3. This decision introduces an affirmative extend-vs-build disposition with teeth that catches exactly this class.

This decision composes with sibling changes in the same release: [ADR-093](ADR-093-scoped-conditional-binding-acceptance-fit-gate.md) (the Stage-2 acceptance-fit gate, which already names "the extend-vs-build disposition asks *extend an existing surface before creating net-new*" as a distinct downstream determination) and the net-new `skill-consultation-map.md` spec (whose net-new choice this ADR's `net-new because in-place infeasible: {reason}` form is the justification vehicle for).

## Decision

1. **Add `SR-G6` to [`stage-05-solutioning.md`](../references/pipeline/stage-05-solutioning.md) §7.2 as a separately-triggered criterion**, mirroring SR-G5's own-trigger + shadow structure. Its two-limb fire-predicate: **(Limb 1)** a *named* existing infrastructure surface plausibly covers the capability-class the solution targets (a file/script/function, a skill or skill mode, a check/gate, a doc section/standard, a config/registry, or a Layer-1 surface), **AND (Limb 2)** the design selected a **net-new** surface placed beside it rather than an **extension** of it. On fire, the design records exactly one of `extend {named surface} because {evidence}` OR `net-new because in-place is infeasible: {reason}`; a net-new surface with no recorded determination is not design-complete.

2. **The trigger is deliberately non-T3.** Folding the net-new branch into the §3.2 / §4.7 T3-riders would re-gate it on T3 and **re-open the deploy.sh-style net-new-accretion fall-through** — the exact gap this decision exists to close, because that accretion class does not trip T3. SR-G6's fire-predicate is the net-new choice itself (existing-infra-covers AND net-new-selected), independent of T3.

3. **SR-G6 is the net-new-branch complement of SR-G1..SR-G4's extend branch — one determination across two branches.** SR-G1..SR-G4 review the extend branch (you extended → justify retain/change); SR-G6 governs the net-new branch (you built beside existing infra → extend it, or justify net-new). The predicates are **mutually exclusive** on the extend-vs-net-new fork, so no capability triggers both; a SR-G6 fork that resolves to *extend* **hands off into** SR-G1..SR-G4 (sequential, not parallel). SR-G6 generalizes §4.7's seam-scoped extend-vs-new to **any** infrastructure surface on a non-T3 trigger — that generalization plus the non-T3 trigger is the load-bearing delta over §4.7.

4. **In [`build-philosophy.md`](../../core/disciplines/build-philosophy.md), extend-before-create is a Maintainability value-extension, not a net-new discipline row.** By extend-before-create's own logic, the Maintainability value ("minimal addition; do not create a second place to keep in sync") plausibly *covers* it (net-new-where-extend-suffices IS a second place to keep in sync — deploy.sh's 33 inline checks, as of authoring, are 33 places), so in-place is **not** infeasible → extend the value. Minting a parallel discipline would be the very anti-pattern the rule forbids. The matrix enriches **only** the Maintainability × Hub/Spokes cell (SR-G6 is a pipeline-stage enforcer); the Maintainability × **Agents** GAP is **not** false-closed.

5. **Rollout — enforce from v3.94 (operator-ratified flip from the phased shadow → warn → enforce plan).** SR-G6 was designed to ship in **shadow** (report-only) for its introducing release, reusing ADR-090's machinery, and graduate to warn then enforce once the false-positive rate on genuine-greenfield-mis-judged-as-covered was characterized — Limb-1 ("*plausibly* covers") being a judgment call for which a day-one hard block risks false-positive-firing on real greenfield. **At the v3.94 Stage 9 plan-review GO gate (2026-07-25) the operator exercised the Stage-9 graduation lever straight to enforce:** SR-G6 **ships enforce from v3.94** (day-one gate-blocking on the fire subset), accepting the Limb-1 judgment-call risk against the criterion's structural (determination-present) check and the operator's own return-to-Solutioning override path. **Intended SR-G5 / SR-G6 asymmetry:** the sibling SR-G5 (structural path-move consumer sweep, ADR-090) **stays shadow** — its `grep -F` over-inclusion makes a day-one block false-positive-prone — while SR-G6 enforces; the two separately-triggered criteria are governed independently in §7.2, and the asymmetry is deliberate, not drift. The introducing release (v3.94) is **exempt** — it cannot fire its own new gate (reflexive-pipeline loop), matching the SR-G5 / §4.7 cutover convention.

6. **No `gate-criteria-spec.md` touch.** SR-G criteria are not registered in `gate-criteria-spec.md` (its Gate-5 slot is empty by design, Gate 4 → Gate 6), so expressing extend-before-create as an SR-G extension leaves that schema untouched. An earlier framing floated a "new Gate-5 criterion (if gate-expressed)" — that limb is N/A-with-reason: it is gate-expressed as an SR-G row, not a Gate-N entry.

## Alternatives Considered

- **Net-new `Gate-5` in `gate-criteria-spec.md`.** Rejected: the Gate-5 slot is empty by design, SR-G criteria are not registered there at all, and minting a net-new gate family where an SR-G extension suffices **violates extend-before-create's own rule**.
- **Fold the net-new branch into §3.2 (extend the T3-rider).** Rejected: it inherits the T3 gate and re-opens the deploy.sh fall-through — the accretion class does not trip T3, so a T3-gated rule structurally misses it.
- **A net-new cross-cutting `D3` discipline in `build-philosophy.md` + a parallel gate.** Rejected: it mints a parallel discipline the Maintainability value already covers — the reflexive anti-pattern. Extend the value instead.

## Consequences

- **(+)** Closes the **non-T3 net-new-accretion class** that both the §3.2/SR-G1..SR-G4 extend gate and the §4.7 seam gate structurally miss.
- **(+)** **Zero new evaluator or gate family** — SR-G6 rides the existing §7.2 Structure-Review table; the determination is a design-spec inspection, not new checker code. (It was authored to reuse ADR-090's shadow → warn → enforce rollout verbatim; the operator's day-one-enforce ratification lands it at the rollout's enforce terminus rather than entering the shadow phase — see Decision § 5.)
- **(+)** **Reflexively self-consistent:** every extend-able surface is extended (the §7.2 table, the Maintainability value, the matrix cell), and the one net-new artifact — this ADR — carries its own `net-new because in-place infeasible` reason.
- **(+)** Provides the `net-new because in-place is infeasible: {reason}` **justification vehicle** the sibling net-new artifacts in this release (e.g. `skill-consultation-map.md`) use to record their net-new choice.
- **(−)** Limb-1 ("plausibly covers") is a **judgment call**, so enforce is a step-change in Stage-5 ceremony on the fire subset → **MODERATE** reversibility on that step, which is why the shadow→enforce lever was operator-gated at Stage 9 rather than shipped hot; the operator ratified day-one enforce at the v3.94 Stage 9 GO gate (2026-07-25), accepting the judgment-call risk with the self-repair override path.
- **(−)** SR-G6 has teeth only once the design records the determination; until the Solutioning persona habitually records it, limb coverage depends on reviewer diligence — and with day-one enforce there is no shadow phase to absorb early misses, so the return-to-Solutioning self-repair path (with operator override) carries that early-adoption load instead.

## Reversibility

**CHEAP / Confidence HIGH** for the introduction. Both corpus edits (the §7.2 SR-G6 row + predicate/posture/compose notes, and the `build-philosophy.md` Maintainability value + matrix cell + enforcer citation) are **additive and in-place** — no ID renumber, no verdict-enum change, no file move — so `git revert` restores the prior §7.2 and charter with no migration. The **enforce** posture is the one MODERATE element (it changes Stage-5 throughput on the scoped fire subset) and was held behind the operator-ratification lever at Stage 9; **the operator exercised that lever to day-one enforce at the v3.94 Stage 9 GO gate (2026-07-25).** Reverting enforce → shadow is a CHEAP text-only Authority-cell change (the fire predicate is unchanged), so the MODERATE tier reflects throughput impact, not rollback cost. The sibling SR-G5 / ADR-090 continue to hold the **shadow** posture — the SR-G5-shadow / SR-G6-enforce split is the intended, independently-governed asymmetry.
